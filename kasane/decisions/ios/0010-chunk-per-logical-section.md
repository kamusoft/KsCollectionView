## Context

ios/ADR-0009 は、1 つの配列を内部で固定件数の塊 (内部セクション) に分けて compositional layout のセクションに載せ、塊の順番で識別すると決めた。その見直しの条件に「グループ化機能で利用者のグループを入れるとき」を置き、グループは「グループ × 内部の塊」の 2 段を前提に設計すること、そのとき満たす 3 条件 (固定ヘッダーが塊の境界で止まらない・列数に合わない分割で不完全な行を作らない・先頭挿入で塊の所属が変わるときの差分更新と位置維持) を帰結に残した。

グループ化機能では、利用者は平らな配列のまま各項目のグループの値を指し、同じ値が続く項目が 1 つのグループになる (core/ADR-0015)。見出しは既定で上端に固定される。layout 値はコレクション全体で 1 つで、列数も 1 つである。

前提:

- compositional layout のセクションヘッダー (boundary supplementary item) とそのピン留めは、compositional layout のセクション単位で付き、UIKit は固定中の見出しをセクションの末尾で押し出す
- 押し出し中の見出しを UIKit が薄めるかは OS の版で違う。iOS 26.5 は押し出し量に応じて属性の透明度で薄め、iOS 18.6 は薄めない。iOS 16 は確かめていない

## Decision

ios/ADR-0009 の決定のうち「1 つの配列を塊に分け、塊の順番で識別する」を本決定で置き換える。塊の件数の決め方・組み直しの条件・境界を見た目に出さない規則・位置の維持を項目 ID に任せることは維持する。

### 塊の区切り方と識別

内部の塊はグループごとに、そのグループの先頭から区切る。1 つの塊が 2 つのグループにまたがることはなく、小さいグループは 1 つの塊になる。塊の件数は全グループ共通で、各グループの最後の塊は端数でよい。端数の行はグループの終わりにだけ現れる。グループを宣言しないときは、配列全体を 1 つのグループとして同じ経路で区切る。

内部セクションの識別は「グループの値 + そのグループの中での塊の順番」とする。同じグループの値が離れて現れる不正入力 (core/ADR-0015) を release で表示し続ける間は、識別に何回目のまとまりかを加えて区別する。

### 塊に割れたグループの見出しの固定

500 件を超えて複数の塊に割れたグループの見出しは、全塊に同じ見出しを pinned で付けたうえで、ライブラリがレイアウト属性の位置を書き換え、グループ全体で 1 つの見出しとして固定する。

- 固定中の見出しは、グループの見出しの本来の位置と固定の上端 (表示範囲の上端に上端の安全領域を足した位置。core/ADR-0017) の大きい方に置き、グループの下端から見出しの高さを引いた位置より下へは行かせない。グループの下端は、グループの最後の行の下端 (その行でいちばん背の高い項目の下端) とする
- 見出しの横位置と幅は、グループの先頭の塊の見出しに揃える
- 表示中の見出しは押し出し中も含めて常に不透明にし、同じグループの他の塊の見出しは透明にして読み上げの対象から外す

これにより塊の境目では見出しの隙間・行へのかぶり・動き・帯の欠けが出ず、グループの境目では固定見出しが次の見出しに押し上げられて (薄れずに) 入れ替わる。見出しは UIKit の supplementary view のままで、差分の適用と再利用は UIKit に任せる。固定を外したときは pinned を付けず、書き換えもしない。

## Alternatives Considered

- **塊を配列全体で区切り、グループの境界と無関係にする**: 却下。グループの見出しとピン留めは compositional layout のセクション単位で付くため、1 つの塊に複数のグループが載ると見出しを置けない。
- **全塊に通常の見出しを付けてピン留めするだけ**: 却下。見出しがグループ内で自分の高さの場所を取り、グループの途中に見出しの帯 (試作で 40pt) が挟まる。UIKit は塊単位で見出しを押し出すため、塊の境目にもグループの境目と同じ押し上げと薄れが出る。
- **2 つめ以降の塊の見出しを場所を取らない形にする (固定前は隠す工夫を含む)**: 却下。塊の先頭の行に見出しがかぶる (試作で 32pt)、または見出しの帯がまるごと消える瞬間が出る。場所を取らない見出しは左右の内側余白を無視して置かれ、入れ替わりで横にずれる。塊単位の押し出しは隠す工夫では消せない。
- **固定見出しを塊の見出しとは別の View としてライブラリが重ねて描く**: 却下。見た目は本決定と同じだが、見出しの内容・高さ・重なり順・読み上げの扱いをすべてライブラリが自前で持つことになる。
- **位置の書き換えだけ行い、押し出し中の薄れは UIKit 標準に任せる**: 却下。薄める版 (iOS 26.5) では押し出しの後半で見出しが見えなくなり、上端に見出しの無い帯 (試作で最大 24pt) が出る。オーナーの目視で、薄れずに押し上げられるほうが自然と判定した。
- **配列全体での塊の順番を識別に使い続ける**: 却下。グループの並び順が変わると、見出しが自分の項目と一緒に動かず、その場で書き換わって項目だけが移動するアニメーションになる。

## Consequences

- 正: 見出しとピン留めをグループの塊に置け、グループの並べ替えでは見出しが項目と一緒に動く。
- 正: 不完全な行はグループの終わりにしか出ず、ios/ADR-0009 の条件 (列数に合わない分割で行を欠かさない) を保つ。
- 正: 位置の維持は項目 ID のアンカーのまま、塊の境界に依存しない。
- 正: 押し出し中の見え方が、UIKit が薄める版と薄めない版で同じになる。
- 負: compositional layout のセクション数が、少なくともグループの数になる。小さいグループが多いデータでは数百〜数千になる。
- 負: 塊に割れたグループでは、同じ見出しのビューが塊の数だけ作られ、表示中の 1 つ以外を透明にして読み上げから外す処理をライブラリが持つ。
- 負: 500 件を超えるグループでは、見出しのレイアウト属性の位置と透明度をライブラリがスクロールのたびに書き換える。項目の追加・削除のアニメーション中の属性と、塊が多いときの書き換えの費用は、この書き換えの上で保守する。
- 負: グリッドでは行の中の項目の高さがそろわないため、グループの下端を求めるのに最後の行の項目をすべて見る必要がある。
- 負: UIKit が押し出し中の見出しを透明度以外の方法で薄める版では、薄れを打ち消せない。
- 負: グループをまたぐ挿入・削除では、2 つのグループの塊が同時に組み直る。

## Revisit When

- グループ化の性能を確かめる Sample 画面で、グループ数の多さが原因の体感不合格が出たとき
- ios/ADR-0009 の前提 (解き直しの費用はグループ単位) が崩れたとき
- UIKit が固定見出しの押し出しの見え方 (位置の動き・透明度での薄め) を変えたとき、または対応 OS の版で透明度以外の薄めが確認されたとき
