## Context

ios/ADR-0009 は、1 つの配列を内部で固定件数の塊 (内部セクション) に分けて compositional layout のセクションに載せ、塊の順番で識別すると決めた。その見直しの条件に「セクション / グループ化機能で利用者の論理セクションを入れるとき」を置き、論理セクションは「論理セクション × 内部の塊」の 2 段を前提に設計すること、そのとき満たす 3 条件 (固定ヘッダーが塊の境界で止まらない・列数に合わない分割で不完全な行を作らない・先頭挿入で塊の所属が変わるときの差分更新と位置維持) を帰結に残した。

セクション / グループ化機能では、利用者は平らな配列のまま各項目のグループの値を指し、同じ値が続く項目が 1 つの論理セクションになる (core/ADR-0015)。layout 値はコレクション全体で 1 つで、列数も 1 つである。

前提: compositional layout のセクションヘッダー (boundary supplementary item) とそのピン留めは、compositional layout のセクション単位で付く。固定中の見出しをセクションの末尾で押し出すとき、UIKit は位置をスクロールと 1:1 で動かし、押し出し量に応じて透明度で薄める (iOS 26.5 Simulator の試作で観測)。

## Decision

ios/ADR-0009 の決定のうち「1 つの配列を塊に分け、塊の順番で識別する」を本決定で置き換える。塊の件数の決め方・組み直しの条件・境界を見た目に出さない規則・位置の維持を項目 ID に任せることは維持する。

内部の塊は論理セクションごとに、そのセクションの先頭から区切る。1 つの塊が 2 つの論理セクションにまたがることはなく、小さい論理セクションは 1 つの塊になる。塊の件数は全セクション共通で、各論理セクションの最後の塊は端数でよい。端数の行は論理セクションの終わりにだけ現れる。

内部セクションの識別は「グループの値 + その論理セクションの中での塊の順番」とする。同じグループの値が離れて現れる不正入力 (core/ADR-0015) を release で表示し続ける間は、識別に何回目のまとまりかを加えて区別する。

500 件を超えて複数の塊に割れた論理セクションの見出しは、全塊に同じ見出しを pinned で付けたうえで、ライブラリがレイアウト属性の位置を書き換え、論理セクション全体で 1 つの見出しとして固定する。表示中の見出しは押し出し中も含めて常に不透明にする。これにより塊の境目では見出しの隙間・行へのかぶり・動き・帯の欠けが出ず、論理セクションの境目では固定見出しが次の見出しに押し上げられて (薄れずに) 入れ替わる。見出しは UIKit の supplementary view のままで、差分の適用と再利用は UIKit に任せる。

## Alternatives Considered

- **塊を配列全体で区切り、論理セクションの境界と無関係にする**: 却下。セクションヘッダーとピン留めは compositional layout のセクション単位で付くため、1 つの塊に複数の論理セクションが載ると見出しを置けない。
- **全塊に通常の見出しを付けてピン留めするだけ**: 却下。見出しがセクション内で自分の高さの場所を取り、論理セクションの途中に見出しの帯 (試作で 40pt) が挟まる。UIKit は塊単位で見出しを押し出すため、塊の境目にも論理セクションの境目と同じ押し上げと薄れが出る。
- **2 つめ以降の塊の見出しを場所を取らない形にする (固定前は隠す工夫を含む)**: 却下。塊の先頭の行に見出しがかぶる (試作で 32pt)、または見出しの帯がまるごと消える瞬間が出る。場所を取らない見出しは左右の内側余白を無視して置かれ、入れ替わりで横にずれる。塊単位の押し出しは隠す工夫では消せない。
- **固定見出しを塊の見出しとは別の View としてライブラリが重ねて描く**: 却下。見た目は本決定と同じだが、見出しの内容・高さ・重なり順・読み上げの扱いをすべてライブラリが自前で持つことになる。
- **位置の書き換えだけ行い、押し出し中の薄れは UIKit 標準に任せる**: 却下。押し出しの後半で見出しが見えなくなり、上端に見出しの無い帯 (試作で最大 24pt) が出る。オーナーの目視で、薄れずに押し上げられるほうが自然と判定した。
- **配列全体での塊の順番を識別に使い続ける**: 却下。グループの並び順が変わると、見出しが自分の項目と一緒に動かず、その場で書き換わって項目だけが移動するアニメーションになる。

## Consequences

- 正: 見出しとピン留めを論理セクションの塊に置け、グループの並べ替えでは見出しが項目と一緒に動く。
- 正: 不完全な行は論理セクションの終わりにしか出ず、ios/ADR-0009 の条件 (列数に合わない分割で行を欠かさない) を保つ。
- 正: 位置の維持は項目 ID のアンカーのまま、塊の境界に依存しない。
- 負: compositional layout のセクション数が、少なくとも論理セクションの数になる。小さいグループが多いデータでは数百〜数千セクションになり、その費用は実物で確かめるまで分からない。
- 負: 500 件を超える論理セクションでは、見出しのレイアウト属性の位置と透明度をライブラリが毎回書き換える。項目の追加・削除のアニメーション中の属性、読み上げでの見出しの数、塊が多いときの書き換えの費用は、この書き換えの上で保守する。
- 負: UIKit が押し出し中の見出しを透明度以外の方法で薄める版では、薄れを打ち消せない。
- 負: 論理セクションをまたぐ挿入・削除では、2 つの論理セクションの塊が同時に組み直る。

## Revisit When

- グループ化の性能を確かめる Sample 画面で、セクション数の多さが原因の体感不合格が出たとき
- ios/ADR-0009 の前提 (解き直しの費用はセクション単位) が崩れたとき
- UIKit が固定見出しの押し出しの見え方 (位置の動き・透明度での薄め) を変えたとき
