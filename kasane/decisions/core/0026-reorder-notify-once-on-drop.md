## Context

D&D 並べ替え機能 (ロードマップ v1-foundation) で、ドラッグで動かした結果を利用者の VM へどう渡すかを決める。KsCollectionView は利用者のプレーンな配列を唯一の正として受け取り、差分計算とアニメーションはライブラリが担う (core/ADR-0003)。並べ替えもこの前提の上に置く。主な利用者は KMP の共有 VM が公開する配列 (`StateFlow` など) をそのまま渡す書き方をとる。

各 OS の慣習は分かれる。iOS は SwiftUI の List の並べ替えも iOS 27 の SwiftUI 標準の並べ替えもドロップの後に 1 回知らせ、UIKit 標準のドラッグ & ドロップはドラッグ中は隙間 (プレースホルダ) を見せるだけで配列に触らない。Android は RecyclerView の ItemTouchHelper も Compose の OSS (`sh.calvin.reorderable`) も、項目が入れ替わるたびに知らせて利用者がその場でリストを書き換える作りである。Compose には公式の並べ替え API が無い。

前提: iOS は UIKit の並べ替えが一覧の表示の上で見せる並びで、Android はラッパーの中に持つ仮の並びで、ドラッグ中の並びを利用者の配列から切り離して見せられる。

## Decision

並べ替えは、指を離したときに 1 回だけ「どの項目をどこへ置いたか」を利用者へ知らせる。ドラッグ中の仮の並びはライブラリが持ち、利用者の配列は書き換えない。利用者の VM が知らせを受けて配列を並べ替えて渡し直したところで、表示の並びが確定する。両プラットフォームとも同じ時機にし、Android の慣習の「入れ替わるたびに知らせる」形には合わせない。

この決定に含まないもの: 行き先の表し方 (ID か位置か、グループをまたぐときの行き先) と、利用者が並べ替えを受け入れなかったとき・保存に失敗したときに表示を元に戻す仕組み (core/ADR-0027)。

## Alternatives Considered

- **項目が入れ替わるたびに知らせ、VM がその都度配列を並べ替えて渡す**: 却下。画面と配列がいつも一致するが、指が項目をまたぐたびに VM の処理が走り、KMP の共有 VM では画面の反映が指より遅れうる。保存のために、ドラッグの終わりを知らせる口も別に要る。
- **ライブラリが利用者の配列を直接書き換える (書き換えられる配列を受け取る)**: 却下。VM の手間はいちばん少ないが、プレーンな配列を受け取る契約 (core/ADR-0003) を改めることになり、KMP の共有 VM が公開する配列をそのまま渡せない。

## Consequences

- 正: 配列が唯一の正のまま並べ替えを足せ、KMP の共有 VM の配列をそのまま使える。ドラッグ中に共有 VM とやり取りしない。
- 正: 知らせを受けたときがそのまま保存の契機になり、ドラッグの終わりを別に知らせる口が要らない。
- 正: iOS の利用者が知っている形 (SwiftUI の並べ替えと同じ時機) になる。
- 負: 利用者が知らせを受けても配列を並べ替えなかったときに表示を元に戻す仕組みが別に要る。同じ値を流さない公開の仕方 (`StateFlow` など) では、配列を渡し直すだけでは戻せない。
- 負: Android の慣習とは時機が違い、入れ替わるたびに知らせる作りの OSS を使う場合も、ラッパーの中で仮の並びを持って包む必要がある。
- 負: ドラッグ中から確定までは表示の並びと配列がずれるため、その間に配列が差し替わったときの扱いを決める必要がある。
