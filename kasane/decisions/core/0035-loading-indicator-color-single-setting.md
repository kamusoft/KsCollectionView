## Context

ライブラリが自分で出す読み込み中の表示は 3 つある。ページングの「次のページの読み込み中」と「最初の読み込み中」は各プラットフォームの標準のくるくるで出し (core/ADR-0024)、Pull to Refresh のインジケータは各プラットフォームの標準の部品で出す (core/ADR-0023)。どれにも色を指定する設定は無い。

標準のくるくるの色は、iOS では親の View に付けた tint、Android では Material のテーマの primary になる。Pull to Refresh のインジケータは、両プラットフォームとも標準のグレー系で出る。そのため、tint や primary にアクセント色を当てたアプリでは、同じ一覧の中でくるくるがアクセント色、Pull to Refresh がグレーになり、読み込み中の色がそろわない (Sample と承認済みのモックの照合で観測)。

ページングの 2 つの表示には利用者が中身を差し替える口があるが、Pull to Refresh には無い。Pull to Refresh はページングを付けない一覧でも使える。ライブラリは標準の表示のための色の値を持っていない。

iOS の標準の Pull to Refresh の部品は、渡した色をそのままでは描かない。色の成分を 2 回掛け合わせた色を、いちばん濃い所でも半透明で描く。色を指定しない標準の色も同じ描き方で、公開の手段では濃さを変えられない。そのため、色をそのまま渡すと指定より暗く薄く出て、中間の明るさの色は暗い下地の上でほとんど見えなくなる。

前提: ページングの 2 つの表示を個別の色にしたい利用者は、差し替え口で自分の表示を出せば足りる。

## Decision

ライブラリが出す読み込み中の表示 3 つ (次のページの読み込み中・最初の読み込み中・Pull to Refresh のインジケータ) の色を、一覧に付ける 1 つの設定でまとめて指定できるようにする。

- 指定した色は 3 つの表示に同時に効く。表示ごとに色を分ける設定は持たない
- 効くのはライブラリが描く表示だけで、利用者が差し替え口に書いた表示には効かせない。差し替えた中身へ色を流す手段が両プラットフォームでそろわないためである
- 設定の置き場は一覧そのものとし、ページングの設定の中には置かない。Pull to Refresh がページングを付けない一覧でも使えるためである
- 指定しないときは、3 つとも各プラットフォームの標準の色のままにする。ライブラリは既定の色の値を持たず、指定しない一覧の見え方は変えない
- Pull to Refresh のインジケータは、色を指定しても各プラットフォームの標準の部品で出す (core/ADR-0023 を保つ)。iOS では、標準の部品が指定した色みで描くように補正した色を渡す。色みは指定どおりになり、濃さは標準の Pull to Refresh と同じで、ほかの 2 つより薄い

設定の名前と形、Android の Pull to Refresh のインジケータの丸い下地の色の扱いは、この決定に含まない。

## Alternatives Considered

- **ページングの読み込み中 (2 つ) と Pull to Refresh で色の設定を分ける**: 却下。Pull to Refresh だけ別の色にしやすいが、そろえるには 2 か所に同じ色を書くことになり、公開 API が各プラットフォーム 2 つになる。
- **3 つの表示それぞれに色の設定を持つ**: 却下。そのまま個別に変えられるが、公開 API・ドキュメント・テストが最も増え、そろえるには 3 か所に書く。ページングの 2 つは差し替え口で個別に変えられる。
- **指定しないときは、ライブラリの固定のグレーで 3 つをそろえる**: 却下。指定しなくてもそろい、両プラットフォームで同じ実値になるが (区切り線の既定の色と同じ方針 — core/ADR-0010)、ライブラリがライトとダークの 2 組の色の値を持ち、表示モードを判定する仕組みが要る。指定しない一覧の見え方が変わり、色がライブラリ独自になる。
- **指定しないときは、テーマの色 (iOS の tint、Android の primary) で 3 つをそろえる**: 却下。指定しなくてもそろうが、Pull to Refresh が両プラットフォームの標準のグレーから外れる。
- **iOS で色を指定したときは、標準の部品の絵の代わりにライブラリがくるくるを描く**: 却下。3 つが同じ部品・同じ濃さでそろうが、引っ張っている途中の標準の動きが無くなり、Pull to Refresh を標準の部品で出す決定 (core/ADR-0023) から外れる。
- **iOS の標準の部品に、指定した色をそのまま渡す**: 却下。実装は最も単純だが、指定より暗く薄く出て、色を指定するとかえって見えにくくなる場合がある。彩度のある色は色みもずれる。
- **指定しないときは、Pull to Refresh の標準のグレー系で 3 つをそろえる**: 却下。指定しなくてもそろい、色の値を持たずに表示モードにも追随するが、Android のくるくるが Material の標準 (primary) から外れる。

## Consequences

- 正: 1 か所の指定で、同じ一覧の 3 つの読み込み中の表示の色が必ずそろう。
- 正: 指定しない一覧は、各プラットフォームの標準の見え方のまま変わらない。ライブラリは色の値を持たず、表示モードへの追随は OS とテーマに任せられる。
- 正: 公開 API の追加は各プラットフォーム 1 つで済む。
- 負: 指定しない限り、tint や primary にアクセント色を当てたアプリでは、くるくると Pull to Refresh の色がそろわないまま残る。
- 負: 指定しないときの色は、両プラットフォームで同じ実値にならない。両プラットフォームで見た目をそろえるアプリは、自分で色を指定する。
- 負: 3 つのうち一部だけを別の色にするには、ページングの表示を差し替え口で書く必要がある。
- 負: Android では、ページングの表示に効く設定が、ページングの設定の引数と一覧の引数に分かれる。
- 負: iOS では、同じ色を指定しても Pull to Refresh のインジケータだけ薄く出る。色の系統はそろうが、濃さはそろわない。
- 負: iOS の補正は、標準の部品の文書に無い描き方に頼る。OS が描き方を変えると、指定と違う明るさで出る。
