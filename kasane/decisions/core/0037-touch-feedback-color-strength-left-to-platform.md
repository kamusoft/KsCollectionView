## Context

項目をタップしたときの反応は、ハンドラを宣言した項目だけが出し、既定は各プラットフォームの標準の塗りである (iOS はハイライト、Android は material3 の波紋 — android/ADR-0003)。利用者は反応の色を指定できる。

指定した色の扱いは両プラットフォームで違う。iOS は渡した色をそのままセルの全面に塗るので、色も濃さも利用者が決める。Android は渡した色を標準の波紋に渡し、波紋は色みだけを使って濃さを自分で決める。

この違いは「同じ値を渡すと Android ではほとんど見えなくなる」ものとして記録され、Sample は両プラットフォームに違う値を渡して見た目をそろえていた。統一の方向は後続の変更で決めることになっていた (android/ADR-0003 の帰結)。

既定の色のダーク対応の探索で、ライブラリが使う版の波紋の実装を読んだところ、波紋は渡した色の不透明度を捨てて自前の値に置き換えており、掛け合わせてはいなかった。提案の段階で Android 16 のエミュレータの画素を比べ、不透明な色を渡したときと、同じ色みの 15% の色を渡したときで、押している間の見え方が一致することを確かめた。統一の動機だった「見えなくなる」は成り立たない。

前提: Android の標準の波紋は、渡した色の不透明度を使わず、標準の濃さで描く (不透明度を置き換える処理は、OS の版によらない Compose のライブラリの側にある)。

## Decision

タップしたときの色の設定は、両プラットフォームで同じ語彙のまま、濃さの決まり方を各プラットフォームの標準の部品に任せる。iOS は渡した色をそのまま塗り、Android は標準の波紋に渡す。ライブラリは両プラットフォームの濃さをそろえる加工をしない。

利用者には、両プラットフォームで近い見え方にしたいときは半透明の色を渡すよう案内する。Sample は両プラットフォームに同じ値を渡す。

統一の動機が成り立たないと分かったことと、標準の部品を保って濃さの違いを受け入れる考え方が読み込み中の表示の色 (core/ADR-0035) と同じであることが理由である。

## Alternatives Considered

- **両プラットフォームとも渡した色の濃さで塗る (Android を変える)**: 却下。利用者が濃さも決められるようになるが、Android のタップの反応を自前で組み直す必要がある。波紋を残す形では OS の係数が残って正確にはそろわず、頼る API は形が変わりつつある。不透明な色を渡すと両プラットフォームで中身が隠れる。
- **両プラットフォームとも色みだけを指定し、濃さは約 10% にする (iOS を変える)**: 却下。同じ値でほぼ同じ見え方になるが、iOS で今できる濃さの指定ができなくなり、iOS の濃さは標準の値ではなくライブラリが決めた値になる。

## Consequences

- 正: ライブラリのコードを変えず、各プラットフォームの標準のタップの反応を保てる。
- 正: Sample は両プラットフォームに同じ値を渡せる。
- 負: 同じ半透明の色を渡しても、濃さは両プラットフォームで一致しない (iOS は指定どおり、Android は標準の濃さ)。
- 負: 不透明な色を渡すと、iOS だけセルの中身が隠れる。
- 負: Android では濃さを指定できず、濃さは Material と OS の版に依存する。

## Revisit When

- 両プラットフォームの濃さの違いが、目視または利用者の報告で受け入れられないと判断されたとき (次の候補は「両プラットフォームとも色みだけを指定する」)
- 前提 (Context) が崩れたとき
