## Context

グループの見出しは既定でスクロール時に上端へ固定される (core/ADR-0015)。利用者が一覧を画面の全体に広げて置く (iOS の `.ignoresSafeArea()`、Android の edge-to-edge) と、一覧の上端はステータスバーやナビゲーションバーの裏にあり、上端に固定した見出しがバーの裏に隠れる。iOS では、項目・見出しの SwiftUI の中身が上端の安全領域に重なった分だけ押し下げられ、高さが増える既存の挙動もあった。

`contentPadding` は「コンポーネント本体とスクロールするコンテンツの間の内側余白」で、ルートのヘッダーの上とフッターの下に入る (core/ADR-0006、core/ADR-0015)。安全領域はこれまで仕様で扱っていなかった。

オーナーは iOS の連絡先アプリの見え方 (見出しはバーのすぐ下で止まり、行はバーの裏を流れる) を正解として示し、Android の edge-to-edge でも同じ現象が起きるため両プラットフォームで揃えるとした。

前提: 出典に前提の記載なし。

## Decision

一覧を全画面に広げて置いた場合、ライブラリが安全領域に合わせるのは、固定中のグループの見出しを上端の安全領域の境目 (バーのすぐ下) より上へ行かせないことだけとする。行はバーの裏を流れる。

- 固定の上端は「表示範囲の上端 + 上端の安全領域」とする。見出しの押し上げ、固定中の見出しに覆われた範囲、回転での位置の復元、ID によるスクロール命令も同じ境目を基準にする
- コンテンツの先頭・末尾には安全領域の分の内側余白を足さない。ルートのヘッダーは安全領域に被ってよく、バーの分の大きさは利用者がルートのヘッダーの大きさで調整する。下端のルートのフッター・最後の行も同じ扱いとする
- 項目・見出し・ルートのヘッダー / フッターの中身は、上下の安全領域の分だけ押し下げない (iOS では SwiftUI の中身に上下の安全領域を渡さない)
- 安全領域に重ならない置き方では、追加の値はすべて 0 で見え方は変わらない
- 左右の安全領域 (横向き) は本決定の対象外とし、従来の挙動のままとする

## Alternatives Considered

- **コンテンツの先頭・末尾を安全領域の内側に収める (ルートのヘッダー・最初の見出しと最後の行が、初期状態で安全領域の内側に来るように余白を足す)**: 却下。ルートのヘッダーの配置は利用者の責任とする (オーナー判断)。

## Consequences

- 正: 全画面に広げた一覧でも、固定中の見出しがバーに隠れず、行はバーの裏を流れる。
- 正: 安全領域に重ならない普通の置き方と、`contentPadding` の意味論は変わらない。
- 正: ライブラリが安全領域を使う箇所が固定の上端の 1 つに絞られ、利用者の余白の指定と二重にならない。
- 負: 全画面に広げた一覧では、利用者がルートのヘッダーの大きさなどでバーの分を空けない限り、初期状態でコンテンツの先頭がバーの裏に入り、末尾も同様に下端のバーの裏に入る。
- 負: 固定の上端を基準にする処理 (押し上げ・覆われた範囲・回転の復元・スクロール命令) のすべてが安全領域の値を読み、両プラットフォームで安全領域の求め方を保守する。
- 負: iOS の項目・見出しの SwiftUI の中身は上下の安全領域を受け取れない。
