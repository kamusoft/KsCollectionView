## Context

list の区切り線の既定の色は、両プラットフォームで同じ実値を比べられるように固定値 1 つと決めていた (core/ADR-0010。OS の semantic color に任せる案はこの理由で却下)。この決定はダークの表示モードを考えていなかった。Sample にライト / ダークの切り替えを入れたところ (cross/ADR-0007)、ライブラリの既定の色について次が見えた。

- 区切り線は、両プラットフォームともダークで明るい線のまま残る
- 画像の読み込み中・失敗の表示は、iOS が OS の灰色を借りていてダークに追随し、Android は固定の灰色でダークでも明るいまま。値はライトでも両プラットフォームで違う

オーナーの目視では、Android の画像の読み込み中の色がダークで明るいまま残る点が問題と判断された。区切り線がダークで明るく残る点は、その時点では問題なしと判断されていた。

同じ問題を先に直した KsSettingsView は、ライブラリがライト / ダーク 2 組の既定の色を持ち、未指定の色だけを表示モードで解決する形を採っている。オーナーの指示で、この形を骨格にする。

前提: ライブラリは配布前で、既定の見え方が変わって困る外部の利用者がいない。利用者のアプリは、端末の表示モードに従うか、画面の構成を上書きして外観を切り替える。

## Decision

ライブラリが自前の値を持つ既定の色 (list の区切り線、画像の読み込み中の表示、画像の失敗の表示) は、ライト用とダーク用の 2 組の固定値で持つ。利用者が色や表示を指定しないときだけ、描くときの表示モードの側の値を使う。値はライト・ダークとも両プラットフォームで同じにする。

利用者が指定した色に、ライブラリは手を加えない (表示モードによって別の色に差し替えない)。色を受け取る公開 API の形は今までどおりで、ライト / ダークの対を表す型は足さない。

表示モードは、iOS は OS が持つ外観の情報 (アプリが上書きした外観を含む) で決める。Android は画面の構成の夜間モードで決める (通常は端末の表示モードに追随し、アプリが画面の構成を上書きしたときはその値)。Material のテーマの配色は判定に使わない。

既定の色の扱いをライブラリの中で 1 通りにし、両プラットフォームで同じ実値を比べられる状態 (core/ADR-0010 が固定値を選んだ理由) をダークでも保つためである。

OS や Material の標準の部品に色を任せている表示 (タップの既定の反応、スクロールインジケータ、読み込み中の表示) は、本決定で値を持つ対象にしない。具体的な値は本決定に含まない。

core/ADR-0010 の決定のうち「色: 既定はライブラリ内部の固定値」を本決定で置き換える。他の決定は維持する。

## Alternatives Considered

- **区切り線は固定値のままにし、画像の色だけ直す**: 却下。画像の既定の色に 2 組の仕組みを入れるのに区切り線だけ固定だと、既定の色の扱いがライブラリの中で 2 通りになる。切り替える作業は小さく、配布前で既定の見え方が変わって困る利用者もいない。
- **画像は Android にダークの値を足すだけにする (iOS は OS の灰色のまま、ライトの値は今のまま)**: 却下。両プラットフォームの値が違うまま残り、値をテストで固定できるのが Android だけになる。
- **画像は Android を iOS の値に合わせ、iOS は OS の灰色を借りたままにする**: 却下。見た目はほぼそろうが、両プラットフォームの値が同じであることをテストで保証できず、iOS だけ別の扱いになる。
- **Android の表示モードをアプリの Material テーマの明るさで決める**: 却下。Material の配色だけでダークにするアプリには追随するが、Material のテーマを使わないアプリでは端末がダークでも常にライトと判定される。iOS に対応するものもない。
- **Android で、利用者が表示モードを渡せる入口を足す**: 今回は採らない。Android だけの公開 API が増える。必要になった時点で足せる。

## Consequences

- 正: 何も指定しない一覧と画像が、ライト・ダークのどちらでも両プラットフォームで同じ色になる。
- 正: 既定の色を、ライト / ダークそれぞれの値で両プラットフォームのテストに固定できる。
- 負: iOS の画像の既定の色が OS の色でなくなり、OS の「コントラストを上げる」設定や将来の OS の配色の変更に追随しない。
- 負: 今は両プラットフォームで値が違う画像の既定の色は、少なくとも一方でライトの見え方が変わる。
- 負: Android で、画面の構成を変えずに Material の配色だけでダークにするアプリでは、既定の色がアプリの見た目とずれる。利用者が色を指定するか、表示を差し替える必要がある。
- 負: 利用者が既定と同じ値を色として指定すると、その色は指定した色として扱われ、ダークでも変わらない。
- 負: ライブラリが値を持つ既定の色を足すたびに、ライト / ダーク 2 つの値を決めて保守する必要がある。

## Revisit When

- Android で、Material の配色だけでダークにするアプリから既定の色のずれが報告されたとき (表示モードを渡す入口を足すかを決める)
- 前提 (Context) が崩れたとき
