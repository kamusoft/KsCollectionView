## Context

セクション / グループ化機能 (ロードマップ v1-foundation) で、利用者がグループをどう宣言するかを決める。KsCollectionView は利用者のプレーンな配列と安定 ID を受け取り、差分計算とアニメーションはライブラリが担う (core/ADR-0003)。並べ替えはデータ層で行い、ライブラリは差分の移動アニメーションを出すだけで、並べ替えの DSL は持たない。旧 AiForms.CollectionView はグループのコレクションを渡す形だった (core/ADR-0009 で議論素材として申し送り)。

API 設計の判断軸として、項目のモデルに手を入れないこと、配列を 1 種類の型に保つこと、KMP の共有モデルを改造せずに使えることを置いている。

前提: 空のグループ (項目が 0 件のグループ) の見出しを出す必要がある画面は、決定の時点で挙がっていない。

## Decision

利用者は今までどおり平らな配列を渡し、各項目の「どのグループか」を表す値 (グループの値) をキーパス / ラムダで指す。ライブラリは配列の順に、同じグループの値が続く項目をまとめて 1 つのセクションにする。セクションの識別はグループの値で行う。

同じグループの値が配列の離れた位置に再び現れる入力 (並べ替え忘れ) は不正入力として扱う (core/ADR-0011 の方針)。利用者アプリの debug ビルドでは assertion で知らせ、release では配列の順のまま別々のセクションとして表示を続け、警告ログを出す。同じ値をわざと何度も使う用途 (送信者ごとの連続したメッセージのまとまりなど) は、グループの値に何番目のまとまりかを含めて表す。

セクションごとに layout 値を持たせる入れ物は無く、layout 値はコレクション全体で 1 つのまま (core/ADR-0006) とする。

セクションのヘッダーは任意の View / Composable で書ける。宣言のクロージャには、そのグループの値と、そのセクションに入る項目が渡される。高さは中身から自動で決まり、高さの指定は持たない (旧 `GroupHeaderHeight` は継承しない)。グリッドでは全幅を占める。セクションが持つのはヘッダーだけで、セクションのフッターは持たない。

セクションのヘッダーは既定でスクロール時に上端へ固定し、設定 1 つで固定を外せる (区切り線の既定表示・opt-out と同じ形)。

セクションとセクションの間の間隔は、行間と同じく layout 値の引数 1 つで宣言する (既定 0。core/ADR-0006 の「間隔は layout 値で宣言する」)。間隔は前のセクションの最終行の後、次のセクションの見出しの前に入り、リストの先頭と末尾には入らない (端は `contentPadding` が受け持つ)。見出しとそのセクションの先頭行の間の間隔も、専用の引数 1 つで宣言する (既定 0。旧 `GroupFirstSpacing` 相当)。行間は行と行の間にだけ入り、見出しの上下には入らない。

```swift
KsCollectionView(items) { item in Row(item) }
    .sections(by: \.category) { category, itemsInSection in Header(category, count: itemsInSection.count) }
```

```kotlin
KsCollectionView(items = items, key = { it.id },
    sections = KsSections(by = { it.category }) { category, itemsInSection -> Header(category, itemsInSection.size) },
) { template { item -> Row(item) } }
```

グループの値・見出し・固定の有無は 1 つの宣言 (Swift は modifier、Kotlin は `KsSections` 型の引数) にまとめ、グループの値の型を保ったまま見出しに渡す。見出しと固定の設定は省略できる。

## Alternatives Considered

### 宣言の形

- **グループの配列を渡す (各グループが見出しの情報と項目の配列を持つ。旧 AiForms と同じ形)**: 却下。項目とは別にグループの型が要り、配列が 1 種類の型でなくなる。共有モデルが平らな配列を返す場合は VM でグループに組み直す必要がある。並べ替えをデータ層に置く決定 (core/ADR-0003) に対して、グループ分けを利用者が組み直す手間が残る。
- **両方の入口を用意する**: 却下。公開 API の入口が 2 つになり、両プラットフォームの実装・テストと利用者向けドキュメント (en/ja の Skill) がそれぞれ倍になる。

### 同じグループの値が離れて現れる入力

- **離れて現れた同じ値を 1 つのセクションに集める**: 却下。並べ替え忘れを黙って直すため気づけず、画面の並び順が配列の順とずれてスクロール命令や位置の指定と食い違う。
- **離れて現れた同じ値を正当な入力として別々のセクションにする**: 却下。並べ替え忘れに気づけない。同じ値が複数あるとセクションの識別が「値 + 何回目か」になり、あいだに別のまとまりが入ると番号がずれてヘッダーの差分アニメーションが崩れやすい。

### 見出しと余白

- **セクションのフッターも用意する (ルートのヘッダー / フッターと揃える)**: 却下。旧 AiForms でも実績のある用途でも使うのは見出しだけで、フッターは後から宣言を足しても既存の利用者コードを壊さない。フッターがあると固定ヘッダーの押し出しやセクション末尾の区切り線・余白の組み合わせが増える。
- **見出しを既定では固定せず、指定したときだけ固定する**: 却下。ロードマップのゴールと実績のある用途は固定される見出しが前提で、毎回 1 行を書かせることになる。iOS 標準の plain なリストも既定で固定する。
- **見出しを常に固定し、設定を持たない**: 却下。見出しを大きな帯やバナーとして使い、固定したくない画面を作れない。
- **セクション間の余白の設定を持たず、見出しの View の余白で作る**: 却下。固定された見出しが余白ごと上端に貼り付き、見出しの上に空白の帯が残る。見出しの無いセクションの間を空けられない。
- **セクションの後ろの余白を持つ (`GroupLastSpacing` 相当)**: 却下。前のセクションの最終行と次の見出しの間はセクション間の間隔が受け持ち、リストの末尾は `contentPadding` が受け持つ。
- **見出しの上下にも行間を入れる (見出しを行と同じに扱う)**: 却下。見出しと先頭行の間だけを行間と別の値にできない。
- **見出しと先頭行の間を見出しの View の余白で作る**: 却下。固定された見出しが余白ごと上端に貼り付き、見出しの下に空白の帯が残る。

## Consequences

- 正: 既存の API に引数とヘッダーの宣言を足すだけで、項目のモデル・配列の型・KMP の共有モデルに手を入れずにグループ化できる。
- 正: データ層で並べた順がそのままグループになり、項目を別グループへ動かすのはグループの値を変えるだけで済む。
- 負: 項目が 0 件のグループは存在できず、その見出しも出せない。
- 負: ヘッダーに出せる情報は、グループの値そのもの (構造体でもよい) とセクション内の項目から取れるものに限られる。
- 正: 正しい入力ではセクションの識別がグループの値そのものになり、並べ替え忘れには開発中に気づける。
- 負: 同じ値を何度も使う用途では、利用者がグループの値に何番目のまとまりかを含める手間を負う。release で不正な入力を受けた間は同じ見出しが複数回表示され、ライブラリはその間だけ同じ値のセクションを内部で区別する。
- 負: 一覧の中でセクションごとに list とグリッドを切り替えることはできない。
- 負: グループ末尾の「もっと見る」や小計の行は、グループの最後の項目のテンプレートに含めて作ることになる。後からフッターを足すときは、セクション末尾の区切り線と余白の規則を見直す。
- 負: 固定あり / なしの 2 通りを、両プラットフォームで同じ見え方に揃えて保守する。
- 負: 旧 AiForms (グループのコレクション) からの移行では、利用者がデータの形を平らに直す必要がある。
