## Context

並べ替えは指を離したときに 1 回だけ利用者へ知らせ (core/ADR-0026)、知らせを受ける処理はその場で受け入れたかを返す (core/ADR-0027)。その知らせで「どの項目をどこへ置いたか」をどう表すかを決める。

グループを宣言した一覧では、前のグループの末尾と次のグループの先頭は配列の中では同じ位置なのに所属が違う。グループをまたいで動かすと VM は項目のグループの値を書き換える必要があるため、どちらかを区別できなければならない。KMP の共有 VM では、画面に出ている配列と VM の最新の配列がずれていることがある。

既存の契約では、スクロール命令は項目の ID で指し (core/ADR-0007)、位置で指す状態モデルは却下している (core/ADR-0003)。iOS 27 の SwiftUI 標準の並べ替えは「この ID の前 / 末尾」とコレクションで行き先を表し、SwiftUI の List の並べ替え (`onMove`) と Compose の OSS は位置で表す。

前提: 項目の安定 ID は配列の中で一意である (core/ADR-0003)。

## Decision

並べ替えの知らせでは、動かした項目と行き先を位置 (何番目) ではなく項目で表す。項目はタップの知らせと同じく配列の要素そのものを渡す。行き先は「この項目の前」か「このグループの末尾」(グループを宣言していなければ一覧の末尾) のどちらかで表し、グループを宣言しているときは行き先のグループの値を添える。

この決定に含まないもの: 知らせの型や名前の形と、移動を配列に当てはめる補助関数を用意するかどうか (提案で設計する)。

## Alternatives Considered

- **位置 (何番目から何番目へ) で表し、行き先のグループの値を足す**: 却下。VM の書き方はいちばん短く SwiftUI の `onMove` や Compose の OSS と同じだが、KMP で画面の配列と VM の最新の配列がずれると別の場所へ動き、「何番目」が取り除く前か後かで間違えやすい。
- **置いた後の並びを丸ごと渡す**: 却下。VM は置き換えるだけで済むが、大量件数では毎回全件を渡すので重く、置いてから処理するまでの配列の変化を消してしまい、保存のために動かした項目を VM が割り出す必要がある。

## Consequences

- 正: 前のグループの末尾と次のグループの先頭を区別でき、VM は書き換える先のグループの値を知らせから得られる。
- 正: 置いてから VM が処理するまでに配列が変わっても、行き先の意味が変わらない。
- 正: スクロール命令・状態モデルと同じく、項目で指す契約にそろう。
- 負: VM は行き先の項目を配列から探して入れる手間がかかり、位置で表す SwiftUI の `onMove` より書く量が多い。
- 負: 行き先の項目が VM の処理の時点で配列から消えている場合の扱い (受け入れないと返す等) は VM が決める必要がある。
