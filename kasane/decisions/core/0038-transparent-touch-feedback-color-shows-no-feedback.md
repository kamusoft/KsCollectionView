## Context

項目をタップしたときの反応は、ハンドラを宣言した項目だけが出し、利用者は反応の色を指定できる。指定した色の扱いは両プラットフォームで違い、iOS は渡した色を不透明度を含めてそのまま塗り、Android は標準の波紋に渡して色みだけを使わせる (core/ADR-0037)。

このため、完全に透明な色を渡したときの結果が両プラットフォームで分かれていた。iOS では何も見えず、反応を消したのと同じになる。Android では波紋が不透明度を捨てて標準の濃さで塗るため、透明の色みである黒が灰色の帯として出る。Android には反応を消す手段がほかに無い。

この食い違いは、ライブラリを使うアプリ (ColorAnalyzer の KMP 版) が反応を消すつもりで透明を渡したところ、Android だけ押した直後に灰色の帯が見えたことで分かった。

前提: Android の標準の波紋は、渡した色の不透明度を使わず、標準の濃さで描く (core/ADR-0037 と同じ前提)。iOS は渡した色をそのまま塗るため、完全に透明な色は見えない。

## Decision

タップしたときの色に完全に透明な色を渡したら、両プラットフォームとも反応を出さない。iOS は今の塗り方のままでこの結果になり、Android は完全に透明な色を受け取ったときだけ標準の波紋に渡さず、反応を出さない。反応を消す専用の設定は足さない。

core/ADR-0037 の決定のうち「Android は渡した色を標準の波紋に渡す」を、完全に透明な色を除く形に置き換える。他の決定 (濃さを各プラットフォームの標準の部品に任せ、そろえる加工をしないこと) は維持する。

同じ値を渡せば両プラットフォームで同じ結果になり、公開 API を変えずに反応を消す手段を持てることが理由である。

## Alternatives Considered

- **反応を消す専用の設定を両プラットフォームに足す**: 却下。色と反応を出すかどうかを別々に指定できるが、両プラットフォームの公開 API が増える。iOS ではすでに透明を渡せば反応が消えるので、透明で消す形でも意味は通る。

## Consequences

- 正: 完全に透明な色を渡せば、両プラットフォームで反応が消える。
- 正: 公開 API は変わらない。
- 負: Android では、渡した色の不透明度は濃さには効かないのに、完全に透明かどうかだけは結果を変える。不透明度の扱いに例外が 1 つできる。
- 負: ほとんど透明な色 (完全に透明ではない色) を渡すと、Android では標準の濃さの反応が出る。
