## Context

配列の差し替えで表示範囲の位置をどう保つかは、プラットフォームの既定で違う。iOS はコンテンツの位置を保ち、Android (`LazyGridState`) は見えている先頭の項目の位置を保つ。差分とアニメーションはライブラリの責務である (core/ADR-0003)。

グループ化機能の差分のアニメーションを両プラットフォームの試作で見比べたところ、Android ではいちばん上で先頭に挿入すると、挿入した項目が表示範囲の上に外れて見えなかった (オーナーが NG と判定)。いちばん下で末尾に挿入すると、挿入した項目が表示範囲の下に外れる現象は両プラットフォームで起きていた。

前提: 表示範囲の外での挿入は利用者に見えないので、振る舞いを揃える利得が無い (オーナー判断)。

## Decision

両プラットフォーム・list / グリッドの両方で、端を表示中の端への挿入はアニメーションが見えるようにする。

- 配列を差し替える直前に、表示範囲がコンテンツの先頭にあるか (上端がコンテンツの上端と一致) と末尾にあるか (下端がコンテンツの下端と一致) を控える。1pt / 1px 未満の差は一致とみなす。コンテンツの先頭・末尾は、ルートのヘッダー / フッターがあればその外側の端とする
- 差し替えで先頭に項目が入り、直前に先頭にいた場合は、表示範囲を先頭に留める
- 差し替えで末尾に項目が入り、直前に末尾にいた場合は、表示範囲を末尾に留める
- 留め方は、挿入のアニメーションと同時に表示範囲が端に追従する形にし、挿入 → 反映後に改めてスクロール、の 2 段の動きにしない
- どちらでもない差し替えは、各プラットフォームの既定の位置の保ち方のままとする

## Alternatives Considered

- **Android の先頭だけを直す**: 却下。末尾への挿入は両プラットフォームで下に外れて見えないまま残る。
- **表示範囲の位置の保ち方を、両プラットフォームで常に同じ方式 (コンテンツの位置、または見えている先頭の項目) に揃える**: 却下。画面外での挿入まで振る舞いを変えることになるが、画面外の挿入は見えないので揃える利得が無い。

## Consequences

- 正: 端を見ている利用者には、端への挿入が常にアニメーションで見え、画面外でひっそり足されたように見えない。
- 正: 端以外の差し替えの振る舞いは各プラットフォームの既定のままで、既存の位置の保ち方を変えない。
- 負: 端以外を表示中の、表示範囲より前への挿入・削除では、表示範囲の位置の保ち方が両プラットフォームで違ったまま残る。
- 負: 末尾に項目を足す操作でも、末尾を表示中なら表示範囲が末尾へ送られる。末尾への追加読み込み (ページング) では、足した項目の後ろのフッターや読み込み中の表示が見え続けるため、次の読み込みが連鎖しうる。ページングの設計でこの規則との関係を扱う。
- 負: 差し替えの直前に表示範囲の位置を控え、挿入のアニメーションと同時に端へ追従させる処理を、両プラットフォームで別々の仕組みで保守する。
