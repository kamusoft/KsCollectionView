## Context

テストは 4 系統ある。iOS 本体、iOS Sample (ユニットテストと、実際の操作を通す UI テスト)、Android 本体、Android Sample である。iOS の 2 系統は Simulator が要り、UI テストは 1 件ごとにアプリを起動する。Android の 2 系統は JVM の上で動き、エミュレータを使わない。

このほかに、端末が要る確認が 2 種類ある。Android 本体には、画像のデコードが端末の上でどう振る舞うかを確かめる、端末をつないで走らせるテストが数件ある。性能検証は基準機で行い、合否はオーナーの体感で決める (cross/ADR-0006)。

完了判定では、手元で 4 系統を絞り込みなしで全件流す (cross/ADR-0008)。検証 CI は `develop` への push の後と `main` 宛ての Pull Request で走り、後者では必須の検査になる (cross/ADR-0010)。

兄弟ライブラリ KsSettingsView は、CI の緑が保証する範囲を「ロジックの全件通過と配線のコンパイル」までとし、アプリを実際に起動する確認を CI に載せていない。CI ではエミュレータも実機も使わない。CI の Simulator の負荷で iOS のテストが一度タイムアウトし、リリース前の確認が不安定になった記録がある。

GitHub の組織には、自前のランナー (Mac mini) が 1 台登録されている。

前提: 手元の完了判定で 4 系統を全件流す決まりが続くこと。性能の合否をオーナーの体感で決める決まりが続くこと。

## Decision

検証 CI は、iOS 本体と Android 本体のテストのうち、Simulator と JVM で走るものを全件走らせる。Sample は両プラットフォームとも、ビルドとユニットテストまでを走らせる。

次の 3 つは CI に載せず、手元の完了条件に残す。Sample の UI テスト、端末をつないで走らせるテスト、性能検証である。CI が使うのは、GitHub が提供する標準のランナーだけとする。

CI の緑が保証するのは、端末を使わないライブラリのテストの全件通過と、Sample がビルドできてユニットテストが通ることまでとする。

理由は次のとおり。UI テストは手元の完了判定で毎回流れているので、CI から外しても失うものが小さい。CI に載せると、性能の低い CI の Simulator で不安定になったとき、`main` 宛ての Pull Request の必須の検査が止まる。性能の合否は体感で決めるので、CI で自動化しても合否を出せない。端末をつないで走らせるテストは件数が少なく、関係する変更のときに手元で流せば足りる。端末の受け皿を作ると、維持するものが増える。

## Alternatives Considered

- **4 系統をすべて走らせる**: 却下。CI の緑が手元の完了判定と同じ意味になる。しかし UI テストが CI で止まると `main` 宛ての Pull Request が進まず、macOS のランナーを使う時間もいちばん長い。
- **本体の 2 系統だけを走らせる**: 却下。macOS のランナーを使う時間はいちばん短い。しかし Sample が壊れても CI では気付けない。
- **端末をつないで走らせるテストだけ、CI のエミュレータで走らせる**: 却下。毎回走るようになる。しかしエミュレータが実機と同じ振る舞いをするかを確かめておらず、エミュレータの起動で CI の時間が延びて不安定さの元になる。
- **組織の自前のランナーに基準機をつないで CI に載せる**: 今は採らない。端末のテストが実機で毎回走り、Android の性能は自動で計測できる。しかし基準機の常時接続と端末の状態の管理が要る。public のリポジトリに自前のランナーをつなぐので、動かせる人と workflow の絞り込みも要る。iOS の性能は体感が合否なので、合否は出ない。

## Consequences

- 正: `main` 宛ての Pull Request の必須の検査が、CI に特有の UI テストの不安定さで止まらない。
- 正: Sample のビルドの崩れと、画面を起動せずに確かめられる部分の崩れには、CI で気付ける。
- 正: CI が GitHub の標準のランナーだけで動き、維持する機材が無い。
- 負: 画面の操作の崩れは CI では見つからず、手元の完了判定に頼る。手元の全件実行を省くと、検出する場所が無くなる。
- 負: 端末をつないで走らせるテストの流し忘れを、CI は止めない。関係する変更のときに手元で流す決まりに頼る。
- 負: CI で性能の退行を検出できないままになる。
- 負: CI の緑は手元の完了判定の緑と同じ意味にならない。緑を見ただけでは、UI テストと端末のテストが通ったとは言えない。
