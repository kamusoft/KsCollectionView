## Context

配布物は 2 つある。SwiftPM の配布物は配信用リポジトリに置く本体の写し (cross/ADR-0015)、Android の配布物は Maven Central へ出す発行物である。

Sample は、どちらのプラットフォームでも本体のソースを直接参照している。そのため Sample のビルドが通っても、配布物として正しいことは言えない。配布物だけが壊れる経路には、写しへのファイルの入れ漏れ、発行物の依存の宣言の漏れ、配信用リポジトリのルートでマニフェストが解決できないこと、がある。Android の Sample は、ソースへの置き換えが外れたら必ずビルドが失敗する形にしてある。

`main` 宛ての Pull Request は、リリースの節目である (cross/ADR-0010)。検証 CI は Simulator・エミュレータ・実機を使わない (cross/ADR-0013)。検査の名前は固定し、`main` の保護が名前で参照する (cross/ADR-0014)。

利用者のアプリは、リリースのビルドでコード縮小を有効にするのがふつうである。本ライブラリには、コード縮小を有効にしたアプリで動かした実績が無い (2026-10-09 時点)。

兄弟ライブラリ KsSettingsView は、専用の利用者役を `main` 宛ての Pull Request のときだけビルドし、必須の検査にしている。以前は開発ブランチでも毎回走らせており、1 回のマージで macOS のランナーを約 54 分使っていたため、今の形に整理した。

前提: `main` 宛ての Pull Request がリリースの節目であること。検証 CI で Simulator・エミュレータを使わない決まりが続くこと。Sample が本体のソースを参照する形のままであること。

## Decision

配布物は、専用の小さな利用者役のプロジェクトをビルドして確かめる。利用者役は、利用者が書くのと同じ書き方で、公開の前の成果物を参照する。この確認は `main` 宛ての Pull Request のときだけ走らせ、`main` の必須の検査にする。`develop` への push では走らせない。

確かめるのはビルドまでとし、利用者役を起動しない (cross/ADR-0013 のまま)。Android の利用者役は、コード縮小を有効にして組み立てる。

Sample は利用者役に使わず、本体のソースを参照する形のままにする。

同じ利用者役を、公開済みの配布物を取りに行く形でも使えるようにする。リリースの工程からどう呼ぶかは、この決定の外に置く。

理由は 3 つある。配布物だけが壊れる経路を、リリースを起動する前の節目で止められる。利用者が書くとおりの参照の書き方が、ビルドできることを確かめられる。配布の経路は本体のコードを変えるたびには壊れにくいので、push のたびに走らせる価値が低い。

## Alternatives Considered

- **Sample を、配布物を参照する形に切り替えてビルドする**: 却下。利用者役を別に持たずに済む。しかし Sample に参照の切り替えが要り、ソースを必ず参照させる今の形に抜け道ができる。利用者が書く参照の書き方は確かめられず、公開の後の確認にも使いにくい。
- **配布物の中身の照合だけにして、ビルドしない**: 却下。数秒で終わる。しかし利用者の側でコンパイルできない壊れ方が見つからない。
- **`main` 宛ての Pull Request で走らせるが、必須の検査にしない**: 却下。`main` の保護を変えずに済む。しかし確認が落ちたまま `main` に入る道が残る。
- **`develop` への push でも毎回走らせる**: 却下。配布物の壊れにいちばん早く気付ける。しかし push のたびに macOS のランナーを使い、配布の経路は本体のコードを変えるたびには壊れにくい。
- **検証 CI には足さず、リリースの工程の中だけで確かめる**: 却下。Pull Request の検査は軽いままになる。しかし壊れに気付くのが、リリースを起動した後になる。

## Consequences

- 正: 写しの入れ漏れ・依存の宣言の漏れ・マニフェストの誤りが、リリースを起動する前に止まる。
- 正: 利用者が書くとおりの参照の書き方が、ビルドできることを確かめられる。
- 正: `develop` への push の検証は重くならない。
- 正: Sample の、ソースを必ず参照させる形を変えない。
- 負: 配布物の壊れは、`develop` に入った時点では気付けず、`main` 宛ての Pull Request まで持ち越す。
- 負: `main` の必須の検査が増え、`main` 宛ての Pull Request のたびに macOS と Linux のランナーを使う。検査の名前を、`main` の保護の側にも登録して保つ必要がある。
- 負: 利用者役のソースと、公開の前の成果物を手元に置く道具を維持する。
- 負: 起動して初めて分かる壊れ方は、この確認では見つからない。
