## Context

iOS の利用者には SwiftPM で配る。SwiftPM が git のリポジトリから解決できるのは、リポジトリのルートにあるマニフェストだけである。本リポジトリのマニフェストは `ios/` の下にあり、ルートにはマニフェストを置かないと決めている (cross/ADR-0002)。このままでは SwiftPM で配れない。

SwiftPM の利用者は、依存するリポジトリを履歴ごと取得する。本リポジトリの履歴は約 30 MB (2026-10-09 時点、84 commit) で、大半は開発の記録に含まれる検証の証跡の画像である。証跡は変更のたびに履歴へ入り続ける。

`ios/` の配布対象は Swift のソースだけで、本体が約 0.4 MB、テストが約 1 MB である。マニフェストが指すソースの場所は `ios/` からの相対なので、`ios/` の中身を別のリポジトリのルートに置けば、マニフェストを書き換えずに解決できる。本ライブラリは外部のライブラリ (Nuke) に依存する。

兄弟ライブラリ KsSettingsView と KsDialogs は、配信用の別リポジトリに写しを置く形で配っている。配信用リポジトリの大きさは 0.4〜0.8 MB である。KsSettingsView は当初、ルートにマニフェストを移して直接配る案だったが、利用者が証跡ごと取得することになると分かって、今の形に変えた。

Android は Maven Central から配る (cross/ADR-0003 が前提にしている)。この決定は SwiftPM の経路だけを扱う。

前提: SwiftPM が、git のリポジトリのルートにあるマニフェストしか解決できず、依存するリポジトリを履歴ごと取得すること。検証の証跡を本リポジトリの履歴に残す運用が続くこと。

## Decision

SwiftPM の配布物は、配信用の公開リポジトリ `KsCollectionView-SPM` を別に持ち、そのルートに `ios/` の本体の写しを置いて配る。利用者が Package URL として指すのは、このリポジトリである。リリースのたびに写しを送り、版を表す tag を付ける。

本リポジトリのルートには、マニフェストを置かない (cross/ADR-0002 のまま)。`ios/Package.swift` を開発用かつ配布用のただ 1 枚のマニフェストとし、配信用リポジトリの側はその写しとする。

配信用リポジトリには、手で commit しない。Issue と Pull Request は受けず、本リポジトリへ案内する。

写しに入れるファイルの範囲、写しを送る工程と tag の付け方は、この決定の外に置く。

理由は 3 つある。利用者が取得するのは本体の写しだけになり、開発の記録や証跡を引かない。既存の決定とマニフェストを変えずに配れる。兄弟ライブラリ 2 つが同じ形で運用しており、写しを作る道具と手順を流用できる。

## Alternatives Considered

- **本リポジトリのルートにマニフェストを置いて、直接配る**: 却下。利用者が見る場所が 1 か所で済み、package の名前も製品名のままになる。しかし利用者が、開発の記録と証跡の画像ごと取得することになり、その量は増え続ける。cross/ADR-0002 の改訂が要る。マニフェストを 2 枚持って食い違いを抱えるか、開発の入口を `ios/` からルートへ移すことになる。
- **ビルド済みのバイナリ (xcframework) で配る**: 却下。利用者の側のビルドが速くなる。しかしリリースのたびにビルドと照合値の管理が要り、Swift の版に縛られ、Nuke への依存を別に包む必要がある。

## Consequences

- 正: 利用者が取得するのは本体の写しだけで、開発の記録・証跡・Android の実装を引かない。
- 正: 本リポジトリは、証跡の残し方を配布の都合で制約されない。
- 正: `ios/Package.swift` を書き換えずに配れ、マニフェストは 1 枚のままになる。cross/ADR-0002 を変えない。
- 正: 兄弟ライブラリと同じ配り方になり、道具と手順を流用できる。
- 負: 2 つ目のリポジトリと、リリースの工程がそこへ書き込むための鍵を持つ。
- 負: 利用者から見て、Package URL は配信用リポジトリ、ソースと Issue は本リポジトリの 2 か所になる。
- 負: 利用者がマニフェストに書く package の名前は、製品名そのものではなく `KsCollectionView-SPM` になる。
- 負: 公開の前に利用者の立場で確かめるには、配信用リポジトリの tag ではなく、手元の写しを参照する形が要る。
- 負: 配信用リポジトリの名前は利用者のマニフェストに残るので、公開の後には変えにくい。
