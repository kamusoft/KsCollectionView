## Context

SwiftPM と Maven で配布するには、リポジトリを GitHub に公開する必要がある。このリポジトリは remote を持たない手元だけのリポジトリで、公開にあたり、これまでの履歴をどう扱うかを決める必要がある。

兄弟ライブラリ KsSettingsView は、公開リポジトリを新しく作り、作業ツリーを単一の initial commit として公開した。履歴に個人のメールアドレスと多数のローカル絶対パスが残っていたためである。

本リポジトリの履歴を 2026-10-08 に調べた結果は次のとおり。

| 確かめたこと | 結果 |
|---|---|
| 規模 | 73 commit、pack 約 30 MB |
| 作者・コミッターのメールアドレス | noreply の 1 種類だけ |
| 履歴の中身の、個人を特定する値とローカル絶対パス (Kasane の標準検査) | 0 件 |
| コミットメッセージのローカル絶対パスとメールアドレス | 0 件 |
| gitleaks による履歴全体の走査 | 検出 0 件 |
| 履歴に残る証跡の画像 | 約 100 件・33 MB。すべて `kasane/changes/` 配下で、作業ツリーからは蒸留のときに削除済み |

本リポジトリは最初の commit から、書き込み時点と commit 時点の検査 (識別子・ローカル絶対パス) が入っている。一方、証跡の画像の画面内に個人の情報が写っていないかは、機械では検査できない。証跡の画像は今後も変更の進行中に commit され、蒸留で作業ツリーから消えても履歴には残る。

前提: 公開の前に行う画像の目視と gitleaks の走査で、履歴から除く必要のあるものが見つからないこと。作者のメールアドレスが noreply であり続けること。

## Decision

公開リポジトリを作るとき、このリポジトリの既存の履歴を書き換えも捨てもせず、そのまま push する。公開されるのは追跡中のすべてのファイルとその履歴で、開発ハーネスの記録 (`kasane/`・`.claude/`・`.codex/`) を含む。

公開の前に、履歴に残る証跡の画像を目で確かめて画面内に個人の情報が無いことを確認し、gitleaks で履歴全体を走査する。gitleaks は公開後も検査として使い続ける。

理由は 3 つある。兄弟ライブラリが履歴を捨てた理由 (個人のメールアドレスとローカル絶対パス) が、本リポジトリの履歴には無い。最初の commit から公開を前提にした検査が入っている。証跡の画像は今後も履歴に入り続けるので、過去の分だけを除いても公開リポジトリの性質は変わらない。

## Alternatives Considered

- **公開リポジトリを新しく作り、作業ツリーを単一の initial commit として公開する (兄弟ライブラリと同じ)**: 却下。過去の証跡の画像は公開されなくなり、兄弟ライブラリと成り立ちが揃う。しかしコミット単位の開発の経緯が公開側から辿れなくなり、開発の場所を新しいリポジトリへ移す作業が要る。兄弟ライブラリがこの形を採った理由は、本リポジトリには当てはまらない。
- **証跡の画像だけを履歴から除いてから公開する**: 却下。過去の画像は公開されなくなり、コミット単位の経緯も残る。しかし履歴の書き換えと、除けたことの確認が要り、commit の ID が変わる。証跡の画像は今後も履歴に入り続ける。

## Consequences

- 正: コミット単位の開発の経緯が、公開リポジトリから辿れる。
- 正: 公開の作業が remote の追加と push で済み、開発の場所を移さない。commit の ID も変わらない。
- 負: 履歴に残る証跡の画像がすべて公開され、clone の大きさに乗る。変更を重ねるたびに増える。
- 負: 画面内の個人の情報は機械で検査できないので、公開前の目視と、以後の証跡を保存するときの確認に頼る。見落としは公開後に取り消せない。
- 負: 兄弟ライブラリ (単一の initial commit から始まる) と、公開リポジトリの成り立ちが揃わない。
- 負: 今後の commit とそのメッセージ、変更の記録もすべて公開の履歴に残る。書く時点で公開を前提にした規律を、検査で保ち続ける必要がある。
