## Context

core/ADR-0003 は、差分計算とアニメーションの適用をライブラリの責務と決めた。iOS は diffable data source が移動・挿入・削除をアニメーションで見せる。Android の Compose Lazy 系で項目の移動・挿入・削除を動かして見せる手段は `Modifier.animateItem()` だけだが、android/ADR-0004 は行の高さ変化の補間 (`ksAnimatedHeight`) を決めたとき「`animateItem` は重ねない」とした。そのため Android は、配列を差し替えると項目が新しい位置へ一瞬で飛んでいた。

ADR-0004 が `animateItem` を退けた理由は、高さ変化の補間に重ねても押し出される行の動きは良くならず、性能の上乗せ (2 列グリッドのフレーム CPU 時間 P90 +19.4%、`animateContentSize` との組み合わせで計測) だけが残ったことだった。項目の移動・挿入・削除を見せる目的では検討していない。

グループ化機能で、グループをまたぐ項目の移動とグループの並べ替えを見せる必要が出た (core/ADR-0015)。後続の D&D 並べ替え機能でも、ドラッグ中に項目がどいて動く見え方に同じ手段が要る。端を表示中の端への挿入は、挿入のアニメーションが見えることを両プラットフォームの契約にしている (core/ADR-0018)。

スクロール性能の合否は基準機でのオーナーの体感で決め、Android の相対計測は比較対象 (素の Lazy グリッド) に対するラッパーの上乗せを測る (cross/ADR-0006、handbook/android/performance-verification)。

前提: 出典に前提の記載なし。

## Decision

android/ADR-0004 の決定のうち「`animateItem` は重ねない」を本決定で置き換える。高さ変化の補間 (`ksAnimatedHeight`) とその利用契約は維持する。

配列の差し替えによる移動・挿入・削除を、Android でも `animateItem` でアニメーションさせる。付け方は次のとおりとする。

| 観点 | 決定 |
|---|---|
| 付ける対象 | 項目、グループの見出し (固定中の見出しを含む)、ルートのヘッダー / フッター |
| 付ける位置 | 項目の修飾のいちばん外側 (`ksAnimatedHeight` より前) |
| 出入り | フェードで見せる |
| 高さの補間との重なり | 同じ一覧で高さの補間が進んでいる間は、配置のアニメーションを止める (出入りのフェードは残す) |
| 末尾への挿入での位置の要求 | 挿入を反映するフレームでは位置を要求せず、次のフレームから配置のアニメーションと同じばねで末尾まで送る。画面の外に足された項目は、最初に配置されたときに一度だけフェードで見せる |

ルートのヘッダー / フッターにも付けるのは、項目だけが動くとフッターが先に新しい位置へ飛び、動いている項目と重なるためである。高さの補間中に配置を止めるのは、補間で押し出される行を配置のアニメーションが追いかけ、行の間に帯ができるためである。末尾への挿入で同じフレームに位置を要求しないのは、Compose が配置と出現のアニメーションを捨てて 1 フレームで末尾へ飛ぶためである。

グリッドで列をまたぐ移動は、`animateItem` の標準の見え方 (元の位置から移動先へまっすぐ動く) のままにする。iOS の標準も同じ動きである。

`animateItem` は既定機能なので、Android の相対計測では比較対象にも同じ位置に付ける。`animateItem` 自体の費用は相対基準に現れないため、ライブラリの「なし / あり」の比較を証跡に残し、合否は体感のゲート (cross/ADR-0006) で決める。

## Alternatives Considered

- **ADR-0004 に従い、Android の移動のアニメーションを D&D 並べ替え機能まで先送りする**: 却下。D&D 並べ替え機能の実装時期は決まっておらず、同じ判断をいずれ解く必要がある。先送りしても解くコストは変わらず、その間 Android だけ項目が飛ぶ見え方が残る。
- **グリッドで列をまたぐ移動を、両プラットフォームで薄れて入れ替わる形に差し替える**: 却下。両プラットフォームで配置のアニメーションを自前で持つことになり、差分の適用・再利用・高さの補間との組み合わせを保守する。両 OS の標準は斜めにまっすぐ動く形で、利用者に見慣れた動きである。
- **末尾への挿入で、差し替えと同じフレームに最後の項目へのスクロールを要求する**: 却下。配置と出現のアニメーションが捨てられ、挿入が即座に反映されたように見える。端を表示中の端への挿入が見えるという契約 (core/ADR-0018) を満たせない。

## Consequences

- 正: 配列の差し替えの見え方が iOS と揃い、差分のアニメーションをライブラリの責務とする core/ADR-0003 を Android でも満たす。
- 正: D&D 並べ替え機能は、項目がアニメーションで動く前提から始められる。
- 正: ルートのヘッダー / フッターも項目と一緒に動くため、差し替えの間に項目と重ならない。
- 負: 全項目・見出し・ルートのヘッダー / フッターに `animateItem` が付き、スクロール中の性能に上乗せが出る。既定機能として比較対象にも付けるため相対基準には現れず、費用の判断は体感に頼る。
- 負: 高さの補間と移動が同時に起きると、補間が動き始めた後の移動はアニメーションせずに新しい位置へ移る。
- 負: 配置のアニメーションを止めるかどうかを決めるため、高さの補間が進んでいるかをライブラリが一覧の単位で追う。
- 負: 末尾への追従は差し替えより 1 フレーム遅れて始まり、画面の外に足された項目を後からフェードで見せる処理をライブラリが持つ。
- 負: 位置の要求と配置のアニメーションの組み合わせは、後続の機能 (ページング・D&D 並べ替え) でも同じ制約 (差し替えと同じフレームで要求するとアニメーションが捨てられる) の上で設計する。

## Revisit When

- 体感のゲートで、`animateItem` を原因とする不合格が出たとき
- Compose が項目の配置のアニメーションを別の手段で提供したとき、または差し替えと同じフレームの位置の要求でもアニメーションを保つようになったとき
