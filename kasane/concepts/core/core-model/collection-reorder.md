# 並べ替え (ドラッグ & ドロップ)

この文書を読むと、一覧に並べ替えを付けたとき、ライブラリがいつ何を利用者へ渡し、どこまでを表示として持ち、利用者の VM (状態を持つ側のモデル) がどう書けば並びが確定するか、そして両プラットフォームで動きが違う所が分かる。配列の差し替えとグループの宣言は [collection-items](collection-items.md)、タップと長押しは [collection-interaction](collection-interaction.md) を先に読むと分かりやすい。

## 目的

長押しの検出・持ち上げ・端での自動スクロール・行き先の計算を、画面ごとに書かせずライブラリが持つ。読み上げ (VoiceOver / TalkBack) を使う人のための、ドラッグの代わりの操作も持つ。Compose の Lazy 系には公式の並べ替えの API が無く、SwiftUI の List の並べ替えは UICollectionView の一覧には効かないためである。正しい並びの出どころは利用者の VM が持つ配列 1 つのままにし (core/ADR-0003)、ライブラリは配列を書き換えない。KMP の共有 VM が公開する配列をそのまま渡せる形にしている。

## 公開 API

```swift
@MainActor final class TaskListModel: ObservableObject {
    @Published private(set) var tasks: [TaskItem] = []
    @Published var isReordering = false                          // 並べ替えのスイッチ

    func move(_ move: KsReorderMove<TaskItem>) -> Bool {          // 置いたときに 1 回だけ呼ばれる
        var next = tasks
        guard let from = next.firstIndex(where: { $0.id == move.item.id }) else { return false }
        var moved = next.remove(at: from)
        if let section = move.group?.base as? TaskSection {
            moved.section = section                               // グループの値は VM が書き換える
        }
        switch move.destination {
        case .before(let target):                                 // この項目の前
            guard let index = next.firstIndex(where: { $0.id == target.id }) else { return false }
            next.insert(moved, at: index)
        case .end:                                                // グループの末尾
            let last = next.lastIndex(where: { $0.section == moved.section })
            next.insert(moved, at: last.map { $0 + 1 } ?? next.count)
        }
        tasks = next                                              // 並べ替えた配列を渡し直す
        return true                                               // 受け入れた
    }
}

KsCollectionView(model.tasks) { task in TaskRow(task) }
    .groups(by: \.section) { section, _ in Text(section.title) }
    .reorder(
        isEnabled: model.isReordering,
        canMove: { !$0.isLocked },
        canDrop: { $0.group != AnyHashable(TaskSection.archived) },
        accessibilityActions: KsReorderAccessibilityActions(previous: "前へ移動", next: "後ろへ移動")
    ) { move in model.move(move) }
```

```kotlin
KsCollectionView(
    items = vm.tasks, key = { it.id },
    groups = KsGroups(by = { it.section }) { section, _ -> Text(section.title) },
    reorder = KsReorder(
        enabled = vm.isReordering,
        onMove = { move -> vm.move(move) },                       // 並べ替えた配列を渡し直して true を返す
        canMove = { !it.isLocked },
        canDrop = { it.group != TaskSection.Archived },
        accessibilityActions = KsReorderAccessibilityActions(previous = "前へ移動", next = "後ろへ移動"),
    ),
) { template { task -> TaskRow(task) } }
```

| 語彙 | Swift | Kotlin |
|---|---|---|
| 並べ替えの設定 | `.reorder(isEnabled:canMove:canDrop:accessibilityActions:onMove:)` modifier | `reorder = KsReorder(enabled, onMove, canMove, canDrop, accessibilityActions)` |
| 並べ替えのスイッチ | `isEnabled: Bool` | `enabled: Boolean` |
| 置いたときの処理 | `onMove: @MainActor (KsReorderMove<Item>) -> Bool` | `onMove: (KsReorderMove<Item>) -> Boolean` (メインスレッドで呼ぶ) |
| 移動の内容 | `KsReorderMove<Item>` (`item` / `destination` / `group: AnyHashable?`) | `KsReorderMove<Item>` (`item` / `destination` / `group: Any?`) |
| 行き先 | `KsReorderDestination<Item>` (`.before(Item)` / `.end`) | `KsReorderDestination<Item>` (`Before(item)` / `End`) |
| 動かせるか / ここに置けるか | `canMove: ((Item) -> Bool)?` / `canDrop: ((KsReorderMove<Item>) -> Bool)?` | 同じ名前の引数 (省略できる) |
| 読み上げの文言 | `KsReorderAccessibilityActions(previous:next:)` | `KsReorderAccessibilityActions(previous, next)` |

語彙は 1 対 1 に対応し、記法は各プラットフォームの流儀に従う (core/ADR-0002)。`.reorder` を付けない一覧 (Kotlin は `reorder = null`) と、付けて並べ替えのスイッチを無効にした一覧は同じ振る舞いになる。移動の内容の `group` は、グループの値の型を消して渡す。グループの宣言と並べ替えの設定が別の宣言で、グループの宣言は任意のためである。

移動の内容を配列に当てはめる補助関数は用意していない。グループの値の書き換え方は利用者のモデルで決まるためである。上の例は、VM が各プラットフォームのコードにある場合の書き方である。`KsReorderMove` は各プラットフォームのライブラリの型なので、KMP の共通のコードにある VM は直接受け取れない。その場合は画面の側で、動かした項目・行き先 (どの項目の前か、または末尾か)・グループの値を VM の引数に移して呼ぶ。

## 責務境界

| 責務 | 持つ側 | 具体 |
|---|---|---|
| 配列の並びと、項目のグループの値 | 利用者 (VM) | ライブラリは配列もモデルも書き換えない。受け入れたら VM が並べ替えた配列を渡す |
| 受け入れるかの判断と保存 | 利用者 (VM) | 置いたときの処理の戻り値で返す。保存の失敗は元の並びの配列を渡し直して表す |
| 業務ルール (動かせるか・ここに置けるか) | 利用者 | 判定を渡し、ライブラリが呼ぶ |
| 長押しの検出・持ち上げ・端での自動スクロール・行き先の計算 | ライブラリ | 下記「保証すること」 |
| ドラッグ中の仮の並びと、受け入れてから配列が届くまでの置いた並び | ライブラリ | 表示としてだけ持つ |
| 読み上げの移動操作を出すこと | ライブラリ | 操作の文言と翻訳は利用者が渡す (core/ADR-0032) |
| ソートとの関係 | 利用者 (VM) | ライブラリはソートを知らない (下記「利用者の VM が守る書き方」) |

## 保証すること

### 並べ替えのスイッチと長押し (core/ADR-0031)

| 並べ替えのスイッチ | 長押し | `onItemLongTap` | `onItemTap` |
|---|---|---|---|
| 有効 | 動かせる項目が持ち上がり、ドラッグが始まる | 動かせない項目も含めて呼ばない | 呼ぶ |
| 無効 (並べ替えを付けていない一覧も同じ) | ドラッグは始まらない | 宣言していれば呼ぶ | 呼ぶ |

項目のどこを長押ししても持ち上がり、ハンドル (つかむための部品) は持たない。有効の間に `onItemLongTap` を呼ばないのは、動かせない項目でだけ呼ぶと、同じ長押しが項目によって別の意味になるためである。タップしたときの押した印 (フィードバック) は、`onItemTap` か `onItemLongTap` を宣言した項目にだけ出す決まりである ([collection-interaction](collection-interaction.md))。有効の間は `onItemLongTap` を宣言していないものとして扱うので、`onItemLongTap` だけを宣言した一覧はタップしてもフィードバックを出さない。

list でもグリッドでも同じに効き、layout 値を差し替えても並べ替えの設定は残る (進行中のドラッグだけは取りやめになる。下記)。

### 置いたときの処理と移動の内容 (core/ADR-0026・0028)

置いたときの処理 (`onMove`) は、ドラッグした項目を置いて指を離したときに 1 回だけ呼ぶ。ドラッグの途中で項目が入れ替わるたびには呼ばない。途中の並びはライブラリが表示としてだけ持ち (仮の並び)、指が項目をまたぐたびに VM の処理や保存が走らないようにしている。渡す移動の内容 (`KsReorderMove`) は、動かした項目・行き先・行き先のグループの値の 3 つで、項目は `onItemTap` と同じく配列の要素そのものである。

| 置いた位置 | 行き先 (`destination`) | `group` |
|---|---|---|
| 置いた位置の後ろに、同じグループの項目がある (元のグループの中でも、別のグループの途中でも) | その項目の前 | 置いたグループの値 |
| 置いたグループの最後 (後ろが次のグループか、一覧の終わり) | 末尾 | 置いたグループの値 |
| グループを宣言していない一覧で、後ろに項目がある | その項目の前 | 無い (nil / null) |
| グループを宣言していない一覧の最後 | 末尾 | 無い (nil / null) |

動かした項目自身は後ろの項目に数えない。位置の番号ではなく項目で表すのは、前のグループの末尾と次のグループの先頭を区別でき、置いてから VM が処理するまでに配列が変わっても行き先の意味が変わらないためである。行き先は、指を離したときに画面に見えている置く先の空き (用語節) の位置から求めるので、項目が置かれた位置と行き先は食い違わない。

次の場面では置いたときの処理を呼ばない。

| 場面 | 結果 |
|---|---|
| 元の位置に置いた | 並びはそのまま (VM に保存を走らせない) |
| 「ここに置けるか」が偽の行き先の上で指を離した | 項目を元の位置に戻す |
| ドラッグを取りやめた (下記) | 同上 |
| 一覧の枠の外で指を離した (上下左右のどちらでも。別の一覧の上を含む) | 同上。並べ替えは持ち上げた一覧の中だけで、別の一覧やアプリの外には置けず、ほかの一覧から来た項目も受けない |

### 受け入れと元に戻す (core/ADR-0027)

| 置いたときの処理の戻り値 | 一覧の振る舞い |
|---|---|
| 受け入れた | 置いた並びのまま VM の配列を待つ。待つ間に届いた配列を、比べる相手の配列 (下記) と比べ、等しくなければ並べ替えを含むかによらずその並びに従う。等しければ (ほかの状態の変化による描き直し) 待ち続ける |
| 受け入れない | 項目を元の位置に戻す |

比べる相手の配列は、置いたときの処理を呼ぶ直前までに一覧へ届いていた最新の配列である。ドラッグ中に保留した配列があればその配列、無ければドラッグの前から表示していた配列になる。「等しい」は配列の中身の比較で決める (iOS は同値比較、Android は同じ参照か同値)。置いたときの処理の中で VM が渡し直した配列は、比べる相手の配列と並びが違うので、届いた時点で表示に適用される。置いたときの処理の中で渡しても、処理から戻った後に渡しても同じである。

時間の経過では戻さない。時間で戻す形にすると、配列が遅れて届く VM で正しい並べ替えが一度戻って見えるためである。保存の成否もライブラリは待たない。VM は受け入れた時点で配列を並べ替えているので、保存が後で失敗したら、並べ替える前の並びの配列を渡し直せば、通常の差し替えとして元の並びで表示される。受け入れの判断は同期で返すため、サーバーに問い合わせないと分からない可否は保存の失敗として扱う。

### グループをまたぐ移動 (core/ADR-0029)

グループを宣言した一覧では、項目を別のグループへ動かせる。ライブラリは行き先のグループの値を渡すだけで、項目のグループの値は書き換えない。確定には VM がグループの値を書き換えた配列を渡す。

| 場面 | 振る舞い |
|---|---|
| 項目が 1 件も無いグループ | 表示されない (core/ADR-0015) ため、そこへは動かせない |
| グループの最後の 1 件をドラッグしている間 | 元のグループの見出しを残す (表示が跳ねず、元のグループへ戻して置ける) |
| 受け入れた時点 | 項目が無くなったグループを見出しごと表示から外す。VM がグループの値を書き換えた配列を渡しても、そのグループは項目が無いので表示されないまま |
| 受け入れてから VM の配列が届くまで | 動かした項目を行き先のグループに属するものとして表示する (見出しのクロージャに渡す、グループ内の項目の一覧も同じ) |
| 受け入れた後に、保存の失敗で元の並びの配列が届いた | 通常の差し替えとしてグループを組み直すので、外したグループも見出しごと戻る |
| 境目 (見出し・グループの間) の近くに置いたときの所属 | プラットフォームで決まり方が違う (下記「両プラットフォームの差」) |

### 動かせるかと置けるかの判定 (core/ADR-0030)

| 判定 | 呼ばれる時機 | 偽を返すと |
|---|---|---|
| 動かせるか (`canMove`) | 項目ごと。長押しで持ち上げる前 | 持ち上がらない |
| ここに置けるか (`canDrop`) | ドラッグ中に行き先の候補ごと (何度も) と、置く直前 | その行き先には項目が入らない。その上で指を離すと元の位置に戻り、置いたときの処理は呼ばない |

「ここに置けるか」には、置いたときの処理と同じ形の移動の内容を渡す。元の位置は判定しない (いつでも戻せる)。どちらも渡さなければ、すべての項目を動かせ、すべての位置に置ける。

置く前に止めるのは、置いてから戻る見た目を避けるためで、置いた後の受け入れは最後の砦として残る。グループをまたがせない制限は「行き先のグループが元と同じか」を見る判定 1 つで書ける。

### ドラッグ中に届いた配列・ページング・スクロール命令 (core/ADR-0033・0034・0007)

ドラッグ中は表示の並びと配列がずれているため、その間に外から届くものを次のように扱う。ここでの「ドラッグ中」は、ドラッグが始まってから、置いて受け入れの結果が出て表示が落ち着くまで (受け入れなかったときは元の位置へ戻り終えるまで) を指す。受け入れた後に VM の配列を待つ間は含まない。待つ間は、置いた並びを対象に、次ページ要求の判定もスクロール命令も普段どおり働く。

| ドラッグ中に届くもの | 扱い |
|---|---|
| 配列 | 表示に適用せず、最新の 1 つを保留する。受け入れたら、保留していた配列は表示に適用しない (上記の「比べる相手の配列」になる)。受け入れなかった・取りやめた・元の位置に置いたときは、項目を元の位置に戻してから保留した最新の配列を適用する |
| 次ページ要求の判定 ([collection-paging](collection-paging.md)) | しない。ドラッグが終わったら判定し直す |
| スクロール命令 (`KsScrollController`) | 溜めておき、ドラッグが終わって配列を適用した後に、受けた順に実行する |

配列をドラッグ中に適用すると、指の下で項目がずれたり消えたりする。次ページ要求には、一度呼んだら状態か配列が変わるまで次を呼ばない仕組みがある。配列を保留したまま判定すると、読み込んだページが表示に出ないまま状態だけが変わってこの仕組みが解け、次のページを続けて要求してしまう。スクロール命令をすぐ実行すると、指の下の一覧が指と関係なく動く。

帰結として、ドラッグ中に届いた変化 (内容の更新・ページの追加) は指を離すまで見えない。末尾まで運んでも一覧は伸びず、読み込んだ先へ運ぶにはいったん置いて運び直す。ドラッグ中の項目が配列から消えても、指を離すまでは持ち上がったままで、受け入れなければ元の位置に戻ってから消える。

一覧には、先頭か末尾を表示しているときにその端へ項目が足されたら、表示範囲をその端に留める規則がある ([collection-items](collection-items.md) の「端を表示中の端への挿入」)。保留した配列を適用するときは、ドラッグの前に表示していた並びとページングの状態を差し替えの直前のものとして、この規則を当てはめるかを決める。

### ドラッグの取りやめ

ドラッグ中に次のどれかが起きたら、ライブラリはそのドラッグを取りやめる。取りやめたドラッグでは項目をどこにも置かせず、置いたときの処理を呼ばない。項目は元の位置に戻り、保留した配列と変わった設定は、戻した後に表示に適用される。戻る時機はプラットフォームで違う (下記「両プラットフォームの差」)。

- 並べ替えのスイッチが無効になった
- layout 値 (list / グリッド・列数・間隔の指定) が変わった
- グループの宣言 (宣言の有無・グループの値の取り出し方・見出しの有無・見出しを上端に固定するかどうか) が変わった
- 操作がシステムに中断された (タッチがシステムに取り消されたときなど)

並べ替えのスイッチが無効の一覧は並べ替えを受け付けない状態なので、途中の移動も成立させない。layout 値やグループの宣言が変わると配置が組み直され、仮の並びと行き先の対応が崩れる。

### 端での自動スクロール

ドラッグ中に指が一覧の見えている範囲の上端か下端の近くにある間、一覧はその向きにスクロールを続け、スクロールで見えた位置に置ける。速さと反応する範囲は各プラットフォームの自然な形に任せ、公開の設定は持たない。iOS は UIKit 標準の反応に従い、Android は端から 64dp の範囲で端に近いほど速くスクロールする (最大 1200dp/秒)。

全画面に広げた一覧 ([collection-layout](../styling/collection-layout.md) の安全領域) では、iOS は上端の反応する範囲を安全領域の境目 (バーのすぐ下) から取る。バーの裏には指を置けないためである。Android は一覧の枠の端から測り、安全領域は使わない。

### 読み上げの移動操作 (core/ADR-0032)

並べ替えのスイッチが有効で、読み上げの文言を渡した一覧は、動かせる項目に「1 つ前へ動かす」「1 つ後ろへ動かす」の 2 つの読み上げ用の操作を出す。渡した文言がそのまま操作の名前になり、ライブラリは文言と翻訳を持たない。

| 項目 | 契約 |
|---|---|
| 前へ動かす | 並びで 1 つ前へ (行き先は 1 つ前の項目の前)。グループの先頭の項目なら前のグループの末尾へ (行き先は末尾、`group` は前のグループの値) |
| 後ろへ動かす | 1 つ後ろへ (行き先は 2 つ後ろの項目の前、無ければ末尾)。グループの最後の項目なら次のグループの先頭へ (行き先は次のグループの最初の項目の前、`group` は次のグループの値) |
| 操作を出さない場合 | 文言を渡していない / 並べ替えのスイッチが無効 / 動かせない項目 / 行き先が無い端 (一覧の先頭の項目の「前へ」、最後の項目の「後ろへ」) / 「ここに置けるか」が偽の行き先 |
| 動かしたとき | ドラッグと同じく置いたときの処理を 1 回呼ぶ。受け入れたら動かして VM の配列を待ち、受け入れなければ動かさない |

確かめたのは自動テストと、Simulator で読み上げの要素とその操作の一覧を取り出して見る所までである。実機の VoiceOver / TalkBack での聞こえ方と、動かした後の焦点は確かめていない。

### 両プラットフォームの差

iOS は UIKit 標準の並べ替えの動きに従い (ios/ADR-0011)、Android は自前のドラッグで指の位置から決める (android/ADR-0007)。そのため次の差があり、契約として受け入れている。移動の内容の形・受け入れ・最後の並びはどちらも同じ規則である。iOS の動きは iOS 18・26 で確かめた範囲で、下限の iOS 16・17 では確かめていない。

| 場面 | iOS | Android |
|---|---|---|
| 置く先の空きが動く時機 | 指を止めてから隙間が動く。指を動かしている間と、速い自動スクロールの間は動かない | list は、持ち上げた項目がほかの項目の半分を越えて重なった時点で置き場所が入れ替わる。グリッドは、指がほかの項目の上に入った時点で、その項目の位置へ置き場所が移り、間の項目が 1 つずつずれる |
| 境目 (見出し・グループの間) | 下の表「iOS の境目での置き方」 | 見出し (見出しが無ければグループの間) より上なら前のグループの末尾、下なら次のグループの先頭 |
| 受け入れないとき | いったん置いた位置に収まり (約 0.3 秒)、約 0.7 秒止まってから、元の位置へ動いて戻る (約 0.3 秒)。離してから戻り終わるまで約 1.3 秒 (Simulator での観測) | 置かずに、離した位置から元の位置へ動いて戻る |
| 取りやめ | ドラッグは指を離すまで続く。取りやめた後はどこにも置けず、指を離したときに元の位置へ戻る。変わった設定はその後に適用される | その場で元の位置へ戻り、変わった設定もその場で適用される |
| 配列を保留し始める時点 | 持ち上げた後、指を動かし始めた時点。その間に届いた配列はその場で適用される | 長押しで持ち上げた時点 |
| 一覧の枠の外へ運んだとき | 持ち上げた項目の絵が、UIKit の既定の小さい板に切り替わる (バーの上など) | 大きさは変わらない。左右の外にある間は置き場所が動かず、上下の外では自動スクロールが続く |
| グループを下へまたいで置いた瞬間 | 約 0.1〜0.2 秒、同じ項目が 2 つ見える (UIKit 標準の並べ替えと同じ見え方) | 起きない |
| 持ち上げの見た目 | UIKit 標準の持ち上げ | 影 (8dp) だけで拡大しない。テンプレートの背景が透明だと下の項目が透ける |

iOS の隙間は、指を止めた位置の項目との関係で決まる (UIKit 標準の並べ替えと同じ動き。Simulator での観測)。

| iOS の境目での置き方 | 隙間が空く位置 |
|---|---|
| 別のグループから運んできて、項目の上で止める | その項目の前 |
| 同じグループの中で、項目の上で止める | 指の下の項目と入れ替わる位置 (下へ運べば項目の後ろ、上へ運べば前) |
| 見出しの上・グループの間で止める | 動かない (境目の位置には空かない)。そこで指を離すと、そのときの隙間の位置に置かれる |
| 次のグループの先頭に置く | 上から運んで、先頭の項目の上で止める (直接置ける) |
| 前のグループの末尾に置く | 下から運んで最後の項目の上で止めると、その項目の前に空く。隙間がそのグループの中に入ったら、もう一度最後の項目の上で止めると、入れ替わって末尾になる |

最後の行の後半 (もう一度止めると末尾になる) は、1 回のドラッグを通した観測では確かめていない。同じグループの中の動き (2 行目) からの推測で、実機での手動の操作とは合っている。

## 利用者の VM が守る書き方

ライブラリは配列を書き換えないため、次の書き方は VM 側の約束である。リポジトリ同梱の Sample「並べ替え」の VM (`ReorderDemoModel`) がこれらの見本である。

| 書き方 | 守らないと |
|---|---|
| 受け入れたと返したら、配列を並べ替えて渡し直す | 次に違う配列が届くまで、表示 (置いた並び) と配列がずれたままになる。ライブラリは時間で戻さない (core/ADR-0027) |
| 保存の失敗は、並べ替える前の並びの配列を渡し直して表す (元の並びは VM が覚えておく) | 表示は置いた並びのまま残る。ライブラリは保存の成否を待たない (core/ADR-0027) |
| 「ここに置けるか」は軽い同期の判定にする | ドラッグ中に行き先の候補ごとに何度も呼ばれ、指の動きに表示が遅れる (core/ADR-0030) |
| グループをまたぐ移動を受け入れるときは、項目のグループの値を移動の内容の `group` に書き換える | 同じグループの値が配列の離れた位置に現れ、不正入力になる (core/ADR-0029。[collection-items](collection-items.md) の「不正入力の扱い」) |
| グループの宣言を付け外しできる画面では、宣言を外している間に動かした項目のグループの値も、行き先の隣の項目に合わせる | 宣言を戻したときに、同じグループの値が離れた位置に現れる |
| 行き先の項目が処理の時点で配列から消えていたら、受け入れないと返す | 置く先が決まらないまま受け入れたことになる (core/ADR-0028) |
| 読み上げの文言を渡す | 操作が出ず、読み上げを使う人は並べ替えられない (core/ADR-0032) |
| ソート中は、並べ替えのスイッチを無効にするか、置いたときの処理で手動の並びへ切り替えて並べ替える | ライブラリはソートを知らない。ソートしたままの配列を渡すと、置いた項目がソートの位置へ動く |

## してはいけないこと

- 配列を並べ替えずに、受け入れたと返さない。表示と配列がずれたまま残る (core/ADR-0027)。
- ドラッグの途中で置いたときの処理が呼ばれることを期待しない。呼ぶのは指を離したときの 1 回だけで、途中の並びは VM から見えない (core/ADR-0026)。
- 並べ替えのスイッチを常に有効にした一覧で、`onItemLongTap` を使おうとしない。有効の間は呼ばれない (core/ADR-0031)。
- 「ここに置けるか」の中で、重い処理やサーバーへの問い合わせをしない。問い合わせが要る可否は、受け入れた後の保存の失敗として扱う (core/ADR-0030)。
- 項目が 1 件も無いグループへ、ドラッグで移せることを期待しない。移し先が空になりうるグループへの移動は、別の操作で用意する (core/ADR-0029)。
- ドラッグを続けさせたい間に、並べ替えのスイッチ・layout 値・グループの宣言を変えない。ドラッグが取りやめになる。
- 置く先の空きの動きが両プラットフォームで同じだと期待しない。境目の決まり方と、受け入れないときの戻り方が違う (上記「両プラットフォームの差」)。
- 複数の項目をまとめて動かす・グループを見出しごと動かす・別の一覧やアプリの外へ持ち出す操作を期待しない。どれも提供していない。

## 用語

| 用語 | 意味 |
|---|---|
| 並べ替えのスイッチ | 並べ替えを受け付けるかを表す真偽値。Swift は `.reorder(isEnabled:)` の `isEnabled`、Kotlin は `KsReorder` の `enabled`。利用者の VM か画面が持つ。iOS の支援技術のスイッチコントロールとは関係がない。 |
| 置いたときの処理 | 指を離したときにライブラリが呼ぶ `onMove`。受け入れたかを真偽値で返す。 |
| 移動の内容 | 置いたときの処理と「ここに置けるか」に渡す `KsReorderMove`。動かした項目・行き先・行き先のグループの値を持つ。API のコメントと変更時の仕様書では「知らせ」と呼んでいる。 |
| 行き先 | 移動の内容の中で、置いた位置を項目で表した値 (`KsReorderDestination`)。「この項目の前」か「末尾」(グループの末尾。グループを宣言していなければ一覧の末尾)。 |
| 置く先の空き | ドラッグ中の画面で、指を離すと項目が入る位置に見える空き。iOS では UIKit が空ける「隙間」、Android では持ち上げた項目の「置き場所」と呼ぶ。行き先 (値) は、指を離したときのこの空きの位置から求める。 |
| 仮の並び | ドラッグ中にライブラリが表示としてだけ持つ並び。配列には書かれない。 |
| 置いた並び | 受け入れてから VM の配列が届くまで表示する並び。 |
| 保留する | ドラッグ中に届いた配列を表示に適用せず、最新の 1 つを持っておくこと。 |
| 取りやめ | ライブラリが、そのドラッグでは項目をどこにも置かせず、置いたときの処理も呼ばないと決めること。項目は元の位置に戻る。 |
| 境目 | グループとグループの間。見出しがあれば見出し、無ければグループの間の間隔。 |
| layout 値 | list / グリッド・列数・間隔を表す公開の値 ([collection-layout](../styling/collection-layout.md))。 |
| 読み上げの移動操作 / 読み上げの文言 | VoiceOver / TalkBack を使う人がドラッグの代わりに使う、1 つ前 / 1 つ後ろへ動かす操作と、その操作の名前として利用者が渡す文字列 (`KsReorderAccessibilityActions`)。 |
| 利用者 | このライブラリを使ってアプリを作る開発者 (とそのコード)。アプリを使う人ではない。 |
