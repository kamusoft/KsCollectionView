# ページングと Pull to Refresh

この文書を読むと、一覧に無限スクロール (ページング) と Pull to Refresh を付けたとき、ライブラリがいつ次のページを頼み、どこに何を表示し、配列を差し替えたときに表示範囲をどこに置くか、そして利用者の VM (状態を持つ側のモデル) がどう書けばその契約が成り立つかが分かる。配列の差し替えと端への挿入の一般の規則は [collection-items](collection-items.md)、安全領域と余白の意味は [collection-layout](../styling/collection-layout.md) を先に読むと分かりやすい。

## 目的

末尾に近づいたことの検出・二重の読み込みの抑止・読み込み中や失敗の表示・Pull to Refresh の接続を、画面ごとに書かせずライブラリが持つ。状態は利用者の VM が持ち、ライブラリは状態を読むだけで書き換えない (core/ADR-0005)。Android の Paging 3 には依存せず、KMP の共有 VM が持つ状態をそのまま 5 つの値へ写せる形にしている。

## 公開 API

```swift
@MainActor final class FeedModel: ObservableObject {
    @Published private(set) var items: [Post] = []
    @Published private(set) var pagingState: KsPagingState = .idle

    func loadNextPage() async {                      // 項目が空なら最初のページを読む
        pagingState = .appending                     // 戻る前に追加読み込み中にする
        do {
            let page = try await api.fetch(after: items.last?.id)
            items += page.posts                      // 配列と状態は同じ回に書く
            pagingState = page.hasMore ? .idle : .endReached
        } catch {
            pagingState = .failed
        }
    }

    func reload() async {                            // Pull to Refresh と再読み込みのボタン
        pagingState = .refreshing
        do {
            let page = try await api.fetch(after: nil)
            items = page.posts                       // 1 ページ目の差し替えと同じ回に待機 / 終端にする
            pagingState = page.hasMore ? .idle : .endReached
        } catch {
            pagingState = items.isEmpty ? .failed : .idle   // 項目があれば失敗にせず戻す
        }
    }
}

KsCollectionView(model.items) { post in PostRow(post) }
    .paging(model.pagingState, threshold: 1) { await model.loadNextPage() }
    .pagingFailedFooter { retry in Button("再試行", action: retry) }
    .pagingEmptyPlaceholder { Text("項目がありません") }
    .refreshable { await model.reload() }            // SwiftUI 標準の宣言をそのまま読む
```

```kotlin
KsCollectionView(
    items = vm.items, key = { it.id },
    paging = KsPaging(
        state = vm.pagingState,                      // mutableStateOf で持つ KsPagingState
        onLoadMore = { vm.loadNextPage() },          // suspend 関数。普通の関数も渡せる
        failedFooter = { retry -> Button(onClick = retry) { Text("再試行") } },
        emptyPlaceholder = { Text("項目がありません") },
    ),
    onRefresh = { vm.reload() },
) { template { post -> PostRow(post) } }
```

| 語彙 | Swift | Kotlin |
|---|---|---|
| 状態 (付属値なし) | `KsPagingState` (`.idle` / `.refreshing` / `.appending` / `.failed` / `.endReached`) | `KsPagingState` (`Idle` / `Refreshing` / `Appending` / `Failed` / `EndReached`) |
| ページングの設定 | `.paging(_:threshold:onLoadMore:)` modifier。`onLoadMore` は `@MainActor () async -> Void` | `paging = KsPaging(state, onLoadMore, threshold)`。`onLoadMore` は `suspend () -> Unit` |
| しきい値 (画面数、既定 1) | `threshold: Double` | `threshold: Float` |
| 次のページの読み込み中 | `.pagingAppendingIndicator { }` | `KsPaging(appendingIndicator = { })` |
| 次のページの失敗 / 終端 | `.pagingFailedFooter { retry in }` / `.pagingEndReachedFooter { }` | `failedFooter = { retry -> }` / `endReachedFooter = { }` |
| 最初の読み込み中 / 失敗 (0 件) / 空 | `.pagingLoadingPlaceholder { }` / `.pagingFailedPlaceholder { retry in }` / `.pagingEmptyPlaceholder { }` | `loadingPlaceholder` / `failedPlaceholder` / `emptyPlaceholder` |
| Pull to Refresh | 一覧に付けた `.refreshable { await }` を一覧が環境値 (`EnvironmentValues.refresh`) として読む。ライブラリの modifier は無い | `KsCollectionView(onRefresh = suspend () -> Unit)` |

語彙は 1 対 1 に対応し、記法は各プラットフォームの流儀に従う (core/ADR-0002)。表示の modifier は `.paging` の前後どちらに付けてもよく、`.paging` の無い一覧では効かない。Pull to Refresh はページングの外に置いてあり、ページングを付けない一覧でも使える。

## 責務境界

| 責務 | 持つ側 | 具体 |
|---|---|---|
| 状態の保持と遷移 | 利用者 (VM) | 5 状態のどれにするかを読み込みの進み具合で書き換える。誤った遷移 (追加読み込み中に取り直す等) をライブラリは防がない |
| ページの取得・件数・終わりの判断 | 利用者 (VM) | ライブラリはページの件数も取得の速さも知らない。最後まで読んだら終端にする |
| 末尾に近いかの判定と次ページ要求の呼び出し | ライブラリ | 下記「発火の条件」 |
| 二重に頼まないこと | ライブラリ | 下記「頼んだ後の待ち方」 |
| 6 つの表示の出し分けと置き場 | ライブラリ | 状態と 0 件かどうかで決める (下記「6 つの表示」)。中身は差し替えられる |
| エラーの文言・取り直しの失敗の知らせ | 利用者 | 差し替えた表示やアプリの画面が VM から読む。ライブラリは文言と翻訳を持たない (core/ADR-0024) |
| Pull to Refresh のインジケータと引っ張りの受け付け | ライブラリ | 各プラットフォームの標準の部品を使う |
| 古い読み込みの結果を捨てること | 利用者 (VM) | 取り直しと追加読み込みが競合したとき (下記「利用者の VM が守る書き方」) |

## 保証すること

### 5 つの状態

状態は付属値 (エラーの値・どの読み込みの失敗か) を持たない列挙で、状態どうしをそのまま比べられる (core/ADR-0019)。ライブラリは状態を読むだけで、次ページ要求を呼んでも状態は利用者が書き換えるまで変わらない。

| 状態 | ライブラリの振る舞い |
|---|---|
| 待機 (`idle`) | 末尾に近ければ次ページ要求を呼ぶ。項目が 0 件なら、しきい値によらず呼ぶ (最初の読み込み) |
| 取り直し中 (`refreshing`) | 自動では頼まない。0 件なら真ん中に読み込み中を出す。差し替えで先頭を表示する合図になる |
| 追加読み込み中 (`appending`) | 自動では頼まない。項目があれば見えている範囲の下端に次のページの読み込み中を、0 件なら真ん中に最初の読み込み中を出す。Pull to Refresh の引っ張りを受け付けない |
| 失敗 (`failed`) | 自動では頼まない。再試行の操作でだけ頼む |
| 終端 (`endReached`) | 頼まない。末尾を表示中の末尾への挿入で末尾に留める (下記「表示範囲の置き方」) |

### 発火の条件 (core/ADR-0020・0034)

状態が待機のとき、次の式が成り立てば次ページ要求を呼ぶ。

```
配列の件数 − 1 − (画面に出ているいちばん後ろの項目の添字) ≦ ceil(しきい値 × 画面に出ている項目の数)
```

添字は配列の 0 始まりの位置である。左辺は「いちばん後ろの項目より後に残っている項目の数」になる。

「画面に出ている」は一覧の表示範囲と少しでも重なる項目で、バーの裏に流れている項目も含み、画面外で前もって組み立てられた項目は含まない。数えるのは項目だけで、グループの見出し・ルートのヘッダー / フッター・ページングの表示は数えない。list でもグリッドでも行ではなく項目の数で数えるため、列数・向き・項目の大きさによらず「末尾の同じ画面数手前」で頼む。しきい値 0 は最後の項目が画面に入ったら頼むことを表す。

項目が 0 件で状態が待機なら、しきい値によらず頼む。VM は最初の読み込みを自分で始めなくてよい。項目が 1 件以上あるのに画面に出ている項目が 1 つも無い (ルートのヘッダーだけで表示範囲が埋まっている等) ときは頼まず、項目が画面に出てから判定する。

判定し直すきっかけは、スクロール・配列の差し替え・状態の変化・しきい値の変化・一覧の大きさの変化 (回転を含む) である。そのため 1 ページが画面に満たない一覧は、スクロールしなくても残りの項目の数が式の右辺を超えるまで続けて頼み、失敗から待機に戻したときもその場で判定される。

並べ替えのドラッグ中 (ドラッグが始まってから、置いて受け入れの結果が出て表示が落ち着くまで) は判定せず、ドラッグが終わってから判定し直す (core/ADR-0034。[collection-reorder](collection-reorder.md))。ドラッグ中は届いた配列を表示に当てないため、判定すると頼んだページが表示に出ないまま待ちが解け、次のページを連鎖して頼むためである。

### 不正なしきい値

しきい値が負の数、または有限でない数 (NaN・無限大) なら不正入力とし、debug は assertion、release は警告ログを出して 0 として扱う (core/ADR-0011)。報告は値が変わった回に 1 度だけ行う。0 にすると毎ページ読み込み中が見えるため、release でも誤りに気づける。

### 頼んだ後の待ち方・再試行・取り消し (core/ADR-0022・0019)

一度頼んだら、その処理が終わり、かつ頼んだ時点から状態か配列の中身が変わるまで、次を頼まない。処理の中で取得を待つ VM でも、VM のスコープに起動してすぐ戻り少し後で状態を書き換える VM でも、二重に頼まない。処理が状態も配列も変えずに戻ったときは、どちらかが変わるまで頼まない。

失敗の表示 (次のページの失敗・失敗 (0 件)) の差し替えには再試行の操作が渡る。再試行は、状態が失敗なら、項目が 0 件かどうかにも Pull to Refresh の有無にもよらず、いつも次ページ要求を呼ぶ。次ページ要求の処理が実行中なら何もしない。

次ページ要求と Pull to Refresh の処理は、ライブラリが一覧の寿命に結びついたタスク (iOS) / コルーチン (Android) で実行し、一覧が破棄されたら取り消す (iOS は一覧の representable が取り除かれたとき、Android は一覧がコンポジションを離れたとき)。別の画面へ進んでも一覧が残っている間は取り消さない。一覧が残るかは各プラットフォームのナビゲーションの仕組みで決まる (下記「両プラットフォームの差」)。

### 6 つの表示 (core/ADR-0024)

ページングを付けた一覧は、状態と項目が 0 件かどうかで次のうち高々 1 つを出す。それぞれの表示に、利用者が中身を書く差し替え口 (上の「公開 API」の表) がある。状態だけが変わった更新 (配列は同じ) でも表示は追随する。

| 状態 | 項目が 1 件以上 | 項目が 0 件 |
|---|---|---|
| 追加読み込み中 | 次のページの読み込み中 | 最初の読み込み中 |
| 失敗 | 次のページの失敗 | 失敗 (0 件) |
| 終端 | 終端 | 空 |
| 取り直し中 | 出さない | 最初の読み込み中 |
| 待機 | 出さない | 出さない |

既定で出すのは 2 つの読み込み中だけで、各プラットフォームの標準のくるくる (iOS `ProgressView`、Android `CircularProgressIndicator`) を文言なし・下地なしで出す。色はアプリの色設定 (iOS の tint、Android の Material の primary) に従い、色を指定する設定は持たない。失敗・終端・空は、差し替え口を書いたときだけ出る。読み込み中の既定を消したいときは、空の View / Composable を渡す。

VM が自分で始めた取り直しの間、項目が並んでいればライブラリは何も重ねない (取り直し中だと見せたいアプリは自分で出す)。

#### 置き場

| 表示 | 置き場 | 位置を決めるもの |
|---|---|---|
| 次のページの読み込み中 | 一覧の見えている範囲の下端の中央に止めて重ね、項目はその裏を流れる。スクロールしても動かない | 下端の安全領域 + 8pt / 8dp だけ上。`contentPadding` では変わらない (core/ADR-0025) |
| 次のページの失敗 / 終端 | 最後の項目の後ろ・ルートのフッターの前 (中身の一部としてスクロールする) | 左右の `contentPadding` の内側で、利用者のルートのフッターと同じ幅。グリッドでは全列にまたがり、横は中央 |
| 最初の読み込み中 / 失敗 (0 件) / 空 | 項目の代わりに、見えている範囲の真ん中に 1 つ重ねる | 上下の安全領域を除いた範囲の真ん中。ルートのヘッダー / フッターは 0 件でも出るが、重なったら 0 件の表示が手前になる |

次のページの読み込み中だけを重ねる置き場にしているのは、中身の一部にすると速いフリックで末尾に追いつくたびに項目と一緒に流れてくるためである (core/ADR-0024)。

#### タッチ・フェード・読み上げ

| 項目 | 契約 |
|---|---|
| 次のページの読み込み中 (既定) | タッチを受けず、下の項目を押せる |
| 次のページの読み込み中 (差し替え) | 表示の範囲のタップを受け止め、押せる部品が無くても下の項目へ通さない。範囲から始めたドラッグは一覧のスクロールになる (スクロールインジケータと、端での伸び・跳ね返りも一覧と同じに出る)。範囲の外は下へ通す |
| 0 件の表示 | 中の操作 (再試行) はヘッダー / フッターと重なっても押せる。表示の外への操作 (ヘッダー / フッター・引っ張り) は妨げない |
| 出入り | 次のページの読み込み中は 0.2 秒のフェードで出入りする。失敗・終端に変わった直後は、消えていく読み込み中とフッターの枠の表示が一瞬重なって見える |
| 読み上げ | 既定の読み込み中は、OS がその部品の言葉で読み込み中の要素として読む (iOS は読み込み中の要素、Android は不定の進捗の semantics)。ライブラリは読み上げの名前を与えない |

### Pull to Refresh (core/ADR-0023)

取り直しの処理を渡した一覧は、先頭で引っ張ると取り直しの処理を呼ぶ。ページングを付けない一覧でも使え、項目が 0 件でも引っ張れる。処理を渡さない一覧は引っ張れない。iOS は `.refreshable` の処理を `UIRefreshControl` につなぎ、Android は material3 の `Modifier.pullToRefresh` と `PullToRefreshDefaults.Indicator` で組む (`PullToRefreshBox` には引っ張りを止める設定が無いため)。

| 場面 | インジケータ |
|---|---|
| 引っ張ってから取り直しの処理が終わるまで | 出す |
| 処理が終わった後 | 状態が取り直し中の間だけ出し続け、取り直し中でなくなったら消す (処理がすぐ戻り、後で状態を戻す VM のため) |
| 引っ張らずに状態を取り直し中にした (VM が始めた取り直し) | 出さない |

状態が追加読み込み中の間と、ライブラリが頼んだ次ページ要求の処理が実行中の間は、引っ張っても取り直しは始まらない。どちらでもなくなれば、また引っ張れる。追加読み込みの結果が取り直しの後に遅れて届き、新しい一覧の後ろに古いページが混ざるのを防ぐためである。

### 表示範囲の置き方 (core/ADR-0021)

ページングを付けた一覧では、配列を差し替えたときの表示範囲を、差し替えの直前に一覧へ渡されていた状態で決める。端を表示中の端への挿入 (用語節。core/ADR-0018、[collection-items](collection-items.md)) のうち末尾側の規則が、ここで置き換わる。先頭側の規則とページングを付けない一覧は変わらない。

| 差し替えの直前の状態 | 表示範囲 |
|---|---|
| 取り直し中 | 差し替えと同時にコンテンツの先頭 (ルートのヘッダーの上端) を表示する。途中までスクロールしていても、件数が大きく変わる差し替え (10,000 件から 1 ページ目に戻す等) でも同じ |
| 終端 | ADR-0018 のまま。末尾を表示中の末尾への挿入は末尾に留める |
| 待機・追加読み込み中・失敗 | 末尾への挿入でも末尾に留めず、各プラットフォームの既定の位置の保ち方にする。届いたページは今の位置の下に現れる。末尾に留めると、送られた先でまた発火の条件をすぐ満たし、スクロールしなくても最後のページまで読み込みが続くため |

最後のページが届くのと同時に終端にした差し替えは、直前が追加読み込み中なので末尾に留めない。0 件の一覧に最初のページが届いたときは先頭のままになる。

Pull to Refresh で始めた取り直しの間 (ライブラリが取り直しの処理を呼んでから、インジケータを出し終えるまで) に届いた差し替えは、直前の状態とページングの有無によらず先頭を表示する。ライブラリが取り直しの間を自分で知っているため、取得が速く「取り直し中」と差し替えが 1 回の描画にまとまっても確実に効く。取り直しの結果が前と同じ中身の配列だった場合も先頭を表示する (iOS はインジケータを出し終えるとき、Android は新しい配列を受け取ったとき)。

### 安全領域 (core/ADR-0025)

一覧を画面全体に広げて置いたとき (iOS の `.ignoresSafeArea()`、Android の edge-to-edge) も、行はバーの裏を流れたまま (core/ADR-0017)、ライブラリが一覧に重ねる次の 3 種類の表示だけを安全領域に合わせる。安全領域に重ならない置き方では安全領域の分のずらしはすべて 0 で、見え方は変わらない。

| 表示 | 合わせ方 |
|---|---|
| Pull to Refresh のインジケータ | 上端の安全領域の境目 (バーのすぐ下) より下に出す。引っ張り始めは境目の下に上から現れる |
| 0 件の表示 | 上下の安全領域を除いた、見えている範囲の真ん中に置く |
| 次のページの読み込み中 | 下端の安全領域の境目 (ナビゲーションバー・ホームインジケータのすぐ上) より上に置く |

iOS で上の `contentPadding` に安全領域の分を入れた一覧では、インジケータはその余白の中に描かれる。入れていない一覧では、取り直しの間だけコンテンツがインジケータの下で止まる余白をライブラリが足し、終われば外す。Android で `ComposeView` を画面の一部に置き、その下端がウィンドウの下端に届かない置き方では、下端の重なりは 0 になる。

### 両プラットフォームの差

公開契約として利用者に見える差で、受け入れたものは次のとおり。

| 場面 | iOS | Android |
|---|---|---|
| 取り直しの間に下へスクロールし、配列を変えずに状態を戻したとき (取り直しの失敗など) | 取り直しを終えるときに先頭へ戻る | スクロールした位置に残る |
| 実行中の処理が取り消される時機 | `NavigationStack` で次の画面を積んでも一覧は残り、取り消さない | Navigation Compose で次の画面へ進むと前の画面はコンポジションを離れ、実行中の処理は取り消される |
| 処理が失敗を投げたとき | `onLoadMore` / `.refreshable` は投げない型なので、失敗は VM の中で扱うしかない | `onLoadMore` / `onRefresh` が投げた例外をライブラリは捕まえない。失敗は VM の中で捕まえて状態にする |
| 「配列の中身が変わった」の見分け (待ち方の解除) | 配列を同値比較で比べる | 配列の参照が変わった回だけ中身を比べる |
| 「末尾へ」のスクロール命令の行き先 | 最後の項目の下端 | 最後の lazy 要素 (ルートのフッターの枠。失敗・終端の表示を含む) の末尾 |

1 行目の差は、iOS が配列を中身で比べるため「失敗して配列がそのまま」と「前と同じ中身の成功」を見分けられず、後者で先頭を表示する手当てが前者にも効くことから来る。そろえるには公開 API に合図を足す必要があり、項目や操作は壊れないため差として受け入れた (出典: kasane/changes/archive/2026-09-29-paging-state-machine/deviation.md)。

## 利用者の VM が守る書き方

ライブラリは状態の遷移を強制しないため、次の書き方は VM 側の約束である。守らないときの結果は ADR の負の帰結として受け入れている。

| 書き方 | 守らないと |
|---|---|
| 次ページ要求の処理から戻る前に状態を追加読み込み中にする (処理の中で取得を待つか、先に状態を書いてから起動する) | 戻ってから書き換えるまでの間に引っ張れ、その取り直しに古いページが混ざりうる (core/ADR-0023) |
| ページの配列と次の状態 (待機・終端) を同じ回に書く。取り直しの配列と待機も同じ回に書く | 配列より先に状態を終端にすると末尾に留めて届いたページを飛ばし、取り直しの配列より先に待機へ戻すと先頭を表示しない (core/ADR-0021) |
| 最初の読み込みを VM が自分で始めない (0 件で待機にしておけば一覧が頼む) | 状態の書き換えが遅れたときに二重に読み込む (core/ADR-0020) |
| 次ページ要求の処理は、失敗の状態からの呼び出し (再試行) と、項目が空のときの呼び出し (最初のページ) を受け付ける | 再試行しても読み込みが進まない。0 件の一覧の再試行も取り直しではなく次ページ要求で来る (core/ADR-0019) |
| 続きがあるまま空のページを返さない。最後まで読んだら終端にする | 終端になるまで頼み続ける。0 件の一覧は終端にしたときだけ空の表示になる (core/ADR-0020) |
| 項目があるときの取り直しの失敗は失敗の状態にせず元の状態に戻し、「更新できませんでした」などの知らせはアプリが出す | いちばん下の項目のすぐ下に再試行が出て、押すと取り直しではなく次のページを頼む (core/ADR-0019) |
| 取り直しを始めたら、それより前に始めた読み込みの結果を捨てる (世代の番号など) | VM が自分で始める取り直しと追加読み込みの競合をライブラリは防がないため、新しい一覧に古いページが混ざる (core/ADR-0023) |
| VM が自分で始める取り直しで先頭から見せたいときは、取り直し中が一覧に届いて (その状態で一度描画されて) から配列を差し替えるか、差し替えと一緒に `KsScrollController.scrollToStart` を出す。届いたことをライブラリは知らせないため、画面側で状態の反映を観測して VM に伝える | 取得がすぐ終わると取り直し中と差し替えが 1 回の描画にまとまり、一覧からは取り直しだと分からず先頭へ送られない (core/ADR-0021) |
| 一覧の破棄で取り消されては困る読み込み (Android で前の画面へ戻る場合など) は、VM のスコープで起動する | 一覧の表示の中で実行される処理は一覧の寿命に結びつき、途中で取り消されて状態が追加読み込み中のまま残りうる (core/ADR-0022) |

リポジトリ同梱の Sample「ページング」の VM がこれらの書き方の見本である。取り直しは「取り直し中が一覧に届いたと画面が知らせてから取得する」手順で先頭を確実にする (知らせるのは画面で、iOS は状態の `onChange`、Android は一覧を描いた回の `SideEffect` で VM に伝える)。また、項目があるときの取り直しの失敗では、取り直しの前が追加読み込み中 (または取り直し中) なら待機に戻す (古い読み込みの結果を捨てているため、追加読み込み中に戻すと先へ進めなくなる)。

## してはいけないこと

- 状態を一覧に書き換えてもらう前提で書かない。次ページ要求を呼んでも状態は変わらず、利用者が書き換えるまで待機のまま次を頼まない。
- 失敗の状態にエラーの中身を載せようとしない。状態は付属値を持たず、文言は差し替えた表示が VM から読む (core/ADR-0019)。
- VM が始めた取り直しの間に、ライブラリの Pull to Refresh のインジケータや重ね表示が出ることを期待しない。項目が並んでいれば何も出ない (core/ADR-0023・0024)。
- 次のページの読み込み中の表示を、一覧の下に自前で重ねたもの (浮いた操作パネル等) から避けるために `contentPadding` の下を広げない。位置は `contentPadding` では変わらず、安全領域だけで決まる (core/ADR-0025)。
- 失敗・終端・空の表示を設定しないまま、失敗や 0 件が画面に伝わると期待しない。既定では何も出ず、Pull to Refresh も無い一覧は失敗したまま止まる (core/ADR-0024)。
- Kotlin の VM で、取り消し (`CancellationException`) を失敗として捕まえない。一覧の破棄による取り消しが失敗の状態になり、戻ったときに自動で頼まれない。捕まえるのは取得の失敗の型に絞る。

## 用語

- **ページング**: 末尾に近づいたら次のページを読み足していく一覧の読み込み方 (無限スクロール)。先頭側へ前のページを足す読み込みは持たない。
- **次ページ要求**: ライブラリが呼ぶ `onLoadMore` の処理。項目が 0 件のときは最初のページの読み込みを意味する。
- **しきい値**: 何画面分手前で次ページ要求を呼ぶかを表す画面数。画面に出ている項目の数に掛けて件数に直す。
- **取り直し**: 一覧を最初から読み直すこと。Pull to Refresh で始まるものと、VM が自分で始めるもの (絞り込みの変更・再読み込みのボタン等) がある。
- **端を表示中の端への挿入**: コンテンツの先頭 (または末尾) を表示しているときに、配列のその端へ項目を入れる差し替え。表示範囲をその端に留める規則がある (core/ADR-0018、[collection-items](collection-items.md))。
- **差し替え口**: 6 つの表示それぞれの中身を利用者が書くための modifier (Swift) / `KsPaging` の引数 (Kotlin)。書かない表示は既定の見え方になる。
- **差し替えの直前の状態**: その配列の差し替えより前に一覧へ渡されたページングの状態。表示範囲の置き方を決める。
- **フッターの枠**: ルートのフッターを置く場所。ページングを付けた一覧では利用者のフッターが無くても置き、失敗・終端の表示をフッターの上に並べる。
- **0 件の表示**: 項目が 0 件のときの 3 つ (最初の読み込み中・失敗 (0 件)・空)。
- **安全領域**: 画面上端・下端のバー・切り欠き・ホームインジケータが占める範囲 ([collection-layout](../styling/collection-layout.md) の用語)。
