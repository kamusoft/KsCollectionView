# Android: 外観の反映とダーク / ライトの確認 (tasks 5.2・5.3 の Android 側、3.2 の作り直しの確認)

- 環境: Android Emulator (sdk_gphone64_arm64 / API 31、1080x2400)、Debug 構成 (`./gradlew :app:assembleDebug`)
- 撮影: エミュレータ + デモデータのみ。ステータスバーは時刻と汎用のアイコンだけで、個人要素が写っていないことを保存後に画像を開いて確かめた。画像グリッドの写真はデモ用の公開画像
- 端末の表示モードは `adb shell cmd uimode night yes|no`、保存した外観は `pm clear` (保存なし) とルートメニューのタップで用意し、画面は開始ルート (`--es ks_start_route demo/<画面>`) またはルートメニューから開いた
- `android-dark-screens-*`・`android-dark-operations-*`・`android-root-system-follows-device.png`・`android-recreate-from-start-route.png` は複数の画面を 1 枚に並べた一覧 (1 枠 = 1 画面、1/3 に縮小)。それ以外は 1/2 に縮小した 1 画面

## 3.2 作り直しが画面回転と同じ扱いであること

- 外観の変更は `Activity.recreate()` で作り直す。logcat には `Schedule relaunch activity` と出て、端末の構成変更 (回転・表示モードの切り替え) と同じ「保存した状態を引き継ぐ作り直し」の経路を通る。上の「システム」の追随の確認では、端末の表示モードの切り替え (構成変更) による作り直しも同じ画面の状態のまま起きている
- 開始ルート: `ks_start_route demo/List` で起動 → 戻るでルートメニューへ →「ダーク」をタップ。作り直し後もルートメニューのままで「リスト」が積み直されず、そこで戻るを 1 回押すとアプリを抜けた (戻り先はルートメニューだけ)。開始ルートの消費済みの印 (`rememberSaveable`) が回転時と同じく引き継がれている (`android-recreate-from-start-route.png`)
- 計測用の初期化 (`MainActivity.onCreate`): 作り直しでは回転時と同じく `onCreate` が再実行される。起動時の追加情報 (Intent) も回転時と同じく残るため、画像キャッシュの消去の要求・読み込み中の計数の要求は回転時と同じ値で再適用され、計数は回転時と同じく初期化される。画像の共有ローダーの差し替え (`installImageLoadingObserver`) は 2 回目以降は既に差し替え済みのローダーに対して呼ばれ、何もせずに戻る。「画像グリッド」を開いてからルートメニューで外観を変えても落ちないことをエミュレータで確かめた

## 5.3 ダークで崩れない

「ダーク」を保存し、端末はライトのまま確認した。判定は `ui/brief.md` の視認性の基準。OS の部品 (ステータスバー・ナビゲーションバー) とライブラリの既定の色 (区切り線「既定」・画像の読み込み中の色・スクロールインジケータ) は 5.4 の対象のため、ここでは読めるかどうかだけを見た。

配色定義のダークの組のコントラスト比 (単体テスト `SamplePaletteParityTest` でも計算して確かめている): 文字 / 下地 15.52、文字 / 行 13.30、補助の文字 / 下地 6.56、補助の文字 / 行 5.62、アクセント / 下地 5.82、アクセント / 行 4.99、アクセントの上の色 / アクセント 5.82、区切り / 行 1.34。いずれも基準 (文字の組 4.5 以上、区切り / 行 1.3 以上) を満たす。

Material の部品が既定で取る色は配色定義から作る (メニューの面 = 下地、スイッチのオフの溝とスライダーの残りの溝 = 区切り、枠・オフのつまみ = 補助の文字、文字 = 文字)。

## 5.3 ライトは変わらない

変更前のビルド (Android のコードを変える前に同じ作業ツリーでビルドした debug APK) と変更後のビルドで、同じ 14 画面 (ルートメニュー・デモ画面 12・検証画面) を端末ライト・外観「ライト」で開始ルートから撮り、ステータスバー (時刻) を除いて画素ごとに差を取った。

| 画面 | 結果 |
|---|---|
| ルートメニュー | 先頭に「外観」の項目群が増えた分だけ異なる (意図した変更)。既存の項目の行の色 #FFFFFF・下地 #F2F2F7・上部バーは同じ |
| リスト・グリッド (固定列)・グリッド (adaptive)・向きで列数変更・テンプレート切り替え・ルートヘッダー/フッター・スクロール制御・大量件数・グループ化・差分更新・検証: 行の高さ変化 | 全画素一致 |
| 画像グリッド | メニューの開閉の印 (▼) の 196 画素だけが異なり、各成分の差は最大 20 / 255 |
| スペーシングと余白 | スライダーの残りの溝だけが異なる。Material の既定の薄紫から配色定義の区切りの色 (#D9D9DE) の灰色へ |

初期表示で出ない状態も見比べた (`android-light-before-after-material-parts.png`。上段はスライダーで上が変更前・下が変更後、中段と下段は左が変更前)。

- 差分更新のグループのスイッチのオフ: 溝が Material の既定の薄紫から区切りの色の灰色へ、枠とつまみが Material の既定の灰色から補助の文字の色へ
- 画像グリッドのプリフェッチのメニューの面: Material の既定の薄紫 (#F3EDF7) から下地の色 (#F2F2F7) へ (各成分の差は最大 5 / 255。下段の右端はダーク)

いずれも Material の部品の既定の色を配色定義に載せる作業 (tasks 4.2) による差で、配色定義のライトの組の値そのものは変えていない。
