## 1. 配色定義を 2 組にする

- [x] 1.1 iOS の Sample 共通の配色定義 (`SampleTheme.swift`) の各色 (accent / background / cell / text / secondaryText / separator) をライト / ダークの 2 組にし、選んだ外観に応じた組を画面側が同じ名前で取れるようにする。ライトの組は今の値のまま、ダークの組は承認 mock の値。色見本 (`swatches`) は項目の内容の色のため両外観で同じ値 (→ Requirement: 両プラットフォーム同値の 2 組の配色)
- [x] 1.2 Android の `SampleTheme.kt` を 1.1 と同じ名前・同じ値・同じ並びで 2 組にする (→ Requirement: 両プラットフォーム同値の 2 組の配色)
- [x] 1.3 Android の単体テストに、iOS の配色定義のライト / ダーク 2 組の値を書き写した表との突き合わせを足す (既存の `SampleScreenParityTest` と同じ形)。あわせて、`ui/brief.md` の視認性の基準の対象の組 (ダークの組) について、コントラスト比が基準以上であることを計算で確かめる (→ Scenario: 両プラットフォームで同じ値 / ダークで崩れない)

## 2. 外観の切り替えと保持

- [x] 2.1 外観の選択肢の定義を両プラットフォームに 1 箇所ずつ置く — 見出し「外観」、項目「システム」「ライト」「ダーク」、読み上げ文言「選択中」、初期値「システム」、保存に使うキー (→ Requirement: 外観の切り替え)
- [x] 2.2 iOS のルートメニューの先頭に「外観」の項目群を置き、選択中の印と読み上げ、選んだ値の保存と起動時の読み戻しを実装する (→ Requirement: 外観の切り替え)
- [x] 2.3 Android のルートメニューに 2.2 と同じ位置・同じ文言で「外観」の項目群を置き、選択中の印と読み上げ、選んだ値の保存と起動時の読み戻しを実装する (→ Requirement: 外観の切り替え)
- [x] 2.4 Android の単体テスト: 外観の文言と並びが iOS と一致すること (1.3 と同じ形の表)、保存が無いときの選択が「システム」であること、保存した値が読み戻せること、選択中の項目だけが「選択中」と読まれること (→ Scenario: 両プラットフォームで同じ構成 / 初回起動は「システム」/ 選んだ値が起動し直しても残る / 読み上げで選択中が分かる)
- [x] 2.5 iOS の UI テスト: 保存が無い状態で起動すると「システム」が選択中、「ダーク」を選んで起動し直すと「ダーク」が選択中、選択中の項目だけが「選択中」と読まれること (保存の初期化は起動引数などテスト側から行い、テストで選んだ外観が他の UI テストや計測の起動に持ち越されないようにする) (→ Scenario: 初回起動は「システム」/ 選んだ値が起動し直しても残る / 読み上げで選択中が分かる)

## 3. 外観の反映

- [x] 3.1 iOS: 選んだ外観でアプリの window の外観を上書きする。起動の分岐 (`SampleLaunchView`) より上に掛け、起動引数で直接開く画面にも効かせる。「システム」は上書きなし。`preferredColorScheme` は使わない (「システム」に戻した後に OS の部品が前の配色で残るため) (→ Requirement: 外観の反映)
- [x] 3.2 Android: 選んだ外観で Activity の表示モードの設定を上書きし、選択が変わったら Activity を作り直す。ダーク用の Activity テーマ (`values-night`) を足し、Compose の Material の配色も外観に合わせる。作り直しは画面回転と同じ扱いとし、計測用の初期化 (`MainActivity.onCreate`) と開始ルートの扱いが回転時と変わらないことを確かめる。ライブラリの `isSystemInDarkTheme()` が上書きした外観を返すことを確かめる (→ Requirement: 外観の反映)
- [x] 3.3 3.1 / 3.2 で使う外部 API (iOS の window の外観の上書き、Android の Configuration の上書きと Activity の作り直し) が採用版の SDK で公開宣言されていることを、宣言の位置とともに実装報告に書く (→ Requirement: 外観の反映)

## 4. 色の載せ替え

- [x] 4.1 iOS: ルートメニューから開ける全画面 (デモ画面と検証画面) で、Sample が自分で描く色のうち配色定義を経由していないもの (色を指定していない文字など) を配色定義に載せる。OS の標準部品 (segmented の Picker・ナビゲーションバー等) は塗り替えない。起動引数だけで開く計測・検証の経路は対象外 (proposal の Non-Goals) (→ Requirement: 両プラットフォーム同値の 2 組の配色)
- [x] 4.2 Android: 4.1 と同じ範囲で、`Color.White` の直書き (`TemplateSwitchDemoScreen.kt` / `DiffUpdateDemoScreen.kt` / `SampleSegmentedControl.kt`)、上部バー、Material の既定の配色のまま描いている部品を配色定義に載せる。`Color.White` はいずれもアクセントの上に載せる文字・つまみの色のため、配色定義に「アクセントの上の色」として足す (ライトは白、ダークは下地のダークの色 — `ui/brief.md` のデザイントークン参照。iOS の配色定義にも同じ名前・同じ値で足す)。計測用ビルドだけの印は対象外 (→ Requirement: 両プラットフォーム同値の 2 組の配色)
