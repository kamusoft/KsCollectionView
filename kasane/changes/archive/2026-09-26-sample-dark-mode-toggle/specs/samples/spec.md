# samples (ライト / ダークの切り替え) — デルタスペック

## ADDED Requirements

### Requirement: 外観の切り替え
両プラットフォームの Sample は、ルートメニューに見出し「外観」の項目群を同じ位置・同じ文言で持つ (SHALL — handbook/cross/sample-parity)。項目は「システム」「ライト」「ダーク」の 3 つで、いずれか 1 つが選択中になる (SHALL)。選択中の項目は印で示し、読み上げでは項目名とあわせて「選択中」と読まれる (SHALL)。選んだ値が保存されていないとき (初回起動) の選択は「システム」とする (SHALL)。選んだ値はアプリを終了して起動し直しても保持される (SHALL)。

#### Scenario: 両プラットフォームで同じ構成
- **GIVEN** 両プラットフォームの Sample
- **WHEN** ルートメニューを開く
- **THEN** 見出し「外観」と「システム」「ライト」「ダーク」の 3 項目が同じ位置・同じ文言で並び、選択中の項目に印がある

#### Scenario: 初回起動は「システム」
- **GIVEN** 外観を一度も選んでいない状態 (インストール直後)
- **WHEN** Sample を起動してルートメニューを開く
- **THEN** 「システム」が選択中である

#### Scenario: 選んだ値が起動し直しても残る
- **GIVEN** ルートメニューで「ダーク」を選んだ
- **WHEN** アプリを終了して起動し直す
- **THEN** 「ダーク」が選択中で、アプリ全体がダークで描かれる

#### Scenario: 読み上げで選択中が分かる
- **GIVEN** 読み上げ機能 (VoiceOver / TalkBack) が有効
- **WHEN** 選択中の外観の項目に触れる
- **THEN** 項目名と「選択中」が読まれ、選択中でない項目では「選択中」が読まれない

### Requirement: 外観の反映
選んだ外観は、Sample の配色・OS が描く部品 (画面上部のバー・ステータスバー・システムの操作部品)・表示モードに従うライブラリの既定の色のすべてに効く (SHALL)。「ライト」「ダーク」は端末の表示モードに関わらずその外観で描き、「システム」は端末の表示モードに従う (SHALL)。選んだその場で反映し、アプリの再起動を要しない (SHALL)。起動引数 (iOS) / 開始ルート (Android) で直接開いた画面にも、保存された外観が効く (SHALL)。

#### Scenario: 「ダーク」を選ぶとアプリ全体がダークになる
- **GIVEN** 端末がライトで、ルートメニューを表示中
- **WHEN** 「ダーク」を選ぶ
- **THEN** 再起動せずに、ルートメニューとそこから開く全画面が Sample のダークの配色で描かれ、OS が描く部品もダークで描かれる

#### Scenario: 「ライト」を選ぶと端末がダークでもライトで描かれる
- **GIVEN** 端末がダーク
- **WHEN** 「ライト」を選び、「大量件数」を開いてスクロールする
- **THEN** 全画面がライトの配色で描かれ、OS が描く部品とライブラリのスクロールインジケータもライトの見え方になって、背景に埋もれずに見える

#### Scenario: 「システム」に戻すと端末の変化に追随する
- **GIVEN** 「ダーク」を選んだ後に「システム」に戻した
- **WHEN** アプリを表示したまま、端末の表示モードをライトとダークの間で切り替える
- **THEN** そのたびに Sample の配色と OS が描く部品 (画面上部のバー・ステータスバーを含む) がそろって端末の表示モードに切り替わり、前の配色のまま残る部品が無い

#### Scenario: 直接開いた画面にも効く
- **GIVEN** 「ダーク」を選んで保存した状態
- **WHEN** 起動引数 (iOS) / 開始ルート (Android) でデモ画面を指定して起動する
- **THEN** その画面がダークで描かれる

### Requirement: 両プラットフォーム同値の 2 組の配色
ルートメニューから開ける全画面 (デモ画面と検証画面) で、Sample が自分で描く色 (背景・文字・区切り・自前の操作部品の塗り) は、Sample 共通の配色定義のライトの組またはダークの組から、選んだ外観に応じて取る (SHALL — cross/ADR-0007)。2 組の同名の色は両プラットフォームで同じ RGBA とする (SHALL)。Sample が自分で描く色を OS の semantic color に任せて表示モードに追随させない (SHALL NOT)。ライトの組は変更前の配色と同じ値とする (SHALL)。OS の標準部品の見た目は Sample の配色で塗り替えなくてよい (MAY — sample-parity の許容される差異)。

#### Scenario: ダークで崩れない
- **GIVEN** 「ダーク」を選んだ状態
- **WHEN** ルートメニューから開ける全画面を開き、各画面にある操作をひととおり行う
- **THEN** 文字・操作部品・区切り・選択の印がどれも背景に埋もれずに読め、背景と前景が同じ明るさで重なって読めない組み合わせが無い (判定は `ui/brief.md` の視認性の基準)

#### Scenario: ライトの見た目は変わらない
- **GIVEN** 「ライト」を選んだ状態
- **WHEN** ルートメニューから開ける全画面を開く
- **THEN** 変更前と同じ配色で描かれる

#### Scenario: 両プラットフォームで同じ値
- **GIVEN** 両プラットフォームの Sample 共通の配色定義
- **WHEN** ライトの組とダークの組の同名の色を突き合わせる
- **THEN** すべて同じ RGBA である
