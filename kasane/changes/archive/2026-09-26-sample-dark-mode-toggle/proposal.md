# Proposal: sample-dark-mode-toggle

## Why

iOS / Android の Sample は、端末をダークモードにすると表示が崩れる。Sample の配色 (`SampleTheme`) は固定の明るい色なのに、OS の部品 (iOS のナビゲーションバーの題名・ステータスバー・segmented の Picker、色を指定していない文字) とライブラリの既定の一部 (スクロールインジケータ) は表示モードに従うため、明るい背景の上に白い文字やインジケータが描かれて読めなくなる。`android-scrollbar-parity` の基準機確認 (Pixel 4a) でインジケータが見えなくなって発覚し、iOS シミュレータでも同じ条件で崩れを確かめた。Sample はプラットフォーム間パリティの検証装置 (cross/ADR-0004) なので、端末の設定しだいで使えなくなる状態は放置できない。

オーナー判断で、Sample の中でライト / ダークを切り替えられるようにする。パリティの規約とは、両プラットフォーム同値の 2 組の配色と同じ切り替えで行うことで両立させる (cross/ADR-0007)。ダークでも Sample が崩れなくなれば、ライブラリの既定の色がダークでどう見えるかを両プラットフォームで比べる検証装置にもなる。

## What Changes

- **外観の切り替え**: ルートメニューに見出し「外観」の項目群を置き、「システム / ライト / ダーク」から選ぶ。初回は「システム」、選んだ値は再起動後も残る。選択中の項目は印と読み上げで分かる。文言・構成は両プラットフォームで同じ (`../KsSettingsView/` の Sample と同じ形)
- **反映の範囲**: 選んだ外観はアプリ全体に効く — Sample の配色、OS の部品、表示モードに従うライブラリの既定の色。選んだその場で反映し、起動引数で直接開く画面にも効く。「システム」では端末の表示モードの変化に追随する (ライト / ダークから戻した後も、ナビゲーションバー等が前の配色で残らない)
- **配色**: `SampleTheme` の各色をライト / ダークの 2 組にし、両プラットフォームで同じ RGBA にする。ライトの組は今の値のまま (ライトの見た目は変えない)。ダークの組は承認 mock で決める
- **色の載せ替え**: ルートメニューから開ける全画面 (デモ画面と検証画面) で、Sample が自分で描く色 (背景・文字・区切り・自前の操作部品の塗り) のうち `SampleTheme` を経由していないものを `SampleTheme` に載せる — iOS の色を指定していない文字、Android の `Color.White` の直書き、既定のままの Material の配色・Activity テーマ。OS の標準部品 (iOS の segmented の Picker・ナビゲーションバー等) の見た目は塗り替えず OS に任せ、外観の上書きで Sample の配色と表示モードを揃える (sample-parity の「許容される差異」: プラットフォームの見た目そのもの)
- **反映の仕組み (両プラットフォームの方針)**: iOS はアプリの window の外観を、起動の分岐 (`SampleLaunchView`) より上で上書きする (`preferredColorScheme` は「システム」に戻した後に OS の部品が前の配色で残るため使わない — KsSettingsView の知見)。Android は Activity の表示モードの設定を上書きし、変更時は Activity を作り直す。作り直しは画面回転と同じ扱いで、計測用の初期化 (`MainActivity.onCreate`) も回転と同じく再実行される
- **完了条件に含める確認**: ライブラリの既定の色に頼る画面 (一覧・画像グリッド・大量件数など) を、両プラットフォーム × ライト / ダークでオーナーが目視し、見つかった問題を記録する。問題の修正はこの change に含めず、確認の後にまとめて簡易起票する

影響する能力: samples (検証装置)

## Non-Goals

- **ライブラリの既定の色のダーク対応** (区切り線の既定が固定の明るい灰色のまま・画像の読み込み中の色が iOS は追随し Android は固定で食い違う 等) — 別の能力 (styling / image-loading) で、core/ADR-0010 の一部改訂を伴う設計判断のため、確認の後に簡易起票する (探索での決定)
- **起動引数だけで開く計測・検証の経路** (ルートメニューに出ない iOS の操作・画像の挙動・計測の検証画面、両プラットフォームの計測用の印) **の色の載せ替え** — デモ画面の集合に入らない技術検証・計測用の経路で、外観の検証の対象ではない。選んだ外観そのものはこれらにも効く
- **sample-parity の規約文面の書き換え** — handbook の書き込み経路 (ksn-distill) で蒸留時に行う (cross/ADR-0007)。実装タスクには入れない

## Impact

- 公開 API・ライブラリのコードの変更なし (Sample だけ)
- Sample の全画面で配色の参照先が変わる (両プラットフォーム)。ライトの見た目は変えない
- Android では外観を変えると Activity が作り直される (回転と同じ)
- 既知のリスク: ライブラリの修正が終わるまで、ダークでは既定の区切り線が明るい線のまま残る (探索で受け入れ済み)
- 保存した外観は計測用の経路にも効く。端末がダークで「システム」のまま計測経路を起動すると、その経路も OS の部品はダークで描かれる

## 級: M

Sample だけの機能追加で公開 API に触れないが、両プラットフォームの全画面の配色の載せ替え・切り替え UI・選択の保持・表示モードの反映を伴い、規約の改訂 (cross/ADR-0007) を含むため S の「局所的」に収まらない (2026-09-26 オーナー確定)

domain: cross   # 両プラットフォームの Sample と cross の規約。実装時のスキル解決は ios + android を結合
