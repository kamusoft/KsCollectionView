## 指摘事項

### [🟡 Minor (優先度: 低)] Android の件数の検査で、字下げの無い `@Test` だけを持つクラスが期待の集合から黙って抜ける

**該当箇所**: `scripts/ci/check-android-test-count.py:161-177` (`test_classes_in_source`)、`scripts/ci/check-android-test-count.py:42-44` (docstring)

**関わる仕様**: verification-ci「Android の検証」— 失敗の条件「テストのソースにあるテストのクラスのうち、結果に現れないものがある」、Scenario「一部のクラスの結果しか無いと落ちる」。

**問題点**: 行頭から始まる行は、まず「宣言・注釈になりうる行」として読まれ、そこで `current` を空にして次の行へ進む。`@Test` かどうかの判定はその後ろにあるので、行頭に書いた `@Test` は、テストとしても、属するクラスを導けない `@Test` としても数えられない。

```kotlin
class ATest {
    @Test
    fun a() {}
}
class BTest {
@Test
fun b() {}
}
```

再現: 上のソースを渡すと、期待の集合は `ATest` だけ、属するクラスを導けない `@Test` は 0 件になる。`BTest` の結果が無くても失敗にならない。docstring の「読み落としたクラスが期待の集合から黙って抜けないように…失敗にする」は、この形には当たらない。

同じく黙って数えられない形として、同じ行でほかの注釈の後ろに書いた `@Test` (`@Ignore @Test`) と、`@Test`・`@ParameterizedTest` 以外のテストの注釈 (`@TestFactory` など) だけを持つクラスがある。

現在のリポジトリにこれらの書き方は無い (検索で 0 件。本体 31・Sample 21 で一致している)。字下げの無い `@Test` は整形されたソースには現れないので、1 周目の指摘 (注釈と同じ行の宣言) より起きにくい。優先度は低い。

**推奨修正**: 次のどちらか。

- 行頭の行の判定の前に `@Test` の判定を置き、行頭の `@Test` を「属するクラスを導けない `@Test`」として失敗にする (数行の入れ替えで済む)。その場合のテストを 1 件足す
- 1 周目で挙げた逆向きの突き合わせ (結果に現れているのに、ソースから導いた集合に無いクラスがあれば失敗にする) を足す。導き方の取りこぼしを、書き方を問わずに拾える

直さない場合は、docstring の「読み落とす書き方は残りうる」の後ろに、行頭の `@Test` は拾えないことを書いておく。
