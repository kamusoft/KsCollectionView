## 確認した観点

- **合意済み乖離との一致**: 2 本とも `build-for-testing` と総称の iOS Simulator の行き先を使用する。テスト実行、Simulator の選択・起動、iOS の実行件数検査は残っていない。
- **ビルド対象**: 本体のテストターゲットの宣言と、Sample の通常スキームのアプリ・ユニットテスト・UI テストの構成を確認した。ホスト側の証跡にも各モジュールのコンパイルが記録されている。
- **失敗の伝播**: ビルド step は `xcodebuild` を直接呼び、終了コードを隠す後続処理や `continue-on-error` を持たない。本体が失敗しても Sample をビルドする条件があり、本体の失敗を取り消す処理はない。
- **前段の失敗とキャンセル**: 本体の step がスキップされた場合とキャンセルされた場合には、Sample を実行しない条件になっている。
- **削除したスクリプトの参照**: リポジトリ全体を検索した。残る名前は過去のレビュー・検証記録と、変更前の確認結果を明示した証跡に限られ、workflow や現行スクリプトからの呼び出しはない。
- **固定すべき識別子**: `lint`・`ios / verify`・`android / verify` の検査名、再利用 workflow の入口、入力なしの呼び出しは維持されている。
- **テストの妥当性**: 置き換えたテストは、ビルド対象、テストを実行しないこと、総称の行き先、失敗時の Sample 継続、失敗を隠す指定の不在を確認する内容になっている。
- **文書とスコープ**: proposal・design・specs は変更されていない。草稿は iOS の緑がテスト通過を保証しないことを明示し、証跡は変更前後を区別している。未完了の公開後タスクも未チェックのままである。
- **検証の範囲**: 指示どおりビルド・テストは再実行していない。ホスト側から提示された 111 件成功、2 本のビルド成功、コードを壊した場合の終了コード 65、actionlint と workflow 定義検査の成功を、提供済みの検証結果として扱った。変更後の GitHub ランナー上での実行は未確認である。

## 指摘事項

### [🟡 Minor] iOS ジョブの失敗原因をビルドだけに限定している

**該当箇所**: `drafts/verification-ci.md:152`

**問題点**: 「`ios / verify` が落ちるのは、ビルドできないときだけ」とあるが、実際には前段の `Select Xcode`・`Show toolchain` の失敗や、ジョブの時間上限でも失敗する。直前の表でも Xcode 選択の失敗を説明しており、この断定と食い違う。「同じコマンドを手元で流すと、同じ失敗が出る」という説明も、ランナー固有の問題には当てはまらない。

**推奨修正**: 「テストの実行結果では失敗しない。ビルドのほか、チェックアウト・ツールチェーンの準備・時間上限でも失敗する」と整理する。手元の同一コマンドは、ビルドエラーを切り分ける手段として案内し、同じ失敗の再現は断定しない。

## アクションプラン

1. 草稿の失敗原因と手元での再現に関する説明を修正する。実装の承認を妨げる指摘ではない。
2. 次の通常の CI 実行で、変更後の 2 本のビルド結果を証跡に追記する。
