## 5. 矛盾・疑わしい記述

- **5-1 (重大) paging.md「ページングの状態を持つモデルを書く」「実行中の読み込みが取り消される時機を知る」**。「取り消された取得は、ふつう `CancellationError` を投げます。これを `.failed` にしないでください」とあり、`FeedModel` は `catch is CancellationError` と `error is CancellationError` でしか取り消しを見分けません。しかし、`URLSession` の async の API は、タスクが取り消されると `URLError(.cancelled)` を投げます。`PostService` を `URLSession` で素直に実装して例を写すと、次のようになります。
  - `loadNextPage` は、取り消しを `.failed` にします (Skill 自身が禁じている形)。
  - `reloadFirstPage` は、取り消しで `refreshFailed = true` にします。

  これは一般的な Swift の知識による指摘で、ライブラリの動きを確かめたものではありません。`Task.isCancelled` も見るか、`URLError.cancelled` も取り消しとして扱う旨が要ります。
- **5-2 (欠け) reorder.md「移動の内容を配列に当てはめる」の `moveAndSave`**。保存に失敗すると `restore(original)` で丸ごと戻します。1 回目の保存が終わる前に 2 回目の移動を受け入れていると、1 回目の失敗で 2 回目の移動まで消えます。本文に注意がなく、「写して使う」と誤った動きになります。
- 5-3 (軽微) paging.md「モデルが守る書き方」の表の 2 行目。「`loadNextPage` は…配列が空のとき (最初のページ) を受け付ける」とありますが、コードの `guard` は状態 (`.idle` か `.failed`) しか見ていません。空のときに最初のページになるのは `posts.last?.id` が `nil` になるからで、説明とコードの対応が取りにくいです。
