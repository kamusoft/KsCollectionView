# セカンドオピニオン: user-docs (spec-001)
**相方**: codex / **label**: so-spec-user-docs-001 / **日付**: 2026-10-10 / **対象**: 提案一式 (`kasane/changes/user-docs/` の proposal.md・design.md・specs/ の 5 枚・tasks.md)
---
静的レビューの結果、**Major 3件、Minor 2件**です。実装前に以下を修正することを推奨します。

1. **Major — 源泉とSkillの対応を1対1に限定できない**
   該当箇所: `kasane/changes/user-docs/design.md:233`
   問題点: `sources` は源泉ごとにSkillの「1枚」だけを記録しますが、Decision 2では `collection-items.md` が `basics.md` と `layout.md` の両方の源泉です。どちらかだけに対応させると、もう一方への追従漏れが起きます。
   推奨修正: 対応先を複数指定できる形にし、一覧にすべての対応先が出るScenarioを追加してください。

2. **Major — 公開APIの変更を拾えない経路がある**
   該当箇所: `kasane/changes/user-docs/design.md:262`
   問題点: 本体ソースを差分対象から外し、公開宣言の「増減」は網羅の道具で拾うとしています。しかし、この道具は現在の名前がSkillにあるかを見るだけです。APIの削除、引数・型・既定値の変更は、概念文書が同時更新されなければどちらの道具にも現れません。
   推奨修正: 追従時に公開APIの削除・シグネチャ変更を確認する工程を追加してください。機械で扱わないなら、ソース差分を人が確認する手順と、その検出限界を明記してください。

3. **Major — 確認工程の書き換え禁止と修正指示が衝突する**
   該当箇所: `kasane/changes/user-docs/specs/user-skills/spec.md:138`
   問題点: 確認は追跡中のファイルを変更できず、Side Effectsも一時ディレクトリと証跡の作成だけです。一方、designの310行とtasksの10.2・10.4は、確認結果を受けてSkillを修正するよう求めています。確認工程に修正を含めると、禁止事項とSide Effectsの上限に違反します。
   推奨修正: 読ませる・使わせる確認と、その後のSkill修正を別工程として定義してください。修正を同じRequirementに含めるなら、変更可能なSkillファイルをSide Effectsに列挙し、書き換え禁止の対象を確認用のソース差し替え等に限定してください。

4. **Minor — 片言語の任意の変更で失敗するScenarioは実現できない**
   該当箇所: `kasane/changes/user-docs/specs/user-docs-consistency/spec.md:192`
   問題点: 日本語版の1枚だけを「変えた」場合、必ず失敗するとしています。しかし、本文の誤字だけを直しても、定義された見出しの深さ・コードブロック等の検査は通ります。tasksの8.2も同じ曖昧さを持ちます。
   推奨修正: GIVENを「見出しを1つ追加する」「コードブロックを1文字変える」など、検査対象の不整合を生む変更に限定してください。

5. **Minor — 使わせる確認の画面の入口が未指定**
   該当箇所: `kasane/changes/user-docs/design.md:298`
   問題点: 生成した画面ファイルだけを差し替えますが、Androidの入口は特定の画面関数を呼びます。生成する関数名・引数・packageの条件を渡さないと、Skillが正しくても入口との接続だけでビルドが失敗し、「書き損じ」に誤分類されます。
   推奨修正: 課題の共通条件として、Androidの入口関数の名前、引数なし、package宣言なしを指定してください。これはライブラリの知識とは別の、検証用の接続条件です。

`decisions/`・`handbook/`・`concepts/`を実装ワーカーに直接書き換えさせるタスクはありません。ビルド・テストの実行、ファイルへの書き込みは行っていません。
