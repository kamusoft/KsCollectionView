## 指摘事項

### [🟡 Minor] iOS の失敗画像の再試行条件に、メモリだけの消去の例外がない

**該当箇所**: `skills/ja/kscollectionview-ios/references/images.md:91`、`skills/en/kscollectionview-ios/references/images.md:91`

**問題点**: 「後で説明するキャッシュの操作の後に、もう一度試される」と書かれているため、`KsImageCache.clear(.memory)` も再試行の手段として読める。

実装では、`ios/Sources/KsCollectionView/KsImageCache.swift:33` の `.memory` 分岐はキャッシュを消すだけで、表示の無効化を行わない。再読み込みを起こす通知は `.all` と `remove` の経路に限られる。表示中の失敗画像に対してメモリだけを消しても、この説明が約束する再試行は起きない。

**推奨修正**: 英日とも、再試行を起こす操作を `clear(.all)` と該当ソースの `remove` に限定して書き、メモリだけの消去では再試行しないことを明記する。

### [🟡 Minor] HTML の属性名と値を改行で分けると、外部リンク検査を通過する

**該当箇所**: `scripts/ci/check-skills.py:189`

**問題点**: `link_targets()` は本文を 1 行ずつ処理している。そのため、次の有効な HTML は `HTML_LINK` に一致しない。

```html
<a href=
"../../../../README.md">README</a>
```

1 行目には値がなく、2 行目には属性名がないため、リンク先が検査へ渡らない。英日双方に同じ記述を追加すると、構成の一致も崩れず、Skill 外へのリンクを見逃す。前回追加されたテストはタグ自体の改行を扱うが、属性名・等号・値の間の改行は扱っていない。

**推奨修正**: コードを除いた本文を複数行で解析するか、HTML タグの終端まで属性の状態を保持して検査する。属性名と値を改行で分けた `href`・`src` の回帰テストを追加し、コード中の例示を除外する既存挙動も保つ。
