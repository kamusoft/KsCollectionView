## 指摘事項

### [🟡 Minor] 記録更新がステージ済みの変更を見逃す場合がある

**該当箇所**: `scripts/docs/skills-refresh.py:381`（差分取得: `scripts/docs/skills-refresh.py:184`）

**問題点**: `record` の未コミット判定は、`git diff HEAD` が返すパスと未追跡ファイルだけを使っている。対象の源泉を変更してステージした後、作業ツリーだけを HEAD の内容に戻すと、インデックスには未コミット変更が残るが、HEAD と作業ツリーの差分は空になる。この状態で `record` は記録を書き換えられるため、「対象のパスに commit していない変更があると書き換えない」という契約を満たさない。

通常の変更は検出でき、後の `status` が変更を拾う経路も残るため、重要度は Minor とする。指摘はコードと Git の比較対象からの静的な判断であり、再現テストは実行していない。

**推奨修正**: `record` の判定では、HEAD とインデックス、インデックスと作業ツリーの差分をそれぞれ調べ、その和集合に未追跡ファイルを加える。源泉をステージした後に作業ツリーだけを戻すケースを追加し、失敗終了と manifest の不変を確認する。

### [🟡 Minor] `status --diff` が削除された源泉の差分本文を表示しない

**該当箇所**: `scripts/docs/skills-refresh.py:349`

**問題点**: 差分本文の出力対象が `status.changed` と `status.renamed` に限られている。削除された源泉は `status.removed` に分類され、削除前の内容も保持されないため、`--diff` を付けてもパスと掛かっていた Skill のページだけが表示される。源泉が削除されたときに、どの説明を Skill から取り除くべきかを、この出力だけでは判断できない。

削除そのものは報告されるため、変更の見逃しではなく、差分本文を出す機能の不足として Minor とする。

**推奨修正**: 削除された源泉にも削除前の内容を保持し、`--diff` では削除前のパスから `/dev/null` への unified diff を出す。源泉削除時にも削除行が表示されるテストを追加する。
