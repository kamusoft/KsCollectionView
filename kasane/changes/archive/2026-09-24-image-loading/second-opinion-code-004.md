### Minor 1

該当箇所:

- `samples/android/.../ImageLoadingObserver.kt:61`
- `samples/ios/.../ImageLoadingObservation.swift:69`

問題点:

計測ログの `kind` が、実際には区別できない要求を確定的に誤分類します。

- Android の `KsImage` は `KsImageRequestFactory.kt:81` で `Precision.EXACT` を指定するため、表示要求も `prefetch-memory` と記録されます。
- iOS の `LazyImage` 直接表示はサムネイル指定を持たないため、表示要求が `prefetch` と記録されます。

`deviation.md` にある「区別できない」という制約自体は合意済みですが、現在のログは曖昧さを表現せず、誤った単一種別を出しています。将来の開始・取消件数を `kind` で機械集計すると誤判定し得ます。

推奨修正:

区別不能な分岐を `display-or-memory-prefetch`、`prefetch-or-loader-display` などの曖昧な名前に変更し、計測資料の集計規則も合わせてください。分類処理を純粋関数に分け、`KsImage`、プリフェッチ、ローダー付属ビューの代表的な要求でテストすると安全です。

### Minor 2

該当箇所:

- `android/.../KsImageCache.kt:15`
- `android/.../KsImageCache.kt:84`

問題点:

公開 KDoc は「戻った時点で削除完了」と無条件に説明していますが、Startup initializer が無効なら `clear` / `remove` は警告付き no-op です。また「消す対象のキャッシュをそもそも持っていない」という内部コメントも正確ではありません。`KsImage` は `LocalContext` から singleton ImageLoader を取得できるため、initializer が無効でも通常表示によってキャッシュが作られ得ます。

no-op という挙動自体は合意済み差分なので問題にしていません。問題は、その例外条件が公開契約と利用者向け注記に反映されていない点です。

推奨修正:

`KsImageCache` の公開 KDoc と利用者向け注記に、AndroidX Startup の初期化が前提であり、無効時は警告付き no-op になることを明記してください。内部コメントも「キャッシュが存在しない」ではなく「共有ローダーを安全に特定できない」に修正するのが適切です。
