## MODIFIED Requirements

### Requirement: 性能計測の自動実行
Sample と同じビルドルートに計測モジュール (Macrobenchmark) を持ち、「大量件数」画面と比較対象に対するスクロール性能の相対計測と、メモリの往復定常化の計測を、人の操作なしに固定手順で実行できる (SHALL)。fixture (件数・列数・可変行高の混在規則・決定的生成) は iOS と同じとする (SHALL)。比較対象にはライブラリの既定機能と同じ機能を同じ位置に付ける (SHALL)。計測結果は事後検証のスクリプトが最新 1 実行の結果だけを読み、テスト名でライブラリ側と比較対象側を対応付け、環境 (機種・OS・構成) の一致を確かめ、各試行の描画フレーム数が 90 に満たない結果を「未判定」として区別し、比較対象に対する劣化 (P90 / P99 の 3 試行集計値) が 10% 以内かを判定する (SHALL)。不合格・未判定・入力不正 (欠損・破損・重複・片側のみ・環境不一致・複数実行の混在) はいずれも非 0 で終了する (SHALL)。絶対値の合格線は判定しない (SHALL NOT)。件数を変えた比較のための試行は持たない (SHALL NOT)。

#### Scenario: 計測の再実行
- **GIVEN** 基準実機を接続した状態
- **WHEN** 計測モジュールを実行する
- **THEN** 同じ操作 (実座標フリック 3 秒 × 3 試行、全項目を通過する往復) が再現され、指標が結果として得られる

#### Scenario: 事後検証
- **GIVEN** ライブラリ側と比較対象側の計測結果
- **WHEN** 事後検証のスクリプトを実行する
- **THEN** 試行ごとの描画フレーム数と、P90 / P99 の劣化率と、合格 / 不合格 / 未判定の判定が出力される

#### Scenario: 描画が少ない試行は未判定
- **GIVEN** 描画フレーム数が 90 未満の試行を含む計測結果
- **WHEN** 事後検証のスクリプトを実行する
- **THEN** その試行は未判定として報告され、合格にはならず、終了コードは非 0 である

#### Scenario: 入力不正は判定しない
- **GIVEN** 片側だけの結果、環境が一致しない結果、または複数実行が混在した出力ディレクトリ
- **WHEN** 事後検証のスクリプトを実行する
- **THEN** 入力不正として理由が出力され、合格・不合格のどちらにもならず、終了コードは非 0 である

## ADDED Requirements

### Requirement: 計測専用の件数指定 (iOS)
iOS Sample は「大量件数」画面を、起動引数で指定した件数で開ける (SHALL)。指定が無いときの件数は 10,000 件のままとする (SHALL)。受理するのは正の整数だけで、不正な値 (0・負数・数値でない・値の欠落・複数指定) のときは既定件数に黙って戻さず起動を失敗させる (SHALL)。件数を指定して開いた画面は件数を表示し (SHALL)、Debug 構成ではさらに自己サイズと推定高さの一致の計数を表示して、数え直しと読み直しの操作を持つ (SHALL)。計数は利用者が操作したときだけ読み直され、スクロール中に自動で更新されてはならない (SHALL NOT)。

#### Scenario: 件数を指定して開く
- **GIVEN** 件数を指定する起動引数を付けて Sample を起動する
- **WHEN** 「大量件数」画面を開く
- **THEN** 指定した件数の項目が同じ生成規則で表示され、画面にその件数が表示される

#### Scenario: 不正な件数
- **GIVEN** 件数の起動引数に 0 または数値でない値を付けて Sample を起動する
- **WHEN** 起動する
- **THEN** 起動は失敗し、既定の 10,000 件で開かれることはない

#### Scenario: Debug 構成では計数を読める
- **GIVEN** Debug 構成の Sample を件数を指定して起動する
- **WHEN** 「大量件数」画面を開き、数え直してからスクロールし、止めてから読み直す
- **THEN** 自己サイズを返したセル数と不一致回数が表示され、数え直しの前の値は含まれない

### Requirement: iOS の計測ドライバの構成
iOS Sample の計測ドライバは、メモリの自動往復と、画像読み込みの観測駆動 (読み込み中スロットの計数の基準点を切って送り、同じ表示サイズで戻す) だけを持つ (SHALL)。メモリの自動往復は、計測専用の launch 経路で全項目を通過する往復を、連続 2 往復の増分がいずれも 1 往復後の値の 2% 以内になるまで重ね (上限 10 往復) (SHALL)、往復ごとの `phys_footprint` と通過した項目数、最終の判定 (定常 / 未判定) を計測の記録に出力する (SHALL)。上限までに定常化しなければ未判定として失敗し、成功として終わってはならない (SHALL NOT)。自動フリックによるスクロール性能の駆動は持たない (SHALL NOT)。

#### Scenario: メモリの自動往復
- **GIVEN** 計測スキームで Simulator に Release 構成を入れた状態
- **WHEN** メモリの計測ドライバを実行する
- **THEN** 往復ごとに全項目の通過と `phys_footprint` が記録に出力され、定常化に達した往復数と判定「定常」が記録される

#### Scenario: 定常化しなければ未判定
- **GIVEN** 上限の往復数まで連続 2 往復の増分が 2% 以内にならない状態
- **WHEN** メモリの計測ドライバを実行する
- **THEN** 判定「未判定」が記録され、ドライバは失敗として終わる

### Requirement: 保持対象の解放の自動確認 (Android)
Android Sample の計測用の入口は、配列の置換と画面離脱の後にテンプレート呼び出しの同時生存 (累計 − 破棄) を読める自動走査を持つ (SHALL)。同時生存のカウンタは画面ではなくプロセスに属し、離脱後の値は離脱先の結果画面の進捗の印から読める (SHALL)。

#### Scenario: 置換と離脱の走査
- **GIVEN** 計測用の入口で 10,000 件を通過した画面
- **WHEN** 走査が配列を置換し、続けて画面を離れて結果画面に遷移する
- **THEN** 置換後の同時生存と離脱後の同時生存が結果画面の進捗の印として読め、計測モジュールがそれを判定できる
