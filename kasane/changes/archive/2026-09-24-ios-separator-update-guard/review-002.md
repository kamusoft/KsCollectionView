## 確認した観点 (修正で新たに問題が入っていないか)

- **既存経路との干渉・二重の構成**
  - 新しく表示に入るセルは、cell provider 内の `configure` と `willDisplay` の `configure` で 2 回構成される
  - 2 回目は同じ構成を当てるため、どちらのガードでも書き込みは起きない
    - タッチ色: 同じオブジェクト
    - 区切り線: 同じオブジェクト、かつ表示/非表示も同じ
  - 区切り線ありのリストでは、同じフレームのレイアウト確定からの揃え直しとも重なる。こちらも同じ理由で書き込みは起きない
  - `willDisplay` に渡る `indexPath` は更新後の位置である。上端の線の判定 (`item == 0 && section == 0`) が差分適用の途中で古い位置を見ることはない。差分の適用完了からの揃え直しもそのまま残っている
- **性能の後退**
  - `willDisplay` での費用は、表示に入るセル 1 つにつき比較数回である。グリッドと区切り線なしのリストで毎フレームの全可視セル走査が止まっている点は変わらない
  - スクロール中の主スレッド費用は、決定 2 の狙いどおり減ったままである
- **決定事項との整合**
  - 決定 2 は「構成の差し替え時と差分の適用完了時の揃え直しは変えない」と定めている。今回の修正はこれに触れておらず、経路を 1 つ足しただけである
  - 利用者から見える挙動は変わらない。変更前もレイアウト確定からの揃え直しが同じ結果を届けていた
- **テストの妥当性** (scratchpad のコピーで変異させて確認。作業ツリーは変更していない)
  - m1: `willDisplay` の override を除去した
    - 新規の 2 テスト (`test表示前に古い色のまま…` と `test表示前に古い区切り線のまま…`) が、テストプロセスのクラッシュで落ちた。親クラスに実装が無いため
    - 除去は検出できる。ただし失敗の形はアサーションではなくクラッシュになる
  - m2: 却下案 B (`updateVisibleCellSeparators` の先頭で `guard showsListSeparators else { return }`) を入れた
    - `willDisplay` がある状態でも、`testグリッドで配列の変更とタッチ色の差し替えが同時に届いても残った可視セルに新しい色が届く` は落ちた (残った 6 セルが `systemFillColor` のまま)
    - 作り直されずに残った可視セルには `willDisplay` が再び呼ばれない。そのため新しい経路では穴が隠れず、決定 3-3 の回帰防止は今も効いている
    - 同じ変異では、グリッド・区切り線なしの 2 テストも落ちた。原因は前置きの待機 (初回適用後の揃え直し ≥ 1) が満たされないことで、検出の本筋ではない
  - 新規テストは、先行組み立てそのものではなく、デリゲートを直接呼んで検証している。ユニットテストのホストでは先行組み立てが起きないためで、そのことはテスト内のコメントに書かれている。前回のプローブの観測 (cell provider の呼び出し回数 = 可視セル数) とも合っており、代替として妥当である

### 🔵 Suggestion (スコープ外・既存) 先行組み立て済みのセルは、同値配列の更新でテンプレートが呼び直されない

**問題点**:
