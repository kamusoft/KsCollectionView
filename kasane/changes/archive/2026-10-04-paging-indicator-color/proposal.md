# Proposal: paging-indicator-color

## Why

ライブラリが自分で出す読み込み中の表示は 3 つある — ページングの「次のページの読み込み中」「最初の読み込み中」と、Pull to Refresh のインジケータ。どれにも色を指定する設定が無い。ページングの 2 つは各プラットフォームの標準のくるくるで、色は iOS では親の View に付けた tint、Android では Material のテーマの primary になる。Pull to Refresh のインジケータは両プラットフォームとも標準のグレー系で出る。そのため、tint や primary にアクセント色を当てたアプリでは、同じ一覧の中で読み込み中の色がそろわない。

`paging-state-machine` の mock との照合で、Sample がこの状態だと分かった (承認 mock のくるくるはグレー、実物はアクセントの青)。オーナーは「インジケータの色はプロパティで持たせる」と判断した。ページングの 2 つは差し替え口で中身ごと変えられるが、Pull to Refresh には差し替え口が無く、利用者が色を変える手段が無い。

## What Changes

- **色の設定を 1 つ足す** (core/ADR-0035): 名前は両プラットフォームとも `loadingIndicatorColor`。Swift は一覧の modifier `.loadingIndicatorColor(_:)`、Kotlin は `KsCollectionView` の引数 `loadingIndicatorColor` (省略できる)。形は既存の区切り線の色 (`listSeparatorColor`) と同じにする
- **効く範囲**: 差し替えていない「次のページの読み込み中」「最初の読み込み中」と、Pull to Refresh のインジケータの 3 つに同時に効く。ページングを付けない一覧でも Pull to Refresh のインジケータに効く
- **差し替えた表示には効かせない**: 利用者が差し替え口に書いた表示は、利用者が自分で色を決める。iOS で中身に tint を流すと再試行のボタンなど読み込み中以外の部品の色まで変わり、Android には差し替えた中身へ色を流す共通の手段が無いため、両プラットフォームで同じ効き方にできない
- **指定しないとき**: 3 つとも今の各プラットフォームの標準の色のまま変えない。ライブラリは既定の色の値を持たない
- **表示中の変更**: 表示中に色を変える・指定を外すと、出ている 3 つの表示はその場で追随する (指定を外すと標準の色に戻る)。iOS の並べ替えのドラッグ中だけは、ドラッグ中に届くほかの設定の変化と同じく (core/ADR-0033 の実装)、ドラッグが終わってから反映する
- **Android の Pull to Refresh**: 指定した色は矢印に効かせ、丸い下地はテーマの色 (material3 の既定) のままにする
- **内部の整理 (iOS)**: 中身が同じになっている既定の表示の型 2 つ (`KsPagingDefaultIndicator`・`KsPagingDefaultProgress`) を 1 つにまとめる。外から見える挙動は変えない
- **公開 API の説明**: 新しい設定の doc コメントに、効く範囲・指定しないときの色・Android では矢印に効き下地はテーマの色であることを書く。既存の doc コメントのうち「標準の読み込み中の表示」の説明も、色の設定に合わせて直す
- **Sample**: 両プラットフォームのデモ画面「ページング」で、`loadingIndicatorColor` に Sample の既存の色「テキスト副」を指定し、3 つの表示を同じ色にそろえる。新しい色・操作の部品は足さない
- **検証**: Scenario ごとの自動テスト (両プラットフォームのライブラリ)。Sample の見え方は、両プラットフォーム × ライト / ダークで mock と照合する。UI テストは足さない

影響する能力: collection-paging (読み込み中の表示の色の設定) / samples (デモ画面「ページング」の色の指定)

- 蒸留時に反映: decisions — core/ADR-0035 を実装の形で確かめて accepted に昇格する
- 蒸留時に反映: concepts — `kasane/concepts/core/core-model/collection-paging.md` の「色を指定する設定は持たない」の記述を、色の設定 (`loadingIndicatorColor`)・効く範囲 (差し替えた表示には効かない)・指定しないときの色・Android の下地の扱いの説明に改める

## Non-Goals

- **指定しないときの色を変える** (固定のグレー・テーマの色・標準のグレー系で 3 つをそろえる) — core/ADR-0035 で却下した。ライブラリの既定の色のライト / ダーク対応は別の change `library-default-colors-dark-mode` で扱う (別の能力で、core/ADR-0010 の改訂を伴う設計判断を要する)
- **Android の Pull to Refresh の下地の色の設定** — Android だけの設定が増え、両プラットフォームの語彙の 1 対 1 (core/ADR-0002) が崩れるため、探索で却下した (設計判断を要する)
- **Pull to Refresh のインジケータの差し替え口** — 色の指定とは別の機能追加で、設計判断を要する
- **画像の読み込み中・失敗の色、区切り線、スクロールインジケータの色** — 別の能力 (image-loading / styling)。`library-default-colors-dark-mode` で扱う
- **Sample の操作のパネルに色の切り替えを足す** — パネルの部品・mock・UI テストが増えるため、探索で却下した (ユーザー判断済み)
- **利用者向けドキュメント (Agent Skills)** — まだ存在せず、配布のフェーズで作る。今回は doc コメントだけを書く

## Impact

- 破壊的変更なし (設定の追加だけ)。色を指定しない一覧の見え方は変わらない。Kotlin の引数は末尾 (`content` の前) に足して既存の引数の順番を変えないので、引数を位置で渡している既存の呼び出しもそのままコンパイルできる
- 両プラットフォームのライブラリ (ページングの既定の表示と Pull to Refresh の部品) と、両 Sample のデモ画面「ページング」に触る
- Sample の「ページング」の見え方が変わる: くるくるがアクセントの青からグレーになり、Pull to Refresh のインジケータ (Android は矢印) が同じグレーになる
- リスク: iOS で指定を外したときに Pull to Refresh の部品が標準の色へ戻るかは、実装で確かめる (Scenario「表示中に指定を外す」のテストで押さえる)
- リスク: iOS のくるくるに付いた色は、既存のテストが探している読み込み中の部品の色として読める見込みである。読めない場合は、色が表示の部品まで渡ることを自動テストで確かめ、実物の色は証跡で確かめる
- リスク: Android で、テーマと合わない色 (例: ライトのテーマで白) を指定すると、テーマの色の下地の上で矢印が見えにくくなりうる。受け入れ済みで、doc コメントに書く
- テストの時間: ライブラリのテストを数件足すだけで、Sample の UI テストは足さない (全系統の合計 10 分以内 — cross/ADR-0008)
