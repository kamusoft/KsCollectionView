## 指摘事項

### 🔵 Suggestion 範囲の外が残ったまま承認され、範囲の中の直しも無いときに、証跡の置き場が無い

**該当箇所**: `.agents/skills/docs-refresh/SKILL.md:138`・`.agents/skills/docs-refresh/SKILL.md:152`、`drafts/user-skill-refresh.md:117`
**問題点**: 修正で、範囲の外の違反を残したまま 6 へ進む経路 (`:115`) がはっきりした。その経路で承認されると、`:138` は「7 の 1 つ目の commit だけを作り」、記録の commit は作らない。一方で `:144` は、1 枚にも記録の対応表にも変更が無いときは 1 つ目の commit を作らない。両方が重なる (例: 利用者役の画面の変更で README の例の検査だけが落ち、Skill の側には直しが要らなかった) と、commit が 1 つもできず、`:152` が「最初に作る commit のメッセージに書く」とした追従の証跡 (扱った源泉・直さなかった理由・検査の結果・確認の判断) を残す場所が無い。記録の commit の ID は更新されないので、次の追従で同じ源泉は再び出る (追従の漏れにはならない) が、その回の判断は失われる。spec の Scenario には掛からない。
**推奨修正**: `:138` に、作る commit が無いときは、証跡を 6 でオーナーに見せた内容とし、commit しないことを伝える、と 1 文足す (草稿の `:117` の表の行も同じに)。あるいは、この組み合わせは起きにくいとして扱わない判断をオーナーに確かめる。

### 🔵 Suggestion 証跡ファイルが、レビューの後の直しと、草稿が引く道具の確かめに追いついていない

**該当箇所**: `evidence/refresh-skill-trial.md:91`・`evidence/refresh-skill-trial.md:137`、`drafts/user-skill-refresh.md:164`
**問題点**: 証跡は 16:02 時点のままで、`:137` は「`SKILL.md` は、上の『Skill の直し』で変えた」とし、`:91` は 3.3〜3.5 の写しが直した説明で動いていると書く。レビューの後の直し (`SKILL.md:54`・`:81`〜`:83`・`:98`・`:107`・`:115`・`:144`・`:152`、`prompt-rewrite.md:27`) は試運転の後に入っており、どの回もこの文面では動いていないことが証跡から読めない。また草稿 `:164` は「2026-10-14 に使い捨ての写しで、`excluded` の源泉を消す・改名して commit し、確かめた」と書くが、その確かめは証跡のどこにも無く、蒸留で handbook に入る文の根拠が辿れない。本レビューで再現した結果では、消した源泉は同じ「無くなった源泉」として出続けたが、改名した源泉は `record` の後に「無くなった源泉」と「対応の決まっていない源泉」に形を変えて出た (`SKILL.md:83`・草稿 `:164` の「同じ源泉が出続ける」は、改名については厳密には形が変わる)。
**推奨修正**: 証跡の「Skill の直し」の表か末尾に、レビュー 001 の後の直しの一覧と、それが試運転の後であること (道具の出力の確かめだけを行ったこと) を足し、草稿 `:164` が引く確かめ (消す・改名の手順と `status` の出力の要点) を記録する。あわせて `SKILL.md:83`・草稿 `:164` の「同じ源泉が出続ける」を、改名では「無くなった源泉と対応の決まっていない源泉として出続ける」と書き分けるかを判断する。
