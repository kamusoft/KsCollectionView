## 指摘事項

### [🟡 Minor] 削除された源泉の渡し先判定が、実際の出力欄名と一致していない

**該当箇所**: `.agents/skills/docs-refresh/SKILL.md:93`、`.agents/skills/docs-refresh/references/prompt-rewrite.md:26`

**問題点**: 渡し先の表は、変わった源泉・改名・削除をまとめて「見直す1枚」のプラットフォーム指定から判定する。しかし、`skills-refresh.py`は削除された源泉について「掛かっていた1枚」を出力する（`scripts/docs/skills-refresh.py:351`）。

たとえばiOSだけに掛かる源泉を削除した場合、表を文字どおり適用すると「見直す1枚」に指定がないため、両方のワーカーへ渡すことになる。書き直しのひな形も「見直す1枚」から対象を埋める説明なので、削除された源泉の対象ページを引き継ぐ箇所が曖昧である。掛からない源泉の例外では両方の欄名を扱っており、通常の削除経路にも同じ対応が必要になる。

**推奨修正**: 渡し先の表とひな形で、「見直す1枚」、削除の場合は「掛かっていた1枚」を使うことを明記する。check時の報告説明も同じ欄名に合わせる。

### [🔵 Suggestion] 既にstageされた別作業の変更を、commit対象から除外する方法を明記する

**該当箇所**: `.agents/skills/docs-refresh/SKILL.md:144`

**問題点**: 追従で変えたパスだけを`git add`することは明記されているが、開始前から別作業の変更がindexに載っている場合の扱いは示されていない。通常の引数なしの`git commit`を選ぶと、その変更も含まれる。試運転証跡ではSampleの変更を作業ツリーに残したケースを確認しているが、既にstageされた変更のケースは確認していない。

「追従で変えていないファイルはcommitしない」という制約自体は明確なので、これは手順の補強提案である。

**推奨修正**: 別作業のstage状態を維持しながら、commitも承認されたパスに限定する方法を明記する。たとえば`git commit --only -- <対象パス...>`を使う方法がある。記録だけのcommitにも同じ限定を適用する。
