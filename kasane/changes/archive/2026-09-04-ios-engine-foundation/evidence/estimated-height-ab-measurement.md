# 推定高さを固定 44 から実測ベースに変えた A/B 実測

機種: iPhone 17 Pro Simulator (iOS 26.5)。
同一ビルドに一時計測を入れ、`--fixed-estimate` の有無だけで推定高さの決め方を切り替えて比較した
(計測コードは測定後に撤去済み)。記録値は `collectionView.contentSize.height` と `contentOffset.y`。

## スクロール制御デモ (list / 行高は一様)

実測された行の高さは 64.33pt で、固定値 44 は 31% 小さい。

| | 修正前 (固定 44) | 修正後 (実測平均 64.33) |
|---|---|---|
| 初回表示の contentSize.height | 4705.0 | **6433.33** |
| 実際の contentSize.height (末尾到達後) | 6433.33 | 6433.33 |
| 初回の見積もり誤差 | **-1728.33 (-26.9%)** | **0.00 (0%)** |
| 「末尾へ」命令中に contentSize が変化した回数 | **25** | **1** |
| 「末尾へ」命令中のレイアウトパス数 | 44 | 27 |
| 末尾到達後の contentOffset.y | 5749.67 | 5749.67 (同一) |

初回表示の時点でコンテンツ全体の高さが正しいため、スクロールインジケータの位置と長さが
最初から実際の位置に一致する。「末尾へ」の到達位置は最終的には両者とも同じだが、
修正前はレイアウト再計算のたびに見積もりが伸びて段階的に近づく (contentSize が 25 回変わる)
のに対し、修正後は 1 回で収束する。

## 大量件数デモ (grid 2 列 / 行高が混在。10,000 件中 7 件に 1 件が長文)

| 推定の決め方 | 推定値 | 初回表示の contentSize.height |
|---|---|---|
| 固定 44 (修正前) | 44.00 | 225,244 |
| 実測の中央値 | 44.33 | 226,906 |
| 実測の平均 (採用) | 51.83 | **264,301** |

真の総高は解析値で約 300,000pt (5,000 行。行の高さは 2 列のうち高い方で決まり、
7 件に 1 件の長文により約 2/7 の行が高くなる)。中央値は短い行が多数派のため固定 44 と
ほとんど変わらず、平均が最も真値に近い。行の積み上げ (= コンテンツ全体の高さ) を
言い当てる推定量として平均を採用した理由がこれ。

## 残る乖離 (grid)

grid では行の高さが「その行の列のうち最も高いセル」で決まるのに対し、実測として拾えるのは
セル単位の高さである。このため行高が混在する grid では平均がなお行の高さを小さめに見積もる
(上表で 264,301 対 約 300,000)。それでも固定 44 に対する誤差は約半分になる。
list では行 = セルなのでこの乖離は生じない。
