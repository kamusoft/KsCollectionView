## 指摘事項

### 🔵 Suggestion ドラッグ中に文言が変わる場合の結合テストが無い
**該当箇所**: `ios/Sources/KsCollectionView/KsCollectionViewController.swift:153`〜`:158`・`:286`〜`:290`・`:1660`〜`:1667`
**問題点**: 部品の有無を構成の値から毎回求めずに控えている理由は、コメントのとおりドラッグの間の食い違いを避けることにある。ドラッグの間は並べ替えの設定だけが先に入れ替わるが、控えの値は変えず、ドラッグが終わって当てる構成と比べて作り直す。この作りの目的そのものであるドラッグ中の変化 (文言を渡す・外す) を固定するテストが、ライブラリのテストに無い。上のプローブ P1・P2 では正しく動いた。ただし、控えの値を構成から毎回求める形に誰かが「簡単に」書き換えても、既存のテストでは気づけない。
**推奨修正**: `KsReorderEngineTests` に、ドラッグ中に文言を渡した場合と外した場合 (外した場合はドラッグ中にスクロールして新しいセルを出す) について、ドラッグが終わった後に部品の有無と操作が新しい構成に揃うことを確かめるテストを足す。P1・P2 の形がそのまま使える。

### 🔵 Suggestion スイッチの切り替えで部品を付けたままにすることを固定するテストが無い
**該当箇所**: `ios/Tests/KsCollectionViewTests/KsReorderEngineTests.swift:853`〜`:876`
**問題点**: 修正の目的の 1 つは、「スイッチのオン / オフでは付け外しせず、中身 (テンプレートと中の `@State`) を作り直さない」ことである。しかし足したテストが見ているのは、最初からスイッチが無効の一覧に部品が付いていることだけで、切り替えの前後で中身を保つことは見ていない。プローブ P3 (中身の view が同じオブジェクトのまま) と P5 (観測する値を渡した一覧でテンプレートを呼び直さない) では成り立っていた。
**推奨修正**: 既存の `test操作はスイッチが無効の間と動かせない項目と端と置けない行き先には出ない` か新しいテストで、次の 2 点を確かめる。スイッチをオフ → オンと切り替えても表示中のセルの `hasReorderAccessibilityContent` が真のまま、中身の view が同じであること。オンに戻すと操作が戻ること。

## 確認した観点

- 仕様充足 (Requirement「読み上げの移動操作」)
  - 文言を渡さなければ部品ごと付かず、操作は出ない
  - スイッチが無効の間は部品を付けたまま、操作を空にする (`KsCollectionViewController+Reorder.swift:249`〜`:257` の guard で空にする)
  - 動かせない項目・端・置けない行き先で操作を出さない判定 (`reorderAccessibilityPlacement`) は変わっていない
  - 文言を後から渡す・外す (足したテストと P3b)、スイッチの切り替え (既存のテストと P3・P5)、ドラッグ中の構成の変化 (P1・P2)、世代の変化 (P6)、layout の同時の変化 (P7) で、表示中のセルの操作が正しく更新される
  - 操作で動かしたときの知らせ・受け入れの経路は変わっていない (既存のテストが成功)
- 修正の正しさ
  - 部品の有無が変わった更新は `reconfiguringAllItems` で全項目を作り直す (`KsCollectionViewController.swift:342`)。表示中と先読み済みのセルは作り直され、再利用の置き場のセルは取り出されるときに `applyContent` を通るので、取り残しは無い
  - ドラッグの間は `deferDuringReorderDrag` が並べ替えの設定だけを入れ替える。控えの値は変えず、終わりに `update` で差を検出する (P1・P2)
  - `applyContent` の中で操作を先に入れるのは、セルの取り出し (`registration`) と可視セルの作り直し (`reconfigureVisibleCells`) の両方の経路で、そのときの差分データソースの並びと塊の表を使う
  - 後に続く `configure(cell:at:)` の呼び出しは、世代と項目が同じなので何もしない
- 並べ替えを使わない一覧
  - 中身の型は `KsRowContentPlacement` だけに戻り、変更前の形と同じ
  - 同じ配列の更新で中身の view を保つ (P4)
  - 観測する値の経路 (ios/ADR-0008) でテンプレートを呼び直さない (P4・P5)
  - `configure` の中の `updateReorderAccessibility` は並べ替えが無いと空の `clear()` だけで、知らせは出ない
- 足場: 今回の範囲で proposal / design / specs / tasks への変更は無い。design Decision 6 の「操作の有無は、配列・スイッチ・判定が変わるたびに付け直す」と合っている
- deviation: 今回の修正は spec の範囲の中の作りの変更で、合意済みの差分を増やしていない。性能の上乗せの受容はオーナー判断として `evidence/perf-ios-reorder.md` の追記にある
- 設計品質
  - 部品の有無を控えの値 1 つと判定関数 1 つで表していて、オーバーエンジニアリングは無い
  - 文言の有無の変化で中身を作り直す (中の `@State` が失われる) のは、layout の種類の変化と同じ扱いで、ios/ADR-0002 (再利用をまたいで中の状態を保たない) の範囲に収まる
  - debug ビルドだけの観測用の値 (`hasReorderAccessibilityContent`・`actionsChangeCount`) は `#if DEBUG` に閉じていて、製品構成には載らない
- 性能: [L-001] の再現で、並べ替えを付けない一覧の上乗せが無くなったことを確かめた。並べ替えが有効で文言を渡した一覧に残る +5〜8 % は、オーナー判断で受容済み (再現はパッケージの指示で変種 c だけにした)
- 並行性・リソース: モデルはセルが持ち `@MainActor`。部品は `@ObservedObject` で観測する形のまま。新しい参照の循環は無い (操作の処理は `[weak self]`)
