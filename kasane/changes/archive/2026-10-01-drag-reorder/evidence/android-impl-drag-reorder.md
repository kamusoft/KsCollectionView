- 0.1 (Android): 固定の見出し (stickyHeader) の下を持ち上げた項目が通るとき、持ち上げた項目が手前に描かれる (#1・#2)。見出しの固定・置き場所の隙間との干渉は**見つからなかった**

# 追加の確認: 粗い刻みで動かして止めたとき、繰り上がった項目の場所が空白のまま残る (2026-09-30)

- 報告: Sample の「並べ替え」で Item 1 を長押しし、`input motionevent` を粗い刻みで送って Item 3 の位置で止めると、繰り上がったはずの項目の場所が背景色の空白のまま残り、次の MOVE で描かれる (`android-sample-drag-shifted-item-not-drawn.png`)
- 環境: 同じエミュレータ `ksn_drag_reorder_impl_api36` (port 5620、操作前に AVD 名を確認)。一時ハーネス (前回と同じ) と、Sample (開始ルート `demo/Reorder`)

## 原因

描画の回は止まっていなかった。空白は持ち上げた項目自身の置き場所 (隙間) で、繰り上がるはずの Item 3 はまだ入れ替わっておらず、指の下に描いた持ち上げた項目の裏に隠れていた。

list の行き先は「指がほかの項目の上半分なら前、下半分なら後ろ」で決めていた。つかんだ位置が項目の中ほどだと、持ち上げた項目は指を中心に描かれる。このため、指が Item 3 の中心を越えるまでは隙間が 1 行上に残り、持ち上げた項目が Item 3 にほぼ重なっても入れ替わらなかった。入れ替わるまでに、指は 1 行ぶん近く動く必要があった。細かい刻みでも同じ位置で止めれば同じ見え方になるはずで、報告の再現では次の MOVE で中心を越えたために描かれたように見えた。

## 直し方

list の行き先を、持ち上げた項目の置き場所を取り除いて詰めた並びの上で求めるように変えた。持ち上げた項目の上端 (指の位置から、持ち上げたときのつかんだ位置を引いたもの) に、いちばん近い置き場所を選ぶ。

- 持ち上げた項目がほかの項目の半分を越えて重なったら入れ替わるので、隙間はいつも持ち上げた項目の下に来る
- 詰めた並びは隙間の位置によらず変わらないため、止まっている間に行き先が行き来しない
- 見出しは項目と同じく数える。見出しの無いグループの境目は、次のグループの最初の項目の上端とし、持ち上げた項目の上端がそれより上なら前のグループの末尾、下なら次のグループの先頭にする

# 追加の確認: 端での自動スクロール中に下端で離すと、一覧の最後のグループの末尾へ置かれる (review-001 Critical 1) / 置く直前の判定 (相方 Major 2) — 2026-09-30

- 環境: エミュレータ `ksn_drag_reorder_impl_api36` (port 5620、操作前に AVD 名を確認、終了後に停止)。Sample「並べ替え」(開始ルート `demo/Reorder`、10,000 件・100 件ずつのグループ)

# 追加の修正: 見えているのが持ち上げた項目だけのとき、一覧の最後のグループの末尾へ飛ぶ (second-opinion-code-002 Major) — 2026-09-30

- 原因: list の行き先の求め方 (`listPlacementAt`) は、表示範囲に数える項目 (持ち上げた項目の置き場所を除く) が 1 つも無いとき、一覧の末尾が表示されていなくても最後のグループの末尾を返していた。画面を占める高い行を持ち上げると、その行だけが見えているのでこの経路を通る
- 直し方: 最後のグループの末尾を返すのは、一覧の末尾 (最後の lazy の項目) が表示されているときだけにした。数える項目が 1 つも無いときは今の行き先を保つ
- 同じ形の経路の確認:
  - グリッドの `placementAt` は、指の下か最も近い項目で決める。見えているのが持ち上げた項目だけなら、その項目が選ばれて今の行き先を保つ。最後の `return` を通るのはルートのフッター (一覧の末尾) の上だけ
  - list で見出しだけが見えるときは、その見出しの前後 (前のグループの末尾か、そのグループの先頭) になり、見えている位置の隣に留まる
  - 固定されて項目に重なっている見出しは数えないため、それと持ち上げた項目しか見えないときも、今の直し方で今の行き先を保つ
- 自動テスト (A/B): `KsReorderHoldTest.onlyLiftedItemVisibleKeepsPlacement`。10 件の list で item-3 だけを表示範囲より高い 800dp にし、item-3 を先頭に表示する。そのまま持ち上げて 30px 動かす
  - 直す前は、置き場所が一覧の末尾へ飛んで後ろの項目 (item-4〜) が繰り上がって見え、失敗する
  - 直した後は、置き場所が元のままで、離しても知らせない (成功)
- エミュレータでは確かめていない。Sample に表示範囲より高い行が無く、条件は自動テストで作った

# 6.3 の指摘の修正: 見出しをまたぐと、動かしている項目の下に謎の背景が出る (2026-10-01)

- 指摘: 基準機 (Pixel 4a / Android 13、benchmark 版) の Sample「並べ替え」で見出しをまたぐと、持ち上げた項目の下に見出しの帯と同じ色の板が影つきではみ出す (`owner-6.3-android-odd-background-across-header.webp`)
- 環境: この作業用に作ったエミュレータ `ksn_drag_reorder_fix63_pixel4a` (Pixel 4a の定義 / API 36、1080×2340、440dpi、port 5640)。操作の前に毎回 `adb -s emulator-5640 emu avd name` でこの AVD であることを確かめた
- 対象: Sample の benchmark 版 (`:app:assembleBenchmark`)。直す前の APK と直した後の APK を作り、同じ手順を繰り返した (A/B)。開始ルート `demo/Reorder` (10,000 件・100 件ずつのグループ、見出しつき・固定、グループ間の間隔 16dp)。パネルは畳んだ
- 操作: `adb shell input motionevent` で長押し (DOWN の後 1.2 秒待つ) からのドラッグを合成した。座標は画面のピクセル

## 原因

持ち上げた項目の影 (8dp) を、項目の上下の間隔まで含む層に付けていた (`KsReorderLift.kt` の `KsReorderLiftNode`。`placeWithLayer` の `shadowElevation`)。この層は、指の下へずらすために、間隔・区切り線・タップ領域を含む項目全体に付けている。項目の上下の間隔 (行間・見出しの下の間隔・グループ間の間隔) は何も描かない透明な範囲で、影の輪郭は層の大きさで決まる。このため、持ち上げた項目がグループの最後の位置 (次のグループの見出しの直前) に来て下にグループ間の間隔 (16dp = 44px) が付くと、影の輪郭が content の下端から 44px 下まで伸びる。輪郭の中は透明なので、ページの色がそのまま見え、その周りと下に影が落ちる。見出しの帯と同じ色の板が影つきではみ出して見えるのはこのためである。見出しをまたぐたびに、持ち上げた項目がグループの最後の位置を通るので出る。

## 直し方

影を付ける層を分けた。

- `ksReorderLift` (項目全体。指の下へずらし、手前に描く) は影を付けない
- 新しい `ksReorderLiftShadow` を間隔の修飾 (`ksItemSpacing`) より内側に付け、持ち上げている間だけ影を付けた層で置く。影の輪郭は content・区切り線・タップ領域の範囲になり、間隔の大きさに左右されない

グリッドの行間 (項目の上の間隔) にも同じ形で効く。
