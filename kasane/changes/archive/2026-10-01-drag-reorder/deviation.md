# Deviation: drag-reorder

- Requirement「グループをまたぐ移動」/ Scenario「見出しの上と下」「見出しの無いグループでも境目で分かれる」(iOS のみ): spec では「置いた位置が見出し (見出しが無ければグループの間の間隔) より上なら前のグループの末尾、下なら次のグループの先頭」と指の位置で決める → 指示により iOS は UIKit 標準のドラッグ & ドロップの隙間に従い、見出しとグループの間の間隔の上では隙間が直前の位置を保つ (下から運んで間隔の上で止めれば次のグループの先頭のまま、前のグループの最後の項目の上を通ってから下げれば前のグループの末尾)。知らせの行き先は置いたときの実際の隙間 (`coordinator.destinationIndexPath`) から求め、見えた隙間と一致させる。前のグループの末尾へはドラッグで置ける (list / 2 列グリッド、iOS 26.5・18.6 で観測。evidence/ios-precheck-uikit-drag-and-drop.md の「再確認」)。Android はこの記録の対象外で spec どおり。理由: UIKit には D&D 中の隙間の位置を差し替える口が無く (delegate の targetIndexPathForMove・レイアウトの targetIndexPath(forInteractivelyMovingItem:) とも D&D 中は呼ばれない)、iOS 標準の並べ替えの動きを保つ (ios/ADR-0011)。オーナー判断 (2026-09-30)
- Requirement「並べ替えのスイッチ」/ Scenario「ドラッグ中にスイッチが無効になる」「ドラッグ中に layout が変わる」、design Decision 7 (iOS のみ): design では「iOS はドラッグのセッションを取り消し」とする → UIKit にはドラッグのセッションを途中で取り消す公開の手段が無い (UIDragInteraction.h の `enabled` は「タッチを無視する」だけで、進行中のドラッグは続くことを Simulator で観測)。実装は、取りやめた後の置き先の提案をすべて「隙間を空けない」(`.move` + `.unspecified`) にし、指を離すと持ち上げた項目を元の位置へ動かして戻し (review-001 の修正で「断って UIKit 標準の取り消しで戻す」から変更)、置いたときの処理は呼ばない。取りやめてから指を離すまでの間は、持ち上げた項目は指に付いたままで、直前の隙間も残る (それ以上は動かない)。変わった構成と控えた配列は指を離した後に当てる。evidence/ios-precheck-uikit-drag-and-drop.md の「実装後の確認」。実装者の記録 (2026-09-30)、オーナー承認 (2026-09-30。取りやめは指を離したときに元の位置へ戻す形でよい)
- design Decision 8 / tasks 5.3 (iOS の Sample のみ): VM を `@Observable @MainActor final class` にする → `ObservableObject` の `@MainActor final class` (`ReorderDemoModel`) で持つ。理由: iOS Sample の配布先の下限が iOS 16 (`samples/ios` の `IPHONEOS_DEPLOYMENT_TARGET`) で、`@Observable` は iOS 17 からしか使えない。「ページング」の `PagingDemoModel` と同じ持ち方。画面に出る挙動・文言は変わらない。実装者の記録 (2026-09-30)
- [付随修正] samples/ios/KsCollectionViewSamples/SampleTheme.swift: 外観で色を切り替える処理 (`adaptive`) を nonisolated にし、中の処理を `@Sendable` にした。理由: プロジェクト既定の分離がメインアクターのため、SwiftUI がアニメーション中にメインでないスレッドから色を解決すると分離の検査で落ちる既存の潜在不具合があり、「並べ替え」の切り替えボタンを押すとクラッシュした。直した後に iOS Sample の全 UI テストが成功 (2026-09-30)
- Requirement「動かせるかと置けるかの判定」(iOS のみ、確かめた範囲): 置けるかの判定に使う隙間の予測 (`KsReorderGapTracker`) は iOS 18.6・26.5 の Simulator の観測から組んだ規則で、配布先の下限 iOS 16 のうち iOS 16・17 では確かめていない (ランタイム未導入、基準機の iPhone 11 も iOS 18.7.8)。規則が外れた場合、置けない位置に一時的に隙間が空く見え方の崩れが起こりうるが、置いたときに判定し直すため置けない行き先で置いたときの処理は呼ばれない。蒸留時に ios/ADR-0011 の確かめた範囲へ書き残す。理由: iOS 16・17 のランタイムを入手して確かめるかをオーナーに諮り、確かめずに記録する判断 (review-001 Minor 3、2026-09-30)
- design Decision 5 (iOS のみ): ドラッグ中の配列の保留・ページングの停止・スクロール命令の溜め置きを「持ち上げてから」行う → iOS は持ち上げた時点 (`itemsForBeginning`) では構成 (スイッチ・layout・グループの宣言) を控えるだけにし、指を動かし始めた時点 (`dragSessionWillBegin`) で控えた構成と比べて違えば取りやめる。配列の保留などは指を動かし始めた時点から行い、持ち上げてから指を動かし始めるまでの間に届いた配列はその場で当たる。理由: UIKit に持ち上げの取り消し (動かさずに離した) を知らせる公開の通知が無く (UICollectionViewDragDelegate で持ち上げに呼ばれるのは itemsForBeginning だけで、dragSessionWillBegin / DidEnd は取り消しでは呼ばれない。Simulator の観測も同じ)、持ち上げから保留すると後始末が確実にできない。review-002 の Minor、オーナー判断 (2026-09-30)
- Requirement「端での自動スクロール」/ design Decision 3 (iOS のみ、上端): design では「自動スクロールと持ち上げの見た目は UIKit 標準のまま」(ios/ADR-0011) → 一覧をバーの裏まで広げた場合 (core/ADR-0017 の全画面の書き方。安全領域の上が 0 より大きい) は、UIKit の上端の反応の帯が一覧の枠の上端から約 60pt (iOS 26) / 50pt (iOS 18) にあってバーの裏に入り、上端の自動スクロールが起きないため、ドラッグのセッションの間だけライブラリが上端 (一覧の上端 + 安全領域の上から下へ、UIKit と同じ幅の帯) の自動スクロールを自前で足す (CADisplayLink で公開の setContentOffset を進め、先頭で止める)。安全領域の上が 0 のときは足さず UIKit 標準に任せる。下端は UIKit 標準のまま。上端の帯の幅と速さは、UIKit 標準の上端 (一覧を安全領域の内側に置いた場合) の Simulator での実測に合わせた自前の値 (帯の中の指の深さで速さが決まり時間では加速しない形。iOS 26 以降は帯 60pt・最大 1100pt/秒、それより前は帯 50pt・最大 830pt/秒) で、iOS 26 より前は UIKit と同じく帯に入ってから約 0.75 秒待って送り始め、指が一覧の外へ出たら止める (review-003 の修正)。上端の安全領域が UIKit の帯より短い配置 (バーの無い全画面など) では、UIKit の帯に入る所では自前で送らず UIKit に任せる (review-004 の修正。この置き方では UIKit の帯のすぐ下で速さが上がる見え方が残り、iOS 26 より前は指が自前の帯から UIKit の帯へ上向きにまたぐと UIKit 自身の待ちで送りが約 0.75 秒止まる)。下端とそろって感じられるかは 6.3 の目視で確かめる。蒸留時に ios/ADR-0011 と design の前提を上端について改める。理由: このままでは全画面の一覧で項目をドラッグで画面の上の外へ運べない。contentInset に安全領域を持たせる案は固定の見出し・Pull to Refresh・ADR 2 本に及び別の change の規模、ドラッグ中だけ inset を足す案は先頭で行き過ぎる (evidence/ios-precheck-uikit-drag-and-drop.md の「review-002 の確認」「(d)」)。review-002 の Major、オーナー判断 (2026-09-30)
- design Decision 3 / Requirement「受け入れと元に戻す」(iOS のみ): design では「UIKit 標準のドラッグ & ドロップの delegate で作り、差分データソースの並べ替えハンドラは使わない。置いたとき performDropWith で onMove を呼び、受け入れなければ置かずに終える」(ios/ADR-0011) → 基準機のオーナーの目視 (tasks 6.3) で「自動スクロールしながらのドラッグで隙間が動き続け触覚が鳴り続ける」「置いた後の収まりが遅い (約 0.9 秒)」と指摘され、UIKit 標準の並べ替え (一覧が自分で並びを動かす reorder-capable な形) に組み替え、隙間が動く速さ (`reorderingCadence`) を slow にする。これで自動スクロール中は隙間が動かない (帯の深い所で 5 秒止めたときの隙間の動きが 69〜81 回から 0〜2 回。帯の浅い所で送りが遅いときは標準と同じく 1 行ごとに動く)。置いた後の収まりは、行の中身に不透明な背景がある場合は組み替えても約 0.9 秒のまま (影が置いた位置に残りドロップのセッションの終わりで消える。iOS 26.5 は UIKit 標準の並べ替えでも同じ行なら残る。iOS 18.6 は標準では薄れるのに本体では残る差があった (グループと読み上げの移動操作の部品がそろうと残る。根本の原因は未特定)。オーナー判断で調べ、置く絵の見た目を指定する公開の口 (`dropPreviewParametersForItemAt`) で影の形を空・背景を透明にして、両 OS とも約 0.3 秒で収まるようにした (持ち上げた絵と影の無い置く先の絵が入れ替わる間に、影は約 0.3〜0.4 秒で途切れずに薄れる。UIKit 標準の約 0.5 秒より少し早い。review-011 の再現計測。iOS 26.5 では UIKit 標準で残る同じ行でも残らない)。2026-10-01。evidence/ios-6.3-rework.md の 2 節 (測り直し) と 9 節 (影の修正)。当初の「約 0.3 秒になる」は測り方の誤りで、review-009 の再現計測で判明)。受け入れないときは、項目がいったん置いた位置に収まってから元の位置へ動いて戻る (spec の「元の並びに戻す」の結果は満たすが、置かずに戻る形ではなくなる)。slow のため指を止めるまで隙間が動かない。蒸留時に ios/ADR-0011 を改める。理由: ドロップで置く形では `reorderingCadence` が効かず (UICollectionView.h の説明は reorder-capable な置き先の上でだけ効く)、置いた後の止まりも置き方の渡し方で変えられない (evidence/ios-6.3-fix-investigation.md)。オーナー判断 (2026-09-30)
- tasks 6.3 のオーナーの目視 (iOS のみ、見え方): 指が一覧の外 (固定の見出しより上・ナビゲーションバーの上) へ出ると、持ち上げた項目のプレビューが UIKit のドラッグの既定の小さい板に切り替わる。UIKit 標準の並べ替えでも同じ見え方で、公開の手段 (UIDragItem.previewProvider・UIDropProposal.prefersFullSizePreview) では大きさを保てなかった (evidence/ios-6.3-fix-investigation.md)。UIKit 標準の見え方として受け入れる。オーナー判断 (2026-09-30)
- 上の組み替えの実装で分かったこと (iOS のみ、2026-10-01 の実装報告と evidence/ios-6.3-rework.md): (1) 受け入れないときは、UIKit が置いた項目の絵をドロップのセッションが終わるまで (置いてから約 0.93〜0.99 秒) 置いた位置に残すため、公式の通知 `collectionView(_:dropSessionDidEnd:)` を待ってから元の位置へ戻す。見え方は「置いた位置に収まる (約 0.27 秒) → 約 0.7 秒止まる → 元の位置へ戻る (約 0.3 秒)」で合計約 1.3 秒。基準機の目視 (6.3 の見直し) で確かめる。(2) design Decision 5 のドラッグ中の扱い (配列の保留・ページングの停止・スクロール命令の溜め置き) は、受け入れないときに戻し終えるまで (最長で約 1 秒) 続き、その間は次の持ち上げを受けない。(3) 境目の項 (UIKit 標準の隙間) の「前のグループの最後の項目の上を通ってから下げれば前のグループの末尾」は、隙間が動く速さが即時の頃の観測。slow では隙間は指を止めた位置で決まり、別のグループの項目の上で止めるとその項目の前に空く。(4) iOS 16・17 で確かめていない範囲に、下のグループへまたいだときに UIKit が確定する位置が見せていた隙間と 1 つずれる現象 (見せていた隙間を正にして揃える) と `dropSessionDidEnd` の時刻が加わる。(5) データソースが並べ替えに対応すると UICollectionViewController が付ける標準の対話的な移動の長押し (`installsStandardGestureForInteractiveMovement`) を切る (長押しの知らせを奪うため)
- tasks 6.3 / design Decision 9 (目視の範囲): tasks では「前へ / 後ろへ移動」の読み上げ (iOS は標準のドラッグの操作と並ぶ見え方) をオーナーが基準機で確かめる → 指示により、読み上げ (VoiceOver / TalkBack) のオーナーの目視は行わない。自動テスト (iOS `KsReorderEngineTests` の読み上げの操作の各件、Android `accessibilityMoveNext`・`accessibilityMoveAcrossGroups`・`accessibilityActionsAbsentWhenNotApplicable` ほか) と Simulator での書き出し (セルの中の SwiftUI の要素に操作が付く。evidence/ios-precheck-uikit-drag-and-drop.md・ios-impl-gap-and-accessibility.log) で担保する。実機の VoiceOver / TalkBack での聞こえ方・動かした後の焦点・iOS で標準のドラッグの操作と並ぶ紛らわしさは未確認として残す。理由: 読み上げの操作手順がオーナーにとって現実的でない (2026-10-01)
- tasks 6.3 のオーナーの目視 (iOS のみ、見え方): グループを下へまたいで置くと、離した瞬間に見せていた隙間へ置いた項目が動きなしで現れ、持ち上げていた絵は指の下の行に約 0.1〜0.2 秒残って別の項目へ溶けて入れ替わる (同じ項目が一瞬 2 つ見える)。UIKit が確定する位置が見せていた隙間より 1 つ後ろになるためで、UIKit 標準の並べ替えでも同じ見え方 (evidence/ios-6.3-rework.md の 10 節、review-011)。並び・知らせ・グループの値は正しい。UIKit 標準の見え方として受け入れる。基準機の見直しでオーナーが問題なしと確認 (2026-10-01)
