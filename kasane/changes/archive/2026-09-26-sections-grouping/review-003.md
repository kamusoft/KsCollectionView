## 指摘事項

### 🟡 Minor (低優先) iOS でグループの宣言 (または見出しの宣言) を外すと、消えていく見出しの中身がフェードの前に消える

**該当箇所**: `ios/Sources/KsCollectionView/KsCollectionViewController.swift:205-207`、`ios/Sources/KsCollectionView/KsCollectionViewController.swift:583-590`
**問題点**: `.groups(by:)` を外した更新 (「差分更新」画面の「グループ」のスイッチを切る操作) では、`groupHeaderLayoutChanged` が立つので、差分の適用の前に `updateVisibleGroupHeaders()` が呼ばれる。`configureGroupHeader` は、新しい構成に見出しの宣言がないため `view.clear()` で中身を外す。その後の snapshot の適用で、見出しはフェードして消える。ただし、フェードしているのはすでに中身が空のビューになる。見出しの宣言だけを外した場合 (`groups(by:)` の見出しなしの形への切り替え) も同じ経路を通る。
プローブで確かめた。見出しつきの 2 グループを表示して宣言を外した。`update(configuration:)` の直後、2 つの見出しのビューは `hostedContentView == nil` になっていた。100ms 後も、表示上の不透明度は 0.37 でフェードの途中なのに、中身は空のままだった。見出しの帯と文字は、行がアニメーションで詰まる前に一瞬で消える。前回の Minor と同じ型 (差分の適用の前に、消えていく見出しを新しい宣言で組み立て直す) の、別の入口にあたる。宣言の切り替えの見え方は spec の契約 (配列の差し替えによる差分の反映) の外なので、低優先とした。静止画では見えない一瞬の不具合で、目視での確認はしていない。上に書いたのは記録の値。
**推奨修正**: 新しい構成に見出しの宣言がない更新 (`configuration.grouping?.header == nil`) では、差分の適用の前の `updateVisibleGroupHeaders()` を呼ばない。表示中の見出しはすべて消えていくビューなので、前の中身のままフェードさせればよい。補助ビューの提供の経路 (`configureGroupHeader` を新しく表示するビューに呼ぶ経路) の `clear()` はそのまま残す。直すなら 5.7 のオーナー目視と同じ画面で、スイッチを切ったときの見え方も確かめる。直さないなら deviation に残す必要はなく、蒸留のときの既知の見え方として扱ってよい。

### 🔵 Suggestion iOS にも「内容だけが変わった項目が見出しに渡る」テストを足す

**該当箇所**: `ios/Tests/KsCollectionViewTests/KsGroupingEngineTests.swift:621`
**問題点**: spec「見出しの内容の更新」は、グループの項目の数だけでなく内容だけが変わる場合も対象にしている。今回 Android には `sameIdItemsWithNewContentReachHeader` が足されたが、iOS のテストは件数の変化 (`test項目数が変わると見出しの内容を作り直さずに更新する`) だけを確かめている。iOS の挙動自体は上のプローブで正しいことを確かめた (適用の完了時に最新の `itemsByID` から組み立てる)。ただ、件数の変化と内容だけの変化では、snapshot の適用に進む理由が違う (位置の変化か、再構成か)。内容だけの経路には回帰の検知がない。
**推奨修正**: ID が同じで内容だけ違う配列を渡し、最後の組み立てに新しい内容の項目が渡ることを確かめるテストを 1 件足す (Android のテストと対にする)。

## 確認した観点

- **仕様充足**: 「見出しの内容の更新」(グループの値と項目の両方が最新になること。構成が等しいまま値の中身が違う場合も、項目の内容だけが違う場合も含む) と、deviation の最後の項目 (取り出し方の切り替えで組み直す) を、両プラットフォームのコードとテストで突き合わせた。足場 (proposal / design / specs) は HEAD から変わっていない。tasks.md と deviation.md は前回のレビューの時点から変わっていない。今回の修正は、deviation への記録が要る仕様の逸脱を含まない
- **修正による回帰**: 今回触れたのは `KsCollectionViewController.swift`・`KsGroupingEngineTests.swift`・`KsCollectionView.kt`・`KsCollectionViewGroupingTest.kt` の 4 ファイル。iOS では、見出しの組み立てを飛ばす条件は取り出し方の切り替えだけに限られ、配列の差し替え・観測する値・見出しの有無・固定の有無の各経路は前と同じ。切り替えと観測する値の変化が同時に届く場合、および塊の表が変わる場合と変わらない場合のどちらでも、組み立ては新しい塊の表で 1 度は行われる。Android では、構成が等しい間の表の同一性 (`remember` の等しさによる比較、同一の参照なら比較を省く) が保たれ、派生の表は作り直されない
- **堅牢性**: 続けて届く更新 (切り替えの適用中に通常の更新が届く) では、適用済みの塊の表は適用の前に差し替わっているため、見出しの組み立ては常に新しい表で行われる
- **テスト**: 追加・変更されたテストは修正前の実装で落ちる形になっている (iOS は古い範囲の組み立てを捕まえる。Android は古い表示名を捕まえる)。待機は条件ベースで行われる
