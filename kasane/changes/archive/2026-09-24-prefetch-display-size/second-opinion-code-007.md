# 独立コードレビュー結果

提示されたテスト結果を前提にした静的レビューです。前回指摘のうち、iOS の表示条件変更時の選び直しと、Android の初回フレームの空白は、実装経路で修正を確認しました。残る2件は実機計測の前に修正が必要です。

### 🟠 Major — Android: 完了済みの先読みも「未完了」と判定する

**該当箇所**: `android/kscollectionview/src/main/kotlin/jp/kamusoft/kscollectionview/KsImageRequestFactory.kt:116`、`KsImageMemoryIndex.kt:65`、`KsImage.kt:228`  
**問題点**: `prefetchPending` は「索引にあり、今はキャッシュに無い先読みキー」で決まります。索引は失敗・取り消し・キャッシュからの追い出し後もキーを残すため、先読みが進行していない画像でも表示要求を画面に出る時点まで遅らせます。「その識別子の先読みが未完了のときだけ遅らせる」という今回の決定を満たしません。  
**推奨修正**: 進行中の要求を取得台帳などで識別し、終了後は遅延対象から外してください。失敗・追い出し後に先行合成で表示要求を開始する回帰テストを追加してください。

### 🟠 Major — iOS: `shown` が切り取られた表示を数え得る

**該当箇所**: `samples/ios/KsCollectionViewSamples/ImageLoadingSlotShownProbeView.swift:34`  
**問題点**: 可視判定は、表示の矩形とウィンドウの交差だけを調べます。コレクションの表示領域の外にあり、祖先ビューで切り取られた先行組み立て済みセルでも、矩形がウィンドウ内に掛かれば `shown` に数えられます。`matchedShown` を「読み込み中が画面に出た回数」として使う実機計測を誤判定する恐れがあります。  
**推奨修正**: 切り取りを行う祖先ビューの可視矩形とも交差させてください。ウィンドウ内にあるがコレクションの表示領域外にあるスロットを数えないテストを追加してください。

### 🟡 Minor — iOS: 監視対象がなくなっても画面更新ごとの監視が続く

**該当箇所**: `samples/ios/KsCollectionViewSamples/ImageLoadingSlotShownMonitor.swift:19`、`:27`  
**問題点**: 一度開始した `CADisplayLink` を停止する経路がありません。計測画面を離れて監視対象が空になっても、周期的な処理が続きます。  
**推奨修正**: 監視対象が空になった時点で `invalidate()` し、次の対象が登録されたときに再開してください。

**境界の確認**: Android の release 構成は `measurement` と計数の実体をソースセットから除外しています。iOS の索引読出しは `DEBUG` 限定です。iOS の計測専用起動経路は Release Sample に含まれますが、Release で計測ドライバを動かすプロジェクト規約に沿うため、今回の違反とは判定しません。計測のために追加されたライブラリ本体の公開 API と、デモ画面の文言・構成の不一致は確認しませんでした。

**判定: CHANGES_REQUESTED**
