## 指摘事項

### 🟠 Major — メモリ消去後、再表示した画像に消去前の画像を使う

**該当箇所**: `ios/Sources/KsCollectionView/KsImage.swift:97`、`ios/Sources/KsCollectionView/KsImageRetainedMatch.swift:38`

**問題点**: 同じ `KsImage` のソースをリモート画像 A → アセット → A と切り替える間に `clear(.memory)` を呼ぶと、アセット表示中も `@State` 内に A の画像が残ります。A に戻した際はキャッシュに項目がなくても保持画像が返り、仕様が求める「次の表示でディスクから再デコード」が起きません。今回追加された回帰テストは、リモート画像を表示し続ける場合だけを確認しています。

**推奨修正**: リモート画像の表示経路を離れた時点で保持画像を破棄してください。上記の切り替えとメモリ消去を組み合わせた回帰テストも追加してください。

### 🟠 Major — 有効な固定幅で iOS アプリが停止し得る

**該当箇所**: `ios/Sources/KsCollectionView/KsPrefetchMetrics.swift:12`

**問題点**: `.fixed(1e19)` は仕様上「有限かつ正」の有効値ですが、ピクセル値を `Int` に変換する際に表現範囲を超え、Swift の変換が停止します。表示倍率を掛けた結果が範囲を超える値でも同様です。

**推奨修正**: `Int` へ変換する前に範囲を確認し、安全に扱える値へ制限してください。大きな有限値と表示倍率を掛けた際の境界をテストしてください。

前回採用された共有キーの署名 URL 差し替えと、表示中のリモート画像を保ったままの `clear(.memory)` 後の再評価は、現行コードと回帰テストで修正を確認しました。deviation.md の合意済み差分は指摘に含めていません。適用規約は `cross/comment-policy`、`sample-parity`、`test-execution`、`runtime-behavior-verification`、`scroll-performance-gate`、iOS・Android の `performance-verification`、および `lessons/code-review` です。指定されたテスト結果を前提とする静的レビューで、ビルド・テストは実行していません。
