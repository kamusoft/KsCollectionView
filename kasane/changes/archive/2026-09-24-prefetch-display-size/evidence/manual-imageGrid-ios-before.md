# 画像グリッド (iOS) の手動フリック計測 — 2026-09-23 (本実装前の対照)

tasks 1.1 / 1.2 (design Decision 8 (1))。本実装の前に、Sample「画像グリッド」を到達点「メモリまで」(走行 3) と「ディスクまで」(走行 4) で固定の操作列どおりにフリックし、現状の対照を残す。完了時の計測 (Decision 8 (3)) はこの記録と比べる。Android の対は [manual-imageGrid-android-before.md](manual-imageGrid-android-before.md) (走行 1・2)。

コードは main の本実装前 (提案改訂のコミット時点)。ios / android / samples のコードは 2026-09-17 の本実装 (performance-criteria-review) のコミットから変わっていない。

数値の取り出し: `xctrace export` で `display-surface-swap` / `hitches-summary` / `hitches-hid-input` / `time-profile` / `device-thermal-state-intervals` を XML にし、Python で集計した (手順は 2026-09-17 の記録と同じ。`hitches` 表は trace に無い)。生 trace・中間ファイル・集計スクリプトはスクラッチにのみ置き、change には置かない。

区間の切り方: HID 入力 (`display-surface-swap` の `hid-time` 列) を 3 秒以上の空白で区切った塊を「HID 区間」、画面の動き (surface swap) を 1 秒以上の空白で区切った塊を「描画区間」とする。描画区間と操作列の段階の対応は当てであり、trace からは断定しない。

- **初回に当たる区間の hitch が 13 件・33.5 ms/s → 41 件・120.7 ms/s に増えた。** 区間長はほぼ同じ (6.47 → 6.22 秒)

到達点「メモリまで」で採った iOS の固定の操作列の記録は本記録が最初である。2026-09-17 の記録とは到達点が違うため**比較不能** (上の表には並べない)。完了時の計測 (「メモリまで」の幅なし / 列幅) はこの走行と比べる。

## 両走行に共通する限界

- 体感はオーナー 1 人・各 1 試行。非接続の対照は行っていない
- 到達範囲 (通過した件数) が取得不能のため、操作量の差を件数で数えられない。描画区間の長さからの当てに留まる
- 描画区間と操作列の段階の対応は当てであり断定しない。各段階の実長は指定と揃っていない
- time profile の占有率は inclusive のため入れ子の項目は重複して数えられ、合計は 100% にならない
- 画像の読み込み・デコード系とプリフェッチの占有はシンボル名の部分一致による上限値で、2026-09-17 の同名の値と照合パターンが同一である保証は無い
- 画像の出方の「2〜3 秒」はオーナーの目測で、計時していない。ネットワーク状態・画像の到着タイミングは記録していない
- 取得・デコードの回数 (ローダーの通知) はこの記録には無い。表示待ちの原因の帰属は完了時の計測 (Decision 8 (3)) で行う
- 画像の出方は滑らかさとは別の観測点で、合否に混ぜていない
- Android の対 (走行 1・2) より画像の出方が速い (2〜3 秒 / 約 5 秒) のは両 platform の観測事実として記録するが、ローダー・ネットワーク経路・端末が違うため、この記録から原因は言わない
