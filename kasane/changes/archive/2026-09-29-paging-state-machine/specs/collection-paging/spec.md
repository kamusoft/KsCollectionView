# collection-paging — デルタスペック

## ADDED Requirements

### Requirement: ページングの状態
ライブラリは、待機・取り直し中・追加読み込み中・失敗・終端の 5 つの値を持つ公開の列挙を両プラットフォームで提供する (SHALL)。値は付属の値 (エラーの値・失敗の種類) を持たない (SHALL)。状態は利用者が持ち、ライブラリは状態を書き換えない (SHALL NOT)。

#### Scenario: ライブラリは状態を書き換えない
- **GIVEN** 状態が待機でページングを付けた一覧
- **WHEN** ライブラリが次ページ要求の処理を呼ぶ
- **THEN** 利用者が書き換えるまで、一覧が参照する状態は待機のまま変わらない

### Requirement: ページングの設定
利用者は一覧に、状態・次ページ要求の処理・しきい値を渡してページングを付けられる (SHALL)。次ページ要求の処理は非同期関数で受ける (SHALL)。しきい値は「何画面分手前で頼むか」を表す画面数で、省略時は 1 とする (SHALL)。ページングを付けない一覧では、ライブラリは次ページ要求を行わず、ページングの表示を出さない (SHALL)。

#### Scenario: ページングを付けない一覧
- **GIVEN** ページングを付けていない一覧
- **WHEN** 末尾までスクロールする
- **THEN** 次ページ要求は行われず、ページングの表示は出ない

### Requirement: 追加読み込みの発火
状態が待機のとき、ライブラリは「画面に出ている項目のうちいちばん後ろの項目より後に残っている項目の数」が「しきい値 × 画面に出ている項目の数 (端数は切り上げ)」以下なら、次ページ要求の処理を呼ぶ (SHALL)。数えるのは項目だけで、グループの見出し・ルートのヘッダー / フッター・ページングの表示は数えない (SHALL)。画面に出ている項目は、一覧の表示範囲と少しでも重なる項目とする (SHALL)。list とグリッドのどちらでも、行ではなく項目の数で数える (SHALL)。項目が 1 件以上あるのに画面に出ている項目が 1 つも無いとき (ルートのヘッダーだけで表示範囲が埋まっている等) は頼まない (SHALL NOT)。

#### Scenario: 既定のしきい値で 1 画面分手前で頼む
- **GIVEN** 100 件の list で、画面に 10 件出ている (しきい値は既定)
- **WHEN** 画面に出ているいちばん後ろの項目が 89 番目 (0 始まり) に届くまでスクロールする
- **THEN** その時点で次ページ要求が 1 回呼ばれ、88 番目までの間は呼ばれない

#### Scenario: しきい値 2
- **GIVEN** 100 件の list で、画面に 10 件出ている (しきい値 2)
- **WHEN** いちばん後ろの項目が 79 番目に届くまでスクロールする
- **THEN** その時点で次ページ要求が呼ばれる

#### Scenario: しきい値 0
- **GIVEN** 100 件の list (しきい値 0)
- **WHEN** 最後の項目が画面に入るまでスクロールする
- **THEN** 最後の項目が画面に入った時点で次ページ要求が呼ばれ、その前には呼ばれない

#### Scenario: グリッドは項目の数で数える
- **GIVEN** 100 件の 2 列のグリッドで、画面に 10 件 (5 行) 出ている (しきい値は既定)
- **WHEN** いちばん後ろの項目が 89 番目に届くまでスクロールする
- **THEN** その時点で次ページ要求が呼ばれる

#### Scenario: 画面に項目が出ていないとき
- **GIVEN** 項目が 1 件以上あり、表示範囲がルートのヘッダーだけで埋まっている一覧 (状態は待機)
- **WHEN** 一覧を表示する
- **THEN** 次ページ要求は呼ばれず、スクロールして項目が画面に出てから判定される

#### Scenario: 見出しとフッターは数えない
- **GIVEN** グループの見出しとルートのフッターを持つ一覧
- **WHEN** 見出しやフッターが画面に出ている状態で判定する
- **THEN** 画面に出ている項目の数・残りの項目の数のどちらにも、見出し・フッター・ページングの表示は含まれない

### Requirement: 判定し直すきっかけ
ライブラリは、スクロールしたとき・配列が差し替わったとき・状態が変わったとき・しきい値が変わったとき・一覧の大きさが変わったときに、発火の条件を判定し直す (SHALL)。

#### Scenario: 1 ページが画面に満たないとき
- **GIVEN** 1 ページの件数が画面に出る項目の数より少ない一覧
- **WHEN** 1 ページ目が届いて状態が待機に戻る
- **THEN** スクロールしなくても次ページ要求が呼ばれ、残りの項目の数がしきい値を超えるまで続く

#### Scenario: 失敗から待機に戻ったとき
- **GIVEN** 末尾近くで状態が失敗になっている一覧
- **WHEN** 利用者が状態を待機に戻す
- **THEN** 発火の条件が判定し直され、条件を満たせば次ページ要求が呼ばれる

#### Scenario: 回転で画面に出る項目の数が変わったとき
- **GIVEN** 縦長で発火の条件を満たしていない一覧
- **WHEN** 回転して画面に出る項目の数が増え、条件を満たす
- **THEN** スクロールしなくても次ページ要求が呼ばれる

### Requirement: 初回の読み込み
項目が 0 件で状態が待機なら、ライブラリはしきい値によらず次ページ要求の処理を呼ぶ (SHALL)。

#### Scenario: 空で待機なら頼む
- **GIVEN** 項目が 0 件、状態が待機、しきい値 0 の一覧
- **WHEN** 一覧を表示する
- **THEN** 次ページ要求が 1 回呼ばれる

### Requirement: 待機のときだけ自動で頼む
状態が取り直し中・追加読み込み中・失敗・終端のとき、ライブラリは発火の条件を満たしていても次ページ要求を自動では呼ばない (SHALL NOT)。

#### Scenario: 終端では頼まない
- **GIVEN** 状態が終端の一覧
- **WHEN** 最後の項目までスクロールする
- **THEN** 次ページ要求は呼ばれない

#### Scenario: 失敗では自動で頼まない
- **GIVEN** 状態が失敗の一覧
- **WHEN** スクロールを続ける
- **THEN** 次ページ要求は自動では呼ばれない

### Requirement: 頼んだ後の待ち方
ライブラリは一度次ページ要求の処理を呼んだら、その処理が終わり、かつ呼んだ時点から状態か配列の中身が変わるまで、次ページ要求を呼ばない (SHALL)。

#### Scenario: VM が状態の書き換えを遅らせても二重に頼まない
- **GIVEN** 次ページ要求の処理がすぐ戻り、少し後で状態を追加読み込み中に書き換える VM
- **WHEN** 処理が戻ってから状態が書き換わるまでの間にスクロールを続ける
- **THEN** 次ページ要求は 1 回しか呼ばれない

#### Scenario: 処理の中で待つ VM
- **GIVEN** 次ページ要求の処理の中で取得を待ち、終わってから配列と状態を書き換える VM
- **WHEN** 処理の実行中にスクロールを続ける
- **THEN** 処理が終わるまで次ページ要求は呼ばれない

#### Scenario: 頼みが無視されたとき
- **GIVEN** 次ページ要求の処理が状態も配列も変えずに戻る VM
- **WHEN** 末尾近くでスクロールを続ける
- **THEN** 状態か配列の中身が変わるまで、次ページ要求は呼ばれない

### Requirement: 一覧が破棄されたときの取り消し
一覧が破棄されたら (一覧を含む画面を閉じた等)、ライブラリは実行中の次ページ要求の処理を取り消す (SHALL)。別の画面へ進んでも一覧が破棄されずに残っている間は取り消さない (SHALL NOT)。一覧が残るかどうかは、各プラットフォームのナビゲーションの仕組みによる。

#### Scenario: 読み込み中に画面を閉じる
- **GIVEN** 次ページ要求の処理の中で取得を待っている一覧
- **WHEN** 一覧を含む画面を閉じる
- **THEN** 実行中の処理は取り消される

### Requirement: 不正なしきい値
しきい値が負の数、または有限でない数なら、ライブラリは不正入力として報告し (debug は assertion、release は表示を続けて警告ログ。core/ADR-0011)、しきい値 0 として扱う (SHALL)。

#### Scenario: 負のしきい値 (release)
- **GIVEN** release ビルドで、しきい値に負の数を渡した一覧
- **WHEN** 一覧を表示してスクロールする
- **THEN** 警告ログが出て、最後の項目が画面に入った時点で次ページ要求が呼ばれる

### Requirement: ページングの表示
ページングを付けた一覧は、状態と項目が 0 件かどうかで、次の 6 つの表示のうち高々 1 つを出す (SHALL)。

| 状態 | 項目が 1 件以上 | 項目が 0 件 |
|---|---|---|
| 追加読み込み中 | 次のページの読み込み中 | 最初の読み込み中 |
| 失敗 | 次のページの失敗 | 失敗 (0 件) |
| 終端 | 終端 | 空 |
| 取り直し中 | 出さない | 最初の読み込み中 |
| 待機 | 出さない | 出さない |

項目が 1 件以上のときの表示は、最後の項目の後ろ・ルートのフッターの前に現れる (SHALL)。項目が 0 件のときの表示は、項目の代わりに 1 つ現れ、ルートのヘッダー / フッターは従来どおり表示する (SHALL)。0 件のときの表示がルートのヘッダー / フッターと重なった場合は 0 件のときの表示が手前になり、その中の操作 (再試行など) は押せる (SHALL)。0 件のときの表示の外への操作 (ヘッダー / フッターへの操作・引っ張り) は妨げない (SHALL)。6 つの表示はそれぞれ利用者が差し替えられる (SHALL)。差し替えていないとき、次のページの読み込み中と最初の読み込み中は各プラットフォームの標準の読み込み中の表示を出し、文言を持たない (SHALL)。差し替えていないとき、次のページの失敗・失敗 (0 件)・終端・空は何も出さない (SHALL)。状態だけが変わったとき (配列は同じ) も、表示は新しい状態に合わせて変わる (SHALL)。

#### Scenario: 次のページの読み込み中 (既定)
- **GIVEN** 項目が 1 件以上あり、表示を差し替えていない一覧
- **WHEN** 状態を追加読み込み中にする
- **THEN** 最後の項目の後ろに標準の読み込み中の表示が現れ、文言は出ない

#### Scenario: 最初の読み込み中 (既定)
- **GIVEN** 項目が 0 件で、表示を差し替えていない一覧
- **WHEN** 状態が追加読み込み中、または取り直し中になる
- **THEN** 項目の代わりに標準の読み込み中の表示が 1 つ現れる

#### Scenario: 失敗・終端・空は既定では出ない
- **GIVEN** 表示を差し替えていない一覧
- **WHEN** 状態を失敗・終端にする (項目が 1 件以上の場合と 0 件の場合の両方)
- **THEN** ページングの表示は何も出ない

#### Scenario: 差し替えた表示が出る
- **GIVEN** 6 つの表示をすべて差し替えた一覧
- **WHEN** 上の表の各組み合わせの状態と件数にする
- **THEN** 表の組み合わせに対応する差し替えた表示だけが出る

#### Scenario: VM が始めた取り直しの間は項目の上に何も出さない
- **GIVEN** 項目が 1 件以上ある一覧
- **WHEN** 引っ張らずに状態を取り直し中にする
- **THEN** 項目はそのまま並び、ページングの表示は出ない

#### Scenario: 状態だけが変わったとき
- **GIVEN** 次のページの読み込み中を出している一覧
- **WHEN** 配列を変えずに状態を待機にする
- **THEN** 読み込み中の表示は消える

#### Scenario: 0 件の表示がヘッダーと重なっても押せる
- **GIVEN** 表示範囲の真ん中まで届く高さのルートのヘッダーを持ち、項目が 0 件で状態が失敗、失敗 (0 件) の表示を差し替えた一覧
- **WHEN** 失敗 (0 件) の表示の中の再試行を押す
- **THEN** 失敗 (0 件) の表示がヘッダーより手前に見え、再試行の操作が行われる

### Requirement: 再試行
失敗の表示 (次のページの失敗・失敗 (0 件)) の差し替えには、再試行の操作が渡される (SHALL)。再試行の操作は、状態が失敗のとき、項目が 0 件かどうかと Pull to Refresh の有無によらず、次ページ要求の処理を呼ぶ (SHALL)。次ページ要求の処理が実行中なら、再試行の操作は何もしない (SHALL)。

#### Scenario: 項目があるときの再試行
- **GIVEN** 項目が 1 件以上あり、状態が失敗で、次のページの失敗の表示を差し替えた一覧
- **WHEN** 差し替えた表示の中で再試行の操作を行う
- **THEN** 次ページ要求が呼ばれる

#### Scenario: 0 件のときの再試行
- **GIVEN** 項目が 0 件で状態が失敗、Pull to Refresh を付けた一覧
- **WHEN** 失敗 (0 件) の表示の中で再試行の操作を行う
- **THEN** 取り直しの処理ではなく、次ページ要求が呼ばれる

### Requirement: Pull to Refresh の接続
利用者は一覧に取り直しの処理を渡して Pull to Refresh を付けられる (SHALL)。iOS は SwiftUI 標準の Pull to Refresh の宣言を一覧に付けた形で、Android は一覧の引数で受ける (SHALL)。取り直しの処理は非同期関数で受ける (SHALL)。ページングを付けない一覧でも使え、項目が 0 件でも引っ張れる (SHALL)。取り直しの処理を渡さない一覧は引っ張れない (SHALL)。

#### Scenario: 引っ張ると取り直しの処理が呼ばれる
- **GIVEN** 取り直しの処理を渡した一覧 (ページングの有無は問わない)
- **WHEN** 先頭で引っ張る
- **THEN** 取り直しの処理が呼ばれる

#### Scenario: 0 件でも引っ張れる
- **GIVEN** 取り直しの処理を渡した、項目が 0 件の一覧
- **WHEN** 引っ張る
- **THEN** 取り直しの処理が呼ばれる

### Requirement: Pull to Refresh のインジケータ
Pull to Refresh のインジケータは、引っ張ってから取り直しの処理が終わるまで出し、処理が終わった後は状態が取り直し中の間だけ出し続ける (SHALL)。処理が終わった時点で状態が取り直し中でなければ消す (SHALL)。引っ張っていないのに状態が取り直し中になったときは出さない (SHALL NOT)。インジケータは上端のバーやステータスバーに隠れずに見える (SHALL)。

#### Scenario: 処理の中で待つ取り直し
- **GIVEN** 取り直しの処理の中で取得を待つ VM
- **WHEN** 引っ張る
- **THEN** 処理が終わるまでインジケータが出て、終わったら消える

#### Scenario: 処理がすぐ戻る取り直し
- **GIVEN** 取り直しの処理の中で状態を取り直し中にしてすぐ戻り、取得が終わってから状態を待機にする VM
- **WHEN** 引っ張る
- **THEN** 状態が待機に戻るまでインジケータが出続ける

#### Scenario: VM が始めた取り直しでは出さない
- **GIVEN** 取り直しの処理を渡した一覧
- **WHEN** 引っ張らずに状態を取り直し中にする
- **THEN** インジケータは出ない

#### Scenario: 全画面の一覧でも見える
- **GIVEN** 行を上端のバーの裏に流す全画面の一覧 (core/ADR-0017)
- **WHEN** 引っ張る
- **THEN** インジケータはバーやステータスバーの裏に隠れずに見える

### Requirement: 追加読み込みの間は引っ張れない
状態が追加読み込み中の間と、ライブラリが頼んだ次ページ要求の処理が実行中の間は、引っ張っても取り直しは始まらない (SHALL)。どちらでもなくなったら、また引っ張れる (SHALL)。次ページ要求の処理から戻った後に状態を追加読み込み中にする書き方では、戻ってから書き換えるまでの間は引っ張れる (この間の取り直しと古い読み込みの競合、および VM が自分で始める取り直しと読み込みの競合は、利用者の VM が扱う)。

#### Scenario: 追加読み込み中に引っ張る
- **GIVEN** 状態が追加読み込み中で、取り直しの処理を渡した一覧
- **WHEN** 先頭で引っ張る
- **THEN** 取り直しの処理は呼ばれない

#### Scenario: 処理の実行中に引っ張る
- **GIVEN** 次ページ要求の処理の中で取得を待ち、状態をまだ追加読み込み中にしていない VM (ライブラリが処理を呼んだ直後)
- **WHEN** 処理の実行中に先頭で引っ張る
- **THEN** 取り直しの処理は呼ばれない

#### Scenario: 追加読み込みが終わった後
- **GIVEN** 追加読み込みが終わって状態が待機に戻った一覧
- **WHEN** 先頭で引っ張る
- **THEN** 取り直しの処理が呼ばれる
