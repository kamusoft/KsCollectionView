# 第 2 段階の確認: 番号を付けずに入れ物を使い回す形 (iOS 17.5) — 2026-10-04

> **最終の形の結果は、末尾の「最終の形の結果」の節にある。** 最終の形は「iOS 18 以降は入れ物を使い回し、それより前の版は変更前のまま作り直す」。それより前の節は、途中で試した形 (番号を付けない形・版で分けて番号を付ける形) の結果で、経緯として残している。

採用する形の作業ツリーを iOS 17.5 で流し、大きな問題が無いかを見た記録である。iOS 27.0・18.6 の分と手順の詳細は verify-hosting-reuse-stage2.md にある。合否は書かない。

Simulator はこの確認のために新しく作り、最後に削除した (`ksn-hosting-reuse2-175` = iPhone 11・iOS 17.5)。

## 先に

- **state の持ち越し: ある。** 項目 0 で変えたテンプレートの内部 state が、そのセルが再利用されて載せた別の項目に出た。この確認の時点の ios/ADR-0012 の草稿は「iOS 16・17 では残りうる」ことを受け入れる内容で、その実測に当たる (経緯。この結果を受けて決定は書き直され、いまの ADR-0012 にその記述は無い)
- **それ以外の問題: 見つからなかった。** クラッシュなし。高さ・`onAppear` と `.task`・入れ物の使い回しのテストは通り、前の項目の文言が見えるフレームは無く、メモリは定常になった

## 1. state の持ち越し (観測)

### テストの結果

iOS 本体のテスト全件 (作業ツリー、Debug 構成、iPhone 11・iOS 17.5): `Executed 535 tests, with 1 failure`。

失敗した 1 件は `KsCollectionScenarioTests` の「セルの再利用が起きる距離を往復するとテンプレートの state は初期値へ戻る」である。

- 失敗の内容: 「復路での state 初期化 が期限内に収束しませんでした。実測値: Optional(true)」。先頭の項目の state を変え、250 番目へ送って先頭へ戻したとき、先頭の項目の state が変えた値のままだった
- 同じテストは、変更前のコード (HEAD の複製) では iOS 17.5 で通った。変更で起きた違いである
- テストは書き換えていない。版で飛ばす処理も足していない

### どう残ったか (スクラッチの観測用テスト)

項目ごとに「展開」の state (初期値は偽) を持つ行を 300 件並べ、項目 0 だけを展開にしてから、可視範囲の半分ずつ送った (セルの再利用が起きる送り方)。テンプレートは呼ばれるたびに違う値を行へ渡し、行が必ず描き直されるようにした。同じ観測を iOS 18.6 でも流した。

| 操作 | iOS 17.5: 展開の state で描かれた項目 | iOS 18.6: 展開の state で描かれた項目 | 項目 0 を載せていたセルが載せた項目 (17.5) |
|---|---|---|---|
| 下向きに 40 段 | 39, 74, 109, 135, 170, 205, 231, 263 | なし | 39, 74, 109, 135, 170, 205, 231, 263 |
| 上向きに 45 段 | 25, 60, 95, 138, 168, 206, 244, 275 | なし | 275, 244, 206, 168, 138, 95, 60, 25 |
| 先頭へ戻った後に表示中のセルを作り直して読む | 項目 0 は偽。展開の項目なし | 項目 0 は偽。展開の項目なし | — |

- iOS 17.5 では、**state はセル (入れ物) に付いて回る。** 項目 0 を載せていたセルが再利用されて載せた項目 (39、74、109、…) が、どれも展開の state で描かれた。項目 0 の state が、そのセルを使った別の項目すべてに出たことになる
- 先頭へ戻ったとき、項目 0 は別のセルに載り、state は初期値だった。項目 0 で変えた state は項目 0 には残らず、別の項目に出ている
- iOS 18.6 では、同じ操作で展開の state で描かれた項目は無かった (OS が戻している)
- 離れた位置へ一度に送って戻す送り方 (失敗した既存のテストの送り方) では、元のセルが再利用されないまま同じ項目へ戻ることがあり、その場合は同じ項目に state が残る (既存のテストの実測値が真だったのはこの形)

### 読み

- この確認の時点の ios/ADR-0012 の草稿にあった「iOS 16・17 では、前の項目の state が次の項目に残りうる」は、iOS 17.5 で実際に起きる (経緯。いまの ADR-0012 は、iOS 18 より前の版を変更前のまま作り直すと決めており、この持ち越しは最終の形では起きない)。残り方は「たまに」ではなく、state を変えたセルが再利用されるたびに、載せた項目に出る
- 利用者が行の内部 state (展開・入力途中など) を使うと、iOS 17 ではスクロールで別の行にその state が出る。state を持たない行と、state をデータ側に持つ行には影響しない

## 版で分けた後の結果 (2026-10-04。ここから下は「版で分ける形」の結果)

ここまでの節は「番号を付けない形」の結果である。この節は、その後に採った「版で分ける形」の作業ツリーを iOS 17.5 で流した結果である。iOS 17.5 は、利用者のテンプレートの中身にセルの再利用の回数を識別の値 (`.id`) として付ける経路を通る。

Simulator は新しく作り直し、最後に削除した (`ksn-hosting-reuse3-175` = iPhone 11・iOS 17.5)。

### 先に

- **state の持ち越し: 無くなった。** 既存の「再利用が起きる距離を往復すると state は初期値へ戻る」は iOS 17.5 で通り、観測用テストでも別の項目に state は出なかった
- **別の問題が 1 つ見つかった。** 足したテスト「再利用で表示に入った項目で onAppear と task が動く」が iOS 17.5 で失敗した。表示から外れた項目の `onAppear` と `.task` が、**余分に 1 回動く**。変更前のコードと「番号を付けない形」では起きない。直していない

### テスト (観測。作業ツリー、Debug 構成、iPhone 11・iOS 17.5)

`Executed 535 tests, with 2 failures`。失敗の 2 つは同じ 1 件のテストの中の 2 つの確認である (失敗したテストは 1 件、成功は 534 件)。

| テスト | 結果 |
|---|---|
| (既存) セルの再利用が起きる距離を往復するとテンプレートの state は初期値へ戻る | 成功 |
| 再利用の前後でセルの中身のビューは同じである | 成功 |
| 高さの違う項目へ再利用されたセルは新しい項目の高さになる | 成功 |
| 再利用で表示に入った項目で onAppear と task が動く | **失敗** |
| 同値配列の更新による表示中のセルの作り直しではテンプレートの state が残る | 成功 |
| 観測する値の変化による表示中のセルの作り直しではテンプレートの state が残る | 成功 |

番号を付ける経路でも、表示中のセルの作り直しでは state が残った (下の 2 件)。

### state の持ち越し (観測)

スクラッチの観測用テスト (300 件、項目 0 だけ展開にして、可視範囲の半分ずつ送る) を流し直した。

| 操作 | 展開の state で描かれた項目 | 項目 0 を載せていたセルが載せた項目 |
|---|---|---|
| 下向きに 40 段 | なし | 39, 74, 109, 135, 170, 205, 231, 263 |
| 上向きに 45 段 | なし | 275, 244, 206, 168, 138, 95, 60, 25 |
| 先頭へ戻った後に表示中のセルを作り直して読む | 項目 0 は偽。展開の項目なし | — |

項目 0 を載せていたセルは前と同じ項目に再利用されたが、どの項目も展開の state では描かれなかった。iOS 18.6 と同じ結果になった。

### 見つかった問題: `onAppear` と `.task` が余分に 1 回動く (観測)

失敗の内容: 先頭 → 中ほど (150) → その先 (250) → 先頭 と送った後、先頭の項目の `onAppear` と `.task` の回数がどちらも 3 だった (テストの期待は 2: 最初の表示と、戻ったとき)。

失敗したテストに記録を足した複製 (スクラッチ) で、項目 0 の出来事の順を取った:

| コード | 項目 0 の出来事の順 (iOS 17.5) |
|---|---|
| 版で分けた形 (番号を付ける経路) | テンプレート → onAppear → task → onDisappear → **onAppear → task** → [項目 0 へ送る] → onDisappear → テンプレート → onAppear → task |
| 変更前のコード | テンプレート → onAppear → task → onDisappear → [項目 0 へ送る] → テンプレート → onAppear → task |

- 余分な `onAppear` と `.task` は、項目 0 が表示から外れた後、先頭へ戻る前に起きている。その間にテンプレートは呼ばれていない。つまり、再利用の列にあったセルに残っていた項目 0 の中身が、もう一度「表示された」と扱われている
- 変更前のコードでは起きない (同じテストは変更前のコードで iOS 17.5 で成功)。「番号を付けない形」でも起きなかった (上の節で、同じテストが iOS 17.5 で成功している)。iOS 18.6・27.0 は番号を付けない経路を通り、起きない
- 高さの並びが一様な別の観測 (300 件すべて高さ 44、同じ送り方) では、セルが再利用されず、余分な回数も出なかった。再利用が起きたときにだけ出る

### 読み (推測。確かめていない)

- 再利用の列から取り出されたセルが表示の階層へ戻る時点で、前の項目の中身がまだ載っており、その後に識別の値の違う次の中身へ入れ替わる。番号を付ける経路では入れ替えが「前の中身を消して新しい中身を出す」になるため、消す前の中身の `onAppear` が先に動いてしまうと読む。番号を付けない経路では同じビューの更新になるので、前の項目の `onAppear` としては動かない
- 利用者への影響: iOS 17 以前で、行の `onAppear` や `.task` で読み込みや記録を始める利用者は、表示から外れた項目についてそれが余分に 1 回動く。動いた直後に `onDisappear` が来て `.task` は取り消される

### 限界 (この節の分)

- 余分な `onAppear` の仕組みは確かめていない (どのセルで、どの時点の呼び出しの中で起きるか)。観測したのは出来事の順と回数だけ
- 余分な回数が出るのを確かめたのは、足したテストの送り方 (高さの違う 3 つの範囲を一度に送る) だけ。通常のスクロール (少しずつ送る) で出るかは確かめていない
- 前の見た目の確認とメモリは、番号を付ける経路ではやり直していない。iOS 17.5 の前の節の結果は「番号を付けない形」のもので、この経路には当てはまらない
- iOS 16 のランタイムは無い
