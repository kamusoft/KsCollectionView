# Proposal: template-parent-state-observation

## Why

iOS では、テンプレートのクロージャの中でしか読まれない親 View の状態 (展開中 ID の集合・選択中 ID など) が変わっても表示に反映されない。クロージャは SwiftUI の `body` 評価の外 (UIKit のセル生成時) で実行されるため、その読み取りは依存グラフに載らず、親 View が再評価されずライブラリへ更新が届かない (ios-engine-foundation のライブ調整で A/B のログ実測により確認)。ios/ADR-0006 が「親の状態を捕捉するテンプレートを成立させる」ために決めた同値配列時の可視セル再構成は、この前提が成り立たない使い方では一度も走らない。

Android (Compose) ではテンプレートが合成の中で実行され親の状態を自動購読するため同じ問題は起きない。iOS だけが「書いたとおりに動かない」状態を解消し、両プラットフォームで同じ書き味を成立させる (ios/ADR-0008)。

## What Changes

- 観測する値を DSL に明示的に渡す modifier を iOS に追加する (仮称 `.observing(_:)`。`Hashable` な値を 1 つ受け取る)。引数式が body の中で評価されることで依存が張られ、値が変わったときだけ可視セルを再構成する。未指定時の挙動は ios/ADR-0006 のまま (親の更新が届くたびに再構成)
- 利用者契約「テンプレートの中で親の状態を読むなら、その状態を観測する値として渡す」を確立し、concepts (項目モデル / iOS エンジン) と利用者向けの説明に反映する。状態を項目に持たせる書き方と、参照型モデルをセルの中で観測する書き方は参考として併記する (推奨ではない)
- 可視セル再構成に SwiftUI のトランザクションを引き渡すと中身の変化がアニメーションするかを spike で確かめる。成立すれば取り込み、しなければ結果を記録して見送る (modifier の採用は結果に依存しない)
- 検証画面「行の高さ変化」から body で状態を読む回避策 (「展開中: N 行」表示) を撤去し、遷移直後の 1 タップ目から親 state 経路の開閉が効くことと、中身のアニメーションの有無を Simulator で確認する

影響する能力: collection-core (親の状態の観測・差分更新) / samples (iOS 固有の検証画面)

## Non-Goals

- Android への対応 API の追加 — Compose が親の状態を自動観測するため不要。状態保持の流儀はプラットフォームごとに残す (core/ADR-0002、ios/ADR-0008)
- テンプレートのクロージャが (項目, content 値) を受け取る形への公開 API 変更 — 効果は modifier と同じで公開面の変更が大きい (ios/ADR-0008 で却下)
- 未指定時に「観測値が変わったときだけ再構成」へ狭めること — 静かな失敗の範囲が広がる (ios/ADR-0008 で却下)
- list と grid で追従が非対称だった内訳の解明 — modifier の導入で症状が消えるかを検証画面で確認するに留め、消えなければ別途起票する (計測に独立した調査が要る)
- ios/ADR-0006 の Consequences の改訂 — 本 change の蒸留時に ios/ADR-0008 の accepted 昇格と合わせて行う

## Impact

- 破壊的変更なし。modifier は純粋な追加で、既存の書き方 (body でも読んでいる場合) は従来どおり動く
- iOS だけに存在する語彙が 1 つ増える。利用者向けの説明で「Android では不要」を明記する
- リスク: アニメーションの spike は成立しない可能性がある。判定は静止画ではなくオーナー目視か offset ログの A/B で行う (lessons inbox: capture-transient-layout-glitch-with-offset-logs)
- リスク: modifier を忘れ、かつ body でも読んでいない場合の無反応は残る。契約の明記で緩和する

## UI アーティファクト

`ui/` は作らない。画面上の変更は検証画面から回避策の表示 (「展開中: N 行」) を取り除くだけで、新しい見た目の設計を伴わない。
