## ADDED Requirements

### Requirement: 利用者役の画面のソースの形

利用者役の画面のソースは、プラットフォームごとに 1 つのファイルで、ルートの README に最小コード例としてそのまま載せられる形でなければならない (SHALL)。ファイルは、コメントを持たず、利用者のアプリのコードとして読める内容 (モデルと、一覧を 1 つ表示する画面) だけを持つ。Android のファイルは、package の宣言を持たない。

この形に変えても、利用者の立場のビルドの確認が行うことと、成功の条件は変わらない。

**Side Effects**: なし

#### Scenario: iOS の画面のソースが 1 つのファイルである
- **GIVEN** iOS の利用者役のソースの置き場
- **WHEN** ファイルの一覧を見る
- **THEN** 画面のソースが 1 つのファイルで、モデルと画面の両方を持つ

#### Scenario: 画面のソースにコメントが無い
- **GIVEN** 両プラットフォームの、利用者役の画面のファイル
- **WHEN** 中身を見る
- **THEN** コメントが 1 行も無い

#### Scenario: Android の画面のソースが package の宣言を持たない
- **GIVEN** Android の利用者役の画面のファイル
- **WHEN** 先頭を見る
- **THEN** package の宣言が無く、import から始まる

#### Scenario: iOS の確認が成功する
- **GIVEN** 書き直した iOS の利用者役
- **WHEN** 切り替えを `local` にして、iOS の利用者の立場のビルドの確認を流す
- **THEN** Simulator 向けと実機向けの両方のビルドが成功し、確認は成功で終わる

#### Scenario: Android の確認が成功する
- **GIVEN** 書き直した Android の利用者役
- **WHEN** 切り替えを `local` にして、Android の利用者の立場のビルドの確認を流す
- **THEN** コード縮小を有効にした組み立てと、依存の確認が成功し、確認は成功で終わる

#### Scenario: 起動して一覧が表示される
- **GIVEN** 書き直した Android の利用者役を、コード縮小を有効にして組み立てたもの
- **WHEN** 手元で 1 回起動する
- **THEN** 一覧が表示される
