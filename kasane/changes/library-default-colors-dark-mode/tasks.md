# Tasks: library-default-colors-dark-mode

適用する規約: handbook/cross/comment-policy・handbook/cross/test-execution・handbook/cross/sample-parity。見た目の正は承認 mock `ui/mock/default-colors-a-ios-standard.html` (`ui/mock/approved.png`。照合するのは色だけ — `ui/brief.md`)、挙動の正は `specs/` の 4 つのデルタスペック。既定の色の値は、承認 mock の「色の表」の値を使う。方向の理由は core/ADR-0036・core/ADR-0037 (どちらも proposed)。提案の段階で確かめた外部の部品の挙動は `evidence/proposal-probes.md`。

性能検証は、オーナー判断の例外で今回行わない (`proposal.md` の Impact)。条件は、項目ごとの仕事量を増やさないこと: 区切り線の色を選ぶのは一覧ごとに 1 回、画像は画像ごとに画面の構成を 1 回読んで色を 1 つ渡すだけにする。これを超える形 (項目ごとの追加の計算・組み立て直し・部品の作り直し) になると分かったら、実装を止めて報告する。

## 1. iOS のライブラリ

- [ ] 1.1 区切り線の既定の色 (`KsHostingCell.defaultSeparatorColor`) を、ライト用とダーク用の値を持ち、線が置かれた場所の外観で OS が解決する色にする。ライト用は今の値のまま、ダーク用は色の表の値。定数は 1 つのまま保つ (同じ色の書き込みを省く判定が、同じオブジェクトかどうかで行われているため)。利用者が指定した色を受け取って線へ渡す経路は変えない。該当箇所に `core/ADR-0036` のコメントを残す (→ Requirement: 区切り線の色 (両プラットフォーム) / Scenario: ライトの既定の色 / ダークの既定の色 / 表示中に表示モードが切り替わる / アプリが外観を上書きした場所に置く (iOS))
- [ ] 1.2 画像の既定の表示 (`KsImageDefaultLoadingView`・`KsImageDefaultFailureView`) の色を、OS の色の参照から、ライブラリが持つライト / ダーク 2 組の値 (色の表) に替える。色は置かれた場所の外観で解決される形にする。形・大きさ・読み上げの扱いは変えない。外観の切り替えで、進行中の取得を取り消したり取得し直したりしない。該当箇所に `core/ADR-0036` のコメントを残す (→ Requirement: KsImage の既定の表示の色 / Scenario: ライトの読み込み中 / ダークの読み込み中 / ライトとダークの失敗 / 表示中に表示モードが切り替わる / 取得の途中で表示モードが切り替わる / 先読みの完了を待つ間の読み込み中 / 上書きした表示モードで決まる / 一覧の外に置いた KsImage)
- [ ] 1.3 既定の色 4 つ (区切り線・読み込み中・失敗の下地・失敗の印) のライト / ダークの値を、テストから読める形で持つ (Android の値と突き合わせるため。置き場と名前は実装で決める) (→ Scenario: 両プラットフォームで同じ値 — collection-layout / image-loading)
- [ ] 1.4 公開 API の doc コメントを直す (handbook/cross/comment-policy の「公開メンバーの doc コメント」):
  - `.listSeparatorColor(_:)`: 指定しないときの既定の色が、置かれた場所の外観 (ライト / ダーク) で変わること。指定した色にライブラリは手を加えないこと
  - `KsImage` の読み込み中・失敗の表示の説明: 差し替えないときの既定の表示の色が、置かれた場所の外観で変わること。差し替えた表示には色を当てないこと
  - `.touchFeedback(color:)`: 渡した色を不透明度を含めてそのまま塗ること、不透明な色を渡すと項目の中身が隠れること、Android は色みだけを使い濃さは標準の波紋が決めること、両プラットフォームで近い見え方にするには半透明の色を渡すこと (`core/ADR-0037`)
  (→ Requirement: 区切り線の色 (両プラットフォーム) / KsImage の既定の表示の色 / タップしたときの色の濃さの決まり方)
- [ ] 1.5 テスト (ライブラリのテストに足す):
  - 既定の区切り線の色を、ライト / ダークの外観で解決した値が、色の表の値と一致する。ライト用は変更前の値と同じ (→ Scenario: ライトの既定の色 / ダークの既定の色 / 両プラットフォームで同じ値)
  - 色を指定していない一覧を出したまま、window の外観をライト → ダーク → ライトに切り替えると、表示中の区切り線の色 (その線の外観で解決した値) が追随し、線の位置と本数は変わらない (→ Scenario: 表示中に表示モードが切り替わる)
  - 一覧を置いた window の外観だけをダークに上書きすると、区切り線がダーク用の値になる (→ Scenario: アプリが外観を上書きした場所に置く (iOS))
  - 外観で値の変わらない色を指定した一覧は、ライト / ダークのどちらでも指定した色のままで、指定を外すとその外観の側の既定の色になる (→ Scenario: 固定の色を指定すると表示モードで変わらない / 指定を外すと表示モードの側の既定の色になる)
  - 画像の既定の表示を、ライト / ダークの外観で描いた結果の色が、色の表の値 (読み込み中・失敗の下地・失敗の印) と一致する (→ Scenario: ライトの読み込み中 / ダークの読み込み中 / ライトとダークの失敗 / 両プラットフォームで同じ値)
  - 既定の読み込み中の表示、既定の失敗の表示を出したまま外観を切り替えると、描いた結果の色が追随し、表示の状態は変わらない (→ Scenario: 表示中に表示モードが切り替わる)
  - 取得を待たせて既定の読み込み中を出したまま外観を切り替えると、取得の要求の数と取り消しの数が増えず、取得を終わらせるとその結果の画像が出る。読み込みを始めてから出た場合と、先読みの完了を待つ間に出た場合の両方で確かめる (→ Scenario: 取得の途中で表示モードが切り替わる)
  - 先読みの完了を待つ間に出る読み込み中の表示も、ダークの外観でダーク用の色になる (→ Scenario: 先読みの完了を待つ間の読み込み中)
  - `KsImage` を置いた window の外観だけをダークに上書きすると、既定の読み込み中の表示がダーク用の色になる (→ Scenario: 上書きした表示モードで決まる)
  - 読み込み中・失敗を差し替えた `KsImage` は、ライト / ダークのどちらでも利用者の表示のまま出る。一覧の外に置いた `KsImage` も、ダークの外観で既定の表示がダーク用の色になる (→ Scenario: 差し替えた表示は変わらない / 一覧の外に置いた KsImage)
  - タップの色: 半透明の色を指定すると、その不透明度のままフィードバックの色に入り、項目の中身の前面に出ることを確かめる。既存のテストが同じことを確かめていれば、そのまま通ることの確認でよい (→ Scenario: 半透明の色を指定する (iOS))
  - 既存の Scenario (色の指定 / 非表示との組み合わせ) を確かめている既存のテストが、そのまま通る (→ Scenario: 色の指定 / 非表示との組み合わせ)

## 2. Android のライブラリ

- [ ] 2.1 区切り線の既定の色 (`KsListSeparatorDefaults`) をライト用とダーク用の 2 つの値にし、一覧が既に読んでいる画面の構成の夜間モード (`isSystemInDarkTheme()`。スクロールインジケータと同じ値) で選ぶ。Material のテーマの配色は判定に使わない。ライト用は今の値のまま、ダーク用は色の表の値。`listSeparatorColor` を指定したときは今までどおり指定した色を使う。該当箇所に `core/ADR-0036` のコメントを残す (→ Requirement: 区切り線の色 (両プラットフォーム) / Scenario: ライトの既定の色 / ダークの既定の色 / 表示中に表示モードが切り替わる / 画面の構成の夜間モードで決まる (Android) / アプリが画面の構成を上書きした場合 (Android) / Material の配色だけをダークにした場合 (Android))
- [ ] 2.2 画像の既定の表示の色 (読み込み中・失敗の下地・失敗の印) をライト / ダーク 2 組の値 (色の表) にし、`KsImage` が画面の構成の夜間モードで選ぶ。読み込み中の色は 2 か所 (組み立てる表示 `KsImageDefaultLoading` と、描く段階で塗る処理) の両方で同じ値にする。表示モードが変わっても、進行中の取得を取り消さず、取得し直さない (描く段階の処理は取得の仕事と描く状態を同じ部品に持っているので、色が変わったときに部品を作り直さない形にする)。形と大きさは変えない。該当箇所に `core/ADR-0036` のコメントを残す (→ Requirement: KsImage の既定の表示の色 / Scenario: ライトの読み込み中 / ダークの読み込み中 / ライトとダークの失敗 / 表示中に表示モードが切り替わる / 取得の途中で表示モードが切り替わる / 先読みの完了を待つ間の読み込み中 / 上書きした表示モードで決まる / 一覧の外に置いた KsImage)
- [ ] 2.3 KDoc を直す (handbook/cross/comment-policy の「公開メンバーの doc コメント」):
  - `listSeparatorColor`: 省略したときの既定の色が、画面の構成の夜間モード (通常は端末の表示モード。アプリが画面の構成を上書きしたときはその値) で変わること。画面の構成を変えずに Material の配色だけでダークにするアプリは色を指定すること
  - `KsImage` の `loading`・`failure`: 省略したときの既定の表示の色が、同じ判定で変わること。画面の構成を変えずに Material の配色だけでダークにするアプリは表示を差し替えること
  - `touchFeedbackColor`: 渡した色の色みだけが使われ、濃さは標準の波紋が決めること (渡した色の不透明度は濃さに効かない)。iOS は渡した色をそのまま塗ること。両プラットフォームで近い見え方にするには半透明の色を渡すこと (`core/ADR-0037`)
  (→ Requirement: 区切り線の色 (両プラットフォーム) / KsImage の既定の表示の色 / タップしたときの色の濃さの決まり方)
- [ ] 2.4 テスト (ライブラリのテストに足す。描いた結果の色を見るテストには `@GraphicsMode(GraphicsMode.Mode.NATIVE)` を付ける — handbook/cross/test-execution。ダークは既存のスクロールインジケータのテストと同じく、端末の表示モードを夜間にして確かめる):
  - 既定の色 4 つのライト / ダークの値が、色の表の値と一致する。区切り線のライト用は変更前の値と同じ (→ Scenario: 両プラットフォームで同じ値 — collection-layout / image-loading)
  - 色を指定していない一覧の区切り線が、ライトではライト用、ダークではダーク用の値で描かれる。位置と本数は同じ (→ Scenario: ライトの既定の色 / ダークの既定の色)
  - 一覧を出したまま表示モードを切り替えると (画面を作り直さずに、一覧に届く画面の構成だけを差し替える)、区切り線の色が追随する (→ Scenario: 表示中に表示モードが切り替わる)
  - 端末の表示モードがダークなら、Material のテーマを置かない場合も、ライトの配色のテーマを置いた場合も、区切り線がダーク用の値で描かれる (→ Scenario: 画面の構成の夜間モードで決まる (Android))
  - 端末の表示モードがライトのまま、一覧に届く画面の構成の夜間モードだけをダークに上書きすると、区切り線がダーク用の値で描かれる (→ Scenario: アプリが画面の構成を上書きした場合 (Android))
  - 画面の構成はライトのまま、ダークの配色の Material のテーマだけを置くと、区切り線がライト用の値で描かれる (→ Scenario: Material の配色だけをダークにした場合 (Android))
  - 外観で値の変わらない色を指定した一覧は、ライト / ダークのどちらでも指定した色のままで、指定を外すとその表示モードの側の既定の色になる (→ Scenario: 固定の色を指定すると表示モードで変わらない / 指定を外すと表示モードの側の既定の色になる)
  - 画像の既定の読み込み中・失敗 (下地と印) が、ライト / ダークそれぞれの値で描かれる (→ Scenario: ライトの読み込み中 / ダークの読み込み中 / ライトとダークの失敗)
  - 先読みの完了を待つ間、画面に出た最初の描画から、既定の読み込み中がダークではダーク用の値で描かれる (既存の最初の描画のテストの、ダークの場合) (→ Scenario: 先読みの完了を待つ間の読み込み中)
  - 既定の読み込み中・失敗を出したまま表示モードを切り替えると、描かれる色が追随し、表示の状態は変わらない (→ Scenario: 表示中に表示モードが切り替わる)
  - 取得を待たせて既定の読み込み中を出したまま表示モードを切り替えると、取得の要求の数と取り消しの数が増えず、取得を終わらせるとその結果の画像が出る。読み込みを始めてから出た場合と、先読みの完了を待つ間に出た場合の両方で確かめる (→ Scenario: 取得の途中で表示モードが切り替わる)
  - 端末の表示モードがライトのまま、`KsImage` に届く画面の構成の夜間モードだけをダークに上書きすると、既定の読み込み中がダーク用の値で描かれる (→ Scenario: 上書きした表示モードで決まる)
  - 読み込み中・失敗を差し替えた `KsImage` は、ライト / ダークのどちらでも利用者の表示のまま出る。一覧の外に置いた `KsImage` も、ダークで既定の表示がダーク用の値になる (→ Scenario: 差し替えた表示は変わらない / 一覧の外に置いた KsImage)
  - 既存のテストのうち既定の色の定数と比べているもの (区切り線・画像の読み込み中) を、表示モードを明示した値と比べる形に直す。既存の Scenario (色の指定 / 非表示との組み合わせ) を確かめている既存のテストは、そのまま通る (→ Requirement: 区切り線の色 (両プラットフォーム) / KsImage の既定の表示の色 / Scenario: 色の指定 / 非表示との組み合わせ)

## 3. Sample

## 4. 確認
