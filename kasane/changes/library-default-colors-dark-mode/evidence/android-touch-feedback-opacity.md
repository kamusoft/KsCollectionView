# Android のタップの色: 不透明度が違う同じ色みを渡したときの濃さ (2026-10-06)

tasks 4.2 の証跡。`specs/collection-interaction/spec.md` の Scenario「不透明度が違う同じ色みを指定する (Android)」を、最終のコードで画素から確かめた。自動テストでは波紋が描かれないため、エミュレータの画面を撮って比べている。手順は提案の段階の実測 (`proposal-probes.md` の 2) と同じで、違いは下の「提案の段階の実測との違い」に書いた。

## 環境と条件

- エミュレータ: Android 16 (API 36)、1080×2400。作業専用に新しく作り、終わってから削除した
- ビルド: この change の作業ツリーのライブラリと Sample (debug)
- 画面: Sample のデモ画面「リスト」、区切り線「既定」。表示モードはライトとダークの両方
- ケース A (不透明): タップしたときの色に、不透明なアクセント色を渡す。比べるために `samples/android/app/src/main/kotlin/jp/kamusoft/kscollectionview/samples/android/ListDemoScreen.kt` の該当の 1 行だけを一時的に書き換えてビルドし、撮り終えてから最終の形に戻した
- ケース B (半透明): アクセント色の 10% を渡す (最終の Sample のまま)
- 操作: 3 行目 (Cherry) を 6 秒押し続け、押し始めのおよそ 1 秒後から 5 秒後までの間に、間をあけて 4 回撮った (4 回とも押している間)。押す前と、離して約 2 秒後も撮った。ライト / ダーク × A / B を 2 回ずつ
- 測り方: 押している行の、文字や線が無い下地の画素を、押す前の同じ位置の画素と比べ、重なっている色の不透明度を逆算した。A と B は、押している行の全画素 (1080×182 = 196,560 個。区切り線は含めない) を突き合わせた

撮る間隔は端末の中の待ち時間 (1.0・0.4・1.2・1.2 秒) に 1 回の撮影に掛かる時間が足されて決まるので、押し始めからの正確な秒数は分からない。

## 結果

4 つの時点のどれでも、A の 2 回と B の 2 回の計 4 枚で、押している行の全画素が一致した (ライト・ダークとも)。

| 表示モード | 測った位置 | 押す前 | 押している間 (A・B とも同じ) | 重なっている色の不透明度 (赤 / 緑 / 青の成分から逆算) |
|---|---|---|---|---|
| ライト | 行の中央 | `#FFFFFF` | `#EDF3FD` | 約 8.7% / 約 8.3% / 約 11% |
| ライト | 行の左端の近く | `#FFFFFF` | `#F0F5FE` | 約 7.2% / 約 6.9% / 約 5.6% |
| ライト | 隣の行 (対照) | `#FFFFFF` | `#FFFFFF` | 0% |
| ダーク | 行の中央 | `#182236` | `#1E2B46` | 約 9.0% / 約 8.4% / 約 8.3% |
| ダーク | 行の左端の近く | `#182236` | `#1D2A44` | 約 7.5% / 約 7.5% / 約 7.3% |
| ダーク | 隣の行 (対照) | `#182236` | `#182236` | 0% |

ライトの青の成分は、下地との差が小さく (255 と 237)、1 段の丸めで値が大きく動くため、目安にしかならない。

- 見た目が変わるのは押した行だけで、離して約 2 秒後は、ステータスバーを除く画面の全画素が押す前と一致した (8 回とも)
- 押している間も、行の文字 (項目の名前と ID) はそのまま読める (`ui/verification/android-list-pressed-light.png`・`ui/verification/android-list-pressed-dark.png`。どちらもケース B)

## 分かったこと

- 不透明なアクセント色を渡しても、アクセント色の 10% を渡しても、押している間の濃さは同じである。渡した色の不透明度は濃さに効かず、色みだけが使われる
- 濃さは、行の中央で約 8〜9%、端で約 7% である。提案の段階の実測 (ライト、15% を渡した場合) と同じ値で、ダークでも同じ程度だった

## 提案の段階の実測との違い

- 半透明の側は 15% ではなく、最終の Sample が渡す 10% で測った
- ダークも測った (提案の段階ではライトだけ)
- 押した直後 (0.3 秒) は撮っていない。いちばん早い時点が約 1 秒後である
- Sample の写しをリポジトリの外に作る代わりに、作業ツリーの 1 行を一時的に書き換えた (撮影の後に戻し、戻した後のビルドを入れ直した)

## 測っていない条件

API 29・30、実機、押してすぐ離す短いタップ、10% と不透明以外の不透明度。撮った画像と生の結果はリポジトリに残していない (押している間の見え方は `ui/verification/` の 2 枚で見られる)。
