# UI Brief: paging-state-machine

## 画面と状態

UI に触れるのは 3 点。ライブラリ本体のページングの表示 (既定の見え方と置き場)、Pull to Refresh のインジケータの位置、Sample のデモ画面「ページング」(sample-parity 準拠)。挙動の正はデルタスペック (どの状態で何を出すか)、見た目の正は承認 mock とこの brief。

### ページングの表示 (ライブラリ本体)

本体の既定の見た目は「読み込み中」の 2 つだけで、各プラットフォームの標準の読み込み中の表示 (iOS は SwiftUI の `ProgressView` の既定の円形、Android は material3 の `CircularProgressIndicator` の不定の既定) をそのまま使う。文言・色・大きさはライブラリで決めず、各プラットフォームの既定に任せる (色は iOS がシステムの既定、Android が `MaterialTheme` の色)。失敗・終端・空は既定で何も出さない (見た目は利用者が決める)。

- **項目があるとき** (次のページの読み込み中 / 失敗 / 終端): 最後の項目のすぐ下、ルートのフッターの上に、一覧の全幅で置く。中身は横方向の中央に揃える。既定の読み込み中の上下には、読み込み中の表示が項目やフッターに接して見えない程度の余白を置く (値は実装で決め、mock の見え方に合わせる)。行間 (rowSpacing) は最後の項目との間に入れない (ルートのフッターと同じ扱い)。list の区切り線は最後の行の下端までで、この表示の周りには引かない
- **項目が 0 件のとき** (最初の読み込み中 / 失敗 / 空): 項目の代わりに、一覧の見えている範囲の真ん中に 1 つ置く。真ん中は上下の安全領域 (バー・ステータスバー・ホームインジケータの分) を除いた範囲で求める。ルートのヘッダー / フッターは 0 件でもそのまま表示し、0 件の表示はそれを避けない。重なったら 0 件の表示が手前に来て、その中の「再試行」は押せる。0 件の表示の外のタッチ (ヘッダー / フッター・引っ張り) は下へ通す
- 状態が変わって表示が出る / 消えるとき、フッターの枠の高さが変わる。表示範囲が跳ねないこと (見ていた項目が動かないこと) を目視で確かめる

### Pull to Refresh のインジケータ

各プラットフォームの標準の引っ張りの部品とインジケータ (iOS は `UIRefreshControl`、Android は material3 の `PullToRefreshDefaults.Indicator`) を使い、見た目は既定のまま。行を上端のバーの裏に流す全画面の一覧 (core/ADR-0017) でも、インジケータはナビゲーションバー・ステータスバーの下端より下に出す (裏に隠さない)。

### Sample「ページング」

- **ルートメニュー**: 既存のデモ画面の末尾 (「差分更新」の次) に「ページング」を追加。両プラットフォームで同じ位置
- **ページング**: 偽の取得元から 1 ページ 50 件ずつ読み込む一覧 (全 10,000 件)。行は「リスト」画面と同じ見た目 (タイトル「Item n」)、グリッドは 2 列で「差分更新」のグリッドと同じセルの見た目
  - 操作のパネル: 「リスト / グリッド」のセグメント、「次の読み込みを失敗させる」「中身を 0 件にする」の 2 つのスイッチ、全幅の「再読み込み」、説明の一行 (通常は「全 10,000 件・1 ページ 50 件」) を、背景が透けるパネルにまとめて画面の下寄りに浮かせる。パネルの外周は画面の端 (左右・下) から余白を取る。一覧は画面の下まで続き、パネル越しに透けて見える
  - 畳む: パネル左上の「‹」で、画面左端 (余白を取った位置) の丸いボタン「›」だけに畳む。丸いボタンで広げる
  - 一覧の下の余白 (`contentPadding` の下) に、パネル (畳んだときは丸いボタン) の高さと余白の分を入れ、末尾までスクロールしたときに最後の項目とページングの表示がパネルの上に出るようにする。畳む / 広げるで余白も変える
  - 状態: 最初の読み込み中 (0 件、既定の読み込み中) / 通常 / 次のページの読み込み中 (既定の読み込み中) / 次のページの失敗 (「読み込めませんでした」+「再試行」) / 終端 (「これ以上ありません」) / 0 件の失敗 (「読み込めませんでした」+「再試行」) / 空 (「項目がありません」) / 項目があるときの取り直しの失敗 (パネルの説明の一行が「更新できませんでした」に変わる) / パネルを畳んだところ
  - 失敗・終端・空の表示は Sample が差し替えて出す。文言はテキスト副の色、「再試行」はアクセント色の文字のボタン。0 件の表示は一覧の真ん中、項目があるときの表示は最後の項目の下
  - Pull to Refresh を付ける (インジケータは既定)
  - mock: `mock/paging-variant-c-floating-panel.html` (6 つの状態を並べた。案 A `mock/paging-variant-a-nav-menu.html` と案 B `mock/paging-variant-b-bottom-bar.html` に対するオーナーの指示で作った案)

### 許容する差異 (sample-parity)

- OS 標準 chrome: `NavigationStack` ⇔ `Scaffold` + `TopAppBar`、セグメント・スイッチ・ボタン・メニューの形状
- 既定の読み込み中の表示と Pull to Refresh のインジケータの見た目 (各プラットフォームの標準の部品。形・色・大きさ・動き)
- 「更新できませんでした」の知らせの出し方は両プラットフォームで同じ場所・同じ文言にする (OS のトースト / スナックバーは使わない)
- 操作のパネルの透け方は両プラットフォームで同じ半透明の色で作り、ぼかし (iOS の material 等) は使わない (Android の対応 OS でぼかしを揃えられないため)

## デザイントークン参照

concepts/ に UI トークンは未登録。Sample は `SampleTheme` (iOS `SampleTheme.swift` を正、Android `object SampleTheme` が同値。ライト / ダーク 2 組、cross/ADR-0007) の既存トークン (accent / 背景 / セル背景 / テキスト主・副 / 区切り線色 / 横の余白 / 行の縦の余白) を使う。失敗・終端・空の表示と「更新できませんでした」はテキスト副、「再試行」はアクセント。操作のパネルの背景はセル背景のトークンに不透明度を掛けた色 (mock では 72%)、枠は区切り線色。新しいトークンは足さない。表示の上下の余白・パネルの余白と不透明度・丸いボタンの大きさなど、この画面だけの値は画面固有の定義に置く。

## 承認モック

案 C を採用 (`mock/paging-variant-c-floating-panel.html`、6 つの状態を並べて撮った `mock/approved.png`。2026-09-27 オーナー承認)。はじめに出した案 A (ナビゲーションバーの「操作」メニュー) と案 B (下部バー) に対し、オーナーが「操作 UI は背景が透けるフローティング配置にし、外周に余白を設けて画面の端に付けない。畳めるとなお良く、畳むのは画面左端に」と指示し、画面の上や下の様子が操作に遮られず常に見えることを理由に作り直した。

- 操作のパネル: セグメント (リスト / グリッド) と、その左の「‹」(畳む)、2 つのスイッチ、全幅の「再読み込み」、説明の一行 (通常は「全 10,000 件・1 ページ 50 件」、取り直しの失敗時は太字の「更新できませんでした」)。背景はセル背景の 72%、枠は区切り線色、角丸、外周は左右・下の端から余白
- 畳んだとき: 左端 (余白を取った位置) の丸いボタン「›」だけが残る
- 一覧はパネルの裏まで続いて透けて見え、下の余白にパネル (畳んだときは丸いボタン) の分を入れて、末尾の表示 (読み込み中・失敗と「再試行」) がパネルの上に出る
- ライブラリの既定の読み込み中は、最後の項目のすぐ下 (②) と 0 件の真ん中 (①) に文言なしで出る。0 件の表示は見えている範囲の真ん中で、パネルは避けない (パネルは Sample の重ね置きで、ライブラリは知らない)

トークンは SampleTheme と同値 (ライトの組: accent #2F6FED / bg #F2F2F7 / cell #FFFFFF / text #111214 / text2 #6E7076 / separator #D9D9DE)。ダークの組はパネルの背景も含めて SampleTheme のダークの組の同じ名前の値を使う (cross/ADR-0007)。パネルの余白・不透明度・丸いボタンの大きさは画面固有の定義に置く。
