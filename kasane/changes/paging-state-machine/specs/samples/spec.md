# samples (ページング) — デルタスペック

## ADDED Requirements

### Requirement: デモ画面「ページング」
両プラットフォームの Sample は、「差分更新」の次に「ページング」を同じ位置・同じ文言で持つ (SHALL — handbook/cross/sample-parity)。画面は偽の取得元から 1 ページずつ読み込む一覧を、ページング・Pull to Refresh を付けて表示する (SHALL)。偽の取得元は全 10,000 件 (「Item 1」〜「Item 10000」、ID は整数) を 1 ページ 50 件で返し、取得には既定 1 秒の遅延を置く (SHALL)。返す内容は両プラットフォームで同じ並びになる (SHALL)。list と 2 列のグリッドを切り替えられる (SHALL)。

#### Scenario: 両プラットフォームで同じ構成
- **GIVEN** 両プラットフォームの Sample
- **WHEN** ルートメニューから「ページング」を開く
- **THEN** メニュー上の位置・画面の文言・読み込まれる項目の並びが同じである

#### Scenario: 開いたら最初のページを読み込む
- **GIVEN** 「ページング」画面を開いた直後 (項目 0 件)
- **WHEN** 何も操作しない
- **THEN** 最初の読み込み中の表示が出たあと、Item 1〜Item 50 が表示される

#### Scenario: スクロールで続きを読み込む
- **GIVEN** 1 ページ目を表示している
- **WHEN** 末尾に向けてスクロールする
- **THEN** 末尾の手前で次のページの読み込みが始まり、Item 51 以降が続く

#### Scenario: 最後まで読むと終端の表示が出る
- **GIVEN** 取得の遅延を縮めて起動した「ページング」画面
- **WHEN** Item 10000 まで読み進める
- **THEN** 「これ以上ありません」が最後の項目の後ろに出て、それ以上は読み込まない

### Requirement: 失敗と空の実演
画面は「次の読み込みを失敗させる」と「中身を 0 件にする」の 2 つの切り替えを持つ (SHALL)。「次の読み込みを失敗させる」がオンの間、偽の取得元はすべての取得を失敗させる (SHALL)。「中身を 0 件にする」がオンの間、偽の取得元は最初のページを 0 件・続き無しで返す (SHALL)。「中身を 0 件にする」を変えたら、画面はその場で再読み込みする (SHALL)。「次の読み込みを失敗させる」は次の取得から効き、切り替えただけでは再読み込みしない (SHALL)。失敗の表示 (項目があるとき / 0 件のとき) は「読み込めませんでした」と「再試行」、終端の表示は「これ以上ありません」、空の表示は「項目がありません」を、両プラットフォームで同じ文言で設定する (SHALL)。VM は失敗の状態からの再試行を受け付ける (SHALL)。

#### Scenario: 次のページの失敗と再試行
- **GIVEN** 1 ページ目を表示し、「次の読み込みを失敗させる」をオンにした後、末尾に向けてスクロールした
- **WHEN** 次のページの読み込みが失敗する
- **THEN** 最後の項目の後ろに「読み込めませんでした」と「再試行」が出て、切り替えをオフにして「再試行」を押すと次のページが読み込まれる

#### Scenario: 最初の読み込みの失敗
- **GIVEN** 「中身を 0 件にする」で 0 件にしたあと、「次の読み込みを失敗させる」をオンにした状態
- **WHEN** 「再読み込み」を行う
- **THEN** 項目の代わりに「読み込めませんでした」と「再試行」が出る

#### Scenario: 0 件
- **GIVEN** 「ページング」画面
- **WHEN** 「中身を 0 件にする」をオンにする
- **THEN** 再読み込みの後、項目の代わりに「項目がありません」が出る

### Requirement: 取り直しの実演
画面は Pull to Refresh と、引っ張らずに VM が始める「再読み込み」の操作を持つ (SHALL)。どちらも 1 ページ目から取り直す (SHALL)。項目があるときに取り直しが失敗したら、VM は状態を取り直しの前に戻し、「更新できませんでした」を画面に出す (SHALL)。項目が 0 件のときに取り直しが失敗したら、状態を失敗にする (SHALL)。取り直しを始めたら、VM はそれより前に始めた読み込みの結果を捨てる (SHALL)。

#### Scenario: 途中から再読み込み
- **GIVEN** 何ページか読み進めて途中までスクロールした状態
- **WHEN** 「再読み込み」を行う
- **THEN** 取り直しの間は項目が並んだままで、取り直しが終わると Item 1 から表示される

#### Scenario: 追加読み込み中に再読み込み
- **GIVEN** 取得の遅延を長くして起動し、次のページの読み込み中の表示が出ている
- **WHEN** 「再読み込み」を行う
- **THEN** 取り直しが終わると Item 1〜Item 50 が表示され、先に始めた読み込みの結果 (Item 51 以降) が後から混ざることはない

#### Scenario: 項目があるときの取り直しの失敗
- **GIVEN** 項目が表示されていて、「次の読み込みを失敗させる」をオンにした状態
- **WHEN** Pull to Refresh で取り直す
- **THEN** 項目はそのまま残り、「更新できませんでした」が出て、失敗の表示は出ない

### Requirement: 操作を畳める
画面の操作 (リスト / グリッドの切り替え・2 つの切り替え・再読み込み・説明の一行) は、畳んで小さなボタンだけにでき、そのボタンで広げると元に戻る (SHALL)。操作を広げていても畳んでいても、末尾までスクロールすれば、最後の項目とページングの表示は操作に隠れずに見える (SHALL)。

#### Scenario: 畳んで広げる
- **GIVEN** 「ページング」画面で操作を広げている
- **WHEN** 操作を畳み、残ったボタンで広げる
- **THEN** 畳んでいる間は小さなボタンだけが残り、広げると切り替えの状態を保ったまま元の操作に戻る

#### Scenario: 末尾の表示が操作に隠れない
- **GIVEN** 次のページの失敗の表示が出ている
- **WHEN** 操作を広げたまま末尾までスクロールする
- **THEN** 「読み込めませんでした」と「再試行」が操作に隠れずに見え、「再試行」を押せる

### Requirement: 起動引数
各プラットフォームの起動の仕組み (iOS の起動引数 / Android の開始ルートと起動の追加値) で、「ページング」画面を直接開け、取得の遅延を変えられる (SHALL)。

#### Scenario: 遅延を縮めて開く
- **GIVEN** 「ページング」と遅延 0 ミリ秒を指定する起動
- **WHEN** アプリを起動する
- **THEN** 「ページング」画面が直接開き、取得が遅延なしで返る
