# Proposal: drag-reorder

## Why

ロードマップ v1-foundation のゴールに挙げた定型機能のうち、D&D 並べ替えはまだどちらのプラットフォームにも無い。Compose には Lazy 系の公式の並べ替え API が無く、SwiftUI の List の並べ替えは UICollectionView ベースの一覧には効かない (iOS 27 の SwiftUI 標準の並べ替えは最低 iOS 16 では使えない)。利用者は今、長押しの検出・持ち上げ・端での自動スクロール・移動先の計算・読み上げの代わりの操作を画面ごとに自分で書くしかなく、書き味も両プラットフォームでそろわない。これは cross/ADR-0001 が 2 プラットフォームライブラリを作る理由に挙げた穴 (Compose のリスト内 D&D) そのものである。

phase-6 の議論 (agenda の決定事項) で、並べ替えの契約と両プラットフォームの実装方式が確定した (core/ADR-0026〜0033・ios/ADR-0011・android/ADR-0007、いずれも proposed)。本提案はそれを実装可能な契約に落とす。

## What Changes

- **並べ替えのスイッチ**: 一覧に並べ替えの有効 / 無効のスイッチを渡す (既定は無効)。有効の間は、項目のどこでも長押しで持ち上げて並べ替えを始め、長押しの知らせは動かせない項目も含めて呼ばない。無効の間は長押しの知らせが今までどおり呼ばれる。タップの知らせはスイッチによらない。ハンドルは持たない (core/ADR-0031)
- **置いたときの知らせ**: 指を離したときに 1 回だけ、動かした項目と行き先 (この項目の前 / このグループの末尾。グループを宣言していれば行き先のグループの値を添える) を知らせる。項目はタップと同じく配列の要素そのもの。ドラッグ中の仮の並びはライブラリが持ち、利用者の配列は書き換えない (core/ADR-0026・0028)
- **受け入れと戻し方**: 知らせを受ける処理はその場で受け入れたか (真偽値) を返す。受け入れなければすぐアニメーションで元の並びに戻し、受け入れたなら置いた並びのまま VM の配列を待つ (時間で戻さない)。保存の失敗は VM が元の並びの配列を渡し直して表す (core/ADR-0027)
- **グループをまたぐ移動**: 見出しをまたいで別のグループへ動かせる。確定には VM が項目のグループの値を書き換えた配列を渡す。空のグループへは移せない。境目に置いたときは見出し (見出しが無ければグループの間の間隔) より上なら前のグループの末尾、下なら次のグループの先頭。最後の 1 件を持ち出してもドラッグ中は元のグループの見出しを残す (core/ADR-0029、agenda の導出)
- **業務ルールの判定**: 任意の「動かせるか」(項目ごと) と「ここに置けるか」(ドラッグ中に行き先ごと。行き先は知らせと同じ形) を渡せる。動かせない項目は持ち上がらず、置けない場所には入らない (core/ADR-0030)
- **list / グリッド**: 両方で同じに効く。layout を差し替えても並べ替えは消えない (agenda の導出)
- **端での自動スクロール**: 両プラットフォームで付ける。速さと反応する範囲は各 OS の自然な形に任せ、公開の設定は持たない (agenda の導出。「自然な形」は推測なので実機で確かめる)
- **読み上げの移動操作**: スイッチが有効の間、動かせる項目に「前へ移動 / 後ろへ移動」の読み上げ用の操作を出す。操作の文言は利用者が渡し、渡さなければ出さない。ドラッグと同じ知らせ・判定・受け入れを通る (core/ADR-0032)
- **ドラッグ中に届いた配列**: 反映を保留して最新の 1 つを持ち、受け入れたら捨てて受け入れた後の配列に従い、受け入れなければ保留した最新の配列へ戻す (core/ADR-0033)
- **ドラッグ中のページングとスイッチ** (提案で決めた細部): ドラッグ中は追加読み込みを頼まず、指を離してから判定し直す (保留した配列と、頼んだ後に配列か状態が変わるまで待つ仕組み — core/ADR-0022 — が噛み合わず、次のページを連鎖して頼むのを防ぐ。core/ADR-0034、amends core/ADR-0020。提案の自己レビューで ADR-0020 との衝突を検出し、オーナー判断で改訂)。ドラッグ中に受けたスクロール命令は、ドラッグが終わって配列を当てた後に順に実行する。ドラッグ中にスイッチが無効になったら、ドラッグを取りやめて元の並びに戻し、知らせない
- **実装方式**: iOS は UIKit 標準のドラッグ & ドロップの delegate で作り、差分データソースの並べ替えハンドラは使わない (ios/ADR-0011)。Android は Compose の公開 API の上に自前で作り、OSS には依存も取り込みもしない (android/ADR-0007)
- **Sample デモ画面「並べ替え」**: 両プラットフォームに sample-parity 準拠で「ページング」の次に追加する。全 10,000 件を 100 件ずつのグループに分けた一覧で、10 の倍数の項目は動かせない項目として示す。操作は背景が透けるフローティングのパネルに置く (handbook/cross/sample-debug-controls): 並べ替えのスイッチ、list / 2 列グリッドの切り替え、グループの有無、「グループをまたがせない」(置けるかの判定の実演)、「置いても受け入れない」(受け入れと戻り方の実演)。スイッチが無効の間の長押しは画面上の帯で知らせる。読み上げの文言を渡す。見え方は承認 mock に従う
- **検証**: Scenario ごとの自動テスト (両プラットフォームのライブラリと Sample)。「並べ替え」画面で、スイッチを有効にした状態の基準機の体感ゲート (cross/ADR-0006) を両プラットフォームで 1 回。持ち上げ・自動スクロール・戻り・固定の見出しとの重なりの見え方は、オーナーの目で確かめる

影響する能力: collection-reorder (新規: スイッチ・知らせ・受け入れ・行き先・判定・グループをまたぐ移動・保留・自動スクロール・読み上げ) / collection-interaction (長押しの知らせ — 並べ替えが有効の間は呼ばない) / samples (検証装置)

- 蒸留時に反映: decisions — core/ADR-0026〜0034・ios/ADR-0011・android/ADR-0007 を実装の形で確かめて accepted に昇格する (0034 の昇格で core/ADR-0020 に `amended-by` を追記)
- 蒸留時に反映: concepts — core/core-model に並べ替えの概念 (公開 API・保証・VM が守る書き方) を新規、collection-interaction の長押しの項 (並べ替えが有効の間は呼ばない)、collection-items の責務境界、ios / android の architecture に並べ替えの部品の責務境界を追記

## Non-Goals

- ハンドル (テンプレートの部品をつかんですぐ動かす) — core/ADR-0031 で持たないと決めた。後から足しても今の書き方を壊さない
- 空のグループへの移動 — 空のグループは表示できない (core/ADR-0015)。グループの宣言を改めるときに併せて見直す (core/ADR-0029)
- グループそのもの (見出しごと) の並べ替え — 議論の対象外で、グループの順は項目の並びから決まる (core/ADR-0015)。見出しのドラッグという別の操作の設計が要る
- 複数の項目をまとめて動かす — 知らせは 1 項目の移動で表す (core/ADR-0028)。まとめて動かす知らせの形は別の設計が要る
- 一覧の外 (別の一覧・別のアプリ) へのドラッグ & ドロップ — 並べ替えは一覧の中の移動に限る (core/ADR-0026)。iPad ではアプリの外への持ち出しを止める
- ソート中の扱いの契約 — ライブラリはソートを知らない (phase-6 agenda の決定。phase-1 の既決)。ソート中はスイッチを無効にする / 知らせを受けて手動の並びへ切り替える、の 2 つの書き方はガイドに載せる
- 端での自動スクロールの速さ・範囲の公開の設定 — 各 OS の自然な形に任せる (agenda の導出)
- 利用者向けガイド (Skill) への記載 — skills/ はまだ無く、配布・ドキュメントのフェーズ (phase-7) が制作する。記載する約束ごと (受け入れたら配列を並べ替えて渡す / 保存の失敗は元の並びの配列を渡し直す / 置けるかは軽い同期の判定 / 読み上げの文言を渡す / グループをまたぐときはグループの値を書き換える / ソート中の 2 つの書き方) は蒸留時に phase-7 へ申し送る
- Android の相対計測 (素の Lazy グリッドとの比較) — 並べ替えは既定では無効で、有効にした一覧だけで動く。性能は「並べ替え」画面の体感で確かめる

## Impact

- 公開 API 追加 (両プラットフォーム): 並べ替えのスイッチ、知らせを受ける処理 (真偽値を返す)、知らせの型 (動かした項目・行き先・グループの値)、「動かせるか」「ここに置けるか」の判定、読み上げの文言。破壊的変更なし
- 既存の振る舞いの変更: 並べ替えを有効にした一覧だけ、長押しの知らせが呼ばれなくなり、ドラッグ中は追加読み込みの判定が止まる (accepted の core/ADR-0020 を core/ADR-0034 で一部置き換える)。スイッチは既定で無効なので、並べ替えを使わない一覧は変わらない
- iOS: コレクションビューにドラッグ & ドロップの delegate を付け、スイッチで長押しの認識器と切り替える。ドラッグ中は配列の適用を待たせる。ドロップ位置 (内部の塊と番号) を項目の行き先に読み替える層が要る
- Android: 長押しの検出・持ち上げ・端での自動スクロール・先頭の項目を動かしたときの位置飛びの回避を自前で作る。項目の修飾 (長押し・`animateItem`・高さの補間) との組み合わせを組み直す
- リスク: 自前の見出しの固定 (iOS のレイアウトの位置の上書き・Android の stickyHeader) とドラッグ中の隙間・持ち上げた項目の重なり順が干渉しないかは未確認。実装の最初に確かめる
- リスク: Android の自前実装の難所 (自動スクロールとドラッグ位置の補正、先頭の可視項目の位置飛び、高さの補間中の配置のアニメーションとの組み合わせ)
- リスク: iOS の UIKit のドラッグ & ドロップが、10,000 件・内部の塊をまたぐ移動で標準どおりに動くか
