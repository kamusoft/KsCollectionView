## 2. iOS: 推定高さと計測の足場
- [ ] 2.1 `KsEstimatedHeight` をセル単位の実測をピクセル格子に量子化して数える最頻値 (同数なら新しい方、繰り返しが無ければ平均、幅が変われば捨てる) にする (→ Requirement: 推定高さと一致するセルの自己サイズ (iOS))
- [ ] 2.2 `KsEstimatedHeight` の単体テストを更新・追加する (同数・繰り返し無し・幅の変化・量子化) (→ Scenario: 微小な測定差は同じ高さとして数える)
- [ ] 2.3 Debug 構成の診断カウンタ (自己サイズを返したセル数・推定と不一致だった回数) を `KsCollectionViewController` に足し、Sample の計測 launch 経路から読めるようにする。エンジンテストで高さ 2 種類 (6 : 1) の 2,000 件を可視化したとき不一致率が 0.20 以下であること、2 列で片方だけ高い配列の行高が高い方に揃うことを確かめる (→ Scenario: 多数派のセルは再解決を起こさない / 複数列で行内に高いセルが 1 つある)
- [ ] 2.4 エンジンテストで、初回表示のコンテンツ高さの誤差が ±5% 以内、末尾までの contentSize 変化回数が 3 回以下であることを最頻値で再検証する (→ Scenario: 合計高さの見積もりを損ねない)
- [ ] 2.5 Sample に起動引数 `--large-count <N>` を足す (既定 10,000、生成規則は同じ、正の整数以外は起動失敗、画面に件数を表示)。UI テストで不正値の起動失敗を確かめる (→ Requirement: 計測専用の件数指定 (iOS) / Scenario: 不正な件数)
- [ ] 2.6 `PerformanceDriverUITests` の自動フリック 2 本と `ScrollWindowSignpost` / `--signpost-scroll-window` を削除し、メモリの自動往復を残す。計測スキームの除外設定を整合させる (→ Requirement: iOS の計測ドライバの構成)
- [ ] 2.7 エンジンテストで、配列の置換後の同時生存が可視の 4 倍未満に戻ること、強参照を手放した後にエンジンへの弱参照が nil になることを確かめる (→ Scenario: 配列の置換で不要な保持が解放される / コレクションの破棄で全て解放される)
