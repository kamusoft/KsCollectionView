# 画像グリッド (iOS) の手動フリック計測 — 2026-09-08

探索中 (論点 6) の追加計測。文字だけの「大量件数」(`manual-largeData-ios-2026-09-08.md`) との対照で、estimated 高さの solver 仮説を確かめる目的。

## 環境

| 項目 | 値 |
|---|---|
| 機種 / OS | iPhone 11 (基準機) / iOS 18.7.8 |
| 構成 | Release、削除してから入れ直し (画像キャッシュは空。cold) |
| fixture | Sample「画像グリッド」(10,000 件・3 列・正方形セル、リモート画像)。起動引数 `--screen 画像グリッド` で直接開く |
| 駆動 | オーナーの手動フリック (自動化なし)。記録の開始は接続成立を確認してから合図した |
| 記録 | Instruments Animation Hitches をプロセス名指定で接続。記録窓 75 秒 (trace の区間長) |
| 熱状態 | 全区間 Nominal (Instruments の thermal state。全区間の観測値) |

接続の注意: `xctrace record --attach` はプロセス名指定でも「端末の起動待ちでタイムアウト」で落ちることが 2 回あった (端末の認識がオンライン / オフラインで揺れる)。「Starting recording」が出るまで再試行し、出てから合図する手順にした。失敗した試行でオーナーが操作した分は cold に戻すため入れ直した。

## 操作条件

| 項目 | 値 |
|---|---|
| 操作列 | **固定の操作列の制定前**の記録。初回の下向きフリック → 再訪 → 連続フリックを自由な順で反復した (段階ごとの所要は未記録) |
| 開始位置 / 到達範囲 | 先頭から開始。到達した件数は未記録 |
| 文字サイズ / キャッシュ状態 | 端末の既定 (値は未記録) / 削除してから入れ直した直後 (画像キャッシュは空、cold) |

操作列が固定される前の記録であるため、固定の操作列で採る以後の記録とは**比較不能**。

## オーナーの体感 (合否の主語。数値を見る前に聞き取り)

- 文字だけの画面と違って常にスムーズ。初回と再訪で差はない
- 連続スクロールも問題なし
- 画像の出方 (別の観測点): 一度読み込んだ画像はすぐに表示される

## 主スレッドの帰属 (time profile、inclusive、主スレッド標本比)

| 経路 | 比率 |
|---|---|
| `CA::Transaction::commit` | 75% |
| セルの生成 `_createPreparedCellForItemAtIndexPath:` | 44% |
| hosting の描画 `ViewRendererHost.render` / `_UIHostingView.layoutSubviews` | 30% |
| hosting の計測 `ViewRendererHost.sizeThatFits` | 20% |
| **`_UICollectionLayoutSectionEstimatedSolver`** | **0% (全 75 秒で 0 標本)** |

集中区間 (20〜26 秒) は主スレッド 82〜88%、セル生成 54〜56%、hosting 計測 25%。最も速く連続フリックした時間帯で、新しいセルの生成 (再利用ごとの hosting の作り直し、ios/ADR-0002) が追いつかなかったと見る。

## 判定

- **体感の合否: 合格**。数値も集中区間を除けば参考スケールの Good 圏で、体感と矛盾しない
- **前回との比較可否**: 同 fixture の過去記録が無く、操作列も固定前のため比較不能
- **solver 仮説の対照として決定的**: 画像グリッドはセルが全て同じ高さ (正方形) で、推定値 (直近の実測平均) と実測が一致するため solver が一度も走らない。文字グリッドは行の高さが 2 種類 (detail の有無) で全体平均がどちらとも一致せず、新しく可視になる全セルが solver を起こす。対策 B (推定値と実測を一致させて invalidation を消す) の効果はこの差が示す上限に近い
- 残る費用はセル生成と hosting で、これは estimated とは無関係。速い連続フリックでの 2 フレーム落ちの原因はこちら

## 限界

- 手動操作なので操作量は記録間で揃わない (cross/ADR-0006)。記録は 1 回
- 画像はリモート取得で、ネットワーク状態は記録していない。集中区間が画像の到着と重なった可能性は trace からは切り分けていない
- 生の trace は退避先 (スクラッチ) にのみ置く
