# 大量件数 (Android) の手動フリック — 2026-09-24

スクロールインジケータ (スクロール中に毎フレーム描くバー) を足した後の体感ゲート ([handbook/cross/scroll-performance-gate.md](../../../handbook/cross/scroll-performance-gate.md))。iOS は変更していないため対の記録は無い。

## 環境

| 項目 | 値 |
|---|---|
| 機種 | Pixel 4a (基準機) |
| OS / API level | Android 13 / API 33 |
| 表示 | 60 Hz |
| 構成 | benchmark ビルド種別 (release と同じ最適化 + profileable)。インジケータを含む作業ツリーから `:app:installBenchmark` |
| fixture | Sample「大量件数」(10,000 件・2 列・固定高と 7 件ごとの長文の混在)。Intent の追加情報 `ks_start_route=demo/LargeData` で直接開く |
| 駆動 | オーナーの手動フリック (自動化なし) |
| 記録 | `dumpsys gfxinfo <package> reset` → 合図 → 操作列 → `dumpsys gfxinfo <package> framestats`。記録窓の実長 40.2 秒 (reset から取得までの時刻差)。Perfetto は取得していない |
| 熱状態 | thermalservice の Thermal Status が記録の前後とも 0 |

## 操作条件

| 項目 | 値 |
|---|---|
| 操作列 | 固定の操作列 (初回: 下へ 10 秒 → 休止 3 秒 → 再訪: 上へ 5 秒 → 連続: 下へ 10 秒) |
| 開始位置 / 方向 | 先頭から下向きに開始 |
| 段階ごとの所要 | 操作列どおり (オーナー申告。秒単位の実測は無い) |
| 到達範囲 | 未記録 |
| 文字サイズ | font_scale 1.0 |
| キャッシュ状態 | 上書きインストール (削除して入れ直していない)。起動直後に強制停止してから画面を開いた |

## オーナーの体感 (合否の主語。数値を見る前に聞き取り)

- 初回・再訪・連続のすべてでスムーズ。問題は感じられなかった (ムラの申告なし)

## 数値 (証跡。合否ではない。取得源は `dumpsys gfxinfo` = HWUI の描画フレーム)

| 指標 (取得源・単位) | 値 |
|---|---|
| 描画フレーム数 (gfxinfo、40.2 秒の窓) | 1,025 |
| janky frames (gfxinfo) | 1 (0.10%) |
| フレーム時間 = 描画 1 フレームの所要時間 P50 / P90 / P95 / P99 (gfxinfo、ms) | 9 / 12 / 13 / 16 |
| 期限超過 (Frame deadline missed) | 1 |
| ヒストグラムの山 | 8〜9 ms に集中 (8 ms = 250、9 ms = 281)、最大 25 ms が 1 件 |
| Missed Vsync / Slow UI thread / Slow issue draw | 0 / 0 / 1 |
| GPU ヒストグラム | 5 ms に集中 (956 / 1,025) |

## 判定

- **体感の合否: 合格**
- 数値 (janky 0.10%・期限超過 1 件・P99 16 ms) は体感と一致する
- **前回との比較可否: 比較不能**。前回の記録 ([2026-09-08](../../archive/2026-09-17-performance-criteria-review/evidence/manual-largeData-android-2026-09-08.md)) は固定の操作列の制定前で、OS 版も未記録のため
- 描画フレーム数 1,025 は窓の 40.2 秒に対して疎だが、窓には合図の往復 (約 12 秒) と休止 3 秒が含まれ、描画は操作中にだけ起きるため、それ自体は異常を示さない

## 同じ回の目視 (記録なし)

体感ゲートの後、同じ基準機で「大量件数」と「テンプレート切り替え」をオーナーが目視した。

| 確認項目 | オーナーの判断 |
|---|---|
| バーの出方・消え方 (ドラッグで即座に出て、止まって約 1 秒後にフェードで消える) | 問題なし |
| 高さの混ざる画面での長さの揺れ・一瞬の逆戻り (exploration 論点 3) | 気にならない → 公式の値のままで確定。独自の推定は作らない |
| 本体をダークモードにしたとき | バーが見えなくなる |

ダークモードの件は iOS シミュレータ (iOS 26.5) でも同じ条件で確かめた。iOS のバーもほぼ白 (249,249,251) で、明るい灰色の背景 (242,242,247) の上ではほとんど見えなかった。ナビゲーションバーの題名とステータスバーの文字も同様に読めなかった。原因は両 Sample がダークモードに追随しない固定色で描かれていることで、ライブラリのプラットフォーム間の食い違いではない。オーナー判断でライブラリは変えず、Sample の件は `sample-dark-mode-toggle` として簡易起票した。

## 限界

- 手動操作のため操作量は記録間で揃わない。到達範囲も記録していない
- 記録は 1 回。体感が迷いなく合格のため、計測器を外した対照は行っていない (handbook の再試行条件)
- gfxinfo の集計は HWUI の描画フレームで、インジケータの描画費用だけを切り出したものではない。インジケータの有無を比べる A/B は採っていない
