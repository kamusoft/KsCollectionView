# Sample のデモ画像に使う公開プレースホルダー画像サービスの選定 (tasks 1.4)

Sample「画像グリッド」(10,000 件・3 列・正方形) のデモ画像を供給する公開サービスの選定記録。
選定日 2026-09-06。ここでは選定と URL の作り方までを決め、Sample の実装は別タスクが行う。

## 選定条件

1. アイテム ID から**決定的な** URL を作れる (同じ ID は毎回同じ画像。スクロールで戻ったときに
   絵が変われば、キャッシュが効いているのか別画像を引いたのかを目視で区別できなくなる)
2. **サイズ指定で正方形**が取れる (承認モックのセルは正方形)
3. API キー・認証が不要 (Sample を clone してすぐ動く)
4. 実写 JPEG が返る (取得バイト数とデコード負荷が計測の対象になるため、単色生成画像では
   ネットワーク・デコードの負荷が現実と乖離する)

## 選定: Lorem Picsum (picsum.photos)

`https://picsum.photos/` の公式ドキュメントで確認した事実:

- `/seed/{seed}` — 「Get the same random image every time based on a seed」。seed から画像への
  写像が固定される (条件 1)
- 幅と高さを続けて指定できる。等しい値を与えれば正方形 (条件 2)。ドキュメントの例は
  `https://picsum.photos/seed/picsum/200/300`
- API キー・認証に関する記述はなく、鍵なしで引ける (条件 3)

実応答での確認 (2026-09-06):

| 要求 URL | 応答 |
|---|---|
| `https://picsum.photos/seed/ks-42/400/400` | 302 → `fastly.picsum.photos/id/347/400/400.jpg?hmac=...` |
| `https://picsum.photos/seed/ks-43/400/400` | 302 → `fastly.picsum.photos/id/50/400/400.jpg?hmac=...` |

seed ごとに別の実写 JPEG (`.jpg`) へ写像され、指定サイズがそのまま配信 URL に現れる (条件 4)。

## URL の作り方

```
https://picsum.photos/seed/ks-<アイテム ID>/400/400
```

- seed は `ks-` を接頭辞に付けたアイテム ID。接頭辞は、他の題材と seed 空間が偶然重なったときに
  「同じ ID なのに別の絵」にならないようにするためのもの
- サイズは **400x400** 固定。承認モックの 3 列グリッドのセルは幅 390pt 級の端末で 1 辺 130pt 前後に
  なり、@3x でも 400px 弱に収まる。実サイズからの縮小デコードは `KsImage` 側が行うため、
  ここでは「@3x で足りる最小の正方形」を選ぶ
- 両プラットフォームで**同じ組み立て**にする (Sample のプラットフォーム間一致)

## 実装側への申し送り

- 応答は 302 リダイレクトで CDN へ飛ぶ。Nuke (URLSession) と Coil (OkHttp) はいずれも既定で
  リダイレクトを追う。キャッシュ鍵は要求元の `picsum.photos` の URL 側であり、リダイレクト先の
  URL に含まれる `hmac` クエリが鍵に混ざることはない (鍵が毎回変わる心配はない)
- ディスクキャッシュが効くまでは 10,000 件の seed ぶんだけ公開サービスへ取得が飛ぶ。計測時は
  実行前にキャッシュを消すか温めるかを揃え、条件を証跡に明記する
- Android Sample には `INTERNET` permission が要る (tasks 6.2)

## identity lint

`picsum.photos` は公開サービスのホスト名であり、`identity-lint.py` の network 群が検出するのは
MAC / SSID / プライベート IP と `lint.internal-hosts` に列挙したホストだけなので、
`kasane/config.yaml` への追加は不要。実際に `python3 scripts/identity-lint.py` を通して 0 件を確認した。

## 代替案

- **placehold.co / dummyimage.com** — 却下。決定的で正方形も取れるが、返るのは文字入りの単色生成画像で、
  バイト数もデコード負荷も実写と桁が違う。計測の題材にならない (条件 4)
- **picsum の `/id/{n}` 形式** — 却下。画像 ID の実在範囲が有限で、10,000 件のアイテムに
  一意な決定的写像を作れない (剰余を取ると別 ID が同じ絵になり、キャッシュの目視判定が濁る)
- **自前の静的画像をリポジトリへ同梱** — 却下。ネットワーク取得・ディスクキャッシュ・プリフェッチの
  到達点という、この変更の検証したい経路そのものが消える
