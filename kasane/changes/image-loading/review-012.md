## 指摘事項

### [🟡 Minor] 改善後・試行 2 の commit の内訳が一次データと合わず、製品コードの費用を「自動化」に付け替えている

**該当箇所**: `evidence/image-grid-measurement-ios.md:318-319`、`deviation.md:99`

**問題点**:
証跡は試行 2 について「同じ commit の内側で**自動化が 4 サンプル**、区切り線の更新と CA の commit が
**2 サンプル**を占めており、**主因はそちら側**と読む」と書いている。commit 区間 (33,972,533,166 ns +
16,984,459 ns) のサンプルを全件取り出すと、実際は次の **5 サンプルだけ**である。

| 時刻 | スタックの先頭付近 | 実体 |
|---|---|---|
| 00:33.983.110 | `KsHostingCell.configureTouchFeedback(color:)` ← `-[UIViewAccessibility setBackgroundColor:]` | 区切り線更新 (製品コード) |
| 00:33.984.110 | `KsImageRequestFactory.makeContext` ← `prepare` | 画像 (証跡の言う 1 サンプル) |
| 00:33.985.109 | `StateObject.Box.update` ← `DynamicBody.updateValue()` | SwiftUI |
| 00:33.988.109 | (空スタック) | 不明 |
| 00:33.989.109 | `KsHostingCell.configureTouchFeedback` ← `KsCollectionViewController.configure(cell:at:)` ← `updateVisibleCellSeparators()` | 区切り線更新 (製品コード) |

食い違いは 2 つある。

1. **件数が合わない**。証跡の内訳は 1 + 4 + 2 = 7 サンプルだが、commit 内は 5 サンプルしかない
2. **帰属が逆を向いている**。commit 内に `XCTest` / `XCUI` / `XCTAccessibilityFramework` のサンプルは
   **0 件**である。「自動化」に数えられたのは、`configureTouchFeedback` のスタックに現れる
   `-[UIViewAccessibility setBackgroundColor:]` — UIKit が `UIView` に付けているアクセシビリティ
   カテゴリであって、駆動側の走査ではない。分類器が `Accessibility` という素の部分文字列で拾うと
   製品コードのサンプルが「自動化」に落ちる (実際、緩い分類では同じ trace の主スレッド自動化が
   47.9%、`XCTest` 系に限ると 37.4% と 10 ポイント動く)

結果として、この commit で識別できる最大の費用は**駆動の足場ではなく、ライブラリ自身の
`updateVisibleCellSeparators` → `configureTouchFeedback` 経路** (5 サンプル中 2) になる。
これは別 change `ios-separator-update-guard` として簡易起票済みの、まさにその経路である。

「画像ロードが主因ではない」という上位の結論自体は、画像が 5 サンプル中 1 という事実から支持されるので
変わらない。ただし**費用を製品側から足場側へ付け替えて記録している**点は、相方 Major が問題にした
「別の文脈で得た結論をその文脈の外へ持ち出す」のと同じ類型で、次に読む人が「残りの hitch は計測の
都合」と受け取る余地を残す。なお窓全体の「自動化 34〜37%」は `XCTAccessibilityFramework` に
限った値で**こちらは正しい** — 誤っているのは commit 内のサンプル単位の内訳だけである。

**推奨修正**: `:318-319` を実測に合わせて書き直す。たとえば「同じ commit の内側は全 5 サンプルで、
区切り線の更新 (`updateVisibleCellSeparators` → `configureTouchFeedback`) が 2 サンプル、SwiftUI の
状態更新が 1、残り 1 は空スタック。**駆動側 (`XCTest` / `XCUI`) のサンプルは commit 内には無い**。
識別できる最大の費用は区切り線更新の側で、これは別途起票済みの経路である」。`deviation.md:99` の
「主因は自動化 4 + 区切り線更新・CA 2 サンプル側」も同じ内容に直す。

### [🔵 Suggestion] 自動化の「19〜24% → 34〜37%」は分類の定義が書かれておらず追試できない

**該当箇所**: `evidence/image-grid-measurement-ios.md:286-287`、`:328`

**問題点**: 「改善前 19〜24% → 改善後 34〜37% に増えている」は、この証跡でいちばん強い

上記 Minor のとおり、`Accessibility` を素の部分文字列で拾うか `XCTest` 系に限るかで、同じ trace の
同じ量が 47.9% と 37.4% に振れる。前半の trace は手元に無いため前半側の値は追試できず、
両者が同じ定義で数えられているかを読み手が確かめられない。

証跡は別途「窓の長さと計測の足場の費用が違うため、前半・後半の値は比較しない」と書いており
(`:150` 付近)、その方針とこの比較との関係も明示されていない (hitch 比とは別の量なので矛盾では
ないが、読み手には分かりにくい)。

**推奨修正**: 「自動化 = `XCTest` / `XCUI` / `XCTAccessibilityFramework` / `AXRuntime` /
`AccessibilityViewGraph` を含むスタック (主スレッドのサンプル比)」のように定義を一行足す。
前半の値が別定義または追試不能なら「前半の値は同じ定義で数え直せない」と限界に添える。
