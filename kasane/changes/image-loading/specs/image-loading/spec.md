# image-loading — デルタスペック

対象能力: 画像のプリフェッチ・専用画像コンポーネント `KsImage`・キャッシュ操作 (iOS / Android 共通の契約。プラットフォーム固有の Requirement は名前に明記)。

## ADDED Requirements

### Requirement: プリフェッチ宣言
`prefetchResources` (Swift modifier / Kotlin 名前付き引数) で、アイテムからそのアイテムが必要とするリモート画像 URL の配列を返すクロージャを宣言できる (SHALL)。データ型にライブラリの protocol / interface への準拠を要求しない (SHALL NOT)。任意引数 `destination` で到達点を `disk` (既定) と `memory` から選べる (SHALL)。宣言が無いコレクションではプリフェッチは一切起きず、可視範囲の観測も行わない (SHALL NOT)。クロージャが空配列を返したアイテムは何も取得しない (SHALL)。

#### Scenario: もうすぐ表示されるアイテムの画像を取得する
- **GIVEN** `prefetchResources` を宣言した画像グリッドが表示されている
- **WHEN** 先頭から末尾方向へスクロールする
- **THEN** 可視範囲の先 (進行方向) にあるアイテムについて、クロージャが返した URL の取得が到達点付きで開始される

#### Scenario: 宣言が無ければ何も起きない
- **GIVEN** `prefetchResources` を宣言していないコレクション
- **WHEN** スクロールする
- **THEN** ローダーへの取得要求は発生しない

#### Scenario: 複数 URL の宣言
- **GIVEN** クロージャが 1 アイテムにつき 2 つの URL を返す宣言
- **WHEN** そのアイテムが先読みの対象になる
- **THEN** 2 つの URL の両方について取得が開始される

### Requirement: プリフェッチの取り消し
先読みの対象から外れたアイテムの取得は取り消される (SHALL)。配列の差し替えで消えたアイテムの取得も取り消される (SHALL)。コレクションが画面から消えた (破棄された) ときは未完了の取得をすべて取り消す (SHALL)。取り消しは進行中の取得にのみ作用し、完了してキャッシュに入ったものは消さない (SHALL NOT)。同じ URL を複数のアイテムが返す場合、その URL の取得はまだ必要としているアイテムが 1 つでも残る限り取り消さない (SHALL NOT)。`prefetchResources` クロージャと `destination` は表示中に差し替えない前提の宣言とし、差し替えた場合は以後の新しい取得にだけ反映される (SHALL)。

#### Scenario: スクロール方向の反転で取り消される
- **GIVEN** 末尾方向へのスクロールで先読みが開始されたアイテム群
- **WHEN** スクロール方向を先頭方向へ反転する
- **THEN** 進行方向の先に無くなったアイテムの取得は取り消され、新しい進行方向の先のアイテムの取得が開始される

#### Scenario: 配列の差し替えで消えたアイテム
- **GIVEN** 先読み中のアイテム X を含む配列
- **WHEN** X を除いた配列に差し替える
- **THEN** X の取得は取り消される

#### Scenario: 共有 URL は最後のアイテムが外れるまで取り消さない
- **GIVEN** アイテム A と B が同じ URL を返す宣言で、両方が先読み中
- **WHEN** A だけが先読みの対象から外れる
- **THEN** その URL の取得は継続し、B も外れた時点で取り消される

#### Scenario: 画面から消えたら全て取り消す
- **GIVEN** 先読み中のアイテムがあるコレクション
- **WHEN** その画面を閉じる
- **THEN** 未完了の取得はすべて取り消される

### Requirement: プリフェッチの到達点
到達点 `disk` では元データをディスクキャッシュに保存するまでで止め、デコードは行わない (SHALL)。到達点 `memory` では元データをディスクに保存した上で、デコード済みの画像をメモリキャッシュにも載せる (SHALL)。どちらの到達点でも、プリフェッチが取得した画像は同じ URL を `KsImage` で表示するときに再ダウンロードなしで使われる (SHALL)。プリフェッチはローダーの共有インスタンスのキャッシュを使い、ライブラリ独自のキャッシュ領域を持たない (SHALL NOT)。

#### Scenario: ディスク到達点の後の表示
- **GIVEN** 到達点 `disk` で URL の取得が完了している
- **WHEN** 同じ URL を `KsImage` で表示する
- **THEN** ネットワークアクセスなしにディスクの元データから表示される

#### Scenario: メモリ到達点の後の表示
- **GIVEN** 到達点 `memory` で URL の取得が完了している
- **WHEN** 同じ URL を `KsImage` で表示する
- **THEN** ネットワークアクセスもデコードのやり直しもなしに表示される

#### Scenario: 到達点が伝わる
- **GIVEN** `destination: memory` を付けた宣言
- **WHEN** アイテムが先読みの対象になる
- **THEN** 取得要求は `memory` の到達点で発行される (既定の宣言では `disk`)

### Requirement: プリフェッチの先読み範囲 (Android)
先読みの対象は、可視範囲の外側で進行方向に並ぶアイテムのうち、可視件数と同数のアイテムとする (SHALL)。可視範囲内のアイテムは先読みの対象にしない (SHALL NOT)。進行方向はスクロールによる可視範囲の変化から判定し、静止時は直前の進行方向を保つ (SHALL)。初期表示時 (スクロール前) は末尾方向を進行方向とみなす (SHALL)。

#### Scenario: 可視件数と同数を先読みする
- **GIVEN** 12 件が可視の画像グリッド
- **WHEN** 初期表示される
- **THEN** 可視範囲の直後の 12 件について取得が開始される

#### Scenario: 進行方向へ移動すると窓が進む
- **GIVEN** 先読み中の窓がある画像グリッド
- **WHEN** 末尾方向へ 1 行分スクロールする
- **THEN** 新しく窓に入った行のアイテムの取得が開始され、可視範囲に入ったアイテムは先読みの対象から外れる (表示側の読み込みに引き継がれ、取得は取り消されない)

### Requirement: プリフェッチの先読み範囲 (iOS)
先読みの対象と取り消しのタイミングは `UICollectionView` のプリフェッチ (`UICollectionViewDataSourcePrefetching`) の判定に従う (SHALL)。通知されたアイテムをそのまま URL に解決して取得を開始・取り消しする (SHALL)。

#### Scenario: システムの先読み通知に従う
- **GIVEN** `prefetchResources` を宣言したコレクション
- **WHEN** システムが先読み対象のアイテムを通知する
- **THEN** そのアイテムの URL の取得が開始され、取り消し通知で取り消される

### Requirement: 共有キャッシュ
プリフェッチと `KsImage` はローダーの共有インスタンス (iOS: Nuke の共有パイプライン、Android: Coil の singleton ImageLoader) を使う (SHALL)。同じローダーの付属ビューを利用者が直接使った場合も同じキャッシュを見る (SHALL)。iOS では、ライブラリの初回利用時に共有パイプラインにディスクキャッシュが設定されていなければ、ディスクキャッシュを有効にした構成で共有パイプラインを差し替える (SHALL)。既に設定されていれば変更しない (SHALL NOT)。

#### Scenario: ローダー付属ビューとキャッシュを共有する
- **GIVEN** プリフェッチで URL の取得が完了している
- **WHEN** 同じ URL をローダー付属のビュー (`LazyImage` / `AsyncImage`) で直接表示する
- **THEN** 再ダウンロードなしで表示される

#### Scenario: iOS のディスクキャッシュ有効化
- **GIVEN** アプリが Nuke の共有パイプラインを構成していない
- **WHEN** ライブラリを初めて使う
- **THEN** 以後の共有パイプラインはディスクキャッシュを持つ (アプリが先に構成していた場合はその構成のまま)

### Requirement: KsImage の画像ソース
`KsImage` は画像ソース `KsImageSource` を受ける (SHALL)。ソースはリモート URL・ローカルファイル・バンドル済みリソース (iOS はアセット名、Android はリソース ID) の 3 種とする (SHALL)。リモート URL を直接渡す便宜形 `KsImage(url)` を持つ (SHALL)。利用者のモデル型にソース型の保持を要求しない (SHALL NOT)。

#### Scenario: 3 種のソースを表示する
- **GIVEN** リモート・ファイル・リソースのソースを持つ 3 つの `KsImage`
- **WHEN** 表示する
- **THEN** それぞれの画像が表示される

#### Scenario: 便宜形
- **GIVEN** `KsImage(url)` の書き方
- **WHEN** 表示する
- **THEN** `KsImage(.remote(url))` と同じ挙動になる

### Requirement: KsImage の表示状態
`KsImage` は読み込み中・成功・失敗の 3 状態を持つ (SHALL)。読み込み中と失敗時の表示は利用者がスロットで差し替えられ、未指定ならライブラリ既定の表示を出す (SHALL)。リモート・ファイルのソースは、メモリキャッシュに無い場合に読み込み中の状態を経由する (メモリキャッシュにあれば読み込み中を経由せず成功になる) (SHALL)。リソースは読み込み中を経由せず成功か失敗になる (SHALL)。失敗した `KsImage` は、そのビューが作り直されたとき (セルの再利用・画面への再入場) と、`KsImageCache` の `clear` / `remove` で世代が進んだときに再試行する (SHALL)。同じビューが表示され続けている間は自動で再試行しない (SHALL NOT)。

#### Scenario: 読み込み中から成功へ
- **GIVEN** メモリキャッシュに無いリモート URL の `KsImage`
- **WHEN** 表示する
- **THEN** 読み込み中の表示が出て、取得完了後に画像に置き換わる

#### Scenario: 失敗時の表示
- **GIVEN** 存在しない URL の `KsImage`
- **WHEN** 表示する
- **THEN** 失敗時の表示 (スロット指定があればその内容、無ければ既定) が出る

#### Scenario: 失敗後の再試行
- **GIVEN** 取得に失敗して失敗表示になっているセルの `KsImage`
- **WHEN** そのセルが画面外に出て再利用され、同じソースで再び表示される
- **THEN** 再度取得を試みる

#### Scenario: スロットの差し替え
- **GIVEN** 読み込み中と失敗時のスロットを指定した `KsImage`
- **WHEN** 読み込み中および失敗の状態になる
- **THEN** それぞれ指定した内容が表示される

### Requirement: KsImage の当てはめ方
`KsImage` は表示枠への当てはめ方を `fit` (枠に収める) と `fill` (枠を埋める) から指定でき、既定は `fill` とする (SHALL)。`fill` で枠からはみ出た部分は表示されない (SHALL)。

#### Scenario: fit と fill
- **GIVEN** 枠と縦横比が異なる画像
- **WHEN** `fit` と `fill` でそれぞれ表示する
- **THEN** `fit` は画像全体が枠内に収まり、`fill` は枠全体が画像で覆われる

### Requirement: KsImage の縮小デコード
`KsImage` は表示枠の実サイズに合わせて縮小した画像をデコードする (SHALL)。縮小の目標は当てはめ方で決まり、`fit` は枠に収まる最大寸法、`fill` は枠を覆う最小寸法とする (SHALL)。枠のサイズが確定するまでは取得を開始せず、読み込み中の表示を出す (SHALL)。枠のサイズが変わったら新しいサイズで再デコードする (SHALL)。`KsImage` の表示のために元寸の画像をメモリに保持しない (SHALL NOT。プリフェッチの到達点 `memory` による元寸の保持は本要件の対象外)。

#### Scenario: 枠より大きい画像
- **GIVEN** 枠より大きい元寸のリモート画像
- **WHEN** `KsImage` で表示する
- **THEN** 表示に使われるデコード済み画像のピクセルサイズは、`fit` では枠のサイズ (表示倍率込み) を、`fill` では枠を覆う最小寸法を超えない。いずれも元寸の画像はメモリに展開されない

#### Scenario: サイズ確定前は取得しない
- **GIVEN** レイアウト前の `KsImage`
- **WHEN** 枠のサイズがまだ 0 である
- **THEN** 取得要求は発行されず、サイズが確定した時点で発行される

### Requirement: KsImage の読み込み取り消しとメモリ保持
`KsImage` が画面外に出て破棄されたとき、未完了の読み込みは取り消される (SHALL)。読み込みが完了した画像はローダーのメモリキャッシュに保持され、同じソース・同じサイズの `KsImage` が再び表示されたときは再デコードなしに表示される (SHALL)。メモリキャッシュから追い出された画像はディスクの元データ (リモート) またはローカルソース (ファイル・リソース) から再デコードされる (SHALL)。

#### Scenario: 画面外へ出た読み込みの取り消し
- **GIVEN** 読み込み中の `KsImage` を含むセル
- **WHEN** フリングでそのセルが画面外に出て破棄される
- **THEN** その読み込みは取り消される

#### Scenario: 戻ってきたときの再表示
- **GIVEN** 一度表示して画面外に出た `KsImage`
- **WHEN** スクロールで戻る
- **THEN** 読み込み中の表示を経由せず即座に画像が表示される

### Requirement: キャッシュのクリア
`KsImageCache.clear(scope)` で `memory` / `disk` / `all` の範囲を指定してローダーの共有キャッシュを消せる (SHALL)。`KsImageCache.remove(source)` でソース単位にメモリとディスクの項目を消せる (SHALL)。消えるのは共有インスタンスのキャッシュであり、同じローダーを使う他画面の画像も対象になる (SHALL)。`clear` / `remove` は呼び出しから戻った時点でキャッシュの削除が完了しており、以後の同じソースの要求はキャッシュに当たらない (SHALL)。`clear(.all)` / `clear(.disk)` / `remove` の後、表示中の該当する `KsImage` は読み込み中の表示に戻って再取得する (SHALL)。`clear(.memory)` は表示中の画像を置き換えず、次に表示されるときにディスクから再デコードする (SHALL)。iOS のアセットに対する `remove` は何もしない (SHALL)。`remove` の後、そのソースの `KsImage` とプリフェッチは、どの表示サイズであっても削除前のキャッシュ項目に当たらない (SHALL NOT)。iOS では `remove` したソースに限り、以後は利用者がローダー付属ビューで直接要求した同じ URL とキャッシュが共有されない (削除前の項目がその側に残り得る) (SHALL)。`clear` は共有に影響しない (SHALL NOT)。

#### Scenario: 全消去の後の表示
- **GIVEN** 表示済み (キャッシュ済み) のリモート画像
- **WHEN** `KsImageCache.clear(all)` を呼ぶ
- **THEN** 表示中の `KsImage` は読み込み中の表示に戻って再ダウンロードされ、その後に表示される同じ画像も再ダウンロードされる

#### Scenario: メモリのみ消去
- **GIVEN** 表示済みのリモート画像
- **WHEN** `KsImageCache.clear(memory)` を呼んでから同じ画像を表示する
- **THEN** 再ダウンロードなしにディスクの元データから再デコードされて表示される

#### Scenario: ソース単位の削除
- **GIVEN** 表示済みのリモート画像 A と B
- **WHEN** `KsImageCache.remove(.remote(A))` を呼ぶ
- **THEN** 表示中の A は読み込み中に戻って再ダウンロードされ、B はそのまま表示され続ける (次の表示でも B はキャッシュから表示される)

#### Scenario: 削除後は別サイズでも旧項目に当たらない (iOS)
- **GIVEN** リモート画像 A を 2 つの異なる枠サイズで表示済み
- **WHEN** `KsImageCache.remove(.remote(A))` を呼び、A をどちらかの枠サイズで再び表示する
- **THEN** 読み込み中を経由して再ダウンロードされる (削除前のどのサイズの項目にも当たらない)

### Requirement: Sample のデモ画面「画像グリッド」
両プラットフォームの Sample に、画面タイトル「画像グリッド」のデモ画面を sample-parity 準拠 (同一文言・同一構成・同一件数) で追加する (SHALL)。画面は大量件数 (10,000 件) の画像グリッドで、プリフェッチの有無 (なし / ディスクまで / メモリまで) を切り替える操作と、キャッシュを全消去する操作を持つ (SHALL)。画像は公開のプレースホルダー画像サービスから取得し、各アイテムの URL はアイテム ID から決定的に生成する (SHALL)。

#### Scenario: 切り替えの反映
- **GIVEN** デモ画面が「なし」で表示されている
- **WHEN** 「ディスクまで」に切り替える
- **THEN** 以後のスクロールで先読みが開始される (ローダーのログで確認できる)

#### Scenario: 全消去
- **GIVEN** 画像が表示済みのデモ画面
- **WHEN** 全消去の操作を行い先頭へ戻る
- **THEN** 表示中の画像が読み込み中を経由して再取得される
