# Requirement と検証層の対応

各欄には実在するテスト名と、そのテストが観測している内容だけを書く。自動検証が無い欄は「自動検証なし」と明示する。
「Simulator 統合」は Simulator 上で走らせた統合テストと、Simulator で実施した手動観測の記録を置く。「実機手動」は実機でしか成立しない観測に限る。

| Requirement / Scenario | unit | Simulator 統合 | 実機手動 |
|---|---|---|---|
| プレーンな配列 / Identifiable 100 件 | `KsSnapshotPlannerTests.testIdentifiable相当の100件を全てsnapshotへ含める` が計画配列の件数を検証 | `KsCollectionEngineTests.test100件をdataSourceへ反映する` が data source 件数を検証 | 自動検証なし (Sample「リスト」でスクロール到達性を目視) |
| 非準拠型の `id:` | `KsSnapshotPlannerTests.test非準拠型のキーパス相当IDで順序を構築する` が計画配列の順序を検証 | `KsCollectionScenarioTests.test非Identifiable型のidキーパスで描画し差分更新のidentityにする` が `UIHostingController` 上で実描画し、`itemId` を identity とする snapshot 順とセルインスタンス維持を検証。組み立ては `KsPublicAPITests.test非Identifiable型をidキーパスで組み立てられる` | 不要 |
| 挿入・削除・移動 | `KsSnapshotPlannerTests.test挿入削除移動後の順序を新配列に合わせる` | `KsCollectionEngineTests.test挿入削除並べ替え後に区切り線の位置を再構成する` が snapshot 順と位置依存表示を検証。`KsCollectionEngineTests.test挿入時に内容不変の要素のセルプロバイダを再実行しない` が無関係要素の非再描画を検証 | 自動検証なし (Sample でアニメーションを目視) |
| 内容変更の再構成 | `KsSnapshotPlannerTests.test同一IDかつ同一キーの内容変更は再構成する` | `KsCollectionScenarioTests.test同一IDかつ同一キーの内容変更でセルインスタンスを維持して再描画する` が `cellForItem` の同一性と新内容の再描画を検証 | 不要 |
| テンプレートキー変更でのセル置換 | `KsSnapshotPlannerTests.test同一IDでキー変更時はセルを置換する` | `KsCollectionScenarioTests.test同一IDでテンプレートキーが変わるとセルを別テンプレートへ置き換える` がセルインスタンスの入れ替わり・再利用識別子の相違・別テンプレートでの描画を検証。`.testレイアウト切替と同時にテンプレートキーが変わってもセルを置き換える` が、レイアウト種別の変更と同一 ID のキー変更が同時に来ても例外なくセルが置き換わることを検証 | 不要 |
| 値キー / 単一テンプレート | `KsTemplateRegistryTests.test値キーごとのテンプレートを登録する` / `.test単一テンプレートは専用キーで解決できる` | `KsPublicAPITests.test値キーの複数テンプレートを組み立てられる` が項目・キー・registry 登録を検証 | 自動検証なし (Sample「テンプレート切り替え」で表示を目視) |
| 未登録キー (debug 検知) | 自動検証なし (assertion のため) | `KsCollectionEngineTests.test未登録テンプレートキーをsnapshot準備時に検知する` が、画面外の要素でも snapshot 準備時に検知されることを検知結果で検証 | 不要 |
| 未登録キー (release フォールバック) | `KsTemplateRegistryTests.testReleaseでは未登録キーを空セルへ解決する` が 1pt の空セルへの解決を検証 (Release + `ENABLE_TESTABILITY=YES` でのみ実行) | 自動検証なし | 警告ログの目視は任意 |
| 重複 ID (release 継続) | 自動検証なし | `KsCollectionEngineTests.testReleaseでは重複IDを後勝ちで解決して表示を継続する` が畳んだ後の snapshot 順を検証 (Release でのみ実行) | 不要 |
| セル再利用時の state 非保持 | 自動検証なし | `KsCollectionScenarioTests.testセルの再利用が起きる距離を往復するとテンプレートのstateは初期値へ戻る` が、`@State` を持つテンプレートを可視範囲の数倍 (300 件中 250 番目) までスクロールして戻し、state が初期値に戻ることを検証 | 自動検証なし (Sample で往復操作して目視) |
| 10,000 件の仮想化・再利用 | `KsCollectionEngineTests.test2000件を全件走査しても同時生存セルを可視範囲と再利用プールに留める` が、2,000 件を表示範囲の半分ずつ送って往復し、各段階の同時生存セル数が可視セル数の 4 倍未満 (安全余裕込みの上限。実測は可視 39 件に対し最大 115 件で約 2.95 倍) に留まることを検証 (同時生存セルの計数は debug ビルドにのみ載るため、このテストは Debug 構成でのみ実行する)。**自動検証の射程は 2,000 件であり、10,000 件は下記の Simulator 計測が担う** | Sample「大量件数」画面の表示確認。メモリは iPhone 17 Pro Simulator (iOS 26.5) の Release 構成で、可視範囲の半分ずつ送って全 10,000 件を通過する往復を、増加が止まるまで記録 (独立 2 実行とも通過項目 10,000 / 10,000 件、5 往復 / 4 往復で定常化。`performance-early-measurement.md`)。計測経路は Sample UI テスト `PerformanceDriverUITests.test大量件数を全件通過で2往復してメモリを表示する` が、2 往復と通過項目 10,000 / 10,000 件の表示を検証 (計測スキームでのみ実行) | hitch time ratio は iPhone 15 (代替機、deviation 記録済み) + Instruments。`performance-early-measurement.md` |
| fixed / adaptive / 向き別列数 | `KsLayoutMetricsTests.test固定3列を返す` / `.testAdaptiveは最小幅を下回らない最大列数を返す` / `.test向き別列数はコンテナ縦横比で切り替える` | `KsCollectionEngineTests.testadaptiveの余白列間と項目幅を実レイアウト属性へ反映する` と `.testコンテナ縦横比の変更で縦2列と横4列を再計算する` が実レイアウト属性で検証 | 自動検証なし (実機の回転・Split View で目視) |
| 動的切り替えの anchor | 自動検証なし | `KsCollectionEngineTests.testリストからグリッドへの切替後も先頭可視要素を表示範囲に残す` / `.testレイアウト切替と同時の先頭側への大量挿入でもアンカーを保つ` / `.testレイアウト切替と同時にアンカーが消えたら近傍要素を表示範囲に残す` が、切り替え後の可視 ID にアンカー (削除時は近傍要素) が含まれることを検証。`.testグリッドからリストへ切替後にスクロールしても全セルが一列になる` が切り替え後の列幅を検証。`.test深い位置で行間を大きく変えても先頭可視要素を表示範囲に残す` と `.test行間を連続して変えても先頭可視要素が変わらない` が、アンカー行を半分クリップした任意 offset から、行間の差し替え (単発・連続) の前後で `frame.minY - bounds.minY` が一致することを検証。`.testアンカーの高さが大きく縮む切り替えでもアンカーを表示範囲に残す` が、アンカーの大部分を表示範囲の上へ出した状態で高さが大きく縮む切り替えを行っても、アンカーが表示範囲内に現れることを検証 | 自動検証なし (長いリスト上で目視) |
| spacing / contentPadding | 列数算出は `KsLayoutMetricsTests` | `KsCollectionEngineTests.testadaptiveの余白列間と項目幅を実レイアウト属性へ反映する` が左右余白・列間・最小幅を、`.test連続するスペーシングと余白変更でレイアウトを作り直さない` がレイアウトオブジェクトの維持を検証。`.test左右の内側余白を変えてもスクロールインジケータをコンポーネント端に保つ` が、左右余白を変えても `contentInset` / `adjustedContentInset` / `verticalScrollIndicatorInsets` が 0 のままであることを検証 | 自動検証なし (インジケータ位置を目視) |
| list 区切り線 | 自動検証なし | `KsCollectionEngineTests.testリスト区切り線を全幅で先頭と行間に表示し即時に切り替える` が色・frame・ON/OFF を、`.test挿入削除並べ替え後に区切り線の位置を再構成する` が位置依存表示の再構成を検証 | 自動検証なし (最終行・grid・opt-out を目視) |
| header / footer | `KsPublicAPITests.test単一テンプレートと利用者向けmodifierを組み立てられる` が公開 modifier の設定値を検証 | `KsCollectionEngineTests.test表示中のheaderと動的件数footerを更新後に再構成する` と `.test内容不変のheader更新でホスティングビューを維持する` が再構成と不要な作り直しの回避を検証。`.testheaderは下方向のスクロールでコンテンツと一緒に画面外へ出る` が、スクロール後も header のコンテンツ座標での位置が変わらず表示範囲から外れること (pin されていないこと) を検証 | 不要 |
| セル自己サイズ (可変行高) | 自動検証なし | `KsCollectionScenarioTests.test本文量の異なる行はそれぞれ必要な高さになる` が、本文量の異なる行のレイアウト属性の高さが本文量に応じて異なり、同じ本文量の行が同じ高さになること、および各行の高さがホストされた内容の fitting size と一致すること (切れ・余分な空白が無いこと) を検証 | 自動検証なし (Sample で切れ・余白を目視) |
| tap / long tap / 子 control 競合 | 自動検証なし | `KsCollectionEngineTests.test選択時に型付き項目を通知する` / `.test長押し成立後の別タッチによる通常タップを抑止しない` / `.testロングタップ未宣言のときは長押し認識器を無効にする` / `.testセル内の操作要素へのタッチではitemTapとfeedbackを発火しない` (セルの hitTest 経由で操作要素を判定させ、item tap 0 回と feedback 非表示を検証)。Sample UI テスト `InteractiveControlUITests.testセル内Buttonの実座標タップを優先する` / `.test長押し宣言時は同一タッチの通常タップを発火しない` / `.test長押し未宣言時は長押し相当の保持でも通常タップを発火する` が実座標タップ・長押しで検証。iPhone 17 Pro Simulator (iOS 26.5) で `--verify-interactive-control` を起動し Button 中央を tap した記録: Button action 1 回 / item tap 0 回 (`interactive-control-after-tap.png`) | 押下中の feedback 描画の目視は未実施 (操作 API が押下中の静止画を返さないため) |
| touch feedback | 自動検証なし | `KsCollectionEngineTests.test不透明な内容の上へ指定色のtouchFeedbackを表示して消す` が描画差で表示・消失を、`.test既定のtouchFeedbackは半透明でセル内容を隠さない` が既定色のアルファを、`.testtouchFeedback色の変更を可視セルへ反映する` が色変更の可視セルへの反映を検証 | 不要 |
| 親の更新の反映 (同値配列) | 自動検証なし | `KsSwiftUIIntegrationTests.test配列が同値でも親のState変更を可視セルへ反映する` が `UIHostingController` 上で親の `@State` (選択中 ID) 変更が可視セルの構成へ届くことを、`KsCollectionEngineTests.test同一配列の再適用ではID解決を行わず可視セルだけ再構成する` が ID 解決を伴わない可視セル再構成を検証 | 不要 |
