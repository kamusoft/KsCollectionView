# collection-core (セクション / グループ化) — デルタスペック

## ADDED Requirements

### Requirement: グループの値によるセクションの宣言
利用者は平らな配列のまま、各項目の「どのグループか」を表す値 (グループの値) をキーパス (Swift) / ラムダ (Kotlin) で指定できる (SHALL)。ライブラリは配列の順に、グループの値が等しい項目が続く範囲を 1 つのセクションとして表示する (SHALL)。セクションはグループの値で識別する (SHALL)。項目のモデルにライブラリ独自の型・interface への準拠や、見出し用の要素の混入を要求してはならない (SHALL NOT)。グループの値を指定しない場合は、これまでどおり配列全体を 1 続きで表示する (SHALL)。項目が 0 件のセクションは存在しない (SHALL NOT)。

#### Scenario: 続いた同じ値が 1 つのセクションになる
- **GIVEN** グループの値が「果物, 果物, 野菜, 野菜, 野菜」と並ぶ 5 件の配列と、グループの値の指定
- **WHEN** 表示する
- **THEN** 「果物」(2 件) と「野菜」(3 件) の 2 つのセクションが配列の順に表示される

#### Scenario: 指定しなければ今までどおり
- **GIVEN** グループの値を指定しない配列
- **WHEN** 表示する
- **THEN** 全要素が 1 続きで表示され、セクションの見出しは表示されない

#### Scenario: 項目のモデルを変えずにグループ化する
- **GIVEN** 既存のプロパティ (例: カテゴリ) を持つ、ライブラリに準拠していない項目型の配列
- **WHEN** そのプロパティをグループの値として指定する
- **THEN** 項目型を変更せずにセクションが表示される

### Requirement: グループの値の型 (Android)
Android では、グループの値は項目の `key` と同じく状態保存 (Bundle) に載せられる型 (文字列・数値・enum・`Serializable`・`Parcelable`) でなければならない (SHALL) — この制約は利用契約として利用者向けドキュメントに明記する (SHALL)。載せられない型のグループの値は不正入力とし、項目の `key` の同じ不正入力と同じ扱い (core/ADR-0011) にする (SHALL)。見出しの識別は項目の `key` と衝突しない (SHALL)。

#### Scenario: 項目のキーと同じ値のグループ
- **GIVEN** 項目の `key` が文字列「果物」の項目と、グループの値が文字列「果物」のセクションを含む配列
- **WHEN** 表示する
- **THEN** 重複キーの不正入力にならず、見出しと項目がどちらも表示される

### Requirement: 同じグループの値が離れて現れる入力
同じグループの値が配列の離れた位置に再び現れる入力は不正入力とする (SHALL)。debug ビルドでは assertion で検知し (SHALL)、release ビルドではクラッシュせず、配列の順のまま別々のセクションとして表示を続け、警告ログを出す (SHALL)。項目を並べ替えたり、どちらかのセクションを消したりしてはならない (SHALL NOT)。

#### Scenario: release ビルドでの離れた同じ値
- **GIVEN** グループの値が「果物, 野菜, 果物」と並ぶ配列 (release ビルド)
- **WHEN** 表示する
- **THEN** アプリはクラッシュせず、「果物」「野菜」「果物」の 3 つのセクションが配列の順に表示され、全項目が表示され、警告ログが出力される (debug ビルドでは assertion で停止する)

### Requirement: セクションをまたぐ差分更新
利用者が配列を差し替えたとき、ライブラリは項目の安定 ID とセクションのグループの値を identity として差分を反映する (SHALL)。グループの値が変わった項目は、新しいセクションへ移動として反映する (SHALL)。セクションの並び順が変わったときは、見出しがそのセクションの項目と一緒に移動する (SHALL)。項目と見出しの移動・挿入・削除は、両プラットフォームとも新しい位置へ飛ばずにアニメーションで反映する (SHALL — core/ADR-0003、Android は android/ADR-0006)。項目が 0 件になったセクションは見出しごと消え、新しいグループの値が現れたらセクションが見出しごと現れる (SHALL)。identity が同じ項目は、セクションをまたいで移動しても同じ項目として扱われる (SHALL)。移動の前後とも可視範囲にある項目のセルは作り直されない (SHALL)。画面外に出た項目のセルの扱いは既存の再利用の契約に従う。並べ替えのための DSL は持たない (SHALL NOT)。

#### Scenario: 項目が別のグループへ移る
- **GIVEN** 「果物」セクションに表示中の項目 X
- **WHEN** X のグループの値を「野菜」に変え、データ層で並べ直した配列を渡す
- **THEN** X は「野菜」セクションへアニメーションで移動して表示され (両プラットフォーム)、移動先も可視範囲にあれば X のセルは作り直されない

#### Scenario: グループの並び順を反転する
- **GIVEN** 「果物」「野菜」の順に並ぶ 2 つのセクション
- **WHEN** 「野菜」の項目を先に並べた配列を渡す
- **THEN** 「野菜」の見出しと項目が先に、「果物」の見出しと項目が後に表示され、見出しはそれぞれのセクションの項目と一緒に移動する

#### Scenario: 最後の項目が消えたセクション
- **GIVEN** 1 件だけの「肉」セクションを含む表示
- **WHEN** その項目を除いた配列を渡す
- **THEN** 「肉」の見出しは表示されなくなる

### Requirement: 先頭を表示中の先頭への挿入
コンテンツの先頭 (ルートのヘッダーがあればその上端) を表示範囲の上端に表示しているときに、配列の先頭へ項目を挿入した場合、表示範囲は先頭に留まり、挿入した項目は表示範囲に入ってアニメーションで現れる (SHALL — 両プラットフォーム。Android の Lazy 系が見えている先頭の項目の位置を保つ既定の挙動で、挿入した項目が表示範囲の上に外れてはならない (SHALL NOT))。セクションありで最初のセクションの先頭に挿入した場合も同じとする (SHALL)。

#### Scenario: いちばん上での先頭への挿入 (list)
- **GIVEN** list を先頭までスクロールした状態
- **WHEN** 配列の先頭に 1 件挿入する
- **THEN** 表示範囲は先頭のままで、挿入した項目が先頭に現れ、元の項目は下へずれる (両プラットフォーム)

#### Scenario: いちばん上での先頭への挿入 (グリッド)
- **GIVEN** 2 列のグリッドを先頭までスクロールした状態
- **WHEN** 配列の先頭に 1 件挿入する
- **THEN** 表示範囲は先頭のままで、挿入した項目が先頭に現れる

### Requirement: セクションを持つ大量件数での仮想化と滑らかさ
セクションを持つ大量件数の配列でも、同時に生成・保持されるセルと見出し (Android はコンポジション) は可視範囲と先読み分に留まり、スクロールで全要素に到達できる (SHALL)。セクションの数が多い配列 (小さいグループが数百) と、1 つのセクションが多数の項目を持つ配列が混ざっても、基準機での手動フリックの体感が滑らかである (SHALL — 判定はオーナーの体感、cross/ADR-0006)。

#### Scenario: セクションの多い大量件数
- **GIVEN** 10,000 件を、1,200 件前後の大きいグループ数個と 5〜30 件の小さいグループ多数に分けた配列 (Sample「グループ化」)
- **WHEN** 基準機で先頭から末尾まで手動でフリックする
- **THEN** オーナーの体感で滑らかであり、見出しの固定と入れ替わりが途切れない。計測器の数値は証跡として残す
