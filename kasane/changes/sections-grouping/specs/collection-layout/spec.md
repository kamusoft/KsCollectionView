# collection-layout (セクション / グループ化) — デルタスペック

## ADDED Requirements

### Requirement: セクションの見出し
セクションの見出しを任意の View (Swift) / Composable (Kotlin) で宣言できる (SHALL)。見出しの宣言には、そのセクションのグループの値とセクション内の項目が渡される (SHALL)。見出しの高さは中身から自動で決まり、高さの指定を要求しない (SHALL)。グリッドでは見出しは全幅を占める (SHALL)。見出しはセクションの先頭行の前に 1 つだけ置かれ (SHALL)、セクションのフッターは持たない (SHALL NOT)。見出しを宣言しない場合、セクションの区切りに見出しは表示されない (SHALL)。ルートのヘッダー / フッターはセクションとは別に、コンテンツ全体の先頭・末尾に置かれる (SHALL)。

#### Scenario: 見出しにグループの値と項目が渡る
- **GIVEN** 「果物」(2 件) と「野菜」(3 件) の配列と、グループの値と件数を表示する見出しの宣言
- **WHEN** 表示する
- **THEN** 各セクションの先頭行の前に「果物 2」「野菜 3」の見出しが表示される

#### Scenario: グリッドでは全幅
- **GIVEN** 2 列のグリッドで見出しを宣言したセクション
- **WHEN** 表示する
- **THEN** 見出しは列に分かれず全幅に表示され、セクションの先頭の項目は次の行の行頭に置かれる

#### Scenario: ルートのヘッダーとの共存
- **GIVEN** ルートのヘッダー / フッターとセクションの見出しの両方を宣言した配列
- **WHEN** 先頭から末尾まで表示する
- **THEN** ルートのヘッダーが最初のセクションの見出しより前に、ルートのフッターが最後のセクションの最終行より後に表示される

### Requirement: 見出しの内容の更新
利用者が配列を差し替えたとき、表示中の見出しには新しい配列でのグループの値とセクション内の項目が渡され、内容が更新される (SHALL)。セクションの項目の数や内容だけが変わり、グループの値が変わらない場合も同じとする (SHALL)。見出しは作り直さずに内容を更新する (SHALL)。見出しの宣言の中で親の状態を読む場合の再描画の条件は、項目のテンプレートと同じとする (SHALL — iOS は観測する値 (`observedValue`) を渡したとき、または配列が差し替えられたとき。Android は Compose の自動の観測)。

#### Scenario: 項目数が変わると見出しの件数が変わる
- **GIVEN** 件数を表示する見出しの「果物」(2 件) セクションが表示されている
- **WHEN** 「果物」に 1 件足した配列を渡す
- **THEN** 見出しの表示が「果物 3」に変わる

#### Scenario: 観測する値で見出しが変わる (iOS)
- **GIVEN** 親の状態 (選択中のグループ) を見出しの中で読み、その状態を観測する値として渡したコレクション
- **WHEN** 親の状態を変える
- **THEN** 表示中の見出しが新しい状態で描き直される

### Requirement: 見出しの固定
セクションの見出しは既定で、そのセクションが表示範囲にある間、表示範囲の上端に固定される (SHALL)。次のセクションの見出しが上端に達すると、固定中の見出しは押し上げられて入れ替わる (SHALL)。押し上げられている間も固定中の見出しは薄れずに表示される (SHALL)。設定 1 つで固定を外せ、外した見出しはコンテンツと一緒にスクロールする (SHALL)。iOS で内部の塊に割れたセクションでも、見出しはセクション全体で 1 つとして固定され、塊の境目で見出しの隙間・行へのかぶり・動き・欠けが現れてはならない (SHALL NOT)。

#### Scenario: 既定で固定される
- **GIVEN** 固定の設定を指定しない、見出しつきの 2 つのセクション
- **WHEN** 最初のセクションの途中までスクロールする
- **THEN** 最初のセクションの見出しが表示範囲の上端に表示されている

#### Scenario: 次の見出しに押し上げられる
- **GIVEN** 最初のセクションの見出しが上端に固定されている
- **WHEN** 2 つめのセクションの見出しが上端に達するまでスクロールする
- **THEN** 最初の見出しは押し上げられて表示範囲から出て、2 つめの見出しが上端に固定される。押し上げられている間、最初の見出しは薄れない

#### Scenario: 固定を外す
- **GIVEN** 固定を外す設定をした、見出しつきのセクション
- **WHEN** セクションの途中までスクロールする
- **THEN** 見出しはコンテンツと一緒に表示範囲の外へスクロールしている

#### Scenario: 内部の塊に割れたセクションの見出し (iOS)
- **GIVEN** 内部の塊の件数を超える項目を持つセクション (見出しつき・固定)
- **WHEN** 塊の境目を通過するまで、ゆっくり、および速くスクロールする
- **THEN** 見出しは上端に固定されたまま動かず、セクションの途中に見出しの隙間や行へのかぶりが現れない

### Requirement: セクションまわりの間隔
layout 値に、セクションとセクションの間の間隔と、見出しとそのセクションの先頭行の間の間隔を宣言できる (SHALL)。どちらも既定値は 0 (SHALL)。セクション間の間隔は前のセクションの最終行の後、次のセクションの見出しの前に入り、コンテンツ全体の先頭と末尾には入らない (SHALL)。行間 (`rowSpacing`) は行と行の間にだけ入り、見出しの前後には入らない (SHALL)。これらの間隔は、固定中の見出しと一緒に上端に貼り付かない (SHALL NOT)。負の値は不正入力とする (SHALL — core/ADR-0011 の方針)。

#### Scenario: 間隔の既定
- **GIVEN** 行間を指定し、セクションの間隔を指定しない見出しつきのセクション
- **WHEN** 表示する
- **THEN** 見出しとそのセクションの先頭行の間、前のセクションの最終行と次の見出しの間には間隔が無く、行と行の間には行間がある

#### Scenario: 2 つの間隔を指定する
- **GIVEN** セクション間の間隔 A と見出しの下の間隔 B を指定した、見出しつきの 2 つのセクション
- **WHEN** 表示する
- **THEN** 最初のセクションの最終行と 2 つめの見出しの間が A、各見出しとその先頭行の間が B で、コンテンツ全体の先頭と末尾には A が入らない

### Requirement: セクションを持つ list の区切り線
セクションを持つ list では、区切り線をセクションごとに、先頭行の上端・行の間・最終行の下端に引く (SHALL — core/ADR-0016)。見出しは前のセクションの最終行の下線と、自分のセクションの先頭行の上線の間に置かれる (SHALL)。見出しを宣言しない場合は、2 つめ以降のセクションの先頭行の上線を出さない (SHALL)。幅・太さ・色・前面に描くこと・非表示の設定・グリッドでは描かないことは、セクションが無い場合と同じとする (SHALL)。

#### Scenario: 見出しの上下に線がある
- **GIVEN** 区切り線を表示する list で、見出しつきの 2 つのセクション
- **WHEN** 表示する
- **THEN** 各セクションの先頭行の上端と最終行の下端、行の間に線があり、2 つめの見出しは最初のセクションの最終行の下線と 2 つめの先頭行の上線の間にある

#### Scenario: 見出しが無いと線は重ならない
- **GIVEN** 区切り線を表示する list で、見出しを宣言しない 2 つのセクション
- **WHEN** 表示する
- **THEN** セクションの境目には線が 1 本だけ表示される

### Requirement: 回転と列数の変化での位置 (セクション)
表示領域の縦横が変わって列数が変わったとき、表示範囲の先頭にあった項目を先頭に保つ (SHALL)。見出しが上端に固定されている場合は、その項目を固定中の見出しのすぐ下に保ち、見出しの裏に隠してはならない (SHALL NOT)。列数が変わっても、各セクションの最終行を除く行は新しい列数で埋まる (SHALL)。

#### Scenario: 固定中の見出しの下に戻る
- **GIVEN** 縦 2 列・横 4 列の向き別列数で、見出しを固定したセクションの途中を表示中 (表示範囲の先頭に項目 X)
- **WHEN** 表示領域が縦長から横長に変わる
- **THEN** 固定中の見出しのすぐ下の行に X が表示される

### Requirement: スクロールインジケータの全体の長さ (Android)
Android のスクロールインジケータは、全体の長さを見積もるときにセクションの見出しとルートのヘッダー / フッターをそれぞれ 1 行、各セクションの最終行を 1 行として数える (SHALL)。行の高さが揃っている場合、コンテンツの末尾に達したときにインジケータが下端に届き、それより手前で下端に着いてはならない (SHALL NOT)。iOS は標準のインジケータのままとする (SHALL)。

#### Scenario: 小さいセクションが多いグリッド
- **GIVEN** 行の高さと見出しの高さが揃った 2 列のグリッドで、奇数件のセクションを多数含む配列
- **WHEN** 先頭から末尾までスクロールする
- **THEN** インジケータは末尾に達したときに下端に届き、途中で下端に着いて止まらない

## MODIFIED Requirements

### Requirement: ルートヘッダー / フッター
コンテンツ全体の先頭・末尾に任意のビューを 1 つずつ配置できる (SHALL)。ヘッダー / フッターはコンテンツと一緒にスクロールし、固定されない (SHALL)。グリッドでは全幅を占める (SHALL)。宣言しない場合は何も表示されない (SHALL)。配列が空でも表示される (SHALL)。ヘッダー / フッターの前後には行間を入れない (SHALL)。`contentPadding` の上端はヘッダーの上に、下端はフッターの下に入る (SHALL — ヘッダー / フッターもコンテンツであり、core/ADR-0006 の内側余白の意味論に従う)。両プラットフォームで同じ位置関係になる (SHALL)。

#### Scenario: ヘッダーのスクロール追従
- **GIVEN** ヘッダーを宣言したリスト
- **WHEN** 下方向へスクロールする
- **THEN** ヘッダーはコンテンツと一緒に画面外へスクロールする

#### Scenario: 内側余白と行間の位置
- **GIVEN** 上下の内側余白と行間を指定し、ヘッダーとフッターを宣言したリスト
- **WHEN** 先頭と末尾を表示する
- **THEN** 内側余白はヘッダーの上とフッターの下にあり、ヘッダーと先頭行の間、最終行とフッターの間には行間が無い (両プラットフォームで同じ)

#### Scenario: 空配列でのヘッダー / フッター
- **GIVEN** ヘッダーとフッターを宣言し、配列が空のリスト
- **WHEN** 表示する
- **THEN** ヘッダーとフッターが表示され、項目は 0 件

#### Scenario: グリッドでの全幅ヘッダー
- **GIVEN** ヘッダーを宣言した 3 列グリッド
- **WHEN** 表示する
- **THEN** ヘッダーは 3 列分の幅を占め、要素はその下から 3 列で並ぶ

### Requirement: 配列の内部分割 (iOS)
ライブラリは配列を、セクションごと (グループの値を指定しない場合は配列全体を 1 つのセクションとする) に、その先頭から内部で固定件数の塊に分けて配置する (SHALL)。1 つの塊が 2 つのセクションにまたがってはならない (SHALL NOT)。塊の件数は全セクション共通で、固定列数と向き別列数では宣言された列数すべての倍数、列数が表示領域の幅で決まる layout (adaptive) では現在解決している列数の倍数とし (SHALL)、塊の境界に列数に満たない行を作ってはならない (SHALL NOT)。列数に満たない行は各セクションの最終行にだけ現れる (SHALL)。adaptive で列数が変わったとき、および layout 値の変更で、現在の塊の件数が新しい列数で割り切れなくなったときだけ塊を組み直し、表示範囲の先頭にあった項目を先頭に保つ (SHALL)。配列が同じでも塊の件数が合わなくなれば組み直す (SHALL)。塊の境界は行間・区切り線・内側余白・セクションの間隔・ルートのヘッダー / フッター・セクションの見出しのいずれにも現れず (SHALL NOT)、塊の分け方は公開 API と利用者の宣言に現れない (SHALL NOT)。項目の追加・削除・並べ替えで塊やセクションの所属が変わる項目は差分更新の対象になり、表示位置の変化と可視セルの扱いは塊が無い場合と同じで、塊の境界で位置が飛んではならず (SHALL NOT)、所属が変わらない可視セルは作り直されない (SHALL)。ID によるスクロール命令と末尾へのスクロール命令は塊とセクションに依らず解決される (SHALL)。項目が空でもルートのヘッダー / フッターは表示される (SHALL)。レイアウトの再解決に要する費用は塊の件数で上限が決まり、配列全体の件数に比例してはならない (SHALL NOT)。

#### Scenario: 塊の境界に不完全な行が無い
- **GIVEN** 2 列のグリッドで、塊の件数を超える配列
- **WHEN** 塊の境界の前後の行を表示する
- **THEN** 境界の直前の行は 2 列とも埋まり、境界の直後の項目は行頭に置かれる

#### Scenario: 塊はセクションをまたがない
- **GIVEN** 2 列のグリッドで、奇数件のセクションの後に別のセクションが続く配列
- **WHEN** 2 つのセクションの境目を表示する
- **THEN** 前のセクションの最終行だけが 1 列で、次のセクションの先頭の項目は見出しの後の行頭に置かれる

#### Scenario: 向き別列数で列数が変わっても不完全な行が無い
- **GIVEN** 縦長で 2 列・横長で 3 列の向き別列数を宣言した、塊の件数を超える配列
- **WHEN** 表示領域が縦長から横長に変わる
- **THEN** 各セクションの最終行を除く全ての行が 3 列で埋まり、表示範囲の先頭にあった項目が先頭に留まる

#### Scenario: adaptive で列数が変わると塊を組み直して位置を保つ
- **GIVEN** adaptive の列数で表示中の、塊の件数を超える配列と、表示範囲の先頭にある項目 X
- **WHEN** 表示領域の幅が変わって列数が変わる
- **THEN** 各セクションの最終行を除く全ての行が新しい列数で埋まり、X が表示範囲の先頭に留まる

#### Scenario: 塊の境界で行間と区切り線が変わらない
- **GIVEN** 区切り線を表示し行間を指定した list で、塊の件数を超えるセクション
- **WHEN** 塊の境界をまたぐ行を表示する
- **THEN** 上端の区切り線はセクションの先頭行だけに出て、境界の前後の行間は他の行間と同じである

#### Scenario: 内側余白は配列全体の上下にだけ付く
- **GIVEN** 上下の内側余白を指定した、塊の件数を超える配列
- **WHEN** 先頭・塊の境界・末尾を表示する
- **THEN** 余白は配列全体の先頭の上と末尾の下にだけあり、塊の境界には無い

#### Scenario: ルートのヘッダーとフッターは 1 つずつ
- **GIVEN** ルートのヘッダーとフッターを宣言した、塊の件数を超える配列
- **WHEN** 先頭から末尾まで表示する
- **THEN** ルートのヘッダーは配列全体の先頭に 1 つ、フッターは末尾に 1 つだけ表示され、項目を空にしても両方が表示される

#### Scenario: 先頭への挿入で塊の所属が変わっても位置が飛ばない
- **GIVEN** 塊の件数を超えるセクションで、表示範囲の先頭に項目 X がある
- **WHEN** そのセクションの先頭に 1 件挿入する
- **THEN** X の位置は挿入した行の高さと行間の分だけ動き、それ以外に飛ばない。所属が変わらない可視セルは作り直されない

#### Scenario: 先頭の削除で塊の所属が変わっても位置が飛ばない
- **GIVEN** 塊の件数を超えるセクションで、表示範囲の先頭に項目 X がある
- **WHEN** そのセクションの先頭の 1 件を削除する
- **THEN** X の位置は削除した行の高さと行間の分だけ動き、それ以外に飛ばない。所属が変わらない可視セルは作り直されない

#### Scenario: セクションをまたぐ挿入で後ろのセクションの塊が組み直る
- **GIVEN** 塊の件数を超える 2 つのセクションで、2 つめのセクションの途中の項目 X が表示範囲の先頭にある
- **WHEN** 最初のセクションの先頭に 1 件挿入する
- **THEN** X は表示範囲の先頭から飛ばず、X のセルは作り直されない

#### Scenario: 塊をまたぐ並べ替え
- **GIVEN** 塊の件数を超える配列を先頭から表示している
- **WHEN** 末尾の塊にある項目 Y を先頭へ移す
- **THEN** Y が先頭に表示され、移動しなかった可視セルは作り直されない

#### Scenario: スクロール命令は塊とセクションをまたいで解決する
- **GIVEN** 塊の件数を超える配列の、最後のセクションの末尾の塊にある項目 Y
- **WHEN** Y の ID へのスクロール命令と、末尾へのスクロール命令をそれぞれ行う
- **THEN** それぞれ Y と末尾の項目が表示範囲に入る

#### Scenario: 件数に比例しない
- **GIVEN** 同じ fixture の 2,000 件と 10,000 件のグリッド (起動引数で件数を指定)
- **WHEN** 基準実機で同じ固定の操作列の手動フリックを行い、初回の段階 (先頭から未訪問域へ下向きに 10 秒) の区間だけを対象に、レイアウトの再解決に要した主スレッド時間の占有率を time profile で比べる
- **THEN** 10,000 件の占有率は 2,000 件の 1.5 倍以下である。証跡には両走行の初回区間の長さと到達件数を残し、2,000 件の走行が初回区間で末尾に達していた場合、または両走行の初回区間の長さの差が 3 秒を超える場合は比較不能として未判定にする
