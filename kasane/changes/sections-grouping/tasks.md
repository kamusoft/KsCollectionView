## 2. iOS エンジン

- [ ] 2.1 配列の走査でグループを作り、グループごとに塊へ区切る。識別子を「グループの値 + 何回目か + グループ内の塊の順番」に広げ、塊の表 (グループ内の位置・塊の数・項目数・見出しの有無) を snapshot と同時に作る (→ Requirement: 配列の内部分割 (iOS) / グループの値によるグループ化。design Decision 3)
- [ ] 2.2 離れて現れた同じグループの値の検知 (debug は assertion、release は別グループで表示継続 + 警告ログ) (→ Requirement: 同じグループの値が離れて現れる入力)
- [ ] 2.3 sectionProvider: グループの先頭の塊に見出し (場所を取る)、2 つめ以降の塊に同じ見出し (場所を取らない) を付け、内側余白で行間・見出しの下の間隔・グループ間の間隔を置く (→ Requirement: グループの見出し / グループまわりの間隔。design Decision 5)
- [ ] 2.4 ルートのヘッダー / フッターをレイアウト全体の boundary supplementary item へ移し、`contentPadding` をその外側に置く (→ Requirement: ルートヘッダー / フッター。design Decision 6)
- [ ] 2.5 見出しの固定 (方式 3c): compositional layout の派生クラスで見出しの属性を複製して書き換える (y・横位置と幅・透明度)。固定を外したときは書き換えない。透明の見出しを読み上げの対象から外す (→ Requirement: 見出しの固定。design Decision 4)
- [ ] 2.6 区切り線の上線の判定を「グループの先頭の塊の先頭の項目」に広げ、見出しなしなら最初のグループだけにする (→ Requirement: グループを持つ list の区切り線。design Decision 7)
- [ ] 2.7 表示範囲の先頭の項目の選び方と回転での復元を、固定中の見出しに覆われた範囲を除いて行い、見出しのすぐ下へ戻す。ID によるスクロール命令も同じずらしを使う (→ Requirement: 回転と列数の変化での位置 (グループ)。design Decision 9)
- [ ] 2.8 グループをまたぐ挿入・削除で、塊の件数の変化判定と世代番号つきのアンカーが成り立つことを確かめ、必要なら直す (→ Requirement: 配列の内部分割 (iOS) の Scenario「グループをまたぐ挿入で後ろのグループの塊が組み直る」)
- [ ] 2.9 見出しの内容の更新: 配列の適用の完了時と観測する値の変化で、表示中の見出し (塊の見出しを含む) に新しい値と項目を設定し直す (→ Requirement: 見出しの内容の更新。design Decision 15)
- [ ] 2.10 エンジンのテスト: グループの構成・見出しの内容の更新・見出しの位置と固定・塊の境目の見出し・間隔・区切り線・差分 (移動・並べ替え・消滅)・不正入力・回転・スクロール命令・ルートのヘッダーの余白。既存のテスト (区切り線・ヘッダー・塊・アンカー) の期待値を新しい規則に合わせる (→ 各 Requirement の Scenario)
- [ ] 2.11 端を表示中の端への挿入: 差し替え前に先頭 / 末尾にいたかを控え、先頭に留まることを確かめ、末尾への挿入では差分のアニメーションの中で末尾に留める (list / グリッド) (→ Requirement: 端を表示中の端への挿入。design Decision 16)

## 3. Android ラッパー

- [ ] 3.1 グループの構成から、並べ方の表 (項目の位置 ⇔ lazy の index、見出しの位置、各項目がグループの先頭行 / 最終行か) を作る (→ Requirement: グループの値によるグループ化。design Decision 8)
- [ ] 3.2 離れて現れた同じグループの値の検知と、状態保存に載らないグループの値の検知 (core/ADR-0011 の扱い) (→ Requirement: 同じグループの値が離れて現れる入力 / グループの値の型 (Android))
- [ ] 3.3 見出しを並べる: 固定するときは `stickyHeader`、外すときは全幅の `item`。キーは内部の `Parcelable` 型 (グループの値 + 何回目か) (→ Requirement: グループの見出し / 見出しの固定 / グループの値の型 (Android)。design Decision 2・8)
- [ ] 3.4 行間を `Arrangement.spacedBy` から項目の余白へ移し、見出しの下の間隔・グループ間の間隔も項目の余白で置く。区切り線・タッチの反応範囲・高さの補間を content の範囲に合わせる (→ Requirement: グループまわりの間隔 / ルートヘッダー / フッター。design Decision 5・6)
- [ ] 3.5 区切り線の上線の判定をグループの先頭行に広げる (→ Requirement: グループを持つ list の区切り線)
- [ ] 3.6 スクロール命令と画像の先読み窓の index の写像を 3.1 の表に置き換える。固定中の見出しの下へずらす (→ Requirement: 回転と列数の変化での位置 (グループ) / 配列の内部分割 (iOS) の Scenario「スクロール命令は…」と同じ契約。design Decision 8・9)
- [ ] 3.7 スクロールインジケータの全体の行数と位置の行番号を 3.1 の表から数え直し、既存の位置の補正と重ねる (→ Requirement: スクロールインジケータの全体の長さ (Android)。design Decision 10)
- [ ] 3.8 使い捨ての試作 (エミュレータで `animateItem` なし / ありを切り替える画面) のオーナー目視で、`animateItem` を付ける位置・フェードの有無・高さ変化の補間と同時に動くときの扱いを決める (→ Requirement: グループをまたぐ差分更新。design Decision 13)
- [ ] 3.9 項目と見出し (固定中の `stickyHeader` を含む) に `animateItem` を付け、見出しのキーでの差分 (移動・並べ替え・消滅) をアニメーションで見せる。既存の「項目に `animateItem` を重ねない」前提のテスト・コメントを直す (→ 同上。android/ADR-0006)
- [ ] 3.10 端を表示中の端への挿入: 差し替え前に先頭 / 末尾にいたかを控え、先頭への挿入なら先頭に、末尾への挿入なら末尾に留める (list / グリッド) (→ Requirement: 端を表示中の端への挿入。design Decision 16)
- [ ] 3.11 Robolectric のテスト: 先頭への挿入・並べ方の表・見出しの位置と固定・間隔・区切り線・差分・不正入力・スクロール命令・インジケータの行数・ルートのヘッダーの余白。既存のテスト (行間・区切り線・ヘッダー / フッター・インジケータ・ヘッダー分の index のずれ) の期待値を新しい規則に合わせる (→ 各 Requirement の Scenario)

## 5. 検証 (evidence/)

- [ ] 5.1 塊の境目の見出しの見え方 (iOS): フレームごとの位置の記録 (ゆっくり / 速く) で隙間・かぶり・動き・欠けが 0 (→ Requirement: 見出しの固定。design Decision 12)
- [ ] 5.2 追加・削除のアニメーション中の見出しの位置 (iOS): 「グループ化」の 2 つの操作でフレームの位置を記録 (→ Requirement: グループをまたぐ差分更新)
- [ ] 5.3 VoiceOver で、塊に割れたグループの見出しが 1 つだけ読み上げられる (iOS) (→ Requirement: 見出しの固定)
- [ ] 5.4 iOS 16 の Simulator で、押し出し中の見出しの薄めが透明度で起きていて 3c で打ち消せることを確かめる (→ Requirement: 見出しの固定)
- [ ] 5.5 基準機の体感 (iPhone 11 相当 / Pixel 4a): handbook/cross/scroll-performance-gate の固定の操作列、「グループ化」画面。記録はオーナーの合図を待って始める。iOS は同じ走行の time profile で見出しの書き換えの主スレッド占有率も記録 (→ Requirement: グループを持つ大量件数での仮想化と滑らかさ)
- [ ] 5.6 Android の相対計測 (比較対象にインジケータと `animateItem` を付けた後) と、既存 fixture の回帰計測 (行間を項目の余白に移した影響)。`animateItem` 自体の費用はライブラリの「なし / あり」の比較を証跡に残し、体感で不合格なら 3.8 に戻って付け方を見直す (→ 同上)
- [ ] 5.7 端を表示中の端への挿入 (両プラットフォーム・list / グリッド): 「差分更新」画面でいちばん上での先頭への挿入、いちばん下での末尾への挿入のアニメーションが見えることをオーナーの目視で確かめる (→ Requirement: 端を表示中の端への挿入)
