# UI Brief: sections-grouping

## 画面と状態

UI に触れるのは 2 点。ライブラリ本体のセクションの見出しの既定の見え方 (固定・押し上げ・余白・区切り線。挙動の正はデルタスペック) と、Sample のデモ画面「グループ化」「差分更新」(sample-parity 準拠)。

### セクションの見出し (ライブラリ本体)

本体は見出しの見た目を持たない (利用者の View / Composable をそのまま置く)。見た目として本体が決めるのは位置関係だけで、これはデルタスペック (collection-layout) が正: 固定と押し上げ・見出しの前後に行間を入れないこと・2 つの間隔の入る場所・list の区切り線の位置。mock はその位置関係を Sample の見た目で示す。

### Sample「グループ化」

- **ルートメニュー**: 既存のデモ画面の末尾 (「画像グリッド」の次) に「グループ化」を追加。両プラットフォームで同じ位置
- **グループ化**: 10,000 件のグリッド (縦長 2 列 / 横長 4 列)。セルは「大量件数」と同じ行の見た目 (タイトル「Item n」、7 の倍数の項目だけ長文の説明)。見出しはグループ名 (「グループ n」) と件数 (「1,200 件」) を左右に置いた全幅の帯で、上端に固定される。セクションの間に間隔を置き、見出しと先頭行の間は行の間と同じ細い間隔
  - 状態: 通常のみ (データはローカル生成で loading / empty / error は無い)
  - 操作 1: 「グループの並び順を反転」
  - 操作 2: 「表示中の項目を 1 つ別のグループへ移す」
  - 操作の置き場は mock で選ぶ (案 A: ナビゲーションバーの右に短い文言で 2 つ / 案 B: 下部に固定したバーに 2 つのボタンと画面の説明)。mock: `mock/grouping-variant-a-nav-actions.html` / `mock/grouping-variant-b-bottom-bar.html`

### Sample「差分更新」

- **ルートメニュー**: 「グループ化」の次に「差分更新」を追加。両プラットフォームで同じ位置
- **差分更新**: 20 件 (動きを目で追える少なさ)。セルは「リスト」画面と同じ行の見た目 (タイトル「Item n」。更新した項目はタイトルに「★ 更新済み」を足す)。上部に表示の切り替え (「リスト / グリッド」のセグメントと「セクション」のスイッチ)。セクションありは 5 件ずつ 4 グループで、見出しは「グループ化」と同じ帯 (グループ名と件数)、固定される。list では区切り線を表示 (既定)
  - 状態: 通常のみ
  - 操作: 対象の位置の切り替え (先頭 / 中ほど / 末尾) と、位置ごとの 挿入 / 削除 / 更新 / 移動、位置によらない 反転 / シャッフル (Android の試作の目視で、末尾・中間の挿入と削除も要ると判定。2026-09-24)
  - 操作の置き場は mock で選ぶ (案 A: ナビゲーションバーの「操作」メニュー / 案 B: 下部に固定したバーに 3 列 × 2 行のボタン)。「グループ化」と同じ案に揃える。mock: `mock/diff-variant-a-nav-menu.html` / `mock/diff-variant-b-bottom-bar.html`

### 許容する差異 (sample-parity)

- OS 標準 chrome: `NavigationStack` ⇔ `Scaffold` + `TopAppBar`、ボタンの形状、戻る導線、メニュー (`Menu` ⇔ `DropdownMenu`)、セグメント・スイッチの形状
- 固定見出しの押し上げの細部 (iOS は UICollectionView の固定、Android は Compose の `stickyHeader`)。薄れないことは両方で守る (デルタスペック)

## リファレンス注釈

references/ なし。見出しの固定と余白の見え方の議論の素材は phase-4 の artifacts (試作の画面 3 枚と証跡: `kasane/roadmaps/v1-foundation/phases/phase-4-sections-grouping/artifacts/`)。試作の画面の見出しの色 (グループごとの色の帯) と「塊 n/m」の表示は試作専用で、採用しない。見出しの上下の余白が揃っていない点は試作の作りの都合で、本実装はデルタスペックの規則に従う。

## デザイントークン参照

concepts/ に UI トークンは未登録。Sample は `SampleTheme` (iOS `SampleTheme.swift` を正、Android `object SampleTheme` が同値) の既存トークン (accent / 背景 / セル背景 / テキスト主・副 / 区切り線色 / 横の余白 / 行の縦の余白) を使う。見出しの帯の背景は画面の背景と同じトークン、グループ名はテキスト主、件数はテキスト副。新しいトークンは足さない。見出しの高さ・セクション間の間隔などこの画面だけの値は画面固有の定義に置く (「画像グリッド」の `ImageGridMetrics` と同じ流儀)。

## 承認モック

案 B を採用 (`mock/grouping-variant-b-bottom-bar.html` と `mock/diff-variant-b-bottom-bar.html`、2 画面を並べて撮った `mock/approved.png`。2026-09-24 オーナー承認)。案 A (ナビゲーションバー / 「操作」メニュー) との違いは操作の置き場のみで、「差分更新」の操作を続けて 1 タップで押せることと、承認済みの「画像グリッド」と置き場が揃うことから下部バーを採った。

- 「グループ化」: 下部バーに「並び順を反転」「項目を別のグループへ」の 2 ボタンを全幅で並べ、その下に画面の説明の文言
- 「差分更新」: 表示の切り替え (「リスト / グリッド」のセグメント + 「セクション」のスイッチ) をナビゲーションバーの下の白い帯に置き、下部バーに位置のセグメント (先頭 / 中ほど / 末尾)、その下に 挿入 / 削除 / 更新 / 移動 の 4 ボタン、さらに 反転 / シャッフル / 元に戻す の 3 ボタン。20 件 (5 件ずつ 4 グループ)。Android の試作の目視 (操作の網羅と件数の多さの指摘) を受けて 2026-09-24 に作り直し、`approved.png` を撮り直してオーナーが再承認した
- 見出しの帯: 画面の背景と同じ色、グループ名 (テキスト主・太字) と件数 (テキスト副) を左右に。固定中の見出しもこの帯のまま

トークンは SampleTheme と同値 (accent #2F6FED / bg #F2F2F7 / cell #FFFFFF / text #111214 / text2 #6E7076 / separator #D9D9DE)。見出しの高さ・セクション間の間隔 (mock では 16)・見出しの下の間隔 (mock では行の間と同じ 1) は画面固有の定義に置く。
