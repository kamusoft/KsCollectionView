# Proposal: sections-grouping

## Why

グループ化 (固定される見出しつき) と、画面向きで列数が変わるグリッドとの組み合わせは、ロードマップ v1-foundation のゴールに挙げた自社実績機能で、旧 AiForms.CollectionView から引き継ぐ機能の最後の大物である。今の KsCollectionView は 1 つの配列を 1 続きで並べるだけで、利用者がグループの見出しを出すには見出しを項目として配列に混ぜるしかなく、項目のモデルを汚し、固定もできない。

phase-4 の議論 (agenda の決定事項) で、セクションの宣言の形 (core/ADR-0015)、list の区切り線のセクションごとの引き方 (core/ADR-0016)、iOS の内部の塊と論理セクションの重ね方と、塊に割れたグループの見出しの固定の方式 (ios/ADR-0010。Simulator の試作 2 周とオーナーの目視で決定) が確定した。本提案はそれを実装可能な契約に落とす。

## What Changes

- **セクションの宣言**: 利用者は平らな配列のまま、各項目の「どのグループか」を表す値 (グループの値) をキーパス / ラムダで指す。配列の順に同じ値が続く項目が 1 つのセクションになり、セクションはグループの値で識別する (core/ADR-0015)
- **セクションの見出し**: 任意の View / Composable。クロージャにグループの値とセクション内の項目が渡される。高さは中身から自動、グリッドでは全幅。セクションのフッターは持たない
- **見出しの固定**: 既定でスクロール時に上端へ固定し、設定 1 つで外せる。iOS で 500 件を超えて内部の塊に割れたグループも、グループ全体で 1 つの見出しとして固定し、グループの境目では薄れずに押し上げられる (ios/ADR-0010 の方式 3c)。Android は Lazy グリッドの固定見出しを使う
- **余白**: layout 値に、セクションとセクションの間の間隔と、見出しと先頭行の間の間隔を 1 つずつ足す (いずれも既定 0)。行間は行と行の間にだけ入り、見出しの上下には入らない
- **list の区切り線**: セクションごとに先頭行の上端・行の間・最終行の下端に引く。見出しを宣言しない場合は 2 つめ以降のセクションの上線を出さない (core/ADR-0016)
- **不正入力**: 同じグループの値が配列の離れた位置に再び現れたら、debug は assertion、release は別々のセクションのまま表示を続けて警告ログを出す (core/ADR-0011 の方針)
- **差分更新**: グループの値が変わった項目は新しいセクションへ移動し、グループの並べ替えでは見出しが項目と一緒に動き、空になったグループは見出しごと消える。移動・挿入・削除は両プラットフォームでアニメーションで見せる。Android は項目も見出しもキーで差分を取り、`animateItem` を付ける (android/ADR-0006、amends android/ADR-0004 の「`animateItem` は重ねない」。提案作成時にオーナー判断で改訂)
- **ルートのヘッダー / フッターの余白を両プラットフォームで揃える**: 前後に行間を入れず、`contentPadding` はヘッダーの上・フッターの下に入れる (core/ADR-0006 の意味論。今は iOS と Android で位置が違う)
- **iOS の内部の塊**: 論理セクションごとに先頭から塊に区切り、「グループの値 + セクション内の塊の順番」で識別する (ios/ADR-0010、amends ios/ADR-0009)。回転時の位置の復元は、固定見出しのすぐ下へ控えた項目を戻す
- **Android のスクロールインジケータ**: 全体の行数をライブラリが数え直し (見出し 1 行・各グループの端数の行 1 行)、全幅の項目による見積もりの短さを解消する
- **Sample デモ画面「グループ化」**: 両プラットフォームに sample-parity 準拠で追加する。10,000 件・縦 2 / 横 4 列、1,200 件前後の大きいグループ 2〜3 個と 5〜30 件の小さいグループ多数、差分アニメーションを確かめる操作 2 つ (グループの並び順の反転 / 見えている項目を別のグループへ移す)
- **Sample デモ画面「差分更新」**: 両プラットフォームに sample-parity 準拠で追加する。少ない件数 (60 件) で、挿入・削除・内容の更新・移動・反転・シャッフルを 1 操作ずつ試せる。list / グリッドとセクションの有無を切り替えられる。今の Sample には配列を差し替える操作がどの画面にも無く、差分のアニメーションを確かめる場所が無かった (オーナー指示)
- **検証**: Scenario ごとの自動テストに加え、「グループ化」画面での基準機の体感 (cross/ADR-0006) と、方式 3c で試作時に未確認だった 4 点 (追加・削除のアニメーション中の見出しの位置・VoiceOver・塊が多いときの書き換えの費用・体感) を evidence/ に残す。Android の相対計測の前に、比較対象の画面へスクロールインジケータを付ける

影響する能力: collection-layout (セクション・見出し・余白・区切り線・インジケータ) / collection-items (セクションの宣言・差分・不正入力) / samples (検証装置)

## Non-Goals

- 項目が 0 件のグループの見出し・グループの配列を渡す入口 — core/ADR-0015 で却下 (必要な画面が出たら Revisit When で再検討)
- セクションのフッター — agenda 決定 (後から足しても利用者コードを壊さない)
- セクションごとの layout 値 (セクションごとに list / グリッドを切り替える) — ロードマップの非ゴール
- セクションの背景装飾 (グループ全体を角丸の板に載せる見た目) — agenda 決定 (旧にもゴールにも無い)
- 並べ替えの DSL — core/ADR-0003 (データ層で並べ替え、ライブラリは差分の移動アニメーションだけ)
- 見出しの高さの指定 (旧 `GroupHeaderHeight`) — core/ADR-0015 (中身から自動)

## Impact

- 公開 API 追加 (両プラットフォーム): グループの値の指定、見出しの宣言、固定の設定、layout 値の 2 つの間隔。破壊的変更なし (いずれも省略時は今の見え方)
- 内部の大きな変更: iOS の snapshot と sectionProvider (塊の区切り方・識別・見出し・余白・区切り線)、Android のグリッドへの並べ方 (固定見出し・見出しの前後の行間・キー)
- リスク: iOS はグループ数がそのまま compositional layout のセクション数になり、小さいグループが多いデータでの費用が未知 (ios/ADR-0010 の負の帰結)。「グループ化」画面の体感で確かめる
- リスク: 方式 3c は、UIKit が押し出し中の見出しを透明度で薄める挙動 (iOS 26.5 Simulator で観測) を打ち消す。対応 OS の範囲 (iOS 16+) で同じ挙動かを確かめる
- 既存の見た目の変更: ルートのヘッダー / フッターまわりの余白 (iOS は `contentPadding.top` の位置、Android はヘッダーの下の行間) が変わる。配布前のため互換の手当てはしない
- リスク: Android の `animateItem` はスクロール中の性能に上乗せが出うる (android/ADR-0004 が禁じた理由)。付け方を試作の目視で決め、相対基準で確かめる
