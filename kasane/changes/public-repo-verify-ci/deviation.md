# Deviation: public-repo-verify-ci

- [付随修正] Android のテストの実行件数を確かめるスクリプト (期待するクラスを集める処理): テストのソースのファイルを走査する順を名前順にした。理由: 失敗の理由に並ぶ場所の順を、実行ごとに同じにするため (2026-10-08)
- [付随修正] workflow の定義を確かめるスクリプト: ランナーで走るジョブが時間の上限を持たないと違反にする検査を足した。再利用 workflow を呼ぶだけのジョブは対象外。あわせて、同じことを確かめていたスクリプトのテスト 1 件を消し、入口の workflow の該当の step のコメントを直した。理由: Requirement「道具の固定と権限」の「各ジョブは時間の上限を持ち」を、workflow を足したり直したりしたときにも機械で守るため。オーナーが同梱を決めた (2026-10-08)
- iOS の検証: spec では「iOS 本体のテストを Simulator で全件走らせ、続けて iOS Sample のビルドとユニットテストを走らせる。実行の件数が 0 のとき、または読み取れないときは失敗で終わる」→ 指示により、検証 CI では Simulator を使うテストを走らせない。`ios / verify` は、本体と本体のテスト、Sample のアプリと Sample のテストがビルドできることだけを確かめる。iOS のテストの実行と件数の確認は、手元の完了判定に任せる。理由: 最初の実行で、手元では通る本体のテスト 1 件がランナーの Simulator で落ちた。オーナーの判断は「CI の上で Simulator を使うテストを続けると、不安定さに悩まされ続ける」(2026-10-08)
- 道具の固定と権限 (iOS の Simulator の選び方): design の Decision 5 では「Simulator は、使える iPhone のうち OS が最も新しいものを、実行のときに選ぶ」→ 上の指示により、Simulator を選ばない (特定の Simulator を起動せずにビルドする)。使う Simulator を選ぶスクリプトと、iOS のテストの実行件数を確かめるスクリプトは、呼ぶ所が無くなるので取り除く。コマンドを流して出力を記録に残すスクリプト (design の Decision 3 の 6 つのうちの 1 つ、tasks 3.6) も、iOS のテストの記録を残すためだけに使っていて、Android は使っていなかったので、あわせて取り除く (ビルドの成否は `xcodebuild` の終了コードで決まる)。3 本のテスト (計 25 件) も取り除く。理由: 同上 (2026-10-08)
- 蒸留時に反映: decisions・cross/ADR-0013 — 検証 CI の緑が保証する範囲から、iOS のテストの実行 (本体の全件・Sample のユニットテスト) を外し、iOS は「ビルドできること」までとする内容に直してから accepted にする。外した理由 (ランナーの Simulator での不安定さ) と、iOS のテストは手元の完了判定が本命であることを書く
