## 指摘事項

### [🟡 Minor (優先度: 低)] クラスの宣言と同じ行の後ろに `object 名前`・`interface 名前` と読める語があると、そのクラスが期待の集合から黙って抜ける

**該当箇所**: `scripts/ci/check-android-test-count.py:183-198` (`test_classes_in_source`)、`scripts/ci/check-android-test-count.py:46-56` (docstring)

**関わる仕様**: verification-ci「Android の検証」— 失敗の条件「テストのソースにあるテストのクラスのうち、結果に現れないものがある」、Scenario「一部のクラスの結果しか無いと落ちる」。

**問題点**: 行頭の行に宣言が複数読めたとき、後ろの行の印が属する先は、その行の最後の宣言になる (`current = declared[-1][1]`)。宣言の語は、コメントや文字列の中でも読まれる。そのため、クラスの宣言の後ろに `object 名前` か `interface 名前` と読める並びがあると、属する先が「結果に現れない宣言」になり、そのクラスの印はすべて数えられない。属するクラスを導けない印にもならない。

```kotlin
class ATest { // interface の実装を確かめる
    @Test
    fun a() {}
}
```

再現: 上のソースを渡すと、期待の集合は空、属するクラスを導けない印は 0 件になる (`// object under test` でも同じ。名前の部分は日本語の文字にも当たる)。ほかにテストのクラスがあれば、`ATest` の結果が無くても失敗にならない。1 行に書いたクラスで、印より前に名前つきの `companion object` や入れ子の `interface` がある場合 (`class ATest { companion object Shared { … } @Test fun a() {} }`) も同じ。

後ろの語が `class 名前` のときは、実在しないクラスが期待に入って失敗になるので、黙っては通らない。

冒頭の説明は、決められない形を 1 つ、拾えない形を 2 つ挙げ、コメントや文字列の中の印については「黙って通る側には倒れない」と書いている。この形はどこにも当たらず、説明から読み取れない。

現在のリポジトリにこの形は無い (行頭の行に宣言が 2 つ以上読める行は 0 件)。クラスの宣言の行の末尾にコメントを書くことも、テストのクラスを 1 行に書くことも、整形されたソースではまず無い。2 周目の指摘より起きにくいので、優先度は低い。承認は妨げない。

**推奨修正**: 次のどちらか。

- 行頭の行に、属する先の違う宣言が 2 つ以上読めたときは、後ろの行のために引き継ぐ先を空にする (`current` を `None` にする)。後ろの字下げした印は「属するクラスを導けない @Test」として失敗になり、黙って通らなくなる。同じ行の中の印の扱い (印より前の最後の宣言) は変えなくてよい。テストを 1 件足す
- 直さない場合は、冒頭の説明の「拾えない形」に、この形を足す
