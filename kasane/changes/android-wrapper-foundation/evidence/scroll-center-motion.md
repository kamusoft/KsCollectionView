# スクロール命令の動きの過程 (Android / Pixel 4a)

オーナー実機確認で挙がった「`scrollTo(id, position = Center)` が行き過ぎてから戻る」の
再現と解消を、**動きの過程のスクロール量の数値**で判定した記録。静止画では往復が写らないため、
毎フレームのスクロール量を採って符号反転の回数で見る。

## 手順

- 画面: Sample「スクロール制御」。操作: 「Item 50」ボタンを 1 回押す (`scrollTo(id = 50, Center)`)
- 端末: Pixel 4a / Android 13。ウィンドウアニメーションの倍率は 1.0
- 採取: 計測用に本体へ毎フレームのログを 1 か所だけ足したビルドで採り、採取後に外した。
  最終コードとの差はそのログ行のみで、スクロールの実装は同一
- スクロール量 = 先頭可視項目の index × 行高 + 先頭可視項目のずれ (行高は全行 193px で一定)
- 判定: 系列の隣接差のうち、全体の進行方向と逆向きのものを数える

ログの抜粋 (`scripts/log-sanitize.py` 経由):

```
09-05 15:36:18.294 D/KsProbe (PID): t=3150579693 idx=0 off=0 h=193
09-05 15:36:18.310 D/KsProbe (PID): t=3150579710 idx=0 off=0 h=193
```

## 結果 (A/B)

| ビルド | ログに現れた位置の更新回数 | 到達位置 | 符号反転フレーム数 | 最大逆行量 |
|---|---:|---:|---:|---:|
| 修正前 (対象を先頭合わせしてから中央へ補正する 2 段階) | 28 | 8,667 px | **15** | 188 px |
| 修正後 (推定高から求めたずれを 1 回の命令へ渡す) | 11 | 8,667 px | **0** | 0 px |

到達位置はどちらも同じ 8,667 px であり、**最終位置だけを見ると差が出ない**。差は過程にだけ現れる。

左の列は debug ビルドでログに現れた位置の更新回数であり、**実際に描画されたフレーム数ではない**
(debug ビルドでは 1 フレームに 100〜300 ms かかる区間があり、描画された相異なる位置は
これより少ない)。判定に使うのは符号反転フレーム数と最大逆行量であり、こちらは描画された
フレームで数えても同じ結論になる。この表の回数を性能の目安として引かないこと。

### 修正前のスクロール量の系列 (px)

```
0, 0, 2512, 6848, 9456, 9457, 9457, 9356, 9168, 9010, 8885, 8801, 8750, 8716,
8695, 8684, 8677, 8672, 8670, 8669, 8668, 8668, 8667, ...
```

いったん 9,457 px (対象の先頭が表示範囲の先頭に来る位置) まで進み、そこから 790 px = 約 4 行分を
15 フレーム (約 250 ms) かけて戻っている。これがオーナーの見た「行き過ぎてから戻る」動き。

### 修正後のスクロール量の系列 (px)

```
0, 0, 883, 4978, 8665, 8667, 8667, 8667, ...
```

行き過ぎが無く、目的の位置へ一方向で着地している。

## 検証層のテストとの対応

同じ判定を Robolectric でも掛けている (`KsCollectionViewInteractionTest`)。

| テスト | 内容 |
|---|---|
| `animatedCenterScrollNeverReversesDirection` | 等高リストの Center。逆向きの移動 0 件 |
| `animatedEndScrollNeverReversesDirection` | 等高リストの End。逆向きの移動 0 件 |
| `animatedCenterScrollNeverReversesWithMixedItemHeights` | 高さの異なる 2 テンプレート混在。高さの推定が外れても逆向きの補正が入らないこと |

修正前の実装でこの 3 件を走らせるといずれも失敗し (逆向き 10〜15 フレーム)、修正後は通る。
