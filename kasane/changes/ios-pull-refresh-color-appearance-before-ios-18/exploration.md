# Exploration: ios-pull-refresh-color-appearance-before-ios-18

## 課題 / 動機

iOS 17.5 で、読み込み中の表示の色に、ライトとダークで値が切り替わる色を指定した一覧を出したまま表示モードをダークへ切り替えても、Pull to Refresh のインジケータの色がライト用の色のまま残る。`library-default-colors-dark-mode` の実装で、iOS のライブラリのテストを iOS 17.5 のシミュレータ (iPhone 15) で全件流したときに見つけた (2026-10-06、オーナー指示で起票)。

- 失敗するテスト: `ios/Tests/KsCollectionViewTests/KsLoadingIndicatorColorTests.swift:294` の「色を指定した一覧の表示モードが変わると Pull to Refresh の部品の色が追随する」。引っ張って取り直しの処理を待たせたまま、window の外観をライト → ダークに上書きする。ライトの確認は通り、ダークの確認 (アサート 2 つ) が落ちる。ダークへ切り替えた後も、部品の色はライト用の色を補正した値のままだった
- 変更前 (`library-default-colors-dark-mode` の実装の前、commit b7c22f8) のソースの写しでも同じ失敗を再現した。同変更が原因ではない
- iOS 18.6・27.0 では同じテストが成功する (567 件すべて成功)
- 関連する既知の未確認: `paging-indicator-color` (archive 済み) は、Pull to Refresh に渡す色を成分ごとの平方根に補正する形にし、「iOS 16・17 での補正は未確認」としていた。今回の失敗はその範囲に当たる
- ライブラリの最低対応は iOS 16 (`ios/Package.swift`)

`ios-adaptive-color-settings-before-ios-18` との違い: そちらは、公開の設定が受け取った SwiftUI の色を UIKit の色へ変換する時点で、外観で値の変わる性質が落ちる話である。このテストは、外観で値の変わる UIKit の色を内部の設定へ直接入れており、その変換を通らない。別の原因である見込みだが、直す場所が重なる可能性はある。

確かさの限界: 原因は調べていない。確かめたのは、テストが読んだ部品の色の値だけで、アプリの画面での見え方は見ていない。iOS 16 はランタイムが無く未確認。
