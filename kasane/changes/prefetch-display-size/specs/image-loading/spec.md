# image-loading — デルタスペック (prefetch-display-size)

対象能力: 画像のプリフェッチ・専用画像コンポーネント `KsImage` (iOS / Android 共通の契約)。基底は `kasane/changes/image-loading/specs/image-loading/spec.md` (archive 後は `kasane/changes/archive/*-image-loading/specs/image-loading/spec.md`)。ここに無い Requirement は基底のまま。

## ADDED Requirements

### Requirement: プリフェッチの表示幅
`prefetchResources` のクロージャが返す各要素 `KsResource` は、URL に加えて任意の表示幅 `KsWidth` を持てる (SHALL)。表示幅は「列幅」(`column`: 現在のレイアウトの 1 列分の幅) と「固定値」(`fixed`: pt / dp の 1 値) のどちらかで、高さ・縦横比・当てはめ方は宣言しない (SHALL NOT)。表示幅の無い要素は元寸の扱いになる (SHALL)。到達点 `memory` では、表示幅のある要素は宣言した幅の正方形を覆う最小の大きさに縮小してデコードした画像をメモリキャッシュに載せ、元寸の画像はメモリに載せない (SHALL)。元寸がその大きさより小さい画像は拡大せず元寸のまま載せる (SHALL)。到達点 `disk` では表示幅を使わず、元データの保存までで止める (SHALL)。列幅は画面の向き・列数・余白から求め、それらが変わった後に始まる先読みは新しい列幅で行う (SHALL)。固定値は有限かつ 0 より大きい値だけを有効とし、無効な値 (0・負数・NaN・無限大・未指定) は不正入力として debug では assertion で停止し、release では警告ログを出してその要素を表示幅なし (元寸) として扱う (SHALL)。列幅が 0 以下に解ける間 (余白と列間隔がコンテナ幅を超える等) は、列幅の要素の先読みを開始しない (SHALL)。

#### Scenario: 列幅で縮小して載せる
- **GIVEN** 3 列のグリッドで、各アイテムの URL を列幅 (`KsResource(url, width: .column)`) で宣言した到達点 `memory` の `prefetchResources`
- **WHEN** 元寸が列幅より大きい画像のアイテムが先読みの対象になり取得が完了する
- **THEN** メモリキャッシュには列幅の正方形を覆う大きさの画像が載り、元寸の画像は載らない

#### Scenario: 固定値で縮小して載せる
- **GIVEN** URL を固定値 (例: `.fixed(40)` pt / `Fixed(40.dp)`) で宣言した到達点 `memory` の `prefetchResources`
- **WHEN** 先読みの取得が完了する
- **THEN** メモリキャッシュには 40 (表示倍率込みの px) の正方形を覆う大きさの画像が載る

#### Scenario: 元寸が小さければ拡大しない
- **GIVEN** 宣言した幅より小さい元寸の画像
- **WHEN** 先読みの取得が完了する
- **THEN** 元寸のままメモリキャッシュに載る

#### Scenario: 幅あり・幅なしの混在
- **GIVEN** 1 アイテムにつき、列幅の要素と表示幅なしの要素を返す到達点 `memory` の宣言
- **WHEN** そのアイテムの先読みが完了する
- **THEN** 列幅の要素は縮小した画像が、表示幅なしの要素は元寸の画像がメモリキャッシュに載る

#### Scenario: 向きが変わると新しい列幅で先読みする
- **GIVEN** 列幅で宣言した到達点 `memory` の画像グリッドが縦向きで先読み済み
- **WHEN** 横向きに変わり、新しいアイテムが先読みの対象になる
- **THEN** 新しいアイテムの取得は横向きの列幅で行われる。既に載っている縦向きの列幅の項目は消されない

#### Scenario: 到達点 disk では幅を使わない
- **GIVEN** 列幅で宣言した到達点 `disk` の `prefetchResources`
- **WHEN** 先読みの取得が完了する
- **THEN** 元データがディスクキャッシュに保存され、メモリキャッシュには何も載らない

#### Scenario: 無効な固定値は幅なし扱い
- **GIVEN** 固定値に 0 を渡した `KsResource` を返す到達点 `memory` の宣言
- **WHEN** release ビルドでそのアイテムが先読みの対象になる
- **THEN** 警告ログが出て、その URL は元寸で先読みされる (debug ビルドでは assertion で停止する)

#### Scenario: 列幅が解けない間は始めない
- **GIVEN** 余白と列間隔の合計がコンテナ幅を超えるレイアウトで、列幅で宣言した到達点 `memory` の宣言
- **WHEN** アイテムが先読みの対象になる
- **THEN** その要素の取得は開始されない (コンテナ幅が広がって列幅が正になった後に対象になったアイテムから開始される)

### Requirement: KsImage のメモリ項目の引き当て
`KsImage` は表示枠の実サイズが確定したとき、同じ識別子 (Requirement「画像の任意キー」) についてライブラリが把握しているメモリキャッシュ項目 (ライブラリの先読みまたは `KsImage` が要求した項目。把握は上限つきで、上限を超えて外れた項目は把握の対象に戻らない) のうち、当てはめ方で枠に合わせるのに必要な拡大率が許容範囲の内側にある項目があれば、それを縮小・再デコードせずに成功状態の表示に使う (SHALL)。把握から外れた項目やローダー付属ビューが載せた項目は引き当ての対象にならず、通常の縮小要求に落ちる (契約違反ではない) (SHALL)。許容範囲は「項目の寸法が必要な寸法の下限倍以上・上限倍以下」で、値はライブラリが定める (SHALL)。範囲内の項目が複数あれば必要な寸法に最も近い項目を使う (SHALL)。範囲内の項目があるときはローダーへ取得要求を出さない (SHALL NOT)。範囲内の項目が無いときは、枠の実サイズに縮小してデコードする要求を出す (SHALL)。引き当てはメモリ項目の画素の置き場 (ハードウェア支援の有無) に依存しない (SHALL)。`KsImageCache` の `clear` / `remove` で消えた項目は引き当ての対象にならない (SHALL NOT)。

#### Scenario: 先読みの縮小済み項目を使う
- **GIVEN** 列幅で宣言した到達点 `memory` の先読みが完了した URL
- **WHEN** 同じ URL を列幅の枠の `KsImage` で表示する
- **THEN** 読み込み中を経由せず、デコードのやり直しもローダーへの要求も無く、先読みが載せた項目で表示される

#### Scenario: 原寸の項目を実機でも使う
- **GIVEN** 表示幅なしで宣言した到達点 `memory` の先読みが完了し、元寸がハードウェア支援の画像としてメモリにある URL (元寸は枠の上限倍以下)
- **WHEN** 同じ URL を `KsImage` で表示する
- **THEN** 読み込み中を経由せず、原寸の項目がそのまま表示に使われ、描画で枠に合わせられる

#### Scenario: 小さすぎる項目は使わない
- **GIVEN** 枠の下限倍未満の寸法の項目だけがメモリにある URL
- **WHEN** その枠の `KsImage` で表示する
- **THEN** その項目は使われず、枠の実サイズで縮小デコードする要求が出る (読み込み中を経由する)

#### Scenario: 大きすぎる項目は使わない
- **GIVEN** 枠の上限倍を超える寸法の項目だけがメモリにある URL
- **WHEN** その枠の `KsImage` で表示する
- **THEN** その項目は使われず、枠の実サイズで縮小デコードする要求が出る

#### Scenario: 縦長の枠に fill するときは高さで判定する
- **GIVEN** 幅は枠と同じだが高さが枠の下限倍未満の横長の項目だけがメモリにある URL
- **WHEN** 縦長の枠に `fill` の `KsImage` で表示する
- **THEN** その項目は使われず、枠の実サイズで縮小デコードする要求が出る

#### Scenario: 消した項目は引き当てない
- **GIVEN** 先読みの項目がメモリにある URL
- **WHEN** `KsImageCache.remove` でそのソースを消してから `KsImage` で表示する
- **THEN** 消した項目は使われず、再取得される

### Requirement: 画像の任意キー
先読みの要素 `KsResource` とリモートの画像ソース (`KsImageSource.remote` / `Remote`、便宜形 `KsImage(url)` を含む) は、URL に加えて任意のキー `key` (文字列) を持てる (SHALL)。画像の識別子は、`key` を指定した画像では `key`、指定しない画像では URL とする (SHALL)。`key` の識別子は URL の識別子と区別され、`key` の文字列がある URL と同じでも、その URL (`key` なし) の画像とは別の画像として扱う (SHALL)。キャッシュを消したソースに付く世代も、他の識別子と衝突しない (SHALL NOT)。`key` を指定した画像は、取得 (ネットワーク) にだけ URL を使い、メモリキャッシュ・ディスクキャッシュの項目・先読みの取得単位・`KsImageCache.remove` の対象は識別子で決まる (SHALL)。先読みの宣言が変わったかどうかは識別子・表示幅の種類・URL で判定し、`key` が同じでも URL が変わった要素は、進行中の取得を取り消して新しい URL で出し直す (失効した URL の取得が失敗したままにならないため) (SHALL)。したがって URL が違っても `key` が同じ画像は同じ画像として扱う (SHALL)。`key` を持てるのはリモートの画像だけで、端末内のファイルとアセット / リソースには持たせない (SHALL NOT)。空文字の `key` は不正入力として debug では assertion で停止し、release では警告ログを出して `key` なし (URL が識別子) として扱う (SHALL)。先読みと表示で `key` が食い違うと別の画像として扱われる (契約違反ではない) (SHALL)。

#### Scenario: 署名が変わっても先読みの項目を使う
- **GIVEN** 到達点 `memory` の宣言で `KsResource(url1, width: .column, key: "p1")` の先読みが完了している
- **WHEN** 同じ画像を署名だけが違う URL で `KsImage(source: .remote(url2, key: "p1"))` として列幅の枠で表示する
- **THEN** 読み込み中を経由せず、ネットワークアクセスもデコードのやり直しも無く、先読みが載せた項目で表示される

#### Scenario: 起動をまたいでもディスクの項目を使う
- **GIVEN** `key: "p1"` を付けたリモート画像が過去の起動で取得され、ディスクキャッシュに保存されている
- **WHEN** アプリを起動し直し、署名だけが違う URL に `key: "p1"` を付けた `KsImage` で表示する
- **THEN** ネットワークアクセスなしにディスクの元データから表示される

#### Scenario: key なしは URL で識別する
- **GIVEN** `key` を付けずに URL1 で取得済みのリモート画像
- **WHEN** 同じ画像を別の URL2 (`key` なし) で表示する
- **THEN** 別の画像として扱われ、URL2 から取得される

#### Scenario: key と URL は衝突しない
- **GIVEN** URL1 (`key` なし) で取得済みの画像 A
- **WHEN** 別の画像 B を `key` に URL1 と同じ文字列を付けて表示し、その後 `KsImageCache.remove(.remote(url1))` (`key` なし) を呼ぶ
- **THEN** B は A の項目を使わずに取得され、`remove` で消えるのは A の項目だけで B の項目は残る

#### Scenario: 削除の世代は別の key と衝突しない
- **GIVEN** `key: "p1"` の画像を `remove` した後に表示し直した画像 P と、`key` に `p1` と世代の区切りを連ねた文字列 (例: `"p1#1"`) を付けた別の画像 Q
- **WHEN** P と Q を表示する
- **THEN** P と Q は互いの項目を使わない

#### Scenario: 署名だけが変わった配列の差し替えでは新しい URL で出し直す
- **GIVEN** `key` を付けた要素で先読みの取得が進行中のアイテム X
- **WHEN** X の URL だけが違う (同じ `key` の) 配列に差し替える
- **THEN** 旧 URL の取得は取り消され、新しい URL で取得が開始される

#### Scenario: 取得済みの画像は署名が変わっても取り直さない
- **GIVEN** `key` を付けた要素で先読みの取得が完了しているアイテム X (X は先読みの対象のまま)
- **WHEN** X の URL だけが違う (同じ `key` の) 配列に差し替える
- **THEN** 出し直された要求は `key` でキャッシュに当たり、ネットワークアクセスは発生しない

#### Scenario: 空文字の key は key なし扱い
- **GIVEN** `key` に空文字を渡した `KsResource` とリモートの画像ソース
- **WHEN** release ビルドで先読みと表示を行う
- **THEN** 警告ログが出て、URL を識別子として扱われる (debug ビルドでは assertion で停止する)

## MODIFIED Requirements

### Requirement: プリフェッチ宣言
`prefetchResources` (Swift modifier / Kotlin 名前付き引数) で、アイテムからそのアイテムが必要とするリモート画像の `KsResource` (URL + 任意の表示幅 + 任意のキー) の配列を返すクロージャを宣言できる (SHALL)。URL だけの配列 (`[URL]` / `List<String>`) は受け付けない (SHALL NOT。配布前の破壊的変更)。データ型にライブラリの protocol / interface への準拠を要求しない (SHALL NOT)。任意引数 `destination` で到達点を `disk` (既定) と `memory` から選べる (SHALL)。宣言が無いコレクションではプリフェッチは一切起きず、可視範囲の観測も行わない (SHALL NOT)。クロージャが空配列を返したアイテムは何も取得しない (SHALL)。表示幅の無い `KsResource` は、到達点 `memory` では元寸の画像をメモリキャッシュに載せる (SHALL)。

#### Scenario: もうすぐ表示されるアイテムの画像を取得する
- **GIVEN** `prefetchResources` を宣言した画像グリッドが表示されている
- **WHEN** 先頭から末尾方向へスクロールする
- **THEN** 可視範囲の先 (進行方向) にあるアイテムについて、クロージャが返した要素の取得が到達点付きで開始される

#### Scenario: 宣言が無ければ何も起きない
- **GIVEN** `prefetchResources` を宣言していないコレクション
- **WHEN** スクロールする
- **THEN** ローダーへの取得要求は発生しない

#### Scenario: 複数 URL の宣言
- **GIVEN** クロージャが 1 アイテムにつき 2 つの要素を返す宣言
- **WHEN** そのアイテムが先読みの対象になる
- **THEN** 2 つの URL の両方について取得が開始される

#### Scenario: 幅なしの要素は元寸を載せる
- **GIVEN** 表示幅なしの `KsResource` を到達点 `memory` で宣言した画像グリッド
- **WHEN** 先読みの取得が完了する
- **THEN** 元寸の画像がメモリキャッシュに載る

### Requirement: プリフェッチの取り消し
先読みの対象から外れたアイテムの取得は取り消される (SHALL)。配列の差し替えで消えたアイテムの取得も取り消される (SHALL)。コレクションが画面から消えた (破棄された) ときは未完了の取得をすべて取り消す (SHALL)。取り消しは進行中の取得にのみ作用し、完了してキャッシュに入ったものは消さない (SHALL NOT)。取得の単位は到達点で決まり、`disk` は識別子 (Requirement「画像の任意キー」。`key` があれば `key`、無ければ URL) 単位 (表示幅が違っても同じ取得として数える)、`memory` は識別子 + 表示幅 (px) 単位とする (SHALL)。アイテムの宣言が変わったかどうかは識別子・表示幅の種類・URL で判定する (SHALL。`key` を指定した要素の URL だけが変わった場合の扱いは Requirement「画像の任意キー」)。同じ単位の取得を複数のアイテムが必要とする場合、まだ必要としているアイテムが 1 つでも残る限り取り消さない (SHALL NOT)。到達点 `memory` で同じ識別子でも表示幅が違う取得は別の取得として数え、一方の取り消しが他方に及ばない (SHALL NOT)。取り消しは取得を始めたときの要求に対して行い、その後に列幅が変わっていても始めたときの取得が止まる (SHALL)。列幅が変わっただけでは、既に始めた取得を取り消さず、出し直しもしない (SHALL NOT)。`prefetchResources` のクロージャと `destination` は表示中に差し替えない前提の宣言とし、差し替えた場合は以後の新しい取得にだけ反映される (SHALL)。

#### Scenario: スクロール方向の反転で取り消される
- **GIVEN** 末尾方向へのスクロールで先読みが開始されたアイテム群
- **WHEN** スクロール方向を先頭方向へ反転する
- **THEN** 進行方向の先に無くなったアイテムの取得は取り消され、新しい進行方向の先のアイテムの取得が開始される

#### Scenario: 配列の差し替えで消えたアイテム
- **GIVEN** 先読み中のアイテム X を含む配列
- **WHEN** X を除いた配列に差し替える
- **THEN** X の取得は取り消される

#### Scenario: 共有 URL は最後のアイテムが外れるまで取り消さない
- **GIVEN** アイテム A と B が同じ URL を同じ表示幅で返す宣言で、両方が先読み中
- **WHEN** A だけが先読みの対象から外れる
- **THEN** その URL の取得は継続し、B も外れた時点で取り消される

#### Scenario: 幅が違えば別の取得 (memory)
- **GIVEN** 到達点 `memory` で、同じ URL を固定値 40 で返すアイテム A と、列幅で返すアイテム B が先読み中
- **WHEN** A だけが先読みの対象から外れる
- **THEN** 40 の取得だけが取り消され、列幅の取得は継続する

#### Scenario: disk では幅違いも 1 つの取得
- **GIVEN** 到達点 `disk` で、同じ URL を固定値 40 で返すアイテム A と、列幅で返すアイテム B が先読み中
- **WHEN** A だけが先読みの対象から外れる
- **THEN** その URL の取得は継続し、B も外れた時点で取り消される

#### Scenario: 向きが変わっただけでは触らない
- **GIVEN** 列幅で宣言した到達点 `memory` の先読みが進行中のアイテム群
- **WHEN** 横向きに変わる (アイテムは先読みの対象のまま)
- **THEN** 進行中の取得は取り消されず、出し直されもしない。その後に新しく対象になったアイテムだけが横向きの列幅で始まる

#### Scenario: 向きが変わった後の取り消し
- **GIVEN** 縦向きの列幅で先読みを開始したアイテム
- **WHEN** 横向きに変わってからそのアイテムが先読みの対象から外れる
- **THEN** 縦向きの列幅で始めた取得が取り消される

#### Scenario: 画面から消えたら全て取り消す
- **GIVEN** 先読み中のアイテムがあるコレクション
- **WHEN** その画面を閉じる
- **THEN** 未完了の取得はすべて取り消される

### Requirement: プリフェッチの到達点
到達点 `disk` では元データをディスクキャッシュに保存するまでで止め、デコードは行わない (SHALL)。到達点 `memory` では元データをディスクに保存した上で、デコード済みの画像をメモリキャッシュにも載せる (SHALL)。メモリに載せる画像の寸法は要素の表示幅で決まり、表示幅なしは元寸、表示幅ありは宣言した幅の正方形を覆う大きさ (元寸が小さければ元寸) とする (SHALL)。どちらの到達点でも、プリフェッチが取得した画像は同じ識別子の画像を `KsImage` で表示するときに再ダウンロードなしで使われる (SHALL)。到達点 `memory` で載せた項目が `KsImage` の枠に対して許容範囲の内側にあり、ライブラリの把握 (Requirement「KsImage のメモリ項目の引き当て」) から外れていなければ、その表示はデコードのやり直しも読み込み中の経由もなしに行われる (SHALL)。プリフェッチはローダーの共有インスタンスのキャッシュを使い、ライブラリ独自のキャッシュ領域を持たない (SHALL NOT)。

#### Scenario: ディスク到達点の後の表示
- **GIVEN** 到達点 `disk` で URL の取得が完了している
- **WHEN** 同じ URL を `KsImage` で表示する
- **THEN** ネットワークアクセスなしにディスクの元データから表示される

#### Scenario: メモリ到達点の後の表示
- **GIVEN** 到達点 `memory` で URL の取得が完了し、載った項目が `KsImage` の枠に対して許容範囲の内側にある
- **WHEN** 同じ URL を `KsImage` で表示する
- **THEN** ネットワークアクセスもデコードのやり直しもなしに、読み込み中を経由せず表示される

#### Scenario: 到達点が伝わる
- **GIVEN** `destination: memory` を付けた宣言
- **WHEN** アイテムが先読みの対象になる
- **THEN** 取得要求は `memory` の到達点で発行される (既定の宣言では `disk`)

### Requirement: 共有キャッシュ
プリフェッチと `KsImage` はローダーの共有インスタンス (iOS: Nuke の共有パイプライン、Android: Coil の singleton ImageLoader) を使う (SHALL)。同じローダーの付属ビューを利用者が直接使った場合も同じキャッシュを見る (SHALL)。ただし `key` を指定した画像 (Requirement「画像の任意キー」) の項目は識別子が `key` になるため、ローダー付属ビューを URL で直接使う側とは共有されない (別の項目として扱われ、壊れはしない) (SHALL)。iOS では、ライブラリの初回利用時に共有パイプラインにディスクキャッシュが設定されていなければ、ディスクキャッシュを有効にした構成で共有パイプラインを差し替える (SHALL)。既に設定されていれば変更しない (SHALL NOT)。

#### Scenario: ローダー付属ビューとキャッシュを共有する
- **GIVEN** `key` なしのプリフェッチで URL の取得が完了している
- **WHEN** 同じ URL をローダー付属のビュー (`LazyImage` / `AsyncImage`) で直接表示する
- **THEN** 再ダウンロードなしで表示される

#### Scenario: key 付きの項目は付属ビューと共有しない
- **GIVEN** `key` を付けたプリフェッチで URL の取得が完了している
- **WHEN** 同じ URL をローダー付属のビューで直接表示する
- **THEN** 先読みの項目は使われず、付属ビュー側の通常の取得になる (先読みの項目も付属ビューの項目も壊れない)

#### Scenario: iOS のディスクキャッシュ有効化
- **GIVEN** アプリが Nuke の共有パイプラインを構成していない
- **WHEN** ライブラリを初めて使う
- **THEN** 以後の共有パイプラインはディスクキャッシュを持つ (アプリが先に構成していた場合はその構成のまま)

### Requirement: KsImage の画像ソース
`KsImage` は画像ソース `KsImageSource` を受ける (SHALL)。ソースはリモート URL・ローカルファイル・バンドル済みリソース (iOS はアセット名、Android はリソース ID) の 3 種とする (SHALL)。リモート URL のソースは任意のキー `key` を持てる (既定は省略) (SHALL。扱いは Requirement「画像の任意キー」)。リモート URL を直接渡す便宜形 `KsImage(url)` と、キー付きの便宜形 `KsImage(url, key:)` を持つ (SHALL)。利用者のモデル型にソース型の保持を要求しない (SHALL NOT)。

#### Scenario: 3 種のソースを表示する
- **GIVEN** リモート・ファイル・リソースのソースを持つ 3 つの `KsImage`
- **WHEN** 表示する
- **THEN** それぞれの画像が表示される

#### Scenario: 便宜形
- **GIVEN** `KsImage(url)` と `KsImage(url, key: k)` の書き方
- **WHEN** 表示する
- **THEN** それぞれ `KsImage(.remote(url))`・`KsImage(.remote(url, key: k))` と同じ挙動になる

### Requirement: KsImage の縮小デコード
`KsImage` は、許容範囲の内側にあるメモリ項目が無いとき、表示枠の実サイズに合わせて縮小した画像をデコードする (SHALL)。縮小の目標は当てはめ方で決まり、`fit` は枠に収まる最大寸法、`fill` は枠を覆う最小寸法とする (SHALL)。枠のサイズが確定するまでは取得を開始せず、読み込み中の表示を出す (SHALL)。枠のサイズが変わったら、新しい枠に対して引き当てをやり直し、範囲内の項目が無ければ新しいサイズで再デコードする (SHALL)。`KsImage` の表示のために元寸の画像をメモリに保持しない (SHALL NOT。プリフェッチによる元寸の保持は本要件の対象外)。`KsImage` はメモリ項目を CPU で縮小せず、必要ならローダーに縮小デコードさせる (SHALL NOT)。

#### Scenario: 枠より大きい画像
- **GIVEN** 枠より大きい元寸のリモート画像で、メモリに項目が無い
- **WHEN** `KsImage` で表示する
- **THEN** 表示に使われるデコード済み画像のピクセルサイズは、`fit` では枠のサイズ (表示倍率込み) を、`fill` では枠を覆う最小寸法を超えない。いずれも元寸の画像はメモリに展開されない

#### Scenario: サイズ確定前は取得しない
- **GIVEN** レイアウト前の `KsImage`
- **WHEN** 枠のサイズがまだ 0 である
- **THEN** 取得要求は発行されず、サイズが確定した時点で発行される

#### Scenario: 枠が変わっても範囲内なら再デコードしない
- **GIVEN** 縦向きの列幅の項目で表示中の `KsImage`
- **WHEN** 横向きになり枠が変わるが、項目が新しい枠に対して許容範囲の内側にある
- **THEN** 再デコードせず、同じ項目で表示を続ける

### Requirement: KsImage の読み込み取り消しとメモリ保持
`KsImage` が画面外に出て破棄されたとき、未完了の読み込みは取り消される (SHALL)。読み込みが完了した画像はローダーのメモリキャッシュに保持され、同じソースの `KsImage` が再び表示されたときに許容範囲の内側にあれば再デコードなしに表示される (SHALL)。メモリキャッシュから追い出された画像はディスクの元データ (リモート) またはローカルソース (ファイル・リソース) から再デコードされる (SHALL)。

#### Scenario: 画面外へ出た読み込みの取り消し
- **GIVEN** 読み込み中の `KsImage` を含むセル
- **WHEN** フリングでそのセルが画面外に出て破棄される
- **THEN** その読み込みは取り消される

#### Scenario: 戻ってきたときの再表示
- **GIVEN** 一度表示して画面外に出た `KsImage`
- **WHEN** スクロールで戻る
- **THEN** 読み込み中の表示を経由せず即座に画像が表示される

#### Scenario: 追い出された項目は再デコードする
- **GIVEN** 表示済みだがメモリキャッシュから追い出された URL の `KsImage`
- **WHEN** 再び表示する
- **THEN** ディスクの元データから枠の実サイズで再デコードされる (再ダウンロードはしない)

### Requirement: KsImage の表示状態
`KsImage` は読み込み中・成功・失敗の 3 状態を持つ (SHALL)。読み込み中と失敗時の表示は利用者がスロットで差し替えられ、未指定ならライブラリ既定の表示を出す (SHALL)。リモート・ファイルのソースは、許容範囲の内側にあるメモリ項目が無い場合に読み込み中の状態を経由する (範囲内の項目があれば読み込み中を経由せず成功になる) (SHALL)。リソースは読み込み中を経由せず成功か失敗になる (SHALL)。失敗した `KsImage` は、そのビューが作り直されたとき (セルの再利用・画面への再入場) と、`KsImageCache` の `clear` / `remove` で世代が進んだときに再試行する (SHALL)。同じビューが表示され続けている間は自動で再試行しない (SHALL NOT)。

#### Scenario: 読み込み中から成功へ
- **GIVEN** メモリキャッシュに項目が無いリモート URL の `KsImage`
- **WHEN** 表示する
- **THEN** 読み込み中の表示が出て、取得完了後に画像に置き換わる

#### Scenario: 失敗時の表示
- **GIVEN** 存在しない URL の `KsImage`
- **WHEN** 表示する
- **THEN** 失敗時の表示 (スロット指定があればその内容、無ければ既定) が出る

#### Scenario: 失敗後の再試行
- **GIVEN** 取得に失敗して失敗表示になっているセルの `KsImage`
- **WHEN** そのセルが画面外に出て再利用され、同じソースで再び表示される
- **THEN** 再度取得を試みる

#### Scenario: スロットの差し替え
- **GIVEN** 読み込み中と失敗時のスロットを指定した `KsImage`
- **WHEN** 読み込み中および失敗の状態になる
- **THEN** それぞれ指定した内容が表示される

### Requirement: キャッシュのクリア
`KsImageCache.clear(scope)` で `memory` / `disk` / `all` の範囲を指定してローダーの共有キャッシュを消せる (SHALL)。`KsImageCache.remove(source)` でソース単位にメモリとディスクの項目を消せる (SHALL)。`remove` の対象はソースの識別子 (Requirement「画像の任意キー」) で決まり、`key` を付けて保存した画像は同じ `key` を付けたソースで消える (URL が違っても消え、`key` なしの同じ URL のソースでは消えない) (SHALL)。消えるのは共有インスタンスのキャッシュであり、同じローダーを使う他画面の画像も対象になる (SHALL)。`clear` / `remove` は呼び出しから戻った時点でキャッシュの削除が完了しており、以後の同じソースの要求はキャッシュに当たらない (SHALL)。`clear(.all)` / `clear(.disk)` / `remove` の後、表示中の該当する `KsImage` は読み込み中の表示に戻って再取得する (SHALL)。`clear(.memory)` は表示中の画像を置き換えず、次に表示されるときにディスクから再デコードする (SHALL)。iOS のアセットに対する `remove` は何もしない (SHALL)。`remove` の後、そのソースの `KsImage` とプリフェッチは、どの表示サイズであっても削除前のキャッシュ項目に当たらない (SHALL NOT)。iOS では `remove` した `key` なしのソースに限り、以後は利用者がローダー付属ビューで直接要求した同じ URL とキャッシュが共有されない (削除前の項目がその側に残り得る) (SHALL)。`clear` は共有に影響しない (SHALL NOT)。

#### Scenario: 全消去の後の表示
- **GIVEN** 表示済み (キャッシュ済み) のリモート画像
- **WHEN** `KsImageCache.clear(all)` を呼ぶ
- **THEN** 表示中の `KsImage` は読み込み中の表示に戻って再ダウンロードされ、その後に表示される同じ画像も再ダウンロードされる

#### Scenario: メモリのみ消去
- **GIVEN** 表示済みのリモート画像
- **WHEN** `KsImageCache.clear(memory)` を呼んでから同じ画像を表示する
- **THEN** 再ダウンロードなしにディスクの元データから再デコードされて表示される

#### Scenario: ソース単位の削除
- **GIVEN** 表示済みのリモート画像 A と B
- **WHEN** `KsImageCache.remove(.remote(A))` を呼ぶ
- **THEN** 表示中の A は読み込み中に戻って再ダウンロードされ、B はそのまま表示され続ける (次の表示でも B はキャッシュから表示される)

#### Scenario: key 付きの画像は同じ key で消える
- **GIVEN** `key: "p1"` を付けて URL1 で表示済みのリモート画像
- **WHEN** `KsImageCache.remove(.remote(url2, key: "p1"))` を呼ぶ (URL は違う)
- **THEN** `key: "p1"` の画像のメモリとディスクの項目が消え、表示中のその `KsImage` は読み込み中に戻って再取得される

#### Scenario: key なしのソースでは key 付きの画像は消えない
- **GIVEN** `key: "p1"` を付けて URL1 で表示済みのリモート画像
- **WHEN** `KsImageCache.remove(.remote(url1))` (`key` なし) を呼ぶ
- **THEN** `key: "p1"` の画像の項目は消えず、表示も変わらない

#### Scenario: 削除後は別サイズでも旧項目に当たらない (iOS)
- **GIVEN** リモート画像 A を 2 つの異なる枠サイズで表示済み
- **WHEN** `KsImageCache.remove(.remote(A))` を呼び、A をどちらかの枠サイズで再び表示する
- **THEN** 読み込み中を経由して再ダウンロードされる (削除前のどのサイズの項目にも当たらない)

### Requirement: Sample のデモ画面「画像グリッド」
両プラットフォームの Sample に、画面タイトル「画像グリッド」のデモ画面を sample-parity 準拠 (同一文言・同一構成・同一件数) で追加する (SHALL)。画面は大量件数 (10,000 件) の画像グリッドで、プリフェッチの有無と形 (なし / ディスクまで / メモリまで / メモリまで (列幅)) を切り替える操作と、キャッシュを全消去する操作を持つ (SHALL)。「メモリまで」は表示幅なし、「メモリまで (列幅)」は列幅の `KsResource` を宣言する (SHALL)。画像は公開のプレースホルダー画像サービスから取得し、各アイテムの URL はアイテム ID から決定的に生成する (SHALL)。

#### Scenario: 切り替えの反映
- **GIVEN** デモ画面が「なし」で表示されている
- **WHEN** 「ディスクまで」に切り替える
- **THEN** 以後のスクロールで先読みが開始される (ローダーのログで確認できる)

#### Scenario: 列幅の先読みに切り替える
- **GIVEN** デモ画面が「なし」で表示されている
- **WHEN** 「メモリまで (列幅)」に切り替える
- **THEN** 以後のスクロールで列幅の先読みが開始され、先読み済みのアイテムは読み込み中を経由せず表示される

#### Scenario: 全消去
- **GIVEN** 画像が表示済みのデモ画面
- **WHEN** 全消去の操作を行い先頭へ戻る
- **THEN** 表示中の画像が読み込み中を経由して再取得される
