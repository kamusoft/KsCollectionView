## 3. 試運転

- [ ] 3.1 本リポジトリで、Claude Code から `/docs-refresh` を確かめるだけの使い方で呼び、追従は要らないと報告され、作業ツリー・記録・履歴が変わらないことを確かめる。続けて追従の使い方で呼び、ワーカーを起動せずに追従は要らないと報告して終わることを確かめる (→ Scenario: Claude Code で名前で呼べる / 変わっていなければ、追従は要らないと報告する / 何も変えない / 変わった源泉が無ければ、ワーカーを起動せずに終わる)
- [ ] 3.2 本リポジトリで、codex に使える Skill を挙げさせ、`docs-refresh` と説明が出ることを確かめる。codex から確かめるだけの使い方を呼び、同じ報告になることを確かめる (→ Scenario: codex で名前と説明が分かる)
- [ ] 3.3 リポジトリの外に、本リポジトリの今の作業ツリーの使い捨ての写し (git の履歴ごと) を作る。写しで、まず本体のソースの公開の宣言でない行だけを変えて commit し、確かめるだけの使い方が、変わった源泉は無いことと、その commit の一覧と、人が本体の差分を見る必要を報告することを確かめる。続けて、両プラットフォームのページングの 1 枚に掛かる概念の文書に、本体のコードで確かめられ、利用者向け Skill に載っていない事実を 1 つ書き足して commit し、確かめるだけの使い方の報告を確かめる (→ Scenario: 本体のソースを変えた commit があれば、一覧と、人が差分を見る必要を報告する / 変わった源泉があれば、源泉と見直す 1 枚を報告する)
- [ ] 3.4 3.3 の写しで、追従の使い方を通しで動かす。Skill ごとにワーカーへ任せること・本体の差分を見る仕方を渡すこと・検査・確かめ方の判断・承認の前に止まって決めたものを見せること・承認の後の 2 つの commit と、その後の確かめるだけの使い方で変わった源泉が無いと出ることを確かめる。最初に見せられたときは言い回しの指摘を 1 つ返し、直して見せ直されることを確かめてから承認する。承認を出す前に、写しの作業ツリーに追従と関係の無い Sample のソースの変更を残しておき、それが commit に入らないことも確かめる (→ Scenario: 両プラットフォームに掛かる源泉が変わると、Skill ごとにワーカーへ任せる / 違反が無くなると、決めたものを見せて止まる / 承認されないと、直してから見せ直す / 承認の後、2 つの commit ができ、追従は要らない状態になる / 追従で変えていないファイルは commit しない / push しない)
- [ ] 3.5 3.3 と同じ作り方の新しい写しで、次の 3 つを確かめる。(1) 記録の commit の ID を履歴に無い値にして確かめるだけの使い方を呼び、理由を報告して、要らないとは言わないこと。(2) ID を戻し、概念の文書の、利用者に見える内容を変えない文 (内部の仕組みの説明) だけを直して commit し、追従の使い方を承認まで通し、記録の commit だけができ、そのメッセージに直さなかった理由があること。(3) 概念の文書を変えて commit せずに残したまま追従の使い方を動かし、承認の後に記録を更新せず、commit していない源泉を伝えること (→ Scenario: 道具が失敗すると、理由を報告し、要らないとは言わない / 直す 1 枚が無かったときは、記録の commit だけを作る / 源泉に commit していない変更があると、記録を更新しない)
- [ ] 3.6 試運転で確かめなかった Scenario (器を起動できない・追従の使い方で道具が失敗する・名前の漏れを確かめられない・検査が落ちる・2 回戻しても残る違反・コード例のコンパイルの報告・確かめ方の判断の各行・片方のプラットフォームにだけ掛かる源泉・本体の複数行の宣言だけを変えた commit・ワーカーが決められなかった箇所・README の検査の違反・1 枚の追加が要るという報告・範囲の外が残ったままの承認) について、追従の Skill の本文とひな形の該当の箇所を、Scenario と 1 つずつ突き合わせて記録する
- [ ] 3.7 試運転の結果 (呼び方・CLI の版・報告・ワーカーの起動の回数・できた commit・確かめたこと) を `evidence/` に残し、写しを消す。本リポジトリの作業ツリーと記録を変えていないことを確かめる
