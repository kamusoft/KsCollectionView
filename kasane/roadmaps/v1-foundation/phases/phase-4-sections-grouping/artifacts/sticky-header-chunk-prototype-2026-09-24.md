# 試作: 塊に割れたグループの固定見出し (iOS) — 2026-09-24

## 目的

ios/ADR-0010 (proposed) により、500 件を超える論理セクション (グループ) は compositional layout の複数のセクション (塊) に割れる。ピン留め (`pinToVisibleBounds`) はセクション単位なので、そのままでは先頭の塊を抜けた時点で見出しが外れる。「グループの全塊に同じ見出しを付けて固定する」系の方式で、次の 2 点が起きるかを確かめた。

1. グループの途中に隙間 / かぶりが出るか
2. 塊の境目で見出しの入れ替わりの動き (押し出し → 同じ見出しの差し替え) が見えるか

使い捨ての試作であり、コードは結果を確かめた後に捨てる。

## 条件

| 項目 | 値 |
|---|---|
| 端末 | iPhone 17 Pro Simulator (iOS 26.5)、表示の最大 60 fps、Debug 構成 |
| 画面 | Sample「見出し固定試作」。2 列固定、行間 8・列間 8、左右の内側余白 8、上 0 / 下 8 |
| セル | 固定高 56pt (高さの解き直しのノイズを避ける)。通し番号とグループ名 |
| 見出し | 高さ 40pt の不透明な帯。グループ名と「塊 n/m」を表示 (どの塊の見出しかを目で区別するため) |
| データ | A 40 件 (1 塊)・B 1,200 件 (500/500/200 の 3 塊)・C 40 件 (1 塊) |
| 境目 | 塊の境目: B 塊1→2 (500/501 件目)、B 塊2→3 (1,000/1,001 件目)。比較用にグループの境目: A→B、B→C |

### 試した方式

| 方式 | 見出しの付け方 | 固定のしかた |
|---|---|---|
| 1 | 全塊に通常の見出し (場所を取る) | 全塊の見出しを UIKit のピン留め |
| 2 | グループ先頭の塊は通常、2 つめ以降の塊は `extendsBoundary = false` (場所を取らない) | 全塊の見出しを UIKit のピン留め |
| 2b | 方式 2 と同じ | 方式 2 + 2 つめ以降の見出しは固定されていない間 alpha 0 (レイアウトの属性を書き換え) |
| 3 | グループ先頭の塊にだけ通常の見出し (固定しない) | ライブラリが固定見出しを collection view の上に自分で重ねて描く (表示範囲の上端が属するグループを求め、グループの末尾で押し出す) |
| 3b | 方式 2 と同じ (全塊に付け、2 つめ以降は場所を取らない) | 全塊をピン留めしたうえで、レイアウトの派生クラスが見出しの属性を書き換える: y をグループ全体で固定した位置 `min(max(上端, グループ先頭), グループ末尾 − 高さ)` に、横位置と幅をグループ先頭の見出しに揃え、表示範囲の上端を含む塊の見出しだけ alpha 1 (他は 0)。グループ最後の塊では UIKit の alpha をそのまま使う |

### 観測のしかた

静止画ではなく、フレームごとの記録で判定した。`CADisplayLink` の各フレームで `contentOffset` を 1 段進め、レイアウトを確定させてから次を記録した。

- `contentOffset.y`
- 表示中の見出しごとに: どの塊のものか、レイアウト属性と実ビューの minY (表示範囲の上端からの距離)、x・幅、zIndex、属性とビューの alpha
- 上端を覆う見出し (見えている見出しのうち上端を含むもの) とその位置
- 上端から見出し 1 つ分 (40pt) の帯のうち、見えている見出しで覆われていない長さ (= その瞬間に見出しの帯が欠けてセルが見えている量)
- 境目ごとの静的な寸法: 塊 k の最終行の maxY と塊 k+1 の先頭行の minY の差、塊の中の行間、次の塊の見出しの素の位置

駆動は 2 通り: ゆっくりのドラッグ相当 (1 フレーム 2pt、境目の 250pt 手前から 150pt 先まで) と速いフリック相当 (1 フレーム 45pt、1,350pt 手前から 900pt 先まで)。各境目で位置を解き直してから駆動した。

## 方式ごとの所見

### 方式 1: 全塊に通常の見出し

- 隙間: 塊の境目の差 48pt (行間 8 + 40)。グループの途中 (500/501 件目、1,000/1,001 件目) に「グループ B 塊 2/3」の帯が挟まり、固定前は行の流れの中を通過する。
- 動き: 境目では、グループの境目とまったく同じ切り替わりが起きる。先頭の見出しが 14pt 押し上げられながら alpha 1 → 0 に薄れ (1pt あたり約 0.067)、その下から同じ見出しが上がってきて固定される。この間の最大 24pt、12 フレーム (24pt 分のスクロール) は上端に見出しの無い帯ができ、セルが透けて見える。
- 実装: 最小 (全塊に見出しを付けて固定するだけ)。
- 罠: 塊の件数 (500) が見た目に現れる。ios/ADR-0009 の「境界は見た目に出さない」に反する。

### 方式 2: 2 つめ以降は場所を取らない

- 隙間: なし (差 8 = 行間)。
- かぶり: 固定前の 2 つめ以降の見出しは、上端の内側余白 (8) の位置から先頭行へ 32pt はみ出して置かれ、501・502 件目の上 32pt を覆う。
- 動き: 方式 1 と同じ押し出しと差し替えが起き、欠けも同じ (最大 24pt × 12 フレーム)。
- 罠: `extendsBoundary = false` の見出しはセクションの左右の内側余白を無視した位置に置かれる (x 0。場所を取る見出しは x 8)。境目で固定見出しが 8pt 左へずれる。

### 方式 2b: 方式 2 + 固定前は見えなくする

- かぶり: なし。
- 動き: 悪化する。先頭の見出しが UIKit の押し出しで消えてから次の見出しが固定位置に現れるまで、見出しの帯全体 (40pt) が 19 フレームにわたって空く。先頭の塊の見出しの押し出しは UIKit がセクション単位で行うため、見えなくする工夫だけでは消せない。
- 罠: 方式 2 と同じ横ずれ。

### 方式 3: ライブラリが固定見出しを重ねて描く

- 塊の境目: 隙間 0、かぶり 0、押し出し 0、欠け 0。固定見出しは境目で一切動かない。
- グループの境目: 自前の押し出し (19 フレーム、-2〜-38pt) で、次のグループの見出しにそのまま押し上げられる。UIKit 標準の薄れがないため、方式 1 のグループ境目とは見え方が違う (合わせるなら薄れも自前で再現する)。
- 実装の難しさ (中〜大):
  - 見出しの View を collection view の外で別に 1 つ持ち、表示範囲の上端が属するグループの判定・位置の計算を毎フレーム (`viewDidLayoutSubviews`) 行う。
  - 重ね描きの内容の更新 (グループの値や項目が変わったとき)、高さの決定 (試作では流れの中の見出しの高さを流用)、z 順 (試作では `zPosition` 1000) を自前で持つ。
  - 流れの中の見出しと重ね描きの 2 つが同じ内容を持つため、VoiceOver から見出しが 2 重に見える恐れがある (未確認)。
  - 差分適用のアニメーション中は、重ね描きがレイアウトの動きに追従しない恐れがある (未確認)。

### 方式 3b: レイアウトの属性を書き換えてグループ全体で固定

- 塊の境目: 隙間 0、かぶり 0、押し出し 0、欠け 0、横ずれ 0。固定位置のまま、塊 1 の見出しから塊 2 の見出しへ alpha で入れ替わる。内容が同じなので見た目は変わらない (試作では区別のため「塊 n/m」を出しているので、そこだけ変わる)。
- グループの境目: UIKit 標準の押し出しと薄れがそのまま残り、グループの見え方は塊に割れないグループと同じ。
- 実装の難しさ (中): 次の段落のとおり、レイアウトの派生クラスで見出しの属性だけを書き換える。

`UICollectionViewCompositionalLayout` の派生クラスで `layoutAttributesForElements(in:)` と `layoutAttributesForSupplementaryView(ofKind:at:)` を上書きし、見出しの属性を複製して書き換える。セルの属性には触れない。見出し 1 つにつき、グループの先頭 / 末尾 / 各塊の先頭項目の属性を数回引く。

- 気づいた罠 (試作で踏んだもの):
  - **UIKit は押し出される固定見出しを薄くする** (押し出し量 14pt で alpha 0 に達する。iOS 26.5 Simulator で観測)。位置だけ書き換えると、固定位置のまま薄れて消える (試作の 1 回目で欠け 40pt × 12 フレームを記録)。グループの途中の塊では alpha を 1 に戻し、グループ最後の塊では UIKit の alpha を残す。
  - **場所を取らない見出しは x・幅が内側余白を無視する** (x 0)。入れ替わりで 8pt 横にずれる (静止画で確認)。グループ先頭の見出しの x・幅に揃える。
  - 全塊の見出しを `pinToVisibleBounds = true` のまま残す。UIKit がスクロールのたびに固定見出しの属性を問い直すのは固定見出しがあるからで、書き換え側で固定を自前にすると問い直しが来なくなる恐れがある。
  - 見出しを自分の高さで場所を取らせるのはグループ先頭の塊だけにする (素の位置の計算は「先頭行の minY − 上端の内側余白 − 見出しの高さ」。見出しは上端の内側余白の外に置かれることを計測で確認)。
  - 差分適用のアニメーション用の属性 (`initialLayoutAttributesForAppearingSupplementaryElement` など) は上書きしていない。挿入・削除のアニメーション中に見出しが UIKit の素の位置から動いて見える恐れがある (未確認)。
  - alpha 0 の見出しのアクセシビリティ上の扱いは未確認。

## 推奨

**方式 3b (全塊に見出しを付け、2 つめ以降は場所を取らない + レイアウトの属性の書き換えでグループ全体で固定) を推奨する。**

- 塊の境目の隙間・かぶり・見出しの動き・欠けを、ゆっくり・速いの両方の駆動で 0 にでき、ios/ADR-0009 の「境界は見た目に出さない」を固定見出しでも保てる。
- グループの境目は UIKit 標準の固定見出しの切り替わり (押し出しと薄れ) がそのまま残り、塊に割れないグループと見え方が揃う。方式 3 はここを自前で再現する必要がある。
- 見出しはレイアウトの supplementary view のままで、差分適用・再利用・自己サイズ・アクセシビリティの並びを UIKit に任せられる。方式 3 は collection view の外に View を 1 つ持ち、位置・内容・高さ・z 順・アクセシビリティをライブラリが保守する。
- 方式 1・2・2b は、UIKit のピン留めがセクション単位で押し出す以上、塊の境目にグループの境目と同じ切り替わりが必ず出る (欠け 24〜40pt、12〜19 フレーム)。工夫で消せない。

本採用の前に確かめること: 差分適用のアニメーション中の見出しの位置 (上の罠)、VoiceOver での見出しの扱い、塊の数が多いときの書き換えの費用、基準機での体感。

## 観測の限界

- 駆動はプログラムからの段階的なスクロールで、指のフリック (UIScrollView の減速) は記録していない。Simulator が 2 台起動していて、操作の注入先を確定できなかったため。
- 記録は Simulator (60 fps) の Debug 構成。実機・Release は測っていない。
- 静止画はオーナーの目視確認の補助として撮っただけで、判定の根拠にしていない。

## 2 周目: 方式 3c (3b + グループの境目の押し出しを方式 3 に揃える)

オーナーの目視 (Simulator) の結果、グループの境目で固定見出しが押し出される見え方は 3b (UIKit 標準の押し上げ + 薄れ) より 3 のほうが自然で、それ以外は 3b で良いとなった。3b を基本に、グループの境目の見え方だけを 3 に揃える変種 3c を試した。見出しの上下の余白 (A は見出しと先頭行の間 0、B・C は 8、最後の行と次の見出しの間 0) は規則を検討中のため変えていない。

### 方式 3 と 3b の押し出しの違い

グループの境目 B→C (C の先頭行 minY 39800) をゆっくり駆動 (2pt/フレーム) で突き合わせた。

| 境目からの位置 (pt) | contentOffset.y | 方式 3: 押し出される見出し (上端からの minY / alpha) | 方式 3b: 押し出される見出し (上端からの minY / alpha) | 方式 3b: 見出しで覆われない上端の帯 (pt) | 次のグループの見出し (両方式) |
|---:|---:|---|---|---:|---:|
| -88 | 39712 | 0 / 1.00 | 0 / 1.00 | 0 | 40 |
| -86 | 39714 | -2 / 1.00 | -2 / 0.87 | 0 | 38 |
| -82 | 39718 | -6 / 1.00 | -6 / 0.60 | 0 | 34 |
| -78 | 39722 | -10 / 1.00 | -10 / 0.33 | 0 | 30 |
| -74 | 39726 | -14 / 1.00 | -14 / 0.07 | 0 | 26 |
| -72 | 39728 | -16 / 1.00 | -16 / 0.00 | 24 | 24 |
| -62 | 39738 | -26 / 1.00 | -26 / 0.00 | 14 | 14 |
| -50 | 39750 | -38 / 1.00 | -38 / 0.00 | 2 | 2 |
| -48 | 39752 | 次の見出しへ交代 (0) | 次の見出しへ交代 (0) | 0 | 0 |

- **押し上げの位置と速さは同じ**: どちらも同じ contentOffset (39714) で押し上げが始まり、スクロール量と 1:1 で動き (2pt ごとに 2pt)、同じ位置 (39752) で次の見出しに交代する。押し上げの位置は両方式とも「グループの最終行の maxY − 見出しの高さ」で、次の見出しの上端とすき間なく接している
- **違いは透明度だけ**: 3b は UIKit が押し出し量に比例して薄くする (alpha = 1 − 押し出し量 / 15。-2pt で 0.87、-14pt で 0.07、-15pt 以上で 0)。そのため押し出しの後半 (-16〜-38pt) の 12 フレームは押し出される見出しが見えず、上端に最大 24pt、見出しの無い帯ができる。方式 3 は押し出しの間ずっと alpha 1.00

### 方式 3c の実装

3b の属性の書き換えのうち、「グループの最後の塊では UIKit の alpha を残す」をやめ、表示範囲の上端を含む塊の見出し (1 グループで 1 つだけ見せている見出し) は常に alpha 1 にした。位置の書き換えは 3b のまま。変更は分岐 1 つ。

### 方式 3c の結果

境目ごとの集計 (ゆっくり 201 フレーム・速い 44〜51 フレーム):

| 駆動 | 境目 | 押し出しのフレーム (範囲) | 上端を覆う見出しが無いフレーム | 欠けの最大 / フレーム数 | かぶり | 上端の見出しの最小 alpha | 上端の見出しの x |
|---|---|---|---|---|---|---|---|
| ゆっくり | B 塊1→2 | 0 | 0 | 0 / 0 | 0 | 1.00 | 8 |
| ゆっくり | B 塊2→3 | 0 | 0 | 0 / 0 | 0 | 1.00 | 8 |
| ゆっくり | A→B | 19 (-38〜-2) | 0 | 0 / 0 | 0 | 1.00 | 8 |
| ゆっくり | B→C | 19 (-38〜-2) | 0 | 0 / 0 | 0 | 1.00 | 8 |
| 速い | B 塊1→2・塊2→3 | 0 | 0 | 0 / 0 | 0 | 1.00 | 8 |
| 速い | A→B・B→C | 1 (-2) | 0 | 0 / 0 | 0 | 1.00 | 8 |

塊の境目の静的な寸法は 3b と同じ (塊 k の最終行 maxY と塊 k+1 の先頭行 minY の差 8 = 行間 8、見出しの帯の挟まりなし)。

- **塊の境目の 4 項目は 0 のまま**: 隙間 0 (差 8 = 行間)、かぶり 0、見出しの動き 0 (押し出し 0 フレーム、上端の見出しは位置 0・x 8 のまま同じ位置で塊 1 → 2 → 3 の見出しに交代)、帯の欠け 0。ゆっくり・速いの両方で同じ
- **グループの境目は方式 3 に揃った**: 方式 3 の記録と同じ contentOffset どうしで突き合わせると、押し出される見出しの位置・次の見出しの位置・上端を覆う見出し・覆われない帯は全フレームで一致した (ゆっくり: 各境目 201 フレーム、速い: 44〜51 フレーム)。3c の見出しは押し出しの間ずっと alpha 1.00
- 突き合わせで一致しなかったのは、方式 3 で重ね描きの下に隠れている流れの中の見出し (次のグループの見出しが重ね描きの真下で上へ流れていく分。ゆっくりで境目ごと 19 フレーム) だけで、画面には出ない

### 残った差

- 記録した項目 (位置・透明度・x・欠け・上端を覆う見出し) では、3c と 3 の見える差は無い
- 記録していない差: 見出しの View の構成が違う (次の表)。見た目には出ない

| 項目 | 方式 3 | 方式 3c |
|---|---|---|
| 固定見出しの実体 | collection view の上に重ねた別の View (z 1000) | UIKit の固定見出しそのもの (zIndex は UIKit が固定中に引き上げる値) |
| 流れの中の見出し | 重ね描きの下を通る (隠れている) | 1 グループで 1 つだけ見せ、他は alpha 0 |
| VoiceOver から見える見出しの数 | 2 重になる恐れ (未確認) | alpha 0 の見出しの扱い次第 (未確認) |
- 1 周目で「本採用の前に確かめること」とした点 (差分適用のアニメーション中の位置、VoiceOver、塊が多いときの書き換えの費用、基準機での体感) は 3c でも未確認のまま
- 3c は UIKit が押し出し中の固定見出しに alpha を掛ける挙動 (iOS 26.5 Simulator で観測した 1 − 押し出し量 / 15) を上書きしている。UIKit がこの薄めを alpha 以外 (別のプロパティや描画) で行う版では効かない
