# D&D 並べ替え

リスト・グリッドのドラッグ並べ替えを両プラットフォームで対称に提供する。

## 論点

論点はすべて決定済み (2026-09-29)。提案で扱うことは下の「提案への申し送り」にまとめた。

### phase-4 からの申し送り (2026-09-24)

- Android の項目の移動・挿入・削除のアニメーションは、セクション / グループ化の change (`sections-grouping`) で `animateItem` を入れて解決した (android/ADR-0006 accepted、amends android/ADR-0004)。D&D はこの前提から始められる

## 決定事項

### 結果の受け渡し (論点 1)

- **知らせるタイミングと仮の並びの持ち主** (論点 1 前半、core/ADR-0026): 指を離したときに 1 回だけ「どの項目をどこへ置いたか」を知らせる。ドラッグ中の仮の並びはライブラリが持ち、利用者の配列は書き換えない。VM が並べ替えた配列を渡し直すと確定する。両プラットフォーム同じ時機
- **受け入れなかったとき・保存に失敗したときの戻し方** (論点 1 後半、core/ADR-0027): 知らせを受ける処理がその場で受け入れたかを返す。受け入れなければすぐアニメーションで元の並びに戻し、受け入れたなら置いた並びのまま配列を待つ (時間で戻さない)。保存の失敗は VM が元の並びの配列を渡し直して表す

### 動かせる範囲と可否 (論点 2)

- **グループをまたぐ移動** (論点 2、core/ADR-0029): このフェーズで提供する。確定には VM が項目のグループの値を書き換えて配列を渡す。空のグループは出せないため、空のグループへは移せない (core/ADR-0015 のまま)
- **list / グリッドの両方で提供** (論点 2、既決事項から導出): list も 1 列のグリッドとして扱い (ios/ADR-0003・android/ADR-0001)、layout 値だけを差し替えられる契約 (core/ADR-0006) のため、並べ替えも layout によらず同じに効かせる
- **行き先の表し方** (論点 2、core/ADR-0028): 動かした項目と行き先を位置ではなく項目 (配列の要素そのもの) で表す。行き先は「この項目の前」か「このグループの末尾」(グループなしなら一覧の末尾) で、グループを宣言しているときは行き先のグループの値を添える
- **可否と置き先の制限** (論点 2、core/ADR-0030): 「動かせるか」(項目ごと) と「ここに置けるか」(ドラッグ中に行き先ごと) の任意の 2 つの判定を渡せる。動かせない項目は持ち上がらず、置けない場所には入らない。「置けるか」は軽い同期の判定に限る (ガイド)
- **境目に置いたときの所属** (論点 2、導出): 見出し (無ければグループの間の間隔) より上なら前のグループの末尾、下なら次のグループの先頭。見出しの無いグループも同じ。紛らわしい一覧は「置けるか」で止める
- **最後の 1 件を持ち出したときの見出し** (論点 2、導出): ドラッグ中は元のグループの見出しを残し (詰まって跳ねない・元へ戻せる)、確定して配列が届いた時点で空のグループは見出しごと消える

### 開始の操作 (論点 3)

- **持ち上げ方** (論点 3): 項目のどこでも長押しで持ち上げる。ハンドルは持たない (後から足しても今の書き方を壊さない)。テンプレートに手を入れずに動く
- **並べ替えのスイッチと長押し** (論点 3、core/ADR-0031、オーナー提案): 一覧に有効 / 無効のスイッチ (仮称「UseDragSort」、既定は無効) を持つ。有効の間は長押しがハンドルの代わりで、長押しの知らせは動かせない項目も含めて呼ばない。タップは変わらない
- **端での自動スクロール** (論点 3、導出): 両プラットフォームで付ける。速さと範囲は各 OS の自然な形に任せ、公開の設定は持たない (推測なので実機で確かめる)
- **アクセシビリティの移動操作** (論点 3、core/ADR-0032): スイッチが有効の間、動かせる項目に「前へ移動 / 後ろへ移動」の読み上げの操作をライブラリが両 OS で出す。文言は利用者が渡し、渡さなければ出さない。ドラッグと同じ知らせ・判定・受け入れを通る

### ソートとの関係 (論点 4)

- **契約にしない** (論点 4): ライブラリはソートを知らない (phase-1 の既決) ため、ソート中の扱いは VM の書き方とし、ガイドに両方を載せる — ソート中はスイッチを無効にする / 知らせを受けたら VM がソートを手動に切り替えて並べ替え、受け入れを返す

### ドラッグ中の配列の差し替え (論点 7)

- **ドラッグ中は保留** (論点 7、core/ADR-0033): ドラッグ中に届いた配列は反映を保留し最新の 1 つを持つ。受け入れたら捨てて受け入れた後の配列に従い、受け入れなければ保留した最新の配列へアニメーションで戻す

### 実装方式 (論点 5・6)

- **iOS** (論点 5、ios/ADR-0011): UIKit 標準のドラッグ & ドロップの delegate で作り、差分データソースの並べ替えハンドラは使わない。ドロップ位置 (塊と番号) を項目の行き先に読み替え、スイッチでドラッグと長押しの認識器を切り替える
- **Android** (論点 6、android/ADR-0007): Compose の公開 API の上に自前で作る。`sh.calvin.reorderable` には依存も取り込みもしない。自動スクロール・先頭の項目を動かしたときの位置飛び・持ち上げを一から解く

## 提案への申し送り

ksn-propose で設計・確認すること (議論で「提案で決める」とした細部)。

| 区分 | 内容 |
|---|---|
| 公開 API の名前と型 | スイッチ (仮称「UseDragSort」)、知らせを受ける処理と戻り値、行き先の型、判定 2 つ、読み上げの文言を渡す口。両 OS で語彙と構造を 1 対 1 に (core/ADR-0002) |
| 補助関数 | 移動を配列に当てはめる補助関数を用意するか (core/ADR-0028)。グループの値の書き換えは利用者のモデル次第 |
| 読み上げの操作 | 操作の種類 (先頭へ・末尾へを足すか) とグループの境目での動き方 (core/ADR-0032) |
| iOS の手当て | iPhone でドラッグを明示的に有効にする、iPad でアプリの外への持ち出しを止める (ios/ADR-0011) |
| ページングとの組み合わせ | ドラッグ中に追加読み込みが発火したとき、保留した配列と頼んだ後の待ち方 (core/ADR-0022・0033) の噛み合わせ |
| 実機での確認 (実装タスク) | 固定の見出しとドラッグの組み合わせ (両 OS)、端での自動スクロールの「自然な形」(推測で決めたもの) |
| ガイドに書くこと | 受け入れたら配列を並べ替えて渡す、置けるかは軽い同期の判定、読み上げの文言を渡す、グループをまたぐときはグループの値を書き換える、ソート中の 2 つの書き方 |
| Sample | 並べ替えのデモ画面を両 OS に追加 (sample-parity・sample-debug-controls)。ソートの切り替えも見せるか |
| 長命層の追随 (蒸留時) | concepts の collection-interaction (スイッチが有効の間は長押しの知らせを呼ばない) と collection-items、各 OS の architecture に並べ替えを追記 |
