# ページの境目でグループが伸びる例 (2026-09-27 の議論で使った図)

メッセージを日付でグループ分けし、1 ページ 5 件ずつ読み込む一覧の例。利用者向けガイドで「ページングとグループの組み合わせ」を説明するときの素材。

| 1 ページ目まで | 2 ページ目が届いた後 | 並び順が崩れた場合 (不正入力) |
|---|---|---|
| **9/27 (3 件)** | **9/27 (3 件)** | **9/27 (3 件)** |
| メッセージ 1〜3 | メッセージ 1〜3 | メッセージ 1〜3 |
| **9/26 (2 件)** | **9/26 (5 件)** ← 伸びる | **9/26 (2 件)** |
| メッセージ 4〜5 | メッセージ 4〜5 | メッセージ 4〜5 |
| | ― ここから 2 ページ目 ― | ― ここから 2 ページ目 ― |
| | メッセージ 6〜8 (9/26 の続き) | **9/27 (2 回目)** ← 同じ日付が離れて出る |
| | **9/25 (2 件)** | メッセージ 6 |
| | メッセージ 9〜10 | … |

- 2 ページ目の先頭が 1 ページ目の最後と同じグループの値なら、新しい見出しは作らず、既存のグループの続きとして下に足される (core/ADR-0015 の「同じ値が続く項目を 1 グループにする」)
- ライブラリは件数を数えない。伸びた項目の配列で見出しのクロージャを呼び直すだけで、「N 件」の表示はアプリの見出しが配列の数から出している
- 同じグループの値が離れて現れる並びは不正入力 (debug は assertion、release は別々のグループで表示を続けて警告ログ。core/ADR-0011・0015)。ページの境目で並び順を崩さないのは利用者 (アプリとサーバー) の責任
