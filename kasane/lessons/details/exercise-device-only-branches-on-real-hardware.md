# 教訓の経緯: 実行環境で実体が変わる資源を扱う分岐は実機で踏むまで未検証

昇格先: kasane/handbook/cross/runtime-behavior-verification.md「実行環境で実体が変わる資源を扱う分岐」(2026-09-08、severity: critical のため 1 件で即昇格。出典 change: image-loading)

## ルール文
**実行環境によって実体が変わる資源** (画像のデコード構成・GPU 資源・センサ・権限・ファイルシステムの権限モデル) を扱う分岐は、単体テストの実行環境 (Robolectric / Simulator) で緑になっても完了としない。その Scenario は**実機で踏む経路を 1 本用意するか、実機での確認を証跡に残すまで「未検証」として扱う**。テスト環境が代替実装 (ソフトウェアのビットマップ、モックのセンサ) を提供している場合、緑は「代替実装では動く」ことしか意味しない。

実装・レビュー・検証のどの段階でも、**公開 API の選択肢が実機だけで落ちる**可能性を、テストの緑では否定できない。

## 経緯
- 2026-09-07 image-loading: レビュー 3 周目のオーナー判断で「元寸を同期で引き当て、その場で縮小して初回描画に使う」経路が両プラットフォームに入った。Android の縮小は取得済みの画像から書き換え可能なビットマップを作る実装で、Robolectric ではソフトウェアのビットマップが返るため通っていた。実機のローダーはハードウェア支援の構成でデコードするため、同じ呼び出しが例外になる。**レビュー 4 周 (ホスト 4 + 相方 4) と verify を通過し、実機計測で初めて発覚**。利用者が到達点メモリを選ぶと確実にクラッシュする状態だった。関連: [[check-tests-exercise-production-path-before-accepting-green]] (あちらは「本番と違う経路を通している」、こちらは「同じ経路だが実行環境が違う」)
