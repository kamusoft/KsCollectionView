## ルール文
修正前後の挙動を比べる目的で `git stash` を使わない。**Kasane の変更は commit されないまま複数便ぶん積み上がる**ため、作業ツリー全体の退避は実装一式を失う操作になる。A/B を取るときは、比較したい**該当箇所だけを一時的に書き換えて元に戻す** (または該当ファイルのコピーを作業ツリー外に置く)。ワーカーへの git 操作の禁止は add / commit / push だけでなく、作業ツリーの状態を一括で動かす操作 (stash / checkout / restore / clean) を含むものとして扱う。

## 経緯
- 2026-09-07 image-loading: レビュー指摘の修正で「修正前に落ちて修正後に通る」A/B を取るよう指示したところ、ワーカーが変更前の状態を作るために `git stash` を実行。この change は 9 便ぶんの実装が未コミットで積み上がっていたため、作業ツリー全体が退避された。`git stash pop` で完全復旧し以後の全テストが緑であることで確認できたが、pop の失敗や競合があれば復旧不能になり得た。ワーカー規律の禁止事項は「git add / commit / push」だけを列挙しており、stash は明文で禁じられていなかった。
