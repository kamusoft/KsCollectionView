# docs-refresh — 利用者向け Skill の追従

利用者向け Skill (`skills/{en,ja}/kscollectionview-{ios,android}/` の 4 部) を、前回追従した commit からの源泉の変更に追従させる。この Skill が持つのは、入口と指揮 (メインの進め方・ワーカーへの任せ方・オーナーに見せる時点) だけである。手順の中身 (道具の出力の読み方・終了コード・直し方・確かめ方の基準) は、handbook のガイド `kasane/handbook/cross/user-skill-refresh.md` にある。この Skill の本文が「ガイドの「〜」」と書いたら、そのガイドの、その名前の節を開いて読む。言葉 (源泉・1 枚・記録・利用者役) は、ガイドの「この文書の言葉」のとおりである。

この Skill の中の言葉:

| 言葉 | 意味 |
|---|---|
| メイン | オーナーの依頼を受けて、この Skill を読み込んだセッション (あなた) |
| ワーカー | メインが器 `ksn-scribe` を指定して起動するエージェント (Claude Code: Agent ツールの `subagent_type` に `ksn-scribe` / codex: エージェントの名前 `ksn-scribe` を指定して spawn) |
| 記録の commit | 記録 (`skills/.manifest.json`) の `syncedCommit`。前回追従したときに見た commit の ID |
| 本体のソース | `ios/Sources` と `android/kscollectionview/src/main` |

## メインが守ること

- 頼まれたときにだけ動く。公開 API を変えた作業の途中などで、自分から追従を始めない
- 概念の文書の本文と、差分の本文を読み込まない。`skills-refresh.py status` は `--diff` を付けずに流し、`git diff` も流さない。メインが見るのは、道具の出力 (一覧と終了コード)・commit の一覧・ワーカーの報告だけである。差分の本文は、ワーカーが自分で出して読む
- 利用者向け Skill の文面を、自分で書き直さない。直しはすべてワーカーに任せる。ワーカーが決められずに戻した箇所も、メインが埋めずにオーナーに諮る
- ワーカーは、常に器 `ksn-scribe` を指定して起動する (Claude Code: Agent ツールの `subagent_type` に `ksn-scribe` を指定する / codex: エージェントの名前 `ksn-scribe` を指定して spawn する)。器を指定しない起動はしない (メインのモデルを継いでしまい、実作業を低コストのモデルに任せる形が崩れる)。器のモデルと effort は器の定義が決める
- ワーカーへの指示は、`references/` のひな形の `{{…}}` を埋めて渡す。ひな形の先頭のコンテキストパッケージの節は削らない (器 `ksn-scribe` は、それが無いと作業しない)
- 追従の中で直すのは、利用者向け Skill の既存の 1 枚と、記録の `sources`・`apiExclusions` だけである。README・Skill の索引・利用者役の画面の直しと、Skill の構成の見直しは行わない (ガイドの「追従の範囲」)
- オーナーの承認の前に、commit も記録の更新もしない。push はしない。追従で変えていないファイルは commit しない
- リポジトリの外に作った作業用の置き場は、使い終わったら `trash` で消す (`rm` は使わない)

## 使い方を決める

| 呼ばれ方 | 使い方 |
|---|---|
| 引数 `check`、または「追従が要るか確かめて」のように確かめるだけを頼まれた | 確かめるだけ |
| 引数なし・引数 `refresh`、または追従そのものを頼まれた | 追従 |
| どちらとも読めない | 確かめるだけで動き、報告の後に、追従に進むかをオーナーに聞く |

## 確かめるだけの使い方

何も書き換えない。作業ツリー・記録・履歴を変えず、ワーカーも起動しない。

1. `python3 scripts/docs/skills-refresh.py status` を流す (`--diff` は付けない)
   - 終了コードが 0 でなければ、標準エラー出力の理由をそのまま報告して終える。このとき「追従は要らない」とは言わない。直し方は、ガイドの「1. 変わった源泉を出す」にある
2. 出力の 1 行目の記録の commit を使い、本体のソースを変えた commit の一覧を出す (ガイドの「道具の拾い方の限界と、人が本体の差分を見る場面」のコマンドの 1 行目。差分の 2 行目は流さない)

   ```bash
   git log --oneline <記録の commit>..HEAD -- ios/Sources android/kscollectionview/src/main
   ```

3. 次の形で報告する

   | 状態 | 報告 |
   |---|---|
   | `status` に、変わった源泉・対応の決まっていない源泉・名前の変わった源泉・無くなった源泉・公開の宣言の増減のどれかがある | 追従が要る。出たものと、見直す 1 枚 (プラットフォームごと。出力の「見直す 1 枚」、無くなった源泉は「掛かっていた 1 枚」のとおり) を並べる。Skill に掛からない源泉だけが出たときは、見直す 1 枚は無いことを添える。そのうえで、掛からない源泉が名前の変わった源泉・無くなった源泉に出ていれば、追従の使い方で記録の `sources` を直す必要があることを、出ていなければ、追従の使い方では記録の commit だけになることを添える |
   | 上が無く、本体のソースを変えた commit がある | 道具の上では変わった源泉は無い。commit の一覧を添え、道具に現れない変更 (複数行の宣言の続きの行・挙動だけの変更) があり得るので、人が本体の差分を見る必要があると書く |
   | どちらも無い | 追従は要らない |

## 追従の使い方

### 1. 器を確かめる

最初に、器 `ksn-scribe` を指定してワーカーを起動できるかを確かめる (Claude Code: Agent ツールで選べるエージェントの種類に `ksn-scribe` がある / codex: spawn できるエージェントの名前に `ksn-scribe` がある)。一覧で確かめられないときは、器の定義のファイルがあるかで確かめてよい (Claude Code: ユーザーかプロジェクトの `.claude/agents/ksn-scribe.md` / codex: ユーザーの `.codex/agents/ksn-scribe.toml`)。

起動できないときは、ここで止まる。メインが代わりに書き直すことも、器を指定しない起動もしない。次の趣旨を伝える。

```
ワーカーの器 ksn-scribe が、この環境に置かれていません。
docs-refresh は、利用者向け Skill の書き直しを ksn-scribe のワーカーに任せる前提で、
メインが代わりに書き直す道を持ちません。
Kasane のリポジトリの scripts/deploy.sh を流して器を置いてから、もう一度呼んでください。
確かめるだけの使い方 (引数 check) は、器が無くても使えます。
今回は、何も変えていません。
```

### 2. 変わった源泉を出す

「確かめるだけの使い方」の 1 と 2 を流す。

- `status` が 0 で終わらなければ、理由を報告して止まる。ワーカーは起動しない
- 追従が要るものが無く、本体のソースを変えた commit も無ければ、追従は要らないと報告して終わる。ワーカーは起動しない
- 出た源泉がすべて Skill に掛からない源泉 (「見直す 1 枚」か「掛かっていた 1 枚」が `Skill に掛からない` と出たもの) で、公開の宣言の増減も、本体のソースを変えた commit も無いときは、次のとおりにする
  - 掛からない源泉が変わった源泉にだけ出たときは、ワーカーは起動しない。4 の 1 と 2 を流し、扱った源泉と「掛からない」の理由を 6 でオーナーに見せる (追従で変えたファイルが無い場合として、7 で記録の commit だけを作る)
  - 掛からない源泉が名前の変わった源泉・無くなった源泉に出たときは、ワーカーを省かない。記録の `sources` の直し (パスを今の名前にする・項目を消す) を、3 のとおりワーカー 1 つに任せる。`record` は `sources` を直さずに記録の commit の ID だけを書き換えるので、直さないと、次の `status` でも出続ける (消した源泉は「無くなった源泉」のまま、改名した源泉は「無くなった源泉」と「対応の決まっていない源泉」に形を変えて出る)

### 3. 書き直しをワーカーに任せる

利用者向け Skill 1 つ (1 プラットフォームの英語版と日本語版の組) ごとに、1 つのワーカーに任せる。ひな形は [references/prompt-rewrite.md](references/prompt-rewrite.md)。ワーカーは、器 `ksn-scribe` を指定して起動する (Claude Code: Agent ツールの `subagent_type` に `ksn-scribe` / codex: エージェントの名前 `ksn-scribe` を指定して spawn)。

どのプラットフォームのワーカーに渡すかは、`status` の出力と commit の一覧から、次のとおり決める。メインは源泉の本文を開いて決めない。

| 出たもの | 渡す先 |
|---|---|
| 変わった源泉・名前の変わった源泉・無くなった源泉 | 「見直す 1 枚」(無くなった源泉は「掛かっていた 1 枚」) に `(ios の Skill だけ)` / `(android の Skill だけ)` とあればその Skill、無ければ両方 |
| 対応の決まっていない源泉 | パスが `kasane/concepts/ios/` の下なら iOS、`kasane/concepts/android/` の下なら Android、ほかは両方 |
| 公開の宣言の増減 | 行のパスが `ios/` なら iOS、`android/` なら Android |
| 本体のソースを変えた commit | プラットフォームごとに `git log --oneline <記録の commit>..HEAD -- ios/Sources` と `... -- android/kscollectionview/src/main` を流し、一覧が出た方 |

- 「見直す 1 枚」か「掛かっていた 1 枚」が `Skill に掛からない` と出た源泉は、上の表に当てない (1 枚を見直すためには、どのワーカーにも渡さない)。変わった源泉に出たものは、扱った源泉として 6 でオーナーに見せる。名前の変わった源泉・無くなった源泉に出たものは、記録の `sources` の直しだけを、ワーカー 1 つに渡す。渡す先は、上の表で渡す先があれば最初に起動するワーカー、無ければ iOS の Skill のワーカーとする (ひな形の「見直す 1 枚」は「なし」にする)
- 両方の Skill に渡すときは、ワーカーを 1 つずつ順に起動する (同じ記録のファイルを 2 つのワーカーが同時に書かないため)。後のワーカーには、先のワーカーが記録に書いた変更を伝える
- ワーカーの報告の「決められなかった箇所」(新しい内容を載せる 1 枚・載せない名前の候補・源泉と本体のコードの食い違いなど) は、メインが埋めずにオーナーに諮る。オーナーが決めた内容を、ひな形の「決まったこと」に書いて、同じプラットフォームのワーカーにもう一度任せる
- ワーカーの報告の「範囲の外の直しが要る箇所」と「今の 1 枚のどれにも入らない内容」は、ワーカーに戻さない。6 でオーナーに伝える (ガイドの「追従の範囲」)
- ワーカーがコード例を変えた・足したのに、コンパイルの結果が報告に無いときは、同じワーカーに戻して確かめさせる
- 「ワーカーに戻す」は、同じプラットフォームの書き直しを、ひな形の「戻された指摘」か「決まったこと」を埋めて任せ直すことである。起動したワーカーに続きを送れる環境なら続きを送ってよく、送れないときは、器 `ksn-scribe` を指定して新しく起動する (Claude Code: Agent ツールの `subagent_type` に `ksn-scribe` / codex: エージェントの名前 `ksn-scribe` を指定して spawn)

### 4. 検査を流す

ワーカーの書き直しが終わったら、メインが次を流す。ワーカーが何も書き換えなかったとき・ワーカーを起動しなかったときも、1 と 2 を流す (README の例の検査は、源泉 (利用者役の画面など) の変更だけでも結果が変わりうるため)。読むのは出力と終了コードだけである。漏れや違反をワーカーに戻すときも、器 `ksn-scribe` を指定する (Claude Code: Agent ツールの `subagent_type` に `ksn-scribe` / codex: エージェントの名前 `ksn-scribe` を指定して spawn)。

1. 公開の宣言の名前の漏れ: `python3 scripts/docs/check-api-coverage.py` (読み方はガイドの「3. 公開の宣言の名前の漏れを見る」)
   - 漏れは、そのプラットフォームのワーカーに戻す。ワーカーは宣言を読み、利用者が使う名前なら 1 枚に載せ、利用者向けでないと判断した名前は、載せない候補として報告する。候補は 3 の「決められなかった箇所」と同じに扱う
   - 終了コードが 3 (確かめられなかった) のときは、漏れが無いとは扱わず、出力の理由を添えてオーナーに諮る
2. ガイドの「4. 検査を流す」の検査 (Skill の整合・README の例・スクリプトのテスト・3 つの lint)
   - 違反は、そのファイルのプラットフォームのワーカーに戻す。追従の範囲の外のファイル (ルートの README・Skill の索引・利用者役の画面など) の違反は、ワーカーに戻さず、6 でオーナーに伝える
   - 同じ違反を 2 回戻しても検査が同じ違反を出すときは、それ以上戻さず、残った違反を添えてオーナーに諮る
3. 戻した直しが終わるたびに、1 と 2 を流し直す。追従の範囲の中の漏れと違反が無くなるまで、オーナーには見せない。範囲の外のファイルの違反は、残ったままで 6 へ進み、範囲の外の直しとしてオーナーに伝える (残ったまま承認されたときは、6 のとおり記録の commit の ID を更新しない)

### 5. 配った先を再現した確認を決めて行う

ワーカーが報告した「変えたもの」を、ガイドの「初回と同じ確かめ方をする場面」の表の行に当てて、読ませる確認と使わせる確認の回数を決める。複数の行に当たるときは、回数の多い方の行を採る。当てた行と理由は、回数が 0 でも 6 でオーナーに見せる。

回数が 1 回以上なら、確認ごとに 1 つのワーカーを、器 `ksn-scribe` を指定して起動する (Claude Code: Agent ツールの `subagent_type` に `ksn-scribe` / codex: エージェントの名前 `ksn-scribe` を指定して spawn)。進め方は、ガイドの「読ませる確認」「使わせる確認の進め方」「5 つの課題」のとおりである。

| 確認 | メインがすること | ひな形 |
|---|---|---|
| 読ませる確認 | リポジトリの外に空の置き場を作り、Skill の 1 ディレクトリ (1 つの言語) だけを写して、その場所だけをワーカーに渡す | [references/prompt-read-check.md](references/prompt-read-check.md) |
| 使わせる確認 | リポジトリの外に空の置き場を作り、英語版の Skill の 1 ディレクトリだけを写して、課題と条件と一緒にワーカーに渡す。書かれたファイルは、メインが作業用の写しの中でビルドする (ガイドの「使わせる確認の進め方」の「作業用の写し」「ビルド」) | [references/prompt-use-check.md](references/prompt-use-check.md) |

- 挙がった指摘・ビルドの失敗の出力・「推測が要ったところ」は、メインが仕分けずに、そのプラットフォームの書き直しのワーカーに渡す (3 のひな形の「戻された指摘」。器 `ksn-scribe` を指定する (Claude Code: Agent ツールの `subagent_type` に `ksn-scribe` / codex: エージェントの名前 `ksn-scribe` を指定して spawn))。直した後は、4 を流し直す
- 作業用の置き場と写しは、確認が終わったら `trash` で消す。本リポジトリの利用者役の画面は入れ替えない

### 6. オーナーに見せて承認を待つ

ガイドの「6. オーナーの承認を得る」の見せるものを、ワーカーの報告と道具の出力から組み立てて見せる。あわせて、残っている範囲の外の直し (あれば) は別の作業で直す必要があることと一緒に、構成の見直し (あれば) は変更の実装で行う必要があることと一緒に伝える。

ここで止まり、承認を待つ。

- 承認されなかったときは、指摘を書き直しのワーカーに戻し (3 のひな形の「戻された指摘」。器 `ksn-scribe` を指定する (Claude Code: Agent ツールの `subagent_type` に `ksn-scribe` / codex: エージェントの名前 `ksn-scribe` を指定して spawn))、4 から流し直して、もう一度見せる
- 範囲の外の直しや構成の見直しが残ったまま承認されたときは、7 の 1 つ目の commit だけを作り、記録の commit の ID は更新しない。その理由 (残った源泉の変更を、次の追従でも見つけられるようにするため) をオーナーに伝える。範囲の中の直しも無く、作る commit が 1 つも無いときは、6 でオーナーに見せた内容をその回の追従の証跡とし、commit を作らないことを伝える

### 7. commit と記録の更新

承認の後に、ガイドの「commit と記録の更新の順」のとおりに行う。

1. 追従で変えたファイル (ワーカーが報告した、利用者向け Skill の 1 枚と、記録のファイル) だけを、パスを名指しして `git add` し、`git commit --only -- <パス…>` で、そのパスだけの 1 つの commit にする。作業ツリーと index のほかの変更 (前から stage されている別の作業の変更を含む) は入れない。利用者向け Skill の 1 枚にも、記録の `sources`・`apiExclusions` にも、追従による変更が無いときだけ、この commit を作らない。直した 1 枚が無く、記録の `sources`・`apiExclusions` だけを直したときも、この commit を作る (`record` は記録のファイルの変更では止まらないので、作らないと、対応表の直しが記録の commit に混ざる)
2. `python3 scripts/docs/skills-refresh.py record` を流す
   - 終了コード 1 で、源泉に commit していない変更があると出たときは、記録を更新しない。commit していない源泉の一覧と、オーナーがそれを commit してから記録を更新する必要があることを伝えて終える。源泉の変更を、メインが commit することはしない
3. 書き換わった記録のファイル (`skills/.manifest.json`) だけを、もう 1 つの commit にする (`git commit --only -- skills/.manifest.json`)
4. `python3 scripts/docs/skills-refresh.py status` を流し、変わった源泉が無いと出ることを確かめて、オーナーに報告する

push はしない。

追従の証跡 (ガイドの「追従の証跡」) は、最初に作る commit のメッセージに書く。1 の commit を作らなかったときは、記録の commit が最初の commit になる。commit が 1 つもできないとき (6 の 2 つ目の箇条と、1 の commit が無いまま 2 の `record` が止まったとき) は、6 でオーナーに見せた内容と、止まった理由として伝えた内容が証跡になる。

```
利用者向け Skill を追従 (<記録の commit の短い ID> からの源泉の変更)

扱った源泉:
- <パス> (<変わり方>): <扱い>
直した 1 枚:
- <Skill の名前>/<1 枚> (英語版・日本語版): <直した内容の要約>
直さなかった源泉と理由:
- <パス>: <理由>
流した検査と結果:
- <検査>: <結果>
```
