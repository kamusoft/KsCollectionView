# ひな形: 使わせる確認

配った先を再現した確認のうち、使わせる確認を 1 回行うときに、メインが、器 `ksn-scribe` を指定して起動したワーカーに渡す (Claude Code: Agent ツールの `subagent_type` に `ksn-scribe` を指定する / codex: エージェントの名前 `ksn-scribe` を指定して spawn する)。器を指定しない起動はしない。1 回ごとに、新しいワーカーを起動する。

渡す前に、メインが次を用意する (進め方の中身は、ガイド `kasane/handbook/cross/user-skill-refresh.md` の「使わせる確認の進め方」と「5 つの課題」)。

- リポジトリの外に、空の作業用の置き場を作る
- 確かめるプラットフォームの英語版の Skill の 1 ディレクトリ (例: `skills/en/kscollectionview-android/`) だけを、その置き場に写す
- 課題を、ガイドの「5 つの課題」の表から選ぶ (新しい機能を載せたときは、その機能を使う課題を 1 つ作る)

ワーカーには、置き場のパスと課題と条件だけを渡す。リポジトリのパス・ガイド・ほかの文書は渡さない。`{{…}}` を埋めてから渡す。先頭のコンテキストパッケージの節は削らない。

```
# コンテキストパッケージ

1. 読むべきスキル: なし (従うことは、この指示の本文にある)
2. change-id: なし
3. 担当範囲: 下の置き場の中に、画面のファイルを 1 つ書くことだけ
4. 制約:
   - 置き場の外のファイルを読まない・書かない。Web を使わない
   - このライブラリについて前から知っていることを使わない。置き場の Skill に書いてあることだけで書く
   - ビルドしない (ビルドは呼び出し元が行う)
   - 報告は、テキストで返す

あなたは、このライブラリを初めて使う開発者のエージェントです。手元にあるのは、次の置き場に
コピーされた Agent Skill 1 つだけです。この Skill だけを頼りに、課題の画面を書いてください。

置き場: {{作業用の置き場のパス}}
プラットフォーム: {{iOS (SwiftUI) か Android (Jetpack Compose)}}

## 課題
{{ガイドの「5 つの課題」の「書かせる画面」の文。例: 続きを読み込む一覧。失敗したときの再試行の表示と、空のときの表示を持ち、Pull to Refresh で取り直す}}

## 条件 (ビルドの入口とつなぐためのもので、ライブラリの知識ではない)
- 画面の名前は ItemListScreen にする。引数を取らない
- 1 つのファイルに収める。ファイルは {{置き場のパス}}/ItemListScreen.{{swift か kt}} に書く
- {{Android のときだけ: package の宣言を書かない。モジュールは Material に依存していない (Material のコンポーネントを使わない)}}
- データは、画面の中で作る仮のものでよい

## 報告の形
- 書いたファイル: <パス>
- 使った Skill の 1 枚: <ファイルと見出し>
- 推測が要ったところ: <Skill に書いてなくて推測で書いたところ・迷ったところを、1 件 1 行で。無ければ「なし」>
```

ワーカーが書いたファイルは、メインがビルドする。リポジトリの外に、本リポジトリの今の作業ツリーの使い捨ての写しを作り、写しの中の利用者役の画面のファイルと入れ替えて、確認のスクリプトを `--mode local` で流す (ガイドの「使わせる確認の進め方」の「作業用の写し」「ビルド」「Android の作業用の写し」)。本リポジトリの利用者役の画面は入れ替えない。

ビルドの結果と「推測が要ったところ」は、メインが仕分けずに、そのプラットフォームの書き直しのワーカーに「戻された指摘」として渡す (書き直しのワーカーも、器 `ksn-scribe` を指定して起動する: Claude Code は Agent ツールの `subagent_type`、codex はエージェントの名前で spawn)。ビルドが落ちた回は、書き直しのワーカーの仕分けが「書き損じ」なら、新しいワーカーで 1 回だけやり直す。置き場と写しは、確認が終わったら `trash` で消す。
