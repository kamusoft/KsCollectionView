# ひな形: 読ませる確認

配った先を再現した確認のうち、読ませる確認を 1 回行うときに、メインが、器 `ksn-scribe` を指定して起動したワーカーに渡す (Claude Code: Agent ツールの `subagent_type` に `ksn-scribe` を指定する / codex: エージェントの名前 `ksn-scribe` を指定して spawn する)。器を指定しない起動はしない。1 回ごとに、新しいワーカーを起動する。

渡す前に、メインが次を用意する (進め方の中身は `kasane/handbook/cross/user-skill-refresh.md` の「読ませる確認」)。

- リポジトリの外に、空の作業用の置き場を作る
- 確かめる Skill の 1 ディレクトリ (1 つの言語。例: `skills/ja/kscollectionview-ios/`) だけを、その置き場に写す

ワーカーには、置き場のパスだけを渡す。リポジトリのパス・ガイド・ほかの文書は渡さない。リポジトリの中で読むと、Skill の外の知識で補って読めてしまい、欠けに気付けないためである。`{{…}}` を埋めてから渡す。先頭のコンテキストパッケージの節は削らない。

```
# コンテキストパッケージ

1. 読むべきスキル: なし (従うことは、この指示の本文にある)
2. change-id: なし
3. 担当範囲: 下の置き場の中のファイルを読むことだけ
4. 制約:
   - ファイルを書き換えない・作らない
   - 置き場の外のファイルを読まない。Web を使わない
   - このライブラリについて前から知っていることを使わない。置き場に書いてあることだけで判断する
   - 報告は、ファイルに書かずに、テキストで返す

あなたは、このライブラリを初めて使う開発者のエージェントです。手元にあるのは、次の置き場に
コピーされた Agent Skill 1 つだけです。

置き場: {{作業用の置き場のパス}}
言語: {{英語版 か 日本語版}}

SKILL.md から始めて、置き場の中のファイルをすべて通して読み、次の 4 つを挙げてください。

1. 意味の分からない言葉 (説明なしに使われている言葉・型・概念)
2. 足りない説明 (やりたいことを書くのに、書いていないことがあって手が止まるところ)
3. Skill の外を見ないと分からないこと (置き場に無いファイル・リポジトリ・文書を前提にしているところ)
4. 冒頭を読んで、これが何で、いつ使うものかが分かるか

## 報告の形
指摘ごとに 1 行で、次の形にする。指摘が無い分類は「なし」と書く。
- <分類 (1〜4)> / <ファイル>:<見出し> / <何が分からないか・何が足りないか>
最後に、冒頭で分かったこと (これが何か・いつ使うか) を 2〜3 文で書く。
```

ワーカーの報告は、メインが仕分けずに、そのプラットフォームの書き直しのワーカーに「戻された指摘」として渡す (書き直しのワーカーも、器 `ksn-scribe` を指定して起動する: Claude Code は Agent ツールの `subagent_type`、codex はエージェントの名前で spawn)。置き場は、確認が終わったら `trash` で消す。
